# 页面点击秒开：路由 chunk 预取 + 运维页数据缓存

## Context（背景）

用户反馈：点击每个页面都要先等一会才打开。排查确认路由层没有阻塞（无 loader/guard，`<Link>` 点击即切换 URL），"等待感"来自三处：

1. **懒加载 chunk 无预取**：16 个页面全部 `React.lazy`（`web/src/app/App.tsx:19-35`），首次点击某菜单时才下载该页 JS chunk，期间内容区只有 Suspense 空白 Spin（`App.tsx:66`）——页面"打不开"的主因。
2. **运维 5 个路由重挂载重加载**：`/clusters|/applications|/websites|/domains|/certificates` 是 5 条独立 Route 渲染同一 `OperationsPage`（`App.tsx:79`），每次切换重挂载、`overviewReady` ref 丢失，重新走顺序加载（`OperationsPage.tsx:75-118`：先 `/ops/resources?kind=…&view=config` 再 `/ops/overview`）。
3. 各页面数据到位前显示 Spin/表格 loading——用户已接受此形态（"没好就加载中"），保留不动。

目标：点击后前端立即切换到目标页面并渲染页面结构，数据未就绪时显示加载态；运维菜单切换利用缓存秒开。

## 实施步骤

### 0. SDD 文档（按 AGENTS.md 流程先行）
新建 `specs/027-instant-page-navigation/`：`spec.md`（需求与验收标准）、`plan.md`（设计）、`tasks.md`（任务清单）。架构影响判断填"不适用"：纯 web 前端交互优化，不改变组件职责、数据路径、协议、存储、部署拓扑；`docs/system-design.md` 不更新，PR 中说明理由。不涉及镜像打包，无需版本号 bump。

### 1. 新建 chunk 预取模块 `web/src/app/route-preload.ts`
- 把 `App.tsx` 里 16 个 `lazy(()=>import(...))` 的导入函数抽出为模块级 loader 注册表（同一模块specifier，Vite 自动去重 chunk）。
- 导出 `preloadRoute(path)`（按 sidebar path 精确/前缀匹配，如 `/machines`+`/agents`→HostsNodesPage、5 个运维路径→OperationsPage、`/dashboards*`→DashboardPage 等）和 `preloadAllRoutes()`（去重后逐个触发 import）。
- `App.tsx` 改为 `lazy(loadX)` 引用这些 loader。

### 2. 两个预取触发时机
- **悬浮/键盘聚焦预取**：`web/src/app/SidebarNavigation.tsx` 的 `<Link>` 加 `onPointerEnter`/`onFocus` → `preloadRoute(path)`。
- **空闲全量预取**：`App.tsx` 登录态 shell 渲染后，用 `requestIdleCallback`（fallback `setTimeout`）串行跑 `preloadAllRoutes()`，仅下载/编译 JS 模块、不发任何 API 请求；内网后台流量可控，点击任意菜单均命中本地缓存秒开。

### 3. 运维页跨路由缓存（stale-while-revalidate）
`web/src/app/OperationsPage.tsx`：
- 模块级 `let opsOverviewCache: Overview | undefined`。
- 挂载时若缓存存在：`overview` state 初始化为缓存、`loading` 初始 `false`、`overviewReady.current=true`、`statusReady` 初始 `true`，随后现有 `load()` 走 quiet 静默刷新路径（`!quiet&&!overviewReady.current` 判断已天然支持），数据到达后更新缓存与界面。
- `/ops/overview` 拉取成功处（`OperationsPage.tsx:99-104`）同步写缓存。
- 效果：集群↔应用↔网站等切换立即显示上次数据，后台静默刷新；10s 轮询兜底一致性。

### 4. Suspense fallback 保留
预取后 fallback（`App.tsx:66`）极少出现，维持现有 `<div className="lm-page"><Spin/></div>` 不改。

## 验证
1. `cd web && npm run typecheck`。
2. 新增 Playwright 验收脚本 `web/test/instant-navigation.mjs`，仿照 `web/test/slow-applications-load.mjs` 的自建 vite dev server + http fixture 模式：
   - fixture：`/ops/overview` 固定延迟（如 3s），`/auth/me` 返回 admin；其余端点立即返回。
   - 断言 A（秒开）：打开 `/overview` 并等 idle 预取完成后，点击"应用管理"，URL 与页面结构（工具栏/表格区）在远小于 fixture 延迟的时间内出现，数据到达前可见 Spin/加载态，随后显示慢速资源名。
   - 断言 B（缓存）：`/applications` 数据可见后切 `/clusters` 再切回，断言立即显示资源（缓存命中，无整页 Spin），且 `/ops/overview` 请求数按预期增加（静默刷新发生）。
3. 手动 `npm run dev` 连真实后端抽查：逐个点击侧边栏菜单，确认首次点击即出页面结构。
4. 完成后在功能分支（自 `main` 新建 `codex/207-instant-page-navigation`）提交；用户要求时再创建 PR。
