# 每表上报聚合周期验收（2026-10-19）

本次范围：每张业务指标表选择一个周期，默认30秒，支持10秒、30秒、1分钟、5分钟、10分钟、30分钟、1小时；同表所有指标与实例遵循配置，不同表独立设置。入口为“管理后台 → 数据表 → 聚合周期”。

2026-10-20与最新main整合后，入口改为“数据管理 → 聚合周期”，已重新执行下述真实专项，report.json为最新结果；完整主干整合验收见[整合记录](../metric-main-integration/README.md)。下表保留首次实现时的检查结果。

## 行为与兼容

- 管理API只接受七档整数标量，数组、字符串、枚举外值返回400；仅管理员可修改。
- 配置保存在SQLite，至少一分钟后的新旧周期共同边界生效。重复保存待生效值不推迟原时间，选回当前周期可撤销待生效项。
- Go、Node、Python、Rust按调用时刻选择该表生效配置，缺省30秒。非法快照保留上一份有效配置。
- 查询步长必须为实际窗口的正整数倍；跨历史周期取公倍数。大盘/告警自动对齐范围与步长，普通查询拒绝不对齐参数；旧无固定窗口数据继续可查。
- 旧SDK配置请求不增加字段；新SDK显式协商metric_windows=1。匿名配置只包含启用的豁免表，无效密钥不降级。

## 真实集成与界面

[专项脚本](../../../scripts/verify-metric-periods.mjs)使用独立中心18887、独立SQLite目录`.local-dev/metric-periods-qa/state`及测试ClickHouse18123。仅向带periodqa前缀的测试表写入；没有向用户运行实例写入测试数据，也没有替换接口响应。

- 七档经真实管理API保存；验证默认30秒及非法周期拒绝。
- 为避免等待最长1小时，隔离SQLite中将本次测试表的配置设为过去已生效。Node SDK通过真实配置接口获取，再经OTLP写入ClickHouse。每表两次flush共3个样本，总值60，各表的window_seconds分别正确；30秒数据以10秒步长查询返回错误。
- 浏览器逐一选择、保存、重新打开七档并检查回显。切换到真实成员会话使保存返回403，确认所选值保留；恢复管理员会话后重试成功。不同表配置保持独立，无pageerror。
- 检查1440px桌面及390px窄屏，聚合周期对话框与操作按钮均位于视口内。截图保存在Git忽略目录`artifacts/screenshots/metric-periods/`。
