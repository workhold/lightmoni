# 使用体验检查与完善

检查了大盘、日志、告警、Agent 和 SDK 接入页，沿用现有界面、颜色、组件和交互。本轮集中修复大盘的加载、保存、复制、删除和窄屏布局，没有重新设计页面。

## 问题与修复

| 原来的行为 | 本次结果 |
| --- | --- |
| 390px 大盘列表撑到 780px，操作列落在屏幕外 | 页面保持 390px；表格内部横向滚动，窄屏隐藏次要列，模板改为单列 |
| 详情首次读取失败，“重试”只刷新列表，详情请求仍只有一次 | 重试真正重新请求当前详情，恢复查询结果 |
| 列表和模板没有独立的加载、失败提示 | 列表、数据目录分别加载和重试；刷新失败保留已有列表 |
| 搜索空白敏感，无匹配时缺少引导 | 名称和描述搜索忽略首尾空白，提供清除搜索 |
| 保存完成没有结果提示，等待时还能改表单 | 保存、复制、创建、删除都有反馈；保存中锁定名称、描述、选项和取消按钮 |
| 告警设置链接复制大盘后，还携带原面板定位 | 新副本清除旧 `panel` / `tab`，保留时间筛选 |
| 删除遇到版本冲突时重复提交旧版本 | 读取最新名称和版本，用户检查后重新确认；不走保存覆盖流程 |
| 旧 SQL 工作台链接会额外添加一条历史记录 | 重定向使用替换，浏览器返回不会再次陷入旧链接 |

四份上一轮验证留下的临时大盘，核对 ID、名称、初始版本、面板及 SQL 均未改动后已删除。其他大盘保留。[清理记录](cleanup.json)。

## 验证

主 Agent 运行 `web/src/features/dashboards/verify-usability.mjs` 连续三轮：每轮都走实际 UI，并使用真实 SQLite、ClickHouse 核对保存后的名称、面板和版本。仅请求延迟、503 失败受控；删除冲突由真实服务端版本更新触发。每轮的临时大盘按最新版本删除，清理失败会使验证失败。

前两轮为开发页面。默认开发端口 5173 被其他项目占用，因此测试浏览器将开发页面的写请求代理到配置的中心 Origin；第三轮直接使用已部署的 `http://localhost:18380`，不走测试代理。没有修改中心的 Origin 校验。
