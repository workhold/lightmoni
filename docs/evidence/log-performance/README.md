# 日志页大量数据性能验证

2026-10-12，在当前源码预览 `http://localhost:15174` 中复现并优化。

原开销来自字段栏：每次渲染逐字段 `rows.find`，同时反复执行属性 JSON 的整数处理和解析。2000 条日志、40 个首次出现在末尾的属性下，输入 `trace 123` 触发 1,383,696 次属性解析。日志表的列定义和单元格也随查询草稿重新创建。

修改后每条结果对象通过 WeakMap 缓存属性解析和原始类型，结果被丢弃后可回收；字段名称及类型一次遍历建立索引。缓存检查原始 JSON 和回退属性对象，保留大整数精度，并在数据替换后更新。原始日志表独立为 memo 组件，列、滚动设置、回调保持稳定；正文显示模式与新行内容仍会更新。时间格式器复用，左右滚动和列宽拖动按动画帧合并。冻结会话的分页复用时间图数据，避免分页时重建图表。

压力脚本：`web/src/features/logs/verify-performance.mjs`。使用 2000 条、2,477,041 字节的受控日志响应，8 个显示列与 40 个末尾属性；收起时间图以测量字段和表格开销。仅通过浏览器请求拦截注入，未修改存储目录或真实日志。计时包含浏览器自动化输入，属于本地前端测试，未衡量后端查询耗时。
