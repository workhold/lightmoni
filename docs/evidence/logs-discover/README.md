# 日志 Discover 改造与验收

沿用 LightMoni 的深色导航、明亮工作区、共享 AntD 控件和蓝色主操作，以日志内容为主角，参考 [Elastic Discover](https://www.elastic.co/docs/explore-analyze/discover/discover-get-started) 的查询、字段探索和结果下钻流程。没有新增全局设计系统。

## 实现变化

- 查询入口分成字面正文、字段表达式和 SQL；修复正文包含冒号时被误解析的问题。表达式提供键盘字段补全和语法帮助。
- 字段栏区分已选/可用字段，提供类型、搜索、完整查询范围 Top 值和显示列操作；属性发现范围明确为当前载入的日志。
- 时间图、原始日志与字段统计位于同一工作区。拖选或桶下钻后可恢复原时间范围，保留其他查询条件。
- 日志提供明确的详情箭头、上一条/下一条、原文/JSON/属性查看以及属性包含、排除和加列操作；支持单行、三行和自动换行。
- 未保存的检索链接保留关键词、多服务、类型化过滤、排序、SQL、列与换行配置，冻结绝对范围。新标签和刷新无需依赖原标签的 history state；链接不携带结果行、登录凭证或查询会话游标。
- 新查询回到列表起点，修复固定时间列遮挡新结果级别表头的问题；刷新继续保留阅读锚点。
- 窄屏搜索独占一行，日志时间显示日期与毫秒；级别色在图表/列表保持一致；区分完整匹配数、已载入数及列表截断。

删除了常驻且重复的聚合摘要卡和结果工具栏中的 SQL/CSV/跨模块按钮堆叠，功能进入字段统计页签及更多菜单；没有删除对象名、范围、截断依据或主操作。

## 实际验证

使用 Docker 主服务 `localhost:18380`、本机 Agent `14318`、SQLite 与 ClickHouse，前端源预览 `localhost:15174`。数据通过 Go/Node SDK 上报，没有替换 API 响应。

| 验证 | 结果 |
| --- | --- |
| `npm --prefix web run typecheck` | 通过 |
| 日志 model / expression 单元回归 | 10 项通过 |
| `examples/logs/smoke.mjs` | SDK 数据、200/400/480 分页、service/typed filter、列、详情/JSON/上下文、保存分享、SQL 返回、CSV、实时暂停/恢复通过 |

## 范围边界

完整 KQL/Lucene/ES|QL、任意字段排序、多表日志检索及索引管理没有在本轮实现。历史列表仍是 2,000 条/8 MiB、2 分钟的有界会话，图表和字段统计分别执行完整范围聚合；不宣称事务快照或与指定 Kibana 版本的完整功能、规模、性能等同。

本轮没有修改后端或部署 Docker 运行版；没有运行生产打包。预览代理用于真实 API 联调，不能替代生产 Origin/CSRF 验收。
