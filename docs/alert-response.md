# 告警响应、值班和通知

本次将告警组改为人员责任组。系统通知接入保存供应商配置，用户资料保存个人联系方式，组内排班决定当时联系谁，P0～P3 策略决定使用什么渠道、何时提醒和升级。全部能力运行在现有 Go 主服务和 SQLite 中。

告警中心默认打开“告警规则”，随后为“告警组”，再展示响应、统计、静默等入口；通知接手链接仍直接打开告警响应。规则名称固定在最左列，等级放在第三列，优先显示高等级规则；创建/编辑时在顶部设置等级。大盘的每个告警条件也可设置P0～P3，并通过“预览告警”弹窗检查固定窗口、条件判断和通知目标。规则编辑器的“执行预览”使用相同弹窗，预览不会保存规则或发送通知。未配置成员或班次的组也可打开排班编辑，不会因空字段崩溃。

## 配置顺序

1. 管理员在“设置 → 通知接入”配置飞书、钉钉、企业微信、邮件、短信、电话或 Webhook。
2. 用户在“设置 → 告警联系方式”填写邮箱、手机号和平台用户 ID；管理员也可以在用户管理中维护。
3. 在“告警中心 → 告警组”选择成员、系统接入、主班、备班、兜底及等级策略。
4. 将组绑定到数据表，或在规则中明确选择责任组；填写业务等级和现场日志、Trace 来源。
5. 在“告警响应”查看接手、升级和现场；“接手统计”查看人员指标；“静默窗口”管理维护时段。

通知链接使用系统的外部访问地址。该地址需要能从值班人的手机和浏览器访问；需要卡片或电话回执的接入还需让供应商访问回调地址。

## 值班排班

支持固定人员、按天、按周和自定义 N 天循环。每个班次均可有多个主班和备班，另有组内兜底人员。第1周通知1、2，第2周通知2、3，可以配置两个周班次后自动循环。

循环起点包含日期和交接时间，按照组的 IANA 时区和当地日历计算，避免夏令时造成班次偏移。支持指定开始与结束的临时替班；替班覆盖该时段的主备配置。界面预览未来14天，API 最多预览90天，并显示缺少主班的日期。

每一轮重新解析当前班次，已经创建的通知保存接收人快照。已接手事件继续由原负责人处理，交班不会自动释放责任。组成员移除、用户停用、联系方式变化、接入停用会在发送前重新检查；开放事件可以由管理员点击“应用当前组配置”，更新排班和策略并保留负责人、历史通知与统计。

## 等级、静默与升级

以下为可编辑的初始模板，分钟数属于本产品默认值。

| 级别 | 通知方式 | 通知窗口 | 默认升级 |
| --- | --- | --- | --- |
| P0 | 电话、短信、群消息 | 全天 | 每2分钟提醒；5分钟备班；10分钟兜底 |
| P1 | 短信、群消息 | 每日09:00～22:00 | 每5分钟提醒；10分钟备班；20分钟兜底 |
| P2 | 邮件、Webhook、群消息 | 每日09:00～22:00 | 每30分钟一轮，3个受理轮次再等待30分钟后按P1通知 |
| P3 | 邮件、Webhook | 工作日09:00～18:00 | 一轮，等待人工处理 |

方法只会使用组选择的系统接入。没有手机号、邮箱或相应接入时显示具体缺口；无人值班或整层没有可用目标时尝试下一层。多主并行通知，组内任一有效成员接手便停止该组的无人响应通知。多个责任组独立接手，A组接手不会停止B组升级。

可以分别设置重复间隔、备班/兜底时间、每层最大轮数、无人接手提级、接手后处理期限。每层用完次数仍可按时间继续升级下一层；最终耗尽后保持待接手并显示原因。技术重试、多个人、多渠道不会增加业务轮次；至少一个渠道受理才算成功通知轮次。第三轮发送后会保留完整的等待时间。

业务原始等级和当前通知等级分别保留。P2按P1通知后仍标明原始P2，重新检查P1的窗口。静默和通知窗口外暂停通知及有效等待计时，避免夜间累计次数后立即跨级；窗口恢复只处理仍然开放的事件。

支持10、30、60、120分钟快速静默，以及全局、组、规则、事件、服务和标签范围的预约/周期静默。周期窗口支持跨夜和星期限制。结束静默保留历史记录，以便准确计算暂停时间。静默不停止规则评估，也不等于接手或恢复。

默认P0接手后30分钟、P1接手后60分钟未续期则重新通知备班。负责人可点“仍在处理”续期，或转交组内其他人；转交后等待对方接手。已经恢复或因配置取消的事件不会被旧链接、晚到回执重新打开。

## 各渠道接手语义

| 接入 | 通知/动作 | 何时算接手 |
| --- | --- | --- |
| 飞书群机器人 | 卡片“开始处理”跳转链接，支持提醒组成员 | 登录并到达告警页，页面自动POST接手 |
| 钉钉群机器人 | ActionCard“开始处理”，手机号/用户ID提醒 | 同上 |
| 企业微信群机器人 | Markdown“开始处理”链接和用户ID提醒 | 同上 |
| 飞书企业应用机器人 | 向成员发送交互卡片 | 可信卡片回调的操作者映射到组成员并原子接手 |
| 阿里云电话 | 原生中间/结束回执；通话查询补偿 | 接听即接手，无需按键 |
| 腾讯云电话 | 原生语音通知回执 | `result=0`且存在接听时间，接听即接手 |
| SMTP邮件 | 正文“开始处理”链接及现场摘要 | 登录后到达告警页自动接手 |
| 阿里/腾讯/华为短信 | 审核模板中的接手链接变量 | 同上；模板必须包含`{{ack_url}}` |
| 通用Webhook | `response_id`、`priority`、`ack_url`和事件内容 | HTTP成功只算受理，接手仍由有效用户完成 |
| Pushplus | 现有推送及回执能力 | 推送成功不等于人工接手 |

普通群机器人无需虚构阅读回执或卡片回调能力。只有专门的接手链接会自动认领，普通详情链接不会。个人短信和邮件链接绑定接收用户，群链接允许当前组内有效成员；未登录时先登录，并保留跳转目的地。GET访问和邮件扫描器预取不会改变状态。

飞书企业应用需配置App ID、App Secret、Verification Token，以及需要时的Encrypt Key。回调地址由系统生成，登录后仅管理员可读取；校验Verification Token、应用、操作者和可选签名/加密。不同企业应用的open_id不能混用。

阿里云`200102`、`200000`、`200001`、`ANSWERED`或正通话时长代表接听；`200010`是关机，不能算接听。回执持久化、去重，早于发送结果到达也能处理；发送时带OutId，原请求丢失CallId时可用回传字段补偿。阿里云查询使用匹配产品的ProdId，TTS默认`11010000138001`，可在接入配置中覆盖。腾讯云只有结束回执时，接手会等回执到达后确认。

供应商受理、送达、接听和人工接手分别记录。无法确认的短信/电话提交保留unknown，不盲目重发。发送结果晚于已接听回调到达时，不会覆盖接听事实。恢复通知面向实际被通知过的人和负责人，默认使用邮件、群消息、Webhook/推送，不再拨电话。

## 自动现场与Trace

日志规则可自动使用来源日志表及其级别/关键词条件。其他规则只有服务关联唯一时才自动推断日志来源；来源不明确时在规则中指定。可将实例标签映射到日志属性，关联Trace表。

触发时保存固定时间范围和最多10条日志、32KiB证据，单条摘要最多500字符，查询超时2秒。时间、service、标签值采用参数绑定。摘要脱敏常见密码、令牌等字段。查询失败、没有匹配和截断均显示状态，不阻断通知或修改负责人。

日志现场中的真实trace_id可一键打开Trace树、耗时瀑布、错误span、属性和事件，再跳回固定时间与表范围的关联日志。Trace查询最多8张表、24小时时间范围和每表2,000个span；缺父span、部分查询失败或截断明确标示不完整，不补造链路。仅时间相近的现场日志是排查线索，不直接判定为根因。

## 个人指标口径

每个`response_id + user_id`只记录一次首次成功受理通知。同轮多渠道、重试、重复回调不扩大分母，恢复通知不计入告警通知数。

- 接手率：本人首次接手的组告警数 / 实际通知本人的不同组告警数。
- 接手时长：首次通知受理到本人首次接手，提供平均、中位数及P95；重复认领、续期或再次转交不会覆盖首次时间。
- 结果：本人接手、其他人接手、自动恢复、配置取消、仍待接手分别列示。
- 常规字段：用户、规则、组、业务原始等级、首次通知级别、首次通知主备层级、通知时间、接手时间、方式和耗时。

可以按通知时间范围、组、首次通知级别筛选。群通知将本轮被提醒的当班成员作为通知对象；实际没有发送成功的任务不计入通知数。未被通知但主动处理的成员会留审计，不把它混进“被通知后的接手率”。没有通知样本的人显示“—”。统计最多20,000条，超过时提示缩短范围。

## SSO和外部目录

现有OAuth登录提供`email_field/phone_field/feishu_id_field/dingtalk_id_field/wecom_id_field`映射，可读取可信UserInfo中的嵌套字段。人工保存的联系方式优先，不会被后续SSO或目录覆盖。此功能扩展现有OAuth资料映射，不将它声明成完整OIDC验证实现。

“设置 → 外部目录与值班Hook”配置POST地址、可选加密Bearer Token、目标组和60～86,400秒同步间隔。请求体为`{"group_id":"…","at":"ISO时间"}`；接口返回示例：

```json
{
  "members": [
    {"user_id": "本地用户ID", "profile": {"email": "ops@example.com", "phone": "13800000001", "feishu_id": "ou_example", "timezone": "Asia/Shanghai"}},
    {"provider_id": "已配置登录提供者ID", "subject": "已绑定外部身份", "profile": {"dingtalk_id": "staff_2", "wecom_id": "staff_2"}}
  ],
  "primary": ["本地用户ID"],
  "backup": ["另一个本地用户ID"],
  "schedule": {
    "mode": "weekly",
    "timezone": "Asia/Shanghai",
    "anchor": "2026-10-12T01:00:00Z",
    "interval_days": 7,
    "shifts": [
      {"primary": ["本地用户ID"], "backup": ["另一个本地用户ID"]},
      {"primary": ["另一个本地用户ID"], "backup": ["本地用户ID"]}
    ],
    "overrides": []
  }
}
```

只能同步已经存在且有效的本地用户或已绑定身份，不能靠邮箱/手机号创建或合并登录账户。上限100成员、1MiB、5秒超时；错误或空结果保留最近成功配置。成员变化需同时给出仍在新成员内的主备、替班等配置。同步与人工修改冲突时丢弃过时结果，并显示错误，不覆盖新配置。

## 实际API

以下路径均位于`/api/v1`，除供应商回调外需登录；系统配置需管理员。

| 路径 | 能力 |
| --- | --- |
| `GET/PUT /auth/notification-profile` | 本人联系方式 |
| `GET/PUT /users/:id/notification-profile` | 管理员/本人联系方式 |
| `/notify/channels` | 系统接入CRUD、测试；`:id/callback-url`读取回调地址 |
| `/alerts/groups` | 成员、排班、替班及分级策略CRUD |
| `POST /alerts/groups/:id/schedule-preview` | 已保存或草稿的排班预览 |
| `GET /alerts/responders`、`/alerts/policy-defaults` | 成员可用性和初始模板 |
| `GET /alerts/incidents`、`/:id` | 组事件、现场、时间线 |
| `POST /alerts/incidents/:id/ack` | 网页接手 |
| `POST /alerts/claim` | 带token的通知接手链接 |
| `POST /alerts/incidents/:id/renew/transfer/escalate/replan` | 分别续期、转交、主动升备班、应用当前配置 |
| `GET/POST /alerts/silences`、`DELETE /:id` | 静默创建、查看和提前结束 |
| `GET /alerts/response-statistics` | 统计及人员明细 |
| `GET /traces/:trace_id` | 有界Trace树数据 |
| `/settings/alert-directory-sources`、`POST /:id/sync` | 目录配置及立即同步 |
| `POST /notify/callbacks/:id/:token` | 不使用登录会话，使用专用秘密/厂商校验的回调 |

SQLite保存`user_notification_profiles`、`alert_responses`、`alert_response_events`、`alert_assignments`、`alert_claim_tokens`、`alert_silences`、`alert_directory_sources`和`alert_voice_receipts`，继续复用规则、状态、事件、渠道和outbox。响应按`episode + group_id`唯一，执行代次取消旧任务，接手令牌只保存摘要。

规则暂停会取消未发送任务并保留episode，恢复后继续原事件；判断条件变化取消旧响应并以新episode评估。表绑定变化即使规则关闭周期提醒也会建立新责任组响应。重启从持久时钟继续计算有效等待，不重新发送整段离线历史。队列先处理较高通知级别。
