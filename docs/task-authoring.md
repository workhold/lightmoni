# 脚本任务创建与调度

任务中心管理执行内容、触发方式、目标主机和执行策略。用户手动创建与内置 AI 创建使用同一任务定义；AI 产生的变更仍需在平台审阅批准。

## 创建脚本

在主机工作台进入任务中心，点击新建任务，选择自定义脚本。可以在空白编辑器输入/粘贴代码，也可上传 UTF-8 `.sh`、`.js`、`.mjs` 文件填充同一编辑器，上传后继续修改。保存的是最终代码，后续修改本机原文件不会改变已保存任务。替换已有代码需确认。

Shell 使用 POSIX `/bin/sh`，Node.js 沿用 ESM 语义（使用 `import`；不会按上传文件名自动切换 CommonJS）。文件和源码最多64KiB。不会自动安装第三方依赖。可选参数填写 JSON 字符串数组（如 `["daily backup", ""]`），原样传递，保留空字符串、换行和空格，不做 shell 插值；工作目录是远端主机的绝对路径，不是用户电脑路径，目录不存在时失败。

## 计划与目标

| 计划 | 使用场景 |
| --- | --- |
| 手动执行 | 保存后，按需审阅并派发；`once` 沿用此含义 |
| 指定时间一次 | 指定未来时间；被消费或错过后不因重启或重新启用重放 |
| 固定间隔 | 每10秒至30天；保存/修改计划后安排下一个未来时段 |
| 日历计划 | 每天、每周、每月；高级模式输入五段分钟级 Cron 和 IANA 时区 |

日历可选择 `Asia/Shanghai`、`UTC` 等时区，页面显示后端计算的未来五次时间。固定使用 cron-parser 5.10.2：America/New_York 春季不存在的02:00转为03:00，秋季重复的01:30只取第一次；每月不存在的日期跳过。预览与实际调度共用计算函数；调度运行仍受启用状态、目标、Agent 能力和执行策略约束。中心默认每5秒扫描，有15秒正常扫描容差；超过容差或中心启动前已到期的计划不补跑。

目标支持主机、主机标签或明确全部主机。标签在实际派发时解析，每次运行固定真实目标和代码版本。尚未安装 Agent 的主机可以是任务目标，暂不执行；任务所需能力不满足时明确显示需升级。

例如上传 `backup.sh` 后设置“每天02:00 / Asia/Shanghai”，目标选择生产数据库标签。保存草稿仅保存配置；明确启用后中心按时创建运行，Agent 出站领取并回传结果，不向主机写 crontab。

## 执行策略与回执

| 设置 | 默认值与范围 |
| --- | --- |
| 超时 | 60秒，可选1–3600秒 |
| 输出上限 | 64KiB，可选1–256KiB |
| 每任务全局并发 | 10，可选1–100；每个 Agent 仍一次只执行一个脚本 |
| 队列等待期限 | 1小时，可选10秒至24小时 |
| 失败重试 | 默认0，可选最多3次；等待默认60秒，可选10秒至1小时 |
| 同任务同主机重叠 | 跳过本次，不抢占原执行 |
| 错过计划 | 不补跑历史时段 |

失败重试会重新执行完整脚本，只针对状态为 failed 且错误码为 script_failed、runtime_unavailable、timeout、output_limit 的明确回执，沿用当时快照；定义版本、目标、绑定或授权已变化时不继续，排队后领取时也再次检查。取消、队列过期、控制或租约丢失及结果未知不自动重试。人工重试沿用现有“重新审阅当前代码和目标”的流程。

每台主机保留独立状态、耗时、退出码、有限stdout/stderr及代码快照。排队和运行中不代表成功；结果未知保留未知。参数和自定义工作目录需要 Agent `task.script.v2`，基础脚本仍可由支持v1的Agent执行。脚本以Agent系统用户权限运行；最小环境和独立目录不构成操作系统沙箱。

指标、拨测和日志模板继续由 Agent 原生处理器持续执行，使用配置 revision 展示状态，不为每个采样建立脚本运行记录。

设计、协议及验收见 [SDD 048](../specs/048-task-authoring-schedules/spec.md) 和 [系统设计第27节](system-design.md#27-任务中心与主机标签sdd-043)。
