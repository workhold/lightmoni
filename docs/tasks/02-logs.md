# 02 — 日志探索

本任务实现 LightMoni 的日志排查入口，参考 Kibana Discover 的主要使用流程。前端使用 React + TypeScript，模块后端使用 Go。本任务书最初用于冻结拟定契约，现已进入实现阶段。已落地接口与资源限制见末尾“实现与验证记录”；前面的设计要求继续作为对标标准，未验证的操作不能按实现完成计为验收通过。

## 目标与范围

用户上报 `service`、`table` 和日志后，不配置项目或数据视图即可选择自动发现的日志表，搜索错误、查看原文和同源上下文，最后带着查询条件进入大盘或告警配置。

首版交付以下闭环：

1. 从系统表目录选择日志表、筛选一个或多个 service，选择时间范围。
2. 输入关键词并添加结构化字段过滤，查看完整查询范围内的时间分布与分页结果。
3. 展开日志查看原文、规范化 JSON、属性和异常堆栈，复制文本或日志链接。
4. 查看同一来源的前后日志，避免混入同机其他服务或同服务其他进程。
5. 开启实时增量、暂停并恢复，断连后提示重新连接或重新查询。
6. 保存、打开、修改、复制和删除共享检索，复制检索/日志分享链接；将检索生成大盘面板草稿、跳转 trace，向告警模块传递查询草稿。

所有登录成员共享检索与数据。任务不引入项目、workspace、多租户或日志 ACL；多份采集 Key、第三方登录由主干负责，告警组与通知路由由告警任务负责。

不纳入首版：完整 KQL/Lucene/ES|QL、任意正则、运行时脚本字段、日志模板自动聚类、索引管理、任意格式插件、完整 Kibana 配置导入，以及不受限的全量导出。日志页提供主干 AI 模块的真实入口和日志上下文；模型执行、凭证和权限由主干 AI 模块负责。完整查询语言兼容属于非首版范围，不能因此删掉可用的关键词检索、typed filters、过滤 chips、字段操作、时间拖选或下面的核心交互。高级 SQL 复用大盘/公共查询入口；它不必支持日志探索全部上下文、游标和实时功能。

### 查询语义

- `table` 是 SDK 给出的业务名；目录同时返回业务名与物理名（例如 `app` 与 `log_app`）。搜索 API 接受目录中的稳定表标识，不接受任意 SQL 标识符。物理名称及表路由由主干维护。
- service 条件是集合内匹配；空集合代表不按 service 限制。同一表允许多个 service。
- 关键词首版作为一个**字面子串**匹配日志正文，可约定 UTF-8 大小写不敏感；空格、引号、`*`、`:` 均视为普通字符，不暗中解释为 KQL 或通配符。不默认遍历每个属性字段。
- 过滤列表以 AND 组合；同一个 `in` 条件内的值是 OR。首版运算符为 `eq`、`ne`、`in`、`not_in`、`exists`、`not_exists`，数值字段另支持 `gt/gte/lt/lte`。禁用条件不进入查询。
- 字段键按字面识别，属性名中的点不是默认的对象路径分隔符。缺失字段、显式 null、空字符串和零分开处理；建议 `ne/not_in` 仅匹配存在且不等的值，查缺失用 `not_exists`。null 和数组/嵌套对象支持范围由主干冻结，不能将所有值转成字符串比较。
- 固定字段类型由 schema 提供。属性类型以主干目录能力为准；同键出现多种类型时展示混合类型，首版只开放明确支持的操作。服务端校验类型、字段、表、数量和长度，所有值经公共查询层参数化。
- 切换表或删除字段后，不静默忽略无效过滤。展示不可应用的条件并要求修改/移除，服务端返回结构化验证错误。

## 拟定数据契约与 API

主干统一维护 OpenAPI/共享 TypeScript 类型、错误码和时间精度。日志模块提供领域请求和编译规则，通过 `internal/query` 执行只读 SQL；不单独创建 ClickHouse 客户端、采集表、鉴权或超时管理。

查询列表、直方图、字段统计、上下文和实时结果使用公共 **typed columns + rows** frame：字段 ID/类型由 columns 描述，rows 按该顺序返回；会话、cursor、scope、时间与错误信息放在公共响应 metadata。前端使用主干 frame 解码器，不能再增加一套日志专用的表格/图表行协议。详情的规范化单条事件结构仍由公共日志 schema 冻结。

### 日志记录最少需要的字段

| 字段 | 用途与约束 |
| --- | --- |
| `event_id` | 重试保持不变，存储查询中唯一可定位；列表去重、详情和链接使用，不能每次读时生成。 |
| `table_id` / `table` | 可信目录标识及业务表名；服务端返回物理表名供 SQL 展示，采集端不能借此指定任意库。 |
| `event_time` | 原始事件时间，历史排序与时间分布使用；不替换成补传时间。 |
| `ingested_at` | 主服务接收/入库时间，用于解释晚到数据与实时刷新；主干明确它标记接收还是写入开始，不当作事件发生时间，也不提供任意时长的查询可见性保证。 |
| `service`、`severity`、`body`、`attributes` | 日志主体与结构属性；body 文本、JSON、异常字段的表示由公共数据模型确定。 |
| `host_id`、`source_id`、`source_seq` | 来源标识和可选源序号；source_id 区分进程实例/文件流，source_seq 在重试与补传后保持不变。 |
| `trace_id`、`span_id` | 可选；缺少 trace 数据时仍能查看关联日志。 |

时间在 API 中使用主干确定的字符串格式/精度；不得经过 JavaScript `number` 储存 Unix 纳秒造成精度损失。

### API 清单（路径为拟定）

| API | 请求/返回要点 | 归属 |
| --- | --- | --- |
| 公共表/字段目录 API | `kind=log`、业务/物理名、稳定 ID、固定字段与属性类型、可查询能力；按需取当前范围内 service | 主干提供，日志模块消费 |
| `POST /api/v1/logs/search` | 表标识、services、绝对 `[from,to)`、keyword、typed filters、时间方向、limit；续页带 session_id/cursor。首次建立有界短时查询会话，返回 rows、next_cursor、resolved_range、session_expires_at、truncated、耗时和 warnings | 日志模块编译，公共查询层执行并缓存 |
| `POST /api/v1/logs/histogram` | 首轮同一 QuerySpec 的完整范围聚合缓存到会话；后续传 session_id 读取。返回真实 bucket 边界/步长和 count、scope、generated_at，空桶补零；计数若非精确须有 relation | 日志模块，复用公共 frame |
| `POST /api/v1/logs/field-values` | 查询、字段、session_id、Top N；返回值、计数、覆盖范围/采样与截断标识；会话内采样与全范围新查询须分开标识 | 日志模块 |
| `GET /api/v1/logs/{table_id}/events/{event_id}` | 返回完整规范化记录、来源能力；找不到区分表不存在和事件未保留 | 日志模块 |
| `POST /api/v1/logs/context` | 锚点 table_id/event_id、方向、数量和 continuation cursor；返回锚点、同源记录、scope、排序与边界 | 日志模块 |
| `POST /api/v1/logs/tail` | 规范化过滤、接收时间窗口/轮询 token、limit；返回 arrivals、scanned_range、next_token、truncated 与需要重查提示。首版按有限重叠窗口 HTTP 轮询，无需 WebSocket | 日志模块，时间范围及限额由主干提供 |
| `/api/v1/logs/saved-searches` CRUD | 保存 QuerySpec 与视图配置；返回 ID、revision、更新时间。修改使用 revision 校验，冲突返回 409；复制读取已有配置后创建新记录，不复制会话或结果 | 日志模块逻辑，SQLite 连接/迁移由主干接入 |

建议 `QuerySpec` 只描述查询含义，与 URL、cursor、session_id、面板 ID 分开。搜索示例只作契约草案：

```json
{
  "table_ids": ["logs-app"],
  "services": ["order-api", "worker"],
  "range": {"from": "2026-10-10T00:00:00Z", "to": "2026-10-10T01:00:00Z"},
  "keyword": {"text": "payment failed", "mode": "literal_substring"},
  "filters": [
    {"field": {"scope": "attribute", "key": "region"}, "op": "eq", "value": {"type": "string", "value": "cn"}},
    {"field": {"scope": "column", "key": "severity"}, "op": "in", "value": {"type": "string_list", "value": ["ERROR", "FATAL"]}}
  ],
  "sort": "event_time_desc",
  "limit": 200
}
```

`histogram` 和字段统计与列表共享相同 QuerySpec，结果绑定同一个查询会话。但会话缓存不是 ClickHouse 数据库事务快照：完整范围统计与有界行查询分别执行时，新增/补传可能产生短暂差异。返回 scope、generated_at 和列表 truncated；不得把当前列表行数当作完整计数，也不得宣称独立聚合与列表严格读取同一瞬时集合。

## 分页、时间、补传和实时正确性

### 历史查询

1. 相对时间在首次请求解析为服务器确定的绝对范围，后续页复用 `[from,to)`；一次点击刷新建立新查询，不能续页时重新解析 `now`。
2. 默认按 `(event_time, event_id)` 降序，event_id 作为同时间记录的稳定决胜键；升序则整组升序。游标使用严格 `<` 或 `>` 的复合边界。若 event_id 只在表内唯一，则加入 table_id 形成完整决胜键。禁止 OFFSET 分页和仅时间游标。
3. **首版采用有界短时查询会话。** 首次请求按稳定键读取匹配结果，冻结事件 ID、排序键、来源和展示字段到公共查询服务的缓存，后续页只读该缓存。列表缓存有条数、单会话/全局字节、并发数和 TTL 限制；主服务重启后会话过期，提示用户重新查询。会话可仅覆盖有界结果，不构建全量数据库快照。
4. 晚到日志即使 event_time 较早，也不会插入已经冻结的会话；刷新后按原 event_time 出现。首次查询被条数或字节上限截断时，必须展示“本次仅载入部分结果”，并建议缩小时间或添加过滤。到缓存末尾不能显示“全部日志已经展示”。
5. cursor 为不透明 token，绑定 session_id、QuerySpec 摘要、排序和位置，由服务端验证；会话内翻页按冻结数组位置即可，不重复查询数据库。变更过滤、表、时间或排序建立新会话；无效/过期 token 返回明确错误，禁止自动退回首页导致重复。
6. 时间图的完整范围聚合在首轮执行并缓存；其 scope 与 generated_at 明确返回。完整范围计数和会话中的部分列表可以不相等，尤其列表已截断时。字段 Top 值默认基于冻结会话的样本并标记；请求全范围统计则属于一次新聚合。
7. 会话含冻结展示字段，因此原始表保留期清理不应使缓存行的文本突然变化；会话过期即删除缓存。按链接重新取详情仍可能返回已过期。后续完整条目若超过缓存大小，API 返回截断或失败，不丢字段后伪装完整。
8. 数据库查询超时/取消返回失败，不缓存未完整返回的结果；受计划条数上限截断的成功结果与资源错误区分。未来大数据量方案可增加存储级可见水位，但不作为首版依赖。

### 实时增量

- 首版按服务器接收时间 `ingested_at` 查询有限重叠窗口，前端按 event_id 去重。比如默认轮询 3 秒、回看重叠 15 秒可作为压测起点，正式参数由主干冻结。不能按 event_time 大于上一条轮询，否则会漏掉断网补传。
- 区分“按到达顺序查看新日志”和“按事件时间查历史”。实时显示晚到标识和 event_time，可保留 arrival 顺序；历史刷新恢复事件时间排序，不无声改写时间。
- 单轮请求固定接收时间 `[last_success - overlap, server_now)`，先完整读取该有界窗口或使用短时会话翻页；本轮全部读完才前进 next_token。空匹配窗口仍可前进，不能只取最后匹配事件的时间。相同接收时间多行以 event_id 决胜；到结果上限时明确 truncated/需要重查，不能直接跳到最新并宣称完整。
- 前端只允许一个轮询请求在途，查询变更取消旧请求并以请求版本忽略迟到响应。下一轮继续有限重叠，晚到的新入库数据通常仍保有新的 ingested_at，event_time 不会被覆盖。
- 时间范围是查询条件。实时默认滚动范围；按事件时间超出窗口的补传不会进入当前实时视图，可通过扩大历史时间范围查到。过滤范围变化时建立新会话，不沿用旧 cursor。
- 暂停保存最近成功窗口。恢复后在限额内补查；暂停、断连或查询失败时间超过约定刷新边界时显示“需要重新查询”。查询可见延迟超过 overlap 的记录可能不出现在实时列表，历史刷新可以查到；实时不是任意时长无漏的订阅协议，不额外引入全局 published_watermark。
- 浏览器缓存有界、按 event_id 去重，不能用 body/time 去重误删内容相同的独立日志。达到窗口上限时明确显示已移除旧行，历史数据仍可重新检索。

### 同一来源上下文

- 来源至少区分 service、host 和进程实例/文件流；`source_id` 应由 SDK/Agent 明确生成或提供，不根据同一个 host/service 推测成一个来源。
- 有稳定 source_seq 时，以该来源的序号及 event_id 排序；没有源序号时可以提供同 source_id 的事件时间上下文，但必须标为“按事件时间排列”，不声称还原原始输出顺序。没有可靠 source_id 时禁用同源上下文并说明原因。
- 锚点所在表与 source_id 保持固定；默认去掉关键词、级别和属性过滤，否则前后记录会被错误过滤。页面显示这一范围变化；不跨表追查来源。
- 上下文新建一个有界查询会话，冻结锚点与前后候选集；向前和向后分别翻页，锚点只展示一次。扩大上下文范围时显式刷新该会话；范围和页限额有界，不将源序号跳号直接断言为丢数据。
- 日志文件轮转、进程重启必须由 Agent/SDK 划分 source epoch；上下文不能只用容易复用的 PID 或路径串接不同实例。

## 与大盘、trace、告警的联动

- 保存检索存 QuerySpec、列顺序/固定列/列宽、时间模式、排序及 revision，不保存结果行、cursor、session_id 或实时连接状态。相对时间打开时重新解析，绝对时间按原范围打开。复制形成新 ID 和独立 revision，不能继续编辑原条目。
- “生成时间图/添加日志列表”发送**面板草稿**到大盘模块，由用户选目标大盘并保存。建议首版面板保存检索配置的副本，并记录来源 ID；后续修改/删除保存检索不自动改变已经保存的大盘。
- 日志模块通过公共查询编译器生成参数化的 count-by-time 查询/规范化日志查询，不能自行拼 SQL 插值。大盘仍以自己保存的 SQL 与面板配置执行；跳转日志时传递声明过的表、service、绝对时间和过滤，不能尝试反解析任意用户 SQL。
- 日志详情的 trace 跳转只携带 trace_id、可选 span_id、service 和绝对时间，trace 查询/页面由主干或后续指定模块提供；未实现完整 trace 页面时，应落到按 trace_id 筛选的关联日志，不伪造完整链路。
- “创建告警”传 QuerySpec/生成查询草稿，并必须携带 `source_table_ids`：来源为公共目录中稳定的表标识，与查询引用集合一致。告警模块据此提供表绑定告警组路由；不能只传 SQL 让对方猜来源，不能遗漏/伪造表 ID 绕过绑定检查。告警任务负责组、窗口、条件和通知，日志模块不启动调度器或创建默认通知渠道。
- 分享链接携带表/事件标识或保存检索 ID 与必要绝对时间。公共路由负责编码/解码；URL 不带采集 Key、不带日志正文或凭证。不把敏感关键词自动同步到 URL；未保存检索可先完成保存再复制链接，按钮必须完成这条操作链，不能成为占位动作。

## 实现与验证记录（2026-10-10）

实际代码归属为 `internal/logs`、`web/src/features/logs` 和 `examples/logs`。入口是 `New(shared.Dependencies) (*Module,error)` / `Register(*http.ServeMux)`，前端默认导出 `LogExplorePage.tsx`。HTTP 接口已实现 search/session 分页、tail、context、单日志读取及保存检索 CRUD；复用主干 Catalog、ReferencedTables、只读 Query 和 typed frame，不建立第二套 ClickHouse 执行器。

实际默认值：单表查询最多 31 天；历史会话 2 分钟、2,000 行、列表和直方图 JSON 行数据共 8 MiB；模块缓存最多 32 个会话/32 MiB。时间图独立冻结且有单独 `histogram_truncated`，不能把图表截断隐藏为完整统计。页内排序为事件时间和事件 ID；读取锚点不在新窗口时保留旧列表并提示重新查询。

实时每 3 秒读取，以 ingested_at 半开区间和 15 秒重叠查询，按 event_id 去重；暂停超过 2 分钟或结果/待处理数据超限要求完整重查。待处理缓冲与展示窗口都有 2,000 行/8 MiB 上限，新到达日志先显示提示，只有用户点击才插入列表。前端保留纳秒事件时间排序，UInt64 固定字段及 JSON 大整数避免经 Float64/JS number 四舍五入后误匹配。

保存检索为真实 SQLite 表，PUT 带 revision，冲突返回 409。修改查询后仍保留保存对象身份；显示列、固定列、列宽、排序和相对/绝对时间模式可以重新读取。浏览器历史保存查询与视图状态、详情 ID；刷新时重新读取原始日志，不把 body 写进分享 URL。窄屏有共享 Drawer 保留字段搜索、增删列与 Top 值操作。时间图提供聚合数据 Modal 作为键盘用户的等价下钻入口。

可复跑入口见 `examples/logs/README.md`：真实 Docker ClickHouse 集成测试、SQLite 边界 fixture、前端数据边界测试及三套真实浏览器脚本。Go/Node demo 经过本机 Agent 上报至主服务。测试仅生成自己的唯一 ClickHouse 表、临时 SQLite 文件及保存检索 fixture；不改其他业务表。完整 UI 结论仍由主干写入 `docs/acceptance.md`，截图不能代替可操作断言。

实际浏览器验证为三套：`smoke.mjs` 覆盖两份 SDK 接入、分页、详情、分享、SQL、CSV 与实时；`interactions.mjs` 覆盖过滤 chips、保存 CRUD/复制、列配置、长日志/详情重载、阅读锚点、751px 字段抽屉与真实错误恢复；`chart.mjs` 验证实际 AntV tooltip、鼠标拖选、UTC 查询、返回恢复、完整聚合计数和键盘时间桶下钻。三套均已通过，具体数据计数及尚未通过的跨模块矩阵记录于 `examples/logs/VERIFICATION.md`。顶栏 AI 使用主干共享 pathname 上下文发布 hook，带当前表 ID、单服务、范围和选中事件；超长事件降为有界元数据与正文片段。

### Discover 查询与聚合工作流改造

2026-10-10 补充：检索栏支持正文关键词、字段表达式和 SQL 两种模式；`service:api level:ERROR @status>=500` 被解析为参数化的类型化过滤 chips。支持引号字面量、AND、字段存在及数值比较；完整 KQL/Lucene、OR/NOT 和正则语言兼容仍不属于首版，但不影响直接构建、编辑、反转、禁用和删除过滤。

新增 `POST /api/v1/logs/aggregate`：请求为 `spec`、固定字段或 `attr:<key>`、Top 限额 1–50（默认 10），返回 typed frame、匹配 total、字段存在 present、truncated、generated_at 与独立完整范围统计 scope。分组及计数是两次只读范围查询，持续写入时可能存在轻微差异，不宣称事务快照。自定义属性按 JSON 原类型分组；数字 500 与字符串 "500" 分开，UInt64 JSON 原字面量保留精度；复杂对象可统计但不提供误导的标量筛选动作。

时间桶可自动或选择 1 秒、10 秒、30 秒、1 分钟、5 分钟、15 分钟、1 小时、1 天，最多 2,000 个桶；非法桶宽/范围返回可恢复错误。时间直方图保留鼠标拖选、点击桶与键盘“分布数据”下钻；五分钟以内范围使用秒级刻度，并保持水平方向。

原始日志与聚合使用同一结果区的 ARIA tabs。顶部仅紧凑 Top 值摘要；751px 完整保留三个 service、Top10 范围与“查看更多”。完整聚合配置和分布结果置于聚合 tabpanel，切换后滚入视口；聚合模式显示完整查询范围语义，隐藏日志冻结会话/末尾提示。点击 service、level 或属性值直接生成过滤并回到原始日志，可继续详情/同源上下文/trace 下钻。方向键左右、Home/End 切换 tab 后将焦点保持在目标 tab。

实际验证：当前 Docker `18380` 的真实 HTTP → Node SDK → Agent `14318` → ClickHouse 数据完成 service/level/status 聚合下钻、原文和保存检索重开。专用本地源页面对同一真实 API 连续三轮得到数字 status=500 的 19 条错误，刷新后保留过滤与保存名称；一分钟绝对范围返回 6 条。独立交互审阅确认原先聚合空白、751px 摘要缺失和分钟刻度重复三项修复通过。证据与最终部署状态见 `web/src/features/logs/evidence/README.md`；水平刻度和焦点的小补丁已通过源页面验证，需主干最后统一 Docker 更新。新补充的 Playwright 聚合/焦点断言尚未重跑，不能将旧三套脚本的通过记录当作新断言的执行结果。
