# 运维工具管理员手册

本手册对应 SDD 026 已实现的网站、证书、容器与 Compose、文件备份和计划任务。系统整体职责参阅[系统设计](system-design.md)；实现及验收边界参阅[规格](../specs/026-operations-platform/spec.md)与[网站验收](../specs/026-operations-platform/validation-websites.md)。

## 1. 先准备执行节点

1. 以管理员登录 LightMoni，在“主机管理 / 节点助手”完成独立 Agent 的安装和注册。
2. 确认节点在线。SDK 可以直接向中心上报，不要求经过 Agent；这些运维动作由选定节点的 Agent 执行。
3. 按需要在节点准备依赖。LightMoni 不会自动安装依赖、停止现有面板或接管已有监听端口。

| 功能 | 执行节点依赖和权限 |
| --- | --- |
| 网站 | Linux、Nginx、`ps`、`id`；运行用户具有受管目录与所选端口权限。root master 使用 nobody 及其主组运行 worker。 |
| 上传证书 | 标准 Node.js 加密库；证书私钥权限 0600。绑定网站还需要 Nginx。 |
| ACME | Certbot、已受管的 HTTP 80 端口网站、可从公网解析并访问的域名、联系邮箱。 |
| 容器 | Docker Engine 和 Docker Compose v2 插件；Agent 有权使用该节点的 Docker。 |
| 本地备份 | 已存在的源目录和存储目录；Linux 上目录、祖先和文件由 root 管理，不允许其他用户写入。 |
| S3 备份 | 已存在的 S3 兼容 bucket、HTTPS 端点、相应对象读写/列举/删除权限和网络。仅 loopback 测试端点允许 HTTP。 |
| 计划任务 | 中心服务持续运行、资源已登记、授权管理员仍有效；真正执行仍依赖对应节点在线和上述工具。 |

网站使用独立 Nginx master、配置、PID 和版本目录。root Linux 的公开静态资产位于 `/var/lib/lightmoni-web/<节点数据目录标识>`，配置/日志/状态和私钥位于私有 Agent dataDir；不会给业务用户开放 Agent 私有目录。非 root 运行使用 dataDir 的同级公共资产目录。已有 Nginx、1Panel 或其他服务占用端口时，应先决定由谁管理入口，或为 LightMoni 选择另一个端口。

## 2. 通用界面流程

打开左侧“运维工具”（`/operations`），选择“网站 / 证书 / 容器与 Compose / 备份恢复 / 计划任务”标签。

1. **新增配置**：填写名称、执行节点和领域配置，保存。保存只登记期望配置，不远程执行。
2. **执行操作**：选择具体动作及参数，点击“预览方案”。这一步仍不执行。
3. **审阅并确认**：核对节点、动作、配置版本和参数，管理员确认后才创建 Agent 任务。方案有效期 30 分钟；资源被修改后旧方案不能批准。
4. **查看结果**：等待节点领取并刷新回执。`queued` 是排队，`succeeded` 才表示执行器完成该动作的验证；`unknown` 表示结果未知，应先检查节点，不能直接把它视为失败后无限重试。

检查状态、日志、发现等只读动作也通过相同确认和回执路径，保证实际观察有来源。管理员可以取消尚未领取的任务；已开始动作不提供“取消即回滚”的保证。

普通成员没有这些管理权限。AI 助手可以读取脱敏配置和执行记录，并为已有资源创建方案；AI 无法批准方案、读取秘密或直接执行任意 SSH/shell。

## 3. 网站

### 3.1 反向代理已有业务

1. 新增网站，选择节点、填写域名，类型选“反向代理”。上游例如 `http://127.0.0.1:3000`，HTTP 端口默认 8088。
2. 可以关联一个已有业务服务用于展示；网站入口与业务服务版本/进程生命周期分别管理。创建网站不会启动业务。
3. 保存后执行“应用配置”。执行器生成独立站点配置，先运行 `nginx -t`，再加载并通过 HTTP 配置摘要及页面访问验证。
4. 使用“验证访问”“查看日志”检查入口。域名 DNS、云安全组、防火墙和公网路由仍需指向此节点及正确端口。

上游只接受 HTTP/HTTPS URL，禁止在 URL 中嵌入用户名、密码、query 或 fragment。HTTPS 上游默认使用节点系统 CA 校验。内部自签上游只有在管理员显式关闭上游证书验证时才可使用；这会保留在配置和审阅内容中。

### 3.2 小型静态站

类型选“静态网站”，界面可编辑 `index.html`，编辑时保留已有其他文件。领域接口也支持 `static_files` 相对路径与文本内容映射。

本轮上限为 200 个文本文件、总计 512 KiB UTF-8 文本、规范化 JSON 配置 900 KiB；拒绝绝对路径、`..`、符号链接和隐藏路径。只放可公开访问的资产。二进制上传、构建产物归档上传和大型站点不在本轮范围。

### 3.3 历史恢复和停用

“检查状态”返回节点实际记录的活动版本及有界版本列表。选择“恢复”，填写其中的 `version`，预览并确认；恢复的是网站配置与对应静态版本，不恢复数据库或上游业务数据。

应用失败会恢复前一配置，并再次验证恢复后的站点。若恢复也失败，回执明确报告恢复失败并保持未知结果边界，需人工检查。“停用网站”只关闭该受管站点；删除平台登记不会隐式停止远程服务，因此已执行过的网站需先成功停用才能删除登记。

独立网关在 Agent 进程重启时继续运行。主机/Agent 启动时只恢复归属明确、与最后验证状态一致的配置；崩溃留下的未验证候选不会被自动启动。

## 4. 证书与 HTTPS

### 4.1 上传现有证书

在“证书”新增同节点证书资源，填写域名、证书链 PEM 和未加密私钥 PEM，保存后执行“安装上传证书”。系统检查 X.509 格式、私钥匹配、域名覆盖、有效期和提供的链关系。替换前还会核对节点上所有绑定网站的最后已验证域名，新证书必须继续覆盖这些域名；SAN 缺失时拒绝替换并保留原证书。私钥加密保存并按具体任务租约下发，落盘权限 0600；读取接口和 AI 不返回 PEM。

随后编辑网站，选择该节点的证书和 HTTPS 端口（默认 8443），保存并应用网站。浏览器仍需信任所用 CA；内部自签证书的 `self_signed` 状态可在结果中看到。

编辑证书时，PEM 留空表示复用之前保存的材料；替换时提供完整新证书和私钥。被网站引用的证书不能删除。

### 4.2 自动申请与续期

1. 先以相同域名创建并成功应用 HTTP **80 端口**的受管网站；不要先绑定尚未安装的证书。
2. 使域名在公网解析到节点，公网 HTTP 80 能到达该网关。IPv4/IPv6 解析都应与实际连通性一致。
3. 新增证书配置，填写准确域名和联系邮箱。选择“申请 ACME 证书”，审阅确认接受 ACME 服务条款。
4. Agent 先在受管 webroot 写入临时 challenge 并本地读回，再调用 Certbot；成功后检查证书并安装。
5. 首次签发后，编辑网站绑定证书，再应用网站。已有绑定证书续期/替换时，执行器自动预检和重载受管网关，验证实际 TLS 握手使用新 fingerprint。

“检查状态”返回真实到期时间、剩余天数、fingerprint 和本地状态一致性。可以为该证书创建每天运行的“续期 ACME 证书”计划；Certbot 在未到续期窗口时可以复用现有有效证书。续期失败保留运行记录并尝试恢复原证书；恢复必须通过旧证书真实 TLS 指纹验证，否则报告恢复失败和未知结果，不能继续自动写操作。不把“计划已触发”显示为“续期成功”。

本轮支持 Certbot HTTP webroot，不支持 DNS challenge 或通配符。公网 CA 发证需要真实域名环境；该部分实现与本轮尚未完成的公网验收边界见[网站验收记录](../specs/026-operations-platform/validation-websites.md)。

## 5. 容器与 Compose

### 5.1 支持的配置

新增资源时填写小写项目名和 **JSON 格式 Compose 子集**。项目名登记后不可修改；使用明确版本标签或 SHA-256 镜像摘要，禁止 `latest` 和无版本镜像。例如：

```json
{
  "services": {
    "web": {
      "image": "nginx:1.27.5",
      "restart": "unless-stopped",
      "ports": ["127.0.0.1:18080:80"]
    }
  }
}
```

支持项目内服务、命名卷/网络、受限端口映射、字面量环境值、容器内参数数组、健康检查和资源限制。禁止 host bind mount、host 网络、特权、外部卷/网络、宿主构建、`env_file`、任意 Compose 扩展和宿主 shell。环境值不会从 Agent 进程环境自动插值。完整字段以[执行器校验](../runtime/src/operations/containers.ts)为准。

环境变量、command、entrypoint 和健康检查测试内容在读取时脱敏。编辑时默认保留原配置和秘密；如要替换，需提交完整文档，不能把 `[redacted]` 占位符当真实值重新保存。

### 5.2 新项目与既有项目

- **新项目**：先执行“发现容器 / 检查状态”，确认没有归属冲突；首次应用使用 `expected_generation: 0`，成功后从回执取得新 `generation`。
- **已有外部项目**：发现只读取，不授予写权限。先审阅配置与实际清单，复制 `inventory_sha256`，执行“接管项目”，填写 generation 0 并明确确认“按照当前配置重新创建容器”。接管不是原地无损勾选。
- **后续动作**：启动、停止、重启、应用和历史恢复均填写最新已观察的 `expected_generation`。代次不符会拒绝；不要猜代次或复用旧截图的值。

启动/停止/重启可指定单个已声明服务，也可以操作整个受管项目。停止不删除命名卷。查看日志需要检查结果中的完整 64 位容器 ID，只读取该项目允许的容器，输出有界。

### 5.3 恢复与未知结果

恢复历史配置需要当前 `expected_generation` 及历史 `target_generation`。这只恢复声明，不回滚数据库数据、卷内容或业务迁移。

遇到未知结果先按第 9 节检查进程、daemon 与节点写锁，再检查实际容器、卷、代次和上次回执；完成恢复后，管理员才可勾选 `acknowledge_unknown` 发起新的应用/恢复。勾选本身不会解除节点写锁。系统不会自动重试未知写动作。已经操作过的受管 Compose 项目保留登记，以维护归属、数据与历史；本轮不提供隐式 `down -v` 或一键销毁。

## 6. 文件备份与恢复

### 6.1 创建策略

新增“备份恢复”资源，填写同节点源目录、目标和限制：

- 本地目标是已存在的独立目录，不得与源目录互相包含。按资源 ID 隔离存储，归档文件使用 0600。
- S3 目标填写端点、bucket、region、prefix 与凭据。凭据加密保存，不返回给浏览器或 AI；相同目标编辑可留空复用，更换目标需重新填写。
- 默认总文件内容 64 MiB、文件及目录 10,000 个、保留最近 7 个常规备份；最大内容 256 MiB、20,000 个条目。

MVP 针对 root 管理的稳定文件目录。源路径、祖先和内容不能由业务用户写入，拒绝符号链接、硬链接和特殊文件。先将允许备份的非机密运行文件归集到专用目录；不要把 SSH 私钥、Agent 凭据、模型 key 或整棵身份目录打进归档。数据库应先通过数据库自身工具导出到受管目录，本功能不保证运行中数据库一致性。

### 6.2 创建、校验和保留

执行“创建备份”会生成清单和摘要、写入目标并读回校验；回执包含 `backup_id`、归档 `sha256`、`source_sha256`、大小、条目数及存储对象版本（目标提供时）。上传完成和恢复成功是两项独立证据。

“备份目录”和“校验备份”同时返回当前源目录的 `current_target_sha256`；恢复需要这个实际观察值。“执行保留策略”只删除超出 `retain_count` 的常规备份；修改保留数量不会立即删除，需要单独执行或计划触发。恢复前副本不被这条常规保留规则清理。

### 6.3 恢复

1. 暂停业务对源目录的写入。
2. 列举或校验目标备份，记录 `backup_id` 和当前 `current_target_sha256`。
3. 发起“恢复”，填入备份 ID 和 `expected_target_sha256`，审阅后独立确认。
4. 系统拒绝审批后变化的目标，先生成 `pre_restore` 备份，在同文件系统暂存并校验，再替换目录、读回校验。回执保留 `pre_restore_backup_id`。
5. 先验证业务，再恢复业务写入；需要撤销时可为恢复前副本创建新的恢复方案。

这是一组可追踪的文件动作，不承诺跨文件系统、在线数据库或业务数据迁移可逆。`unknown` 时先检查源目录和前副本，避免再次覆盖。

## 7. 计划任务

在“计划任务”选择已有资源、其**当前配置版本**、允许动作、五字段 cron 和 IANA 时区，例如 `0 2 * * *` 配 `Asia/Shanghai` 表示每天当地 02:00。

本轮允许备份 create/verify/prune、证书 renew、网站/Compose inspect；不支持任意 shell、业务部署或自动恢复。verify 还要填写固定备份 ID。创建默认停用；管理员显式启用即授权后续仅执行所登记的资源版本、动作和参数。

- 相同 UTC 分钟槽只执行一次，中心重启不补跑错过的窗口。
- 上次仍活动时跳过本次，历史记录显示 `skipped_busy`。
- 资源配置修改使原授权失效，需要编辑计划，核对新版本并重新授权。
- 授权管理员禁用/降权、目标消失、下发错误或未知结果会停用计划；先处理原因再授权。
- “立即运行”仍受授权、版本和并发约束；不要用它绕过未知结果审阅。

在计划历史查看触发与关联运行记录，进入运行详情取得节点真实回执。节点离线会排队并可能超时；到期、失败或未知均有明确状态。

## 8. 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 配置保存成功但远端没变化 | 仍需“执行操作 → 预览 → 管理员确认”，保存不是执行。 |
| Nginx 预检失败 | 检查节点是否安装 Nginx、证书是否已安装、端口和配置是否冲突；不会改写现有面板配置。 |
| ACME 提示网关条件不满足 | 先在同节点、同域名成功部署受管 HTTP 80 网站，确认 DNS、公网访问与邮箱。 |
| TLS 可连接但浏览器不信任 | 检查 CA 信任、完整链、域名及有效期；内部自签成功安装不等于公网信任。 |
| Compose 代次或清单冲突 | 重新检查真实状态，重新生成方案，不能强行重用旧代次或旧清单摘要。 |
| 备份路径被拒绝 | 核对 root 所有权、权限、链接、源/存储重叠、文件数和大小上限。 |
| 恢复提示目标已变化 | 停止写入，重新取摘要并人工批准新方案。 |
| 计划停用或显示 unknown | 查看停用原因和关联回执，实际检查目标后重新授权，不自动重复写操作。 |

目前未覆盖应用商店、数据库实例运维、DNS challenge、Kubernetes、WAF、任意远程文件编辑或跨节点滚动发布。监控、systemd 部署、人工 SSH 和本页运维领域各有明确边界，不能把“有菜单 / 已保存配置”当成实际能力已执行。

## 9. 未知结果与节点写锁恢复

网站、证书、Compose 和备份共用节点写锁 `<Agent dataDir>/operations/execution.lock`。它用独占文件创建防止多个 runner 同时修改节点共享状态。结果为 unknown、Agent 被强制终止或机器崩溃时保留锁；不会因为 PID 不存在或锁时间较长自动移除。后续写动作返回 `operations_node_locked`，只读 inspect/logs 仍可生成方案并执行。

恢复必须由管理员核实后进行：

1. 在平台检查关联运行、operation ID 和最后回执；在目标节点检查锁内的 operation ID、PID 和时间。锁内不含凭据。
2. 确认原执行进程及其子进程已停止。Docker/Compose 客户端退出不能证明 daemon 已停止处理请求，还要检查真实容器、卷、网络、健康与受管代次；网站要检查实际 Nginx 配置、监听与 TLS 指纹；备份要检查源目录、归档和恢复前副本。
3. 只有在确认没有旧写操作仍在进行且已确定恢复方案后，人工移除这个准确的 `execution.lock` 文件。不要删除整个 operations 目录、registry、配置或历史，也不要定时清锁。
4. 重新获取现场摘要/代次，生成并批准新方案。Compose 的 pending/unknown 还需显式勾选 `acknowledge_unknown`；被停止的计划须核对资源和参数后重新授权。

相同 Agent 身份必须使用同一持久 dataDir；不要将同一身份复制到多个目录或多台机器运行。中心租约和节点文件锁不提供跨独立数据目录的分布式 fencing。所有 Docker 操作固定本机 `default` context，不使用用户保存的远端 currentContext。
