# 038 登记主机与 Agent 身份一体化

## 驱动目标

主机是唯一受管资产，Agent 是主机的管理通道。用户最终明确不保留独立脚本接入与历史兼容路径，直接采用“先登记主机、平台部署、签发时绑定主机”的统一架构。SDK 独立直报，与主机登记和 Agent 安装解耦。

## 需求

1. Agent 只经“登记主机 → 选择 SSH 凭据保留期限 → SSH 预检 → 审阅确认 → 平台安装”接入。主机可先登记而不立即部署，登记需填写名称、目标地址/端口/用户名；可信指纹与凭据可以稍后补充。
2. 中心签发 enrollment 时必须绑定真实已登记主机；公共独立签发接口停止创建 token。兑换、激活、注册/心跳均核验服务端预约，客户端不能指定资产 ID 或抢占关联。
3. Agent 控制面强制独立 control 凭据，移除共享 SDK Key fallback。没有主机预约的旧 token/身份拒绝接入，不自动建档、不回填历史 Agent、不按 hostname/IP/host_id 猜测主机。
4. 手动关联接口与页面入口移除。平台安装在注册先于安装回执时仍关联原主机；关联、心跳与 ID 幂等，不覆盖用户名称/SSH配置。每台主机最多一个 Agent，Agent 只有一个所属主机。
5. 主机列表唯一来源是平台主机资产，Agent 仅补充通道状态、观测 hostname 和任务。不得出现 node: 合成资产或“独立接入节点”。成员仅获得主机 ID/名称和原有 Agent 可见元信息，不获得 SSH 元数据。
6. 用户可编辑同一主机的名称及完整 SSH 连接配置，平台 ID 不可改。观测 hostname 不自动成为可信 SSH 地址，平台不猜测登录用户或可信指纹；凭据保存/清理规则沿用既有设计。
7. 主机有活跃 Agent 身份时先移除 Agent 再删除，避免后续心跳重建；移除/卸载 Agent 保留主机。删除前仍检查凭据、终端、任务与计划。
8. 不自动删除实际用户数据库中的旧资产/身份；不对其提供旧协议兼容。旧身份无法接入时明确提示重新从主机管理部署。只更新本地隔离演示数据。
9. 不增加 SDK 环境变量、SDK 发现或 SDK→Agent 强制链路；不声称识别容器物理宿主机。

## 验收

- 新独立签发、无主机token兑换/激活/注册、共享SDK Key控制面全部拒绝，SDK数据面行为不变。
- 平台部署与真实主机预约正常，注册早于完成回执仍只有原主机；伪造machine_id/名称/host_id不能抢占。
- 重复注册/心跳/重启不增资产，不覆盖用户名称；未认证/撤销/移除请求不恢复资产。
- 手动关联接口不可用，列表不显示无主机Agent；只读权限、删除保护、名称/SSH配置编辑与批量回归通过。
- 本地平台按新架构启动并实际查看登记、配置、通道与任务逻辑；不操作线上/vchive。
- 仓库HLD/LLD与Doca正文/原生图同步回读；更新正式GitHub PR，等待用户合入。
