# 独立执行器运维迁移与发行收尾

2026-11-01。用户明确要求补齐 PR #64 的迁移和验收，与其他会话改动统一合入并发布。前置 #62/#63 已合入 fd3685e，尚未发布镜像。

普通 Agent 保持非 root、无 Docker 组/capability，不再接收运维载荷、制品或写任务。现有平台应用、Compose/Registry/OpenResty、网站、证书、备份和 systemd/制品适配器复用既有校验及状态机，通过独立 root 执行器的签名通道运行；不得把整个 Agent 以 root 启动，也不得让普通凭据成为转发 root 命令的权限。

新增独立默认关闭的 operations.managed.v1，表示高信任的受管主机运维（含批准的程序部署、挂载和系统服务），区别于现有受限无挂载容器管理及任意 root 脚本。管理员审阅主机/发行摘要后安装并启用；每个运维作业仍绑定既有精确批准配置、目标、版本、独立执行器/策略代次、短租约和单次在线开始许可。凭据不复制到普通 Agent；root 只加载 root 自有发行代码，运维私有运行目录与普通 Agent 隔离。

保留既有任务、AgentJob、运维 run 和事件界面。以同一 job ID 建立独立执行器 lineage，普通通道不能领取、读取载荷、制品或回执；root 回执在原事务内驱动现有领域校验和状态更新。旧已领取执行不重放；未领取旧写任务取消并提示重新提交，未知执行保留人工核对边界。自动协调只使用现有管理员批准的资源版本，不把定时任意 root 脚本纳入首版。

Agent 重装核验、按源代理、内外网地址与网站流程均保留。更换身份或执行器代次、撤权、离线、配置改变或 lease 失效不开始新动作；已发生副作用丢失结果转 unknown，不自动重跑。升级/回退和卸载不恢复已撤销策略，不删除业务数据；同机 Agent/执行器/Docker/业务任务保持互斥。

验收需覆盖中心旧通道停派与全接口主体隔离、签名与过期/重放/撤权、完整领域回执、真实隔离 Linux/systemd/Docker 运维及双架构发行包。功能完成和发行验证分开记录；不改用户线上主机。架构变化同步 docs/system-design.md 和 Doca 原生章节/图并最新版本回读，和实施同一 PR。
