# 旧 Agent 业务数据接管

新发行保持普通 Agent 非 root、无 Docker 组与 capability。应用、网站、Compose、证书、备份及制品发布需要在主机详情安装独立执行器，再审阅启用默认关闭的 `operations.managed.v1`。批准的程序、挂载和运维配置可控制整台主机，管理员须信任这些资源。

没有旧业务目录的新主机可以直接使用新能力。已有 `/var/lib/lightmoni-agent/operations` 的主机默认拒绝对应写操作，避免创建空数据副本。不能靠清空旧记录、删除锁、重新 enrollment 或回退高权限普通 Agent 绕过。

接管须由管理员在主机上以 root 执行：

1. 先核对中心和本机任务。真实 unknown、未确认回执或旧执行锁必须先调查，不可删锁冒称完成。备份业务数据，并安排停机窗口。
2. 停止普通 Agent、独立执行器、旧 Nginx 网关及使用旧目录的业务容器。迁移工具会再次核对服务、进程、Docker 挂载和 journal；只停止服务并不能证明容器已停止写入。
3. 执行 `lightmoni-executor migration plan`。它返回 root 私有审阅目录、文件数和精确 `plan_sha256`。逐项检查冻结的 Compose、Nginx、状态文件、路径重写、挂载及数据 UID/GID；审阅目录包含业务秘密，不可放入工单或仓库。
4. 审阅认可后执行 `lightmoni-executor migration apply --expected-plan-sha256 <完整摘要>`。该动作明确授权冻结快照成为 root 意图。目标业务目录非空时拒绝合并覆盖；应先调查已有业务，不能直接删除它。
5. 核对数据字节、数字 UID/GID、迁移回执及源目录仍保留，再启动执行器；按原资源重新发布并验证网站、数据库与日志。重新创建的容器应核对绑定的新数据路径。确认恢复前保留停机窗口和备份。

首版快照上限 512 MiB、20 万项，拒绝符号链接、硬链接、设备、竞争写入和运行中业务。更大数据、外部挂载、未知状态及不支持的文件类型需要人工设计迁移，不能自动退回普通权限通道。旧目录不自动删除；完成后也不要启动旧 Agent 写入旧业务数据。被拒绝或失败的审阅目录保留现场，重新规划前由 root 核对具体文件和失败阶段，不能用通配删除清理。

Agent 安装/升级只精确清理本平台旧 `20-lightmoni-docker.conf`，并在停服后复验。未知 drop-in、全局组、ACL 和 socket 权限保留并拒绝。旧高权限 unit 仅保留作证据，不作为回退目标；迁移后失败保持安全停服、disable 和维护锁，不恢复旧授权。

执行器升级、回退、repair、卸载统一从主机详情的维护入口审阅。unknown 只读核对原记录，不重复提交；repair 不重新注册身份或重建 journal。程序维护不删除业务目录、容器或卷，也不恢复已撤销策略。发布镜像本身不会升级生产中心或目标主机。
