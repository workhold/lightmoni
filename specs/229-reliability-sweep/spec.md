# 部署、运行状态与 AI 助手可用性

## 使用场景

- 管理员在不同架构的机器上启动已有发布镜像，或使用源码构建本机镜像。新实例能拉取所需依赖，源码构建使用独立镜像名。初始化和升级期间数据库凭据通过受保护的运行时链路传递。
- Agent 恢复遇到 SSH 错误时，管理员可读取固定原因和退出码。终端检测到连接凭据过期时，关闭会话并清理过期绑定。
- 用户以文档支持的 HTTP 地址访问工作台。应用商店、主机运维、AI 发送和监控查询均能生成原有格式的请求标识。
- 管理员从 AI 审阅链接打开已登记的服务部署或既有运维计划。发起预检、执行或回滚后，在同一页面看到最新状态和所选执行的时间线。切换后迟到的旧响应不会覆盖当前选择。应用安装抽屉能区分未部署、已取消和进行中。
- 数据表目录暂不可用时，用户仍可打开助手、查看历史并发起分析。发送途中断线或重新打开运行中的会话时，页面读取本次请求的持久回执，保留未确认提交的草稿。

## 可验收条件

1. 根 Compose 将已发布的中心镜像解析为 `linux/amd64`，源码覆盖配置使用当前构建平台与独立镜像名。两种配置共用既有 Compose 项目和持久卷。
2. 从真实的非 loopback HTTP 浏览器地址打开应用页，页面能够挂载。助手发送使用符合 UUID v4 格式的请求标识。
3. 服务页面在不点击刷新的情况下显示预检与部署终态。慢返回与故障期间保留属于当前选择的有效结果。旧配置的历史失败不覆盖当前安装进度。
4. 已受理的 AI 请求断线后只跟踪自身 turn。尚未确认受理时保留同一请求标识供重试。服务端对已受理标识拒绝重复执行。旧客户端可继续省略标识。
5. 目录读取报错时，已启用的模型仍可完成一轮对话。恢复中会话的最终回复、失败或取消会显示在该会话时间线中。
