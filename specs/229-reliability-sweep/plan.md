## 技术背景与设计

- Compose 发布使用明确的镜像平台。本机源码构建通过覆盖文件选择本地镜像，沿用原项目的网络、端口和持久卷。
- 中心 ClickHouse HTTP 客户端通过 POST 正文传输 SQL 和数据。连接鉴权仍用请求头，查询参数继续使用现有绑定方式。
- SSH 错误仅保留枚举诊断和有限退出码。终端和文件会话在快速鉴权发现过期时清理对应绑定。
- React 页复用现有接口，只在预检或部署有活动状态时安静刷新。服务和部署选择以 URL 参数为准，旧请求在导航和卸载时失效。
- 浏览器复用 Web Crypto 生成 UUID v4，支持安全和普通 HTTP 上下文。助手目录加载独立于模型设置和会话数据。
- 助手把可选客户端请求标识关联到中心持久化的用户事件。断线回读使用该标识或已知 turn ID。会话详情按现有证据计算状态，浏览器重新打开运行中会话时继续读取。

## 宪章与架构影响

通过 I–VI 门槛。数据库凭据走保护链路，浏览器 UUID 只关联请求。中心保有会话授权、业务状态与工具审批。复用既有事件和数据卷。部署平台和源码镜像、ClickHouse 请求边界及 AI 会话协议更新系统设计第 17、20、201 章。前端进度读取更新第 16 章。状态和兼容细节见[数据模型](data-model.md)和[契约](contracts/interfaces.md)，验证见[联调步骤](quickstart.md)。
