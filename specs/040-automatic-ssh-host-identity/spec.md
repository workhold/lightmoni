# 040 自动记录 SSH 主机身份

## 驱动目标

用户登记主机只提供名称、SSH 地址、端口、用户名和所选登录凭据，不理解或填写 SSH 服务端公钥/指纹，也不确认首次主机身份。平台在首次真实 SSH 握手时自动记录公钥与指纹，后续自动比对。管理员可在主机详情只读查看和复制公钥、指纹。

## 需求

1. 删除登记、编辑的指纹输入，以及主机页“连接凭据安全提示”横幅。密码/私钥及默认 6h、其他期限、永久保存契约保持。
2. 主机公钥、指纹和首次记录时间是服务端产生的只读元数据。登记/编辑 API 不接受人工写入身份字段；既有已保存指纹继续固定，匹配的连接可补全公钥。
3. 首次 SSH 握手无需用户确认，以同一握手中收到的服务端公钥自动建立固定身份；不能把另一条扫描连接的任意公钥无条件加入信任。后续公钥不匹配必须停止连接，不自动覆盖旧记录，不执行远程命令或打开终端。
4. 首次记录按主机 ID 与 SSH 地址/端口原子绑定，并发只能记录一个身份。握手过程中主机被修改/删除、凭据失效或操作取消时不能继续使用过时目标。地址/端口改变清空身份及旧检查/计划；仅改名称或用户名不清除同一端点身份，但仍使相关计划失效。
5. SSH 预检、网页终端、安装/卸载和批量、AI 固定工具使用同一规则。缺少首次身份不再置灰；缺少凭据/忙状态/权限等原有约束保留。预检首次记录身份后绑定新 revision，部署/卸载计划继续固定此身份和目标，执行不绕过审批。
6. 主机详情未连接时展示“首次 SSH 连接后自动记录”，连接后展示标准 OpenSSH 公钥文本、SHA256 指纹及记录时间；用户无需确认。成员与 AI 维持现有最小可见范围，不增加凭据、SSH 公钥等元数据访问。
7. 按 SDD 同步仓库系统设计与 Doca 对应章节/原生图，保存后回读验证。更新 GitHub PR16，保留本地 18080 查看；不自动合并、发镜像或操作线上/vchive。

## 验收

覆盖无指纹登记→首次预检/终端自动记录→后续匹配→不同key拒绝及原pin保留；密码和私钥路径；原pin补全公钥；并发首次连接、地址/端口变更与旧计划失效；错误认证、取消、撤销、终端生命周期；中英文/窄屏详情只读，无身份输入或确认。SSH 使用本机隔离测试服务，UI 使用拦截 API 的生产 bundle。
