# SDD 131：面板响应与文件管理会话

状态：规格先行，2026-11-12。

## 现状与目标

主机在线状态已经由 Agent 默认每 30 秒上报心跳，中心持久保存并在 GET `/machines` 中读取；普通开页不执行 SSH。文件管理则对目录、文件、版本、写入和写后刷新等每个 HTTP 请求分别建立 SSH/SFTP 连接，串行交互明显迟滞。本次降低主机页重复读取与文件操作的连接等待，并明确状态的新鲜度。保留管理员授权、主机身份和文件版本核对。

## 用户场景与验收

1. 管理员打开主机页时，主机列表先于辅助 Agent/标签请求可用；定时和焦点刷新不堆积旧请求。在线标签来自 Agent 最近上报及 `observed_at`，普通查看不触发 SSH。上报陈旧时显示陈旧或离线，不把历史快照当作实时探测。
2. 管理员进入文件管理并连续浏览、打开、编辑和刷新时，相同登录会话、主机和凭据的多个面板复用一个短时 SSH/SFTP 连接。首次打开优先使用主机列表已加载的账户与凭据元数据，创建会话时一并读取初始目录，避免详情、建连、列目录三次串行浏览器请求；列表缺少账户元数据时才读取详情。普通旧 HTTP 客户端不传会话头时保持原逐请求行为。最后一个面板关闭、凭据撤销或绑定/主机目标变化、服务停止、会话闲置或最长时限到达时释放连接和主机忙锁；后续读取可重新建会话，写入中断仍按未知结果提示核对，不盲目重放。
3. 页面升级后，主 HTML 与 SPA 回退响应不允许浏览器存储；带内容哈希的 JS/CSS/其他构建资源可长期 `immutable` 缓存，未版本化资源采用有界缓存。构建变更使 HTML 引用的新 URL 随内容哈希改变，旧构建资源缺失时明确返回 404，不把 HTML 当脚本。

## 功能要求

- FR-001：主机状态继续由 Agent 心跳及中心数据库计算，不因页面读取发起 SSH。页面分开接收主机、Agent、标签响应；刷新请求合并或取消过期请求，活动操作的独立进度轮询不受影响。
- FR-002：文件会话只允许管理员浏览器 cookie 会话建立；使用随机、不可预测的会话 ID，绑定管理员登录会话、主机、所选凭据及目标/凭据修订。ID 不进入 URL、审计或日志。每次请求重新核对授权及绑定，不向浏览器提供 SSH 秘密。
- FR-003：每台主机至多一条文件会话占用既有终端忙锁；会话闲置 20 秒或运行满 10 分钟后不接受新操作，最多 20 条连接。同一管理员登录会话、主机和凭据可由多个面板共享一条连接；每个面板关闭释放一个引用，最后一个关闭释放会话，在途操作有界结束。不同凭据不抢占已有会话。中心关闭强制释放。过期仅允许在新操作开始前重建，不在不确定的远端写入期间自动重试。
- FR-004：文件读写、类型和大小限制、原子发布、版本冲突、结果核对、审计字段及管理员边界保持 SDD107 契约；同一会话中的操作串行，避免共享 SFTP 包装器并发修改。
- FR-005：HTML 设置 `Cache-Control: no-store`；仅文件名带构建内容哈希的 `/assets/` 使用一年 `immutable`，未版本化静态资源有界缓存，缺失的构建资源返回 404 与 `no-store`。API 继续保持自己的缓存和权限策略。
- FR-006：浏览器直连主机只作为本次可行性评估。浏览器无原生 SSH/SFTP；现有 Agent 仅监听本机环回地址，也没有可供网页使用的 TLS、CORS、范围授权和 SSH 账户权限等价能力。因此本次不开放 Agent 入站文件端口，不下发 SSH 凭据到前端。未来可另行评估浏览器 → 中心 → Agent 主动建立的持久出站通道 → 受限文件 helper，避免主机开放入站端口；该通道的协议、授权、审计及 helper 与 SSH 账户的权限等价性须独立设计，不属于本 PR。
- FR-007：文件面板使用已加载的 `/machines` 账户及凭据元数据选择可复用凭据；仅当调用方没有提供该元数据时回退读取主机详情。所选凭据仍须由中心在建连时核对权限、有效性和主机绑定，不能信任前端缓存。建连请求可带绝对 `initial_path`，中心在同一受限 SSH/SFTP 会话内返回与现有 `GET files` 同形的 `initial_directory`。省略 `initial_path` 的请求与响应保持原样；初始读取失败必须回收本次新建会话或仅撤销本次共享引用，不留下忙锁/额外引用。
- FR-008：对普通文件的读取采用最多 8 个并行、每段最多 32 KiB 的有界 SFTP READ 流水线，并按偏移精确重组。短读需继续补齐该段；提前 EOF、大小或打开前后元数据变化仍按文件变化处理。保持现有 1 MiB 文本/8 MiB 上传上限、内容 SHA256 版本、超时与取消及写入结果未知语义；失败时等待读取收束并关闭句柄，不让并发 READ 泄漏到下一操作。

## 成功标准

- 测试证明普通主机列表/详情读取没有 SSH，慢辅助响应不阻塞已成功的主机列表，刷新不会产生并行积压。
- 同一文件会话连续两个文件请求只建立一次 SSH；同一登录的多个面板可共享，跨用户/登录会话、凭据变化、目标变化、闲置和最终关闭不能复用；现有无会话头调用仍可用。
- 主机列表含账户元数据时，首次打开文件面板只需一条浏览器文件请求即可取得会话与根目录；旧建连请求不带初始路径时响应不变，初始目录失败不泄漏会话引用。带延迟的真实 SFTP 测试验证大文件读取准确、短读/提前 EOF 的安全处理和有界并发。
- 实际构建检查 HTML 引用内容哈希 URL；HTTP 集成检查 GET/HEAD、SPA 回退、带哈希资源、未版本化资源及缺失资源的缓存头和状态码。

## 架构影响

文件管理连接生命周期从逐 HTTP 请求改为管理员浏览器会话绑定的短时中心 SSH/SFTP 会话，属于控制路径与连接状态变化。首次建连合并初始目录读取，普通文件 READ 在该连接内部有界流水线化；不改变 Agent 上报路径、SSH 凭据所有权和浏览器网络拓扑。同步仓库 `docs/system-design.md` 第 107 章及新增第 131 章，并按本轮用户提供的开发流程同步 Doca《LightMoni 系统设计基线》，保留原生图块，写后用最新版本回读目标文字和现有图的节点、连线。
