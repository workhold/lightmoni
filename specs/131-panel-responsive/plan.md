# 实施计划：面板响应与文件管理会话

**分支**：`codex/131-panel-responsive`　**日期**：2026-11-12　**规格**：[spec.md](spec.md)

## 基线与决策

- Agent `controlLoop` 默认 30 秒 POST 心跳；`/machines` 从 SQLite `last_seen` 计算在线，不走 SSH。列表请求对每台主机多次查账户、网络、容量、执行器等，页面还并行请求 `/agents` 和标签，当前 `Promise.allSettled` 等全部完成才显示任意成功数据。保留现有状态来源，优化读模型和页面响应时序，并用测试/计数验证。
- 文件面板当前每 HTTP 请求 `acquireTerminal`、SSH 握手、创建 SFTP、完成即销毁；一个保存后刷新相当于两次握手。采用中心短时内存会话与现有终端租约；同一登录、主机、凭据的多个面板共享连接并按引用释放，不建立浏览器到主机的新网络拓扑。20 秒闲置限期缩短忙锁占用，10 分钟绝对限期防泄漏；过期后的新请求重新建连。
- 浏览器直连要新增 Agent 可达 HTTPS/WSS 端点、双向身份与范围授权、TLS/跨域、撤销审计及与所选 SSH 账号等价的本机文件权限。Agent 当前仅环回 HTTP 且常驻身份 `lightmoni-agent`，不可安全地用浏览器直连替换本次 SSH 文件通路。
- Vite 已输出内容哈希文件名并在每次构建重新写入 `index.html`。无需额外查询参数；按路径和文件名设置缓存策略，旧资源缺失返回 404。

## 实现顺序

1. 完成规格、计划、HTTP 契约与任务，确定状态来源、会话授权、关闭与过期语义。
2. 调整主机页请求调度及必要的中心读模型，保留活动操作独立轮询；记录查询/耗时对比与无 SSH 证据。
3. 实现文件会话创建、复用、失效、序列化与关闭，前端管理其生命周期；沿用旧无会话头文件 API。验证真实隔离 SSH/SFTP、权限、版本冲突、写入未知与回收。
4. 收紧静态响应缓存头与 404；实际构建检查哈希 URL，运行定向 HTTP 测试。
5. 同步仓库系统设计与 Doca，最新版本回读文字及原生图；同步 `origin/main`、检查差异与相关测试，建立 GitHub `main` PR 并记录兼容影响和验收证据。

## 安全与兼容

文件会话只存在中心内存，重启后失效。打开会话需已登记凭据及可信主机身份；会话 ID 是短时授权句柄，仅在响应和请求头传递。每次操作重新检查管理员 cookie、登录会话、租约有效性和请求取消。会话串行且最多 20 条；文件内容、SSH 密钥和会话 ID 不落库或日志。旧客户端省略会话头时仍执行原路径。新版本不自动升级 Agent、不改变 Agent 凭据或对外端口。部署时中心重启会关闭旧文件会话，浏览器新请求重新建立；不重试结果未知的写入。
