# 实施设计

## 状态投影与仓库诊断

前端在应用资源的实例摘要、部署修订与恢复状态上判定“待核实”，沿用中心已有的新鲜度和健康证据。保留地址仅说明流量保护，不代表运行已核对。仓库版本查询仍经既有受管主机作业；仅把 `privileged_execution_pending` 映射为具体的主机任务入口，不改变围栏准入。

## 断链补传

Agent SQLite 队列在入队容量检查和取下一个待发送批次前，以批次创建时间批量删除超过 `min(max_age_seconds,max_retention_seconds)` 的 pending 数据；receipt 继续按原去重窗口保存。新参数在旧配置加载时取得默认 1 小时值，因此现有显式 24 小时接收年龄配置无需迁移。发送循环在成功 ACK 后等待 `replay_interval_ms`，失败继续退避。Docker 日志补采游标前移至保留窗口的起点，源序号不回退。过期数量进入无敏感数据的运行事件。

## 应用页加载

前端记录正在执行的总览请求。自动轮询和窗口重新聚焦只在没有请求运行时发起，保留慢首屏结果；手动刷新、筛选变化仍取消旧请求并发起新读取。中心总览在一次请求内复用过滤后的资源集合，避免为列表和数量重复读取及解密。API 结构、权限与轮询间隔不变。

## 架构影响

适用：队列保留与清理改变 Agent 本地存储生命周期；成功 ACK 节流改变 Agent→中心的数据路径；日志游标改变补采范围。同步 `docs/system-design.md` 的 Agent 队列章节和 Doca 系统设计基线同章节，写后回读目标文字与原生图节点、连线。应用状态和仓库提示仅改变现有状态投影与界面，不改变权限或部署拓扑。

应用页加载修复不新增组件、接口、凭据、存储或控制路径，只避免重叠读取和重复解密，架构同步不适用；同一 PR 的 Agent 变更仍按上段完成两端同步。

## 验证

运行 Agent 队列、补传及 Docker 日志回归，Web 状态投影与仓库界面检查，TypeScript 类型检查。验证围栏仍生效，记录未覆盖的生产主机核对与线上升级范围。
