# SDD 134：应用状态、仓库阻塞提示与断链补传

## 用户场景

1. 管理员查看已发布应用时，能分清正在部署、已确认运行、运行状态过期、执行结果未知和失败；保留服务地址不被误当成健康证明。
2. 管理员打开系统镜像仓库的镜像版本时，若同主机有尚未结束或核对的提权任务，页面明确指出阻塞原因并能进入该主机的执行记录核查。
3. Agent 与中心长时间断链后恢复，超过保留窗口的待发送数据不再上送，仍在窗口内的批次按原始时间戳有节制地发送，避免瞬间压满中心。

## 功能要求

1. 已发布应用仅在全部目标实例有新鲜的成功核对且版本一致时显示“运行中”。已有实例但观察超时或恢复任务因未知执行结果受阻时显示“待核实”，而不是无期限“待处理”；真正排队或部署中仍显示“待处理”。状态详情应保留服务地址保护及阻塞原因。
2. 仓库版本查询遇到 `privileged_execution_pending` 时显示可读原因和目标主机执行记录入口。不得绕过主机写入围栏或自动认定未知任务已经完成。
3. Agent 新增 `max_retention_seconds` 作为可配置的最大待发送年龄，默认 1 小时；启动和持续运行中批量清理超过窗口的 pending 批次，释放队列容量，保留已有 receipt 去重窗口。既有 `max_age_seconds` 的接收年龄校验保持原语义；永久错误的 quarantine 保留人工处理契约。
4. Docker 日志补采也受同一时间窗口约束，旧游标前移时保留源序号，避免将断链前很久的日志打成新批次上送。
5. 增加可配置的成功发送间隔，默认 1 秒；发送数据的原始事件时间和批次标识不改写，网络错误继续按现有指数退避。过期丢弃以计数事件可见，不记录敏感 payload。

## 验收标准

- 新鲜成功核对显示运行中；同一实例核对过期或恢复被未知结果阻塞显示待核实；未有实例的发布仍显示待处理。
- 仓库读取被提权围栏拒绝时，页面给出主机执行记录链接；围栏仍阻断新作业。
- 队列跨重启保存：超过 1 小时的 pending 批次不发送且释放容量；未过期批次按顺序、每批至少间隔 1 秒；ack 丢失重试仍保持字节和 ID 不变。
- Docker 日志游标落后保留窗口时，不生成窗口外日志的待发送批次。

## 边界与假设

- 保留窗口可由 Agent 本地配置调整；既有配置中显式设置的 `max_age_seconds` 不被覆盖。有效保留时间不超过两个参数中的较小值。
- 平滑补传指限制发送节奏，不改写遥测事件发生时间，否则历史图表将失真。
- 线上未知执行结果必须按已有主机核对流程处理；本轮不替用户做生产主机状态修正。
