# Feature Specification: Agent 首装残留与恢复闭环修复

**Feature Branch**: `codex/122-agent-install-recovery`
**Created**: 2026-11-11
**Status**: Ready
**Input**: 用户要求修复线上 Agent 安装失败后卡住的问题，防止再次发生。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在派发前发现覆盖残留 (Priority: P1)

管理员对仅残留 Agent 或 helper 服务覆盖目录的主机执行首装检查，应看到已有安装残留并转到现有恢复卸载流程，不能继续签发或派发首装。

**Why this priority**: 线上故障由旧卸载留下覆盖文件、首装检查误报干净引发。
**Independent Test**: 对两个固定覆盖目录分别创建空目录、普通配置及悬空链接，验证检查与首装入口均拒绝，不下载、不交换身份。
**Acceptance Scenarios**:
1. **Given** 仅残留任一受管服务覆盖目录，**When** 首装预检，**Then** 返回已有安装并阻止生成首装计划。
2. **Given** 预检后新出现覆盖目录，**When** 派发或执行 fresh 安装，**Then** 再次拒绝且不签发或交换身份。

### User Story 2 - 显式卸载清理覆盖残留 (Priority: P1)

管理员审阅并确认现有恢复卸载计划后，安全的固定覆盖目录应与程序一起删除，业务数据保留，下一次预检可继续。

**Why this priority**: 只有发现残留而不能通过受管卸载清理，仍会反复失败。
**Independent Test**: 执行真实 shell 的恢复卸载和离线卸载，检查覆盖目录消失、业务数据保留、后续预检通过。
**Acceptance Scenarios**:
1. **Given** 身份缺失且仅有 root 所有、不可被其他用户写入的平面覆盖文件，**When** 确认恢复卸载，**Then** 安全删除两个覆盖目录，保留业务数据和无关服务目录。
2. **Given** 覆盖目录或子项为符号链接、嵌套目录、特殊文件、非 root 所有或可被其他用户写入，**When** 卸载，**Then** 拒绝删除程序和覆盖文件。
3. **Given** 已审阅的覆盖文件内容或名称被改变，**When** 执行卸载，**Then** 证据校验拒绝执行；停止服务后再次检查路径安全。

### User Story 3 - 失败原因可见且恢复入口可用 (Priority: P2)

管理员应能看到覆盖拒绝的明确原因。在只读核对返回服务端错误后，页面应重新读取同一部署记录，读回成功即可继续核对或人工结束，不需关闭对话框。

**Why this priority**: 泛化的退出码和页面锁定放大了故障恢复成本。
**Independent Test**: 校验 SSH 诊断白名单与部署回执；页面模拟核对 502、读回成功/失败、切换主机等情形。
**Acceptance Scenarios**:
1. **Given** 安装因禁止的服务覆盖被拒绝，**When** 保存失败回执，**Then** 显示明确原因与退出码，输出不包含原始日志或凭据。
2. **Given** 只读核对报错，**When** 同一记录成功读回，**Then** 保留错误提示和原记录，恢复操作入口；读回失败或目标不匹配仍要求只读刷新。

### Edge Cases

- 隐藏文件、悬空链接、权限异常、服务停止失败、生命周期锁或未决业务操作均必须保持保守拒绝。
- 没有身份文件的残留可以由现有 SSH 恢复卸载处理，不因缺少 Agent 程序或 Node 而要求自动重装。
- SSH 超时、断线和非零退出仍不能证明没有远端副作用，结果继续保留 unknown，绝不自动重复安装或忽略安全覆盖检查。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 首装检查、派发前检查与 fresh 安装必须一致识别两个受管服务覆盖目录，包括空目录与悬空链接。
- **FR-002**: 在线与离线显式卸载必须检查固定目录及全部子项的类型、所有者和写权限，不跟随符号链接，不清理无关目录。
- **FR-003**: 恢复卸载证据必须包含覆盖目录及其文件名、内容与安全元数据的变化；删除前重新验证安全条件。
- **FR-004**: 卸载成功必须清除覆盖目录并完成现有服务不存在的检查；默认保留身份、配置与业务 operations 数据，purge 也保留业务数据。
- **FR-005**: 服务覆盖拒绝必须通过固定原因白名单传递，不把原始 SSH 日志暴露到诊断。
- **FR-006**: 恢复请求失败后必须有界读回同一记录；目标、请求代次或对话框变化时丢弃旧结果，读回未确认时禁用变更操作。
- **FR-007**: 需要真实 shell、服务端集成和页面交互回归证据，覆盖正常清理与拒绝路径。

### Key Entities *(include if feature involves data)*

- **安装足迹**：现有固定路径清单，补齐服务覆盖目录。
- **卸载观测与计划**：沿用现有快照摘要、路径安全和安装存在标记，不新增表或字段。
- **部署记录**：沿用现有状态、诊断和人工恢复审计。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 两个覆盖目录的全部残留测试在身份签发或交换前被拦截。
- **SC-002**: 安全残留经一次已确认卸载后可重新检查安装，无关文件和业务数据字节不变。
- **SC-003**: 不安全残留和计划后变化测试全部拒绝，删除次数为零。
- **SC-004**: 核对失败但记录可读时，无需关闭窗口即可继续恢复；记录不可读时不允许变更操作。

## Assumptions

- 使用现有主机、SSH 身份、卸载确认、生命周期锁和人工结束机制；不自动删除残留或提高 Agent 权限。
- 既有 unknown 记录仍需按现有人工结束/核对流程处理，不伪造成功或失败。
- 架构影响：不适用。本修复补齐现有受管程序目录的校验与清理，并复用已有记录读回；组件职责、控制/数据通道、存储、协议形状、凭据边界和部署拓扑不变。`docs/system-design.md` 与 Doca 无需改写。

## Release authorization — 2026-11-11

用户在修复 PR 交付后要求发版部署。本轮通过 GitHub PR 合入 main，以合并后的完整 SHA 为构建输入，发布固定标签 `20261111-agent-install-recovery-v1` 的 linux/amd64 与 linux/arm64 中心镜像；包含同源码的安装器、卸载器与两平台 Agent 发行包。保留当前镜像、原 Compose、环境与数据备份，仅更新中心镜像并核对线上健康、下载内容和恢复界面。存量 Agent 不自动升级，主机恢复沿现有显式审阅流程。本轮发版未改变架构，架构同步不适用。
