# Feature Specification: 统一中心服务与执行节点运行时

Created: 2026-10-17 · Branch: feat/node-runtime-migration · Status: Implemented · validation completed; PR pending

## User intent and scope

用户明确选择将中心服务和 LightMoni Agent 都迁移到 Node.js/TypeScript。现有网页、监控行为、数据和八语言接入继续提供；Go SDK 是业务客户端，保留 Go SDK 不代表平台仍依赖 Go 服务。Agent 独立运行，生命周期不绑定业务实例。沿用“节点助手”入口和 PR 合入主干的流程。

## User Scenarios & Testing

### US1 管理员升级后继续使用 (P1)

已有管理员升级平台后，原账户、会话、密钥、模型配置、节点与任务、大盘、日志搜索和告警规则仍可用，无需重新录入。

Acceptance: 使用旧存储的副本启动新服务，能够登录、解密配置、读取设置和会话；原 API 路径、权限、返回类型和错误语义兼容；主页及所有业务页面继续加载。

### US2 数据可靠接收和查询 (P1)

业务继续使用原 SDK 或 Agent 上报，平台保留原时间、整数精度和幂等语义；查询依旧有权限和资源限制。

Acceptance: 日志、指标、链路的两种编码和压缩均可接收；丢 ACK 重试不重复计数，身份、批次及历史目标表不改变；超大批次、非法数据、Key 越权被拒绝。精确整数与纳秒时间保持，查询不能访问私有表或执行写操作。

### US3 执行节点独立工作与恢复 (P1)

管理员升级节点后，既有节点身份、待补传数据、采集任务和目录读取位置保留，离线缓存、重试和故障诊断可用。

Acceptance: 原节点数据目录可读取；已确认批次不会因进程重启丢失，队列满返回背压；指标、拨测、目录日志和 SDK 配置代理继续执行；多标签任务同步和无任务撤除保持；业务启停不控制 Agent 生命周期。

### US4 日志、大盘、告警和助手等价使用 (P1)

管理员及成员继续使用已有查询、保存搜索、图表、告警接手与通知、AI 流式分析和草稿审阅。

Acceptance: 既有角色边界、版本冲突、SSE 历史及取消、价格和用量快照保持；告警不会因切换调度器重复发送，后台待发送记录可恢复；AI 只能读或生成待审阅草稿。

### US5 部署与后续开发 (P2)

维护者通过统一运行时构建并启动中心和节点。现有环境变量、CLI、安装命令和平台双架构分发继续可用。

Acceptance: 平台运行镜像和 Agent 运行包不需要启动 Go 进程；固定依赖、优雅退出、健康检查和持久卷说明完整，SDK 打包保留原语言支持。变更通过独立 PR 审阅。

## Requirements

- FR-001 中心及 Agent 的实际业务执行迁为新运行时，不通过反向代理或子进程保留 Go 服务作为隐藏实现。
- FR-002 保留全部已实现公开路由和 OTLP/节点/SSE 契约；缺失功能不能返回虚假成功或空列表冒充迁移完成。
- FR-003 旧 SQLite schema、master.key、密码散列、加密格式、会话、价格账本和迁移标记可继续读取，迁移有备份与验证。
- FR-004 Agent identity、队列 BLOB、receipt 指纹、日志偏移及缓存兼容，已确认批次的重放和背压语义保持。
- FR-005 精确 64 位数值、十进制告警条件、纳秒时间和日志游标不能发生静默精度损失。
- FR-006 身份/角色/Origin/Key 表授权、只读 SQL 控制、查询取消与资源预算保持；秘密不进入浏览器响应或诊断。
- FR-007 告警评估、接手、日程、静默、通知回调和 outbox 有唯一调度所有者，切换不重复执行。
- FR-008 AI 模型、工具、历史、取消、预算、用量及计费与原实现等价；Mastra 复用，宿主继续掌握凭据和业务权限。
- FR-009 部署脚本、安装下载、双架构包、README 和开发启动同步；Go SDK 和其它语言 SDK 继续提供原 API。
- FR-010 通过旧新差分、隔离集成、浏览器及实际启动验证后，才切换默认入口和移除已替代的 Go 业务实现。

## Edge cases

旧 ACK 丢失且重试跨版本、带未知 protobuf 字段、64 位边界、历史队列非空、目录轮转/截断、写库部分成功、连接中断、Key 轮换、跨地址复用密钥、请求取消、进程中断账本、并发版本冲突、单一告警调度、无任务/空标签、无模型目录、通知失败重试。

## Success criteria

- SC-001 中心与 Agent 可在不启动旧服务进程的情况下运行完整产品场景。
- SC-002 已实现路由均在迁移覆盖清单中对应实现和验收，不存在未说明的功能删除。
- SC-003 旧数据库及节点目录样例升级后，身份、配置、记录数、冻结内容和可精确数值一致。
- SC-004 队列重启、任务撤除、查询边界、权限、告警恢复及 AI 完整交互通过隔离验证。
- SC-005 容器和安装包的启动、退出及健康检查有实际证据，生产切换前存在可恢复快照。

## Assumptions

保留八语言客户端及 SDK 兼容；不添加新模型能力或远程任意命令。先在副本和独立端口验证，未通过等价验证前本地 8080 保持现有可用服务。中心和 Agent 迁移使用一个新功能分支，完成后提交独立 PR，未经授权不合并。
