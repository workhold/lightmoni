# SDD 022：Docker 实例与 main 对齐

- 日期：2026-10-25
- 分支：`codex/docker-main-alignment`
- 应用源码基线：`2a35bf025a821c683bd1854c9a89555913ca4243`

## 问题与目标

本地 `18880` 已运行最新 main，但 `18380` 的 Docker 中心仍由历史临时 Compose 文件管理，镜像没有最新服务部署 API 和 SDK 周期模块。官方 npm、Debian 下载路径在本机容器网络中极慢，导致新镜像没有完成构建。

1. Dockerfile 与两种 Compose 部署方式允许选择公开 npm、Debian 与 Node 归档镜像源，默认仍使用官方源；npm 锁文件校验和与 Debian 签名校验保持启用。Node 二进制始终与官方发行站的 SHA256 清单核对。
2. 镜像记录构建修订号，部署使用明确镜像标签；不通过固定 `0.1.0` 标签判断源码版本。
3. 将现有 Docker 中心升级到 main 应用源码，保留 `18380`、现有用户、SQLite 主密钥和 ClickHouse 数据。
4. 当前实例改用仓库的标准 Compose 与受限 `.env`，不继续使用复制环境变量、含明文凭据的临时 JSON 部署文件。
5. 完成独立容器验证、现有实例升级与读回，保留旧镜像、状态备份和可执行回滚命令。

## 架构影响

不适用：本次只修正既有 Docker 构建参数、修订号标识和现有 Compose 的运维使用。中心 + ClickHouse 拓扑、数据卷布局、HTTP/OTLP 协议、凭据用途、SDK/Agent 分发和 AI 工具边界均不改变；现有系统设计已经描述该部署方式。因此不修改 `docs/system-design.md` 或 Doca 在线图文。

## 验收

- 两种 Compose 能解析并继承构建参数，必填数据库配置仍会拒绝空值。
- 最新源码完整构建 Linux 镜像，包含四种 SDK、双架构 Agent 和 SHA256 清单。
- 独立中心/ClickHouse 健康，网页、管理员登录、真实日志写入与只读查询、包下载校验通过；重建容器后数据保留。
- `18380` 升级后最新功能模块存在，用户与数据保留；标准 Compose 可检查、重建和回滚。
- 源码、证据、PR 和日志不包含实例密码或 token。
