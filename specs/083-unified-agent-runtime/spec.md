# SDD083：统一 Agent 与运行权限模式

## 用户目标

一台主机只安装一套 LightMoni Agent、运行一个常驻 Agent 服务。相同程序提供 root / user 两种运行权限；新安装默认 root，用户可取消。安装、权限切换、升级、回退和卸载属于统一生命周期。所有任务无论权限、UI/AI/MCP/调度来源均需鉴权、持久化执行记录与审计。

## 必须满足

- 单一 `lightmoni-agent.service`、程序发行目录、current 指针和用户可见 Agent ID；不再安装独立 root 常驻服务。既有签名任务执行模块作为 Agent 内部模块复用，内部执行签名凭据不能表现为第二台节点或第二套安装。
- 配置 `runtime_mode: root | user` 与递增 `permission_generation`；真实 UID/EUID 必须匹配。新安装计划显式包含模式，默认 root；升级保留原模式，不能因默认值自动提权。
- 统一安装包包含两种模式。用户取消 root 后以专用普通账户运行，不能访问 Docker/root 能力；实际能力由运行身份、环境依赖与平台授权共同决定。
- 普通脚本即使由 root Agent 调度也固定以专用普通账户执行，清空附加组并禁止获得新权限；不能继承 Agent 的 root 身份。root 脚本和受管动作继续使用批准、签名计划、start permit、租约、journal 和 unknown fence。
- 切换模式必须先生成绑定主机、SSH目标/凭据修订、当前/目标模式、权限代次、发行的维护计划，由有权限的管理员确认。通过 root/免交互 sudo SSH 执行固定维护程序；普通 Agent 不自提权，不保存 root 登录密码。
- 切换、升级、卸载与在途/未知任务、终端和其他维护互斥。切换暂停新派发；无有效回执时保留 unknown/维护门禁，禁止自动重放。切换前排队任务不得扩大原批准权限。
- 切换成功必须持久化精确绑定的完整成功回执，并与同一 boot_id、UID/GID、目标权限代次及发行 SHA 的新鲜心跳匹配；root 另核验内部签名身份在线。短暂目标心跳不解围 unknown；只读 reconcile 可用新有效凭据恢复回执或证明原账户已恢复，不重放 apply。
- 切换保留主机和 Agent ID。旧配置、程序、任务缓存不能未经验证直接被 root 信任；root启动须验证代码与敏感配置归属。降权只调整 Agent 自有状态，不递归 chown operations 业务持久数据。
- 升级仅一个入口并保留模式；卸载同时清理内部执行状态并撤销关联执行授权。业务服务、用户数据和审计历史保留。旧独立服务如存在，明确要求受管清理，不能默默双开或直接信任旧状态。
- 审计记录发起人、来源/批准、目标主机、计划摘要、实际账户、权限代次、每步状态与结果；秘密只允许经受保护运行时传递，不能进入计划正文或公开回执。

## 验收与边界

覆盖两种安装模式、真实账户与配置不符拒绝、root模式普通脚本降权、权限切换双向、陈旧/过期/重放/凭据撤销拒绝、维护互斥、升级保留模式、统一卸载、内部签名执行及审计。Linux/systemd 真实隔离环境与本地fixture分开记录，不擅自升级用户线上主机或恢复已经撤销的root权限。
