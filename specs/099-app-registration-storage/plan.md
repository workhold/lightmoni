# 实现设计

沿用PR129独立工作区。原主工作区发行文件不动。用户确认尚未上线，因此直接重构存储，旧布局仅作为历史证据，不作为新运行分支。

应用路径辅助函数要求稳定application_id，实例配置/版本/初始化/默认数据在applications/<application_id>/instances/<instance_id>。默认Compose卷显式命名，带应用和实例身份；项目标识与容器归属标签保持受控。恢复检查、对账和清单使用同一布局。

网站根websites/<website_id>含归属标记、current及versions/<内容摘要>。每版本nginx.conf聚合该网站所有域名分组，ssl/auth/public按分组ID细分；私有metadata与探针只在网站目录。网关目录仅保存全局配置、网站版本引用和网关状态，通过两个受控只读bind挂载网关根与网站根。全局配置引用精确不可变网站版本，原子切换完整索引保留跨网站一致性。成功后更新各网站current；失败恢复完整旧索引和网站指针。网关历史不保存网站私钥、鉴权哈希或静态正文。

新增持久网站落点与删除记录。网关派发记录网站曾部署的机器；DELETE网站创建幂等清理意图并停用网站、驱动现有DNS撤销。逐机website.remove移除已撤下的网站及全局历史引用，停止/不存在的网关先保存剔除该网站的索引。在线仍引用该网站时拒绝清理。离线持久等待，已知失败可重试，未知执行保持核对门禁。全机成功且DNS/引用保护通过后才store.remove注销登记。共享证书与应用数据保留。删除中的网站禁止编辑和重新发布。

operations.platform.storage.v2能力约束新布局作业领取，固定身份路径不接受调用者任意根。更新管理员UI提示、清单和删除进度。测试覆盖独立多网站发布/回滚/实际SSL鉴权、逐机删除与重启/离线/unknown、越权路径、应用跨ID/实例数据隔离与初始化保留；类型检查、真实Docker及浏览器验证后更新同一PR和架构证据。
