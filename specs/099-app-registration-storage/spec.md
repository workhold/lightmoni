# 应用与网站按资源 ID 隔离存储

日期：2026-11-07。分支：codex/099-app-registration-storage。用户追加：项目尚未上线，直接采用新布局，不实现旧目录迁移或双布局兼容。

1. 已卸载应用允许删除登记，实例/引用/未知执行保护继续保留；应用数据目录属于 applications/<application_id>/instances/<instance_id>/，配置、初始化、持久数据和状态均在此之下。默认命名卷显式包含应用与实例身份；自定义外部路径/卷保留明确覆盖语义。同应用不同实例不得意外共享数据。应用卸载及删除登记保留业务数据。
2. 每个网站属于 websites/<website_id>/，域名仅为元数据。版本目录同时保存网站 nginx.conf、SSL副本、鉴权哈希、认证探针和静态文件，current 指向网站当前版本。多域名分组在网站版本内区分。网关主配置仅 include 网站不可变版本，不保存网站秘密正文。
3. 网站发布先写独立版本，nginx -t 后切换网关索引及网站 current，重载和HTTP/TLS/鉴权验证失败恢复旧索引和指针。一个网站变化不改写其他网站版本。删除需要撤下路由、清理DNS、消除旧网关回滚引用，确认各宿主网站目录删除后再注销登记；共享中心证书资源保留。
4. 删除请求持久保存逐机器状态；离线、权限撤销、执行失败或unknown时保留登记和待处理/异常状态。重启和重复请求不丢进度、不重复已成功清理；unknown不盲目重放。实际清理只能删除固定根下归属匹配的网站目录，不能跟随任意路径或误删其他网站/应用。
5. 管理员详情显示应用ID根、实例根、网站ID根、独立配置/SSL/鉴权/静态目录与删除进度。清单只读、分页、有界、不含秘密；新版存储能力单独标识，旧Agent不能领取新布局作业。

架构影响：适用。目录/容器只读挂载、网站版本与删除控制路径、回执及能力协议发生变化。同一PR同步 docs/system-design.md 第99节与用户要求的Doca基线，回读并保留原生图。仅开发和验证，不合并、发版或部署生产。
