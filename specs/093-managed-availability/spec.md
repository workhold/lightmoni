# Feature Specification: 托管可用性保护与应用就绪检查
**Feature Branch**: `codex/093-managed-availability`
**Created**: 2026-11-04
**Status**: Implemented and verified
**Input**: 避免短暂 Agent 失联导致下线/删除解析；每集群最小在线比例；应用健康检查；先启动后切换。

## User Scenarios & Testing
### User Story 1 - 短暂失联保持服务 (Priority: P1)
管理员希望 Agent 网络抖动时服务地址稳定。独立测试：中断已就绪实例心跳并恢复。
1. 失联不足 N 分钟保留发现、网关解析和运行状态，不自动迁移。
2. 连续失联达到 N 分钟后按预算处理；恢复清除失败计时；中心重启不丢失计时/成员。
### User Story 2 - 集群比例与先启动后切换 (Priority: P1)
管理员独立设置各集群最低比例。独立测试：三副本、60% 下连续多故障及替换。
1. 最低数量向上取整为 2，没有 ready 替换最多自动撤掉一个已发布成员。
2. 替换先启动、通过就绪检查再撤销旧实例；失败/未知不切换。
3. 升级一次只处理一个实例，真实 ready 数不得低于预算；不能中断则先额外启动，资源不足展示等待。
4. 保留的疑似故障地址标记降级/保护，不伪造健康；显式停止/移除/缩容尊重用户意图。
### User Story 3 - 应用健康检查 (Priority: P1)
用户在手动及托管应用登记 HTTP/TCP 检查。独立测试：真实 HTTP 响应和容器状态组合。
1. HTTP 默认 GET、路径 /、状态码 200、超时 3 秒、间隔 30 秒，均可配置。
2. 配置检查时常驻容器运行且检查成功才 ready；无配置沿用容器运行及 Docker 健康状态。
3. 非预期状态、重定向、超时不 ready；从未 ready 的实例不进入发现/DNS。
### Edge Cases
- 单副本/100% 比例需要额外容量；有状态不自动搬迁本地数据。
- 零副本最低数零；多集群预算隔离；未知结果保留执行栅栏。
- 目标由本机授权端口派生；拒绝任意目标、协议相对路径、控制字符。
- 旧应用缺省使用安全默认值，不删除存量数据。

## Requirements
- FR-001: 失联/失败宽限为整数 1–60 分钟，默认 5，连续失败才主动撤流/迁移。
- FR-002: 各集群最低百分比为整数 0–100，默认 60；按期望副本数向上取整。
- FR-003: 发现、网站后端、网关 DNS 共用持久成员判断。
- FR-004: 主动撤流守住最低成员数；真实 ready 与受保护地址分别展示。
- FR-005: 替换当前代际成功 ready 后原子提升槽位、退役旧实例，再清理。
- FR-006: 滚动升级遵守真实 ready 预算，不足时先 surge；资源不足明确 pending。
- FR-007: HTTP 支持端口、路径、状态码列表、间隔、超时；发布和持续检查共用。
- FR-009: 替换后旧实例须等待路由确认和连接排空；网关入口等待已验证 DNS 更新后至少一个 TTL，失败保留旧进程。失败替换允许显式重试，未知结果仍须先检查。
- FR-008: 保留权限、签名执行快照、未知结果及有状态边界。
### Key Entities
应用宽限策略；集群最低比例；应用就绪配置；实例最后就绪、连续失败、已发布成员与替换槽位。

## Success Criteria
- SC-001: 5 分钟策略下中断 4 分钟再恢复，无退役和 DNS 成员变更。
- SC-002: 三副本/60% 无 ready 替换时已发布成员不会因自动撤流少于 2。
- SC-003: 替换失败/未知不停止旧实例；ready 后每槽位一个正式实例。
- SC-004: 有执行证据覆盖 200/204/503/重定向/超时与无检查容器场景。
## Assumptions
默认 5 分钟/60%；比例约束平台主动撤流，不能保证故障机器真实可用，界面明确区分；不新增代理、数据复制或跨机数据迁移。
