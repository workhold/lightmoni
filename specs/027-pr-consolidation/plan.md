# 实施计划

1. 从最新 origin/main 建立整合分支，记录四个 PR 的固定 head 与审查结果。
2. 依次保留开源迁移、GitHub 工作流、导航与调研提交，逐处解决与 main 的冲突。
3. 将 main 的 `/operations` 管理员入口加入统一导航配置；维护已有路由和 AI 页面上下文。
4. 核对许可证打包、SDK 路径以及调研时点，完成相关测试和 Web 构建、界面验收。
5. 推送整合分支，创建中文 PR，回读校验并按用户授权合并；再关闭被替代 PR，回读最终状态。

验证证据与具体限制记录于 `validation.md`；涉及秘密或运行时配置的内容不进入证据。
