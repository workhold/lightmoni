# 027 合并待处理 GitHub PR

## 目标

将用户指定的 GitHub PR #1、#3、#4、#5 整合为一个面向最新 main 的 PR，解决冲突并完成验证后合入。只有在整合已落地后关闭被覆盖的旧 PR；不直接推送 main，不改动线上容器或远程 Agent。

## 范围

- 保留 #1 的 Apache-2.0、GitHub 开源入口、SDK 元数据与 Go 模块路径迁移。
- 保留 #3 的 GitHub 推送和 PR 协作规则。
- 保留 #4 的导航分类、当前分组自动展开、其余分组默认收起、图标模式和角色过滤；同时纳入 main 已有的运维功能入口。
- 保留 #5 的 1Panel 调研，并明确报告时点，避免将已落地的 SDD 026 能力描述为当前缺失。

## 验收

1. 四个原 PR 的有效变更均被整合，main 已有运维页面与权限保持可用。
2. 管理员可在运维分类访问主机、节点、部署和运维页面；普通成员不显示管理员入口，直接访问仍受原路由保护。
3. 导航分组、路由切换、中英文、收起模式可用；Web 构建与相关 SDK 测试、打包检查通过，限制如实记录。
4. 新 PR 通过 GitHub 合入 main 后，关闭四个已被替代的旧 PR，并以整合 PR 说明去向；保留其他仍有独立价值的 PR。

## 架构影响

不适用。本次整合已存在的许可、托管流程、调研及 Web 导航展示，不改变组件职责、数据/控制路径、凭据边界、存储、协议、部署拓扑或 AI 工具边界。main 的系统设计与 Doca 基线继续有效，无需重复改写。
