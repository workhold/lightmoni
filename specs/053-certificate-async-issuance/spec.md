# 证书创建后自动异步申请与签发步骤日志

日期：2026-10-31。分支：`codex/053-certificate-async-issuance`。

## 用户需求与验收

1. 管理员创建证书成功后自动申请一次，立即返回已保存的资源与后台执行回执，不等待 ACME/DNS；自签与上传同样自动生成/导入首个版本，是否自动续期不影响首次申请。编辑已有证书不重新自动申请。
2. 表格实际状态显示“申请中”，旁边日志图标可直接查看该证书本次及历史申请；轮询更新当前阶段、耗时、逐步结果和失败原因。关闭窗口、切换页面不终止中心后台申请；旧执行无步骤日志时明确说明旧原因无法恢复。
3. 日志覆盖排队/开始、ACME 账号、CSR/订单、授权、DNS TXT 创建及厂商回读、DNS 公网传播等待、挑战提交/验证、订单签署、证书下载/保存、TXT 清理。自签/上传显示各自真实步骤，不伪造 ACME 过程。传播等待提供次数，清理失败与主失败分别保留。
4. 手动 issue/renew 同样立即返回 202 后台回执，内部网站首次 HTTPS 获取材料仍可等待现有同步契约；自动续期沿用授权与去重，并记录步骤。并发重复申请返回已有执行或明确 busy，不重复提交 CA/DNS。
5. 失败保留实际阶段、稳定错误码、可读原因、可用的 CA 类型/HTTP 状态/厂商 request ID；不能只剩 acme_issuance_failed。输出必须脱敏且有界，禁止私钥、EAB、凭据、挑战 token/TXT 值、Authorization、原始请求响应或堆栈进入回执/日志/前端。
6. 首次申请意图随资源保存持久化，创建后进程中断不能静默遗漏；已经开始但中心重启的执行标记未知并保留历史，不自动重放不明 CA/DNS 写入。失效管理员、revision 改变、删除/关闭与现有凭据守卫继续生效。
7. 实时步骤使用 SQLite 有序执行日志，管理员接口读取；同一事件通过既有事务 outbox 投递 ClickHouse 系统日志，ClickHouse 不可用不阻塞实时诊断。成员不能发起或读取证书步骤，既有单条 DNS 和其他运维行为保持兼容。

## 架构影响

适用：证书创建触发后台执行、运行回执/步骤日志持久化和查询路径发生变化。同步 `docs/system-design.md` 第 33.3–33.5、44 章及新增 53 章；Doca 同一主题增加正文与原生流程图并回读文本、节点和连线，保留现有图块和无关内容。凭据继续仅在中心加密使用，不新增 Agent 证书签发权限或外部队列。

截图中的旧执行只保存通用错误码，无法凭此确认真实域名失败原因；以可重现的 CA/DNS 失败夹具验证具体诊断保留，不擅自重试线上申请。
