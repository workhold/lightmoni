# Feature Specification: 网站多集群入口与线路流量管理

**Feature Branch**: `codex/043-website-cluster-routing`
**Created**: 2026-10-30
**Status**: Implemented; draft PR #19, pending review
**Input**: 用户要求调整已安装应用的部署集群及配置；全局唯一 OpenResty，集群独立入口域名；网站托管服务自动发现或手动集群后端；展示实际集群并支持开关、权重和运营商/省份线路；健康驱动 CNAME 撤下及默认线路回退。

## User Scenarios & Testing

### User Story 1 - 调整应用部署与集群入口 (Priority: P1)
管理员在应用及网站 OpenResty 管理入口编辑已有安装配置，增加或移除部署集群，调整每集群机器、副本及资源，为每个入口集群设置稳定域名。
**Why this priority**: 集群域名隔离入口机器变更，避免逐网站修改解析。
**Independent Test**: 创建一套双集群 OpenResty，修改入口域名和部署目标后刷新读回；普通商店应用同样可以编辑配置。
**Acceptance Scenarios**:
1. **Given** 全局已安装 OpenResty，**When** 新增部署集群，**Then** 仍是同一个应用，网站页显示全部部署及入口域名。
2. **Given** 某集群仍有运行实例，**When** 移除部署，**Then** 明确提示先停用并清理，不能丢失仍运行实例的控制状态。
3. **Given** 已安装普通应用，**When** 编辑安装配置，**Then** 保存后可按集群发布新修订，身份及安装秘密保留。

### User Story 2 - 网站共享配置与实际集群 (Priority: P1)
托管模式选择应用服务及命名端口，自动绑定该服务部署集群；手动模式选集群后填写各集群代理。公共域名、证书、路径选项只配置一次。实际集群列表提供独立启停和流量配置。
**Why this priority**: 消除逐集群重复配置，保持可见和可控制。
**Independent Test**: 托管网站选择双集群服务，保存、发布、刷新能显示两个实际集群；手动网站保留两个不同代理地址。
**Acceptance Scenarios**:
1. 托管服务部署到新集群后，网站自动发现并绑定；没有健康后端时不虚报可服务。
2. 手动模式仅绑定明确选择的集群，新增、移除和再次编辑不丢失其他集群后端。
3. 集群临时关闭立即退出网站 DNS 期望集合，重新开启后需现场验证才恢复流量；其他集群不受影响。

### User Story 3 - 按线路和健康维护 CNAME (Priority: P1)
默认线路包含所有开启且有已验证入口的集群，按权重分流。高级设置为集群指定厂商实际支持的运营商、省份线路；单个集群可以同时承接默认和若干高级线路。
**Why this priority**: 南北就近解析，故障后回退默认。
**Independent Test**: 南北两集群默认 1:1，并各自承接省份线路；南方入口失效后，南方专线和默认中的南方记录撤下，默认只保留北方。
**Acceptance Scenarios**:
1. 网站域名的记录值始终是对应集群入口域名，单个入口机器改变不重写各网站 CNAME。
2. 仅开启且经网站配置验证的健康入口参与解析；失联、过期观察、配置失败或手动关闭不产生新流量。
3. 厂商/域名套餐不支持权重或所选线路时，展示明确错误，不能静默改成默认或宣称成功。
4. 仅维护平台拥有的记录；外部记录、外部修改、未知写入结果保持原有保护。

### Edge Cases
- 全部入口故障时撤下平台拥有的解析，显示无健康入口；不能把无效目标当作默认兜底。
- DNS 缓存有 TTL，撤下不是即时流量切换保证；厂商接受和公网传播分别显示。
- 旧网站未配置集群入口域名时保持原 A/AAAA 行为；明确开启新 CNAME 模式后全部目标必须具有入口域名。
- 移除运行中的部署仍需先停用/清理；托管网站引用关系允许自动发现变化，手动绑定仍需先解除。
- 集群入口域名可由用户外部维护；选择托管域名时平台维护已验证入口的 A/AAAA，DNS 凭据留在中心。
- 高级线路使用厂商返回的线路 ID 与名称，不能自行拼接省份或运营商编码。

## Requirements

### Functional Requirements
- **FR-001**: 全局只能存在一套 OpenResty 应用，允许配置最多 100 个部署集群；所有应用支持编辑已有安装配置。
- **FR-002**: OpenResty 集群部署保存独立稳定域名和可选托管 DNS 区域；托管时只汇总本集群健康入口地址。
- **FR-003**: 网站提供手动/托管绑定模式；托管选择一次服务和 HTTP(S) 命名端口，自动发现其部署集群。
- **FR-004**: 网站集群保存 enabled（默认 true）、weight（默认 1，正整数）及高级线路列表（默认仅默认线路）。
- **FR-005**: 展示配置集群、现场生效状态和 DNS 状态；开关、权重、线路修改可单独保存并保留其他公共配置。
- **FR-006**: 新网站默认 CNAME 模式；网站各线路仅维护开启且已验证健康集群的 CNAME，默认按相对权重分流。
- **FR-007**: 托管入口失效或关闭后自动撤下其全部线路目标，剩余默认集群继续承接，恢复验证后重新加入。
- **FR-008**: 提供厂商实际线路查询，验证权重与线路套餐能力；未支持/未知状态不能宣称已生效。
- **FR-009**: 保存配置仍是草稿，发布冻结公共配置；集群流量策略属于单独即时策略，不依赖网站重新发布。
- **FR-010**: 保持管理员、revision、确认、授权撤销、操作回执及 DNS 归属保护；相关契约和回归验证覆盖上述路径。

### Key Entities
- 应用部署：应用与集群的关联，保存机器/副本、资源和入口域名。
- 网站集群流量策略：自动发现或手动选择的集群、开关、相对权重、默认及高级线路。
- DNS 线路：云账号域名实际可用的线路标识、显示名称和套餐能力。
- DNS 归属记录：网站或集群入口拥有的厂商记录及线路、权重和状态。

## Success Criteria

### Measurable Outcomes
- **SC-001**: 同一 OpenResty 应用可从 1 个集群增到 2 个，并在网站页读回入口域名。
- **SC-002**: 托管网站仅选择一次服务即可发现两个集群，手动网站保留两份不同后端，公共配置只有一份。
- **SC-003**: 南北集群默认 1:1 和省份分流可核对实际厂商回读；模拟南方故障后只剩北方默认记录，恢复后重新加入。
- **SC-004**: 关闭、权重更新、线路变更、未知写入、外部修改及授权撤销均有自动验收证据，前端完成保存读回和失败保留输入。

## Assumptions
- “男方集群”按“南方集群”理解。高级线路能力由用户的域名套餐提供，平台不自动购买或升级套餐。
- 集群至少一台入口仍健康并有该网站成功回执时可继续承接；全部入口失效才撤下该集群。
- 旧数据维持旧解析方式，新模式显式记录；外部维护的入口域名不会由平台擅自修改。
- 本次按现有管理员控制面实现；不新增外部健康探测服务或跨集群后端代理。
