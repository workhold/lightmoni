# Agent 重装收尾与按来源镜像代理

## 背景与目标

生产恢复暴露两条断链：旧 Agent 留下的 retired/orphaned 实例挡住同主机调度，即使 Docker 已无容器；OpenResty 的 nginx 预检隐式从 Docker Hub 拉取，网络超时既没有按源代理，也只显示通用命令错误。目标是让重装后经核验自动释放旧占用，并让管理员为明确镜像来源设置代理。

## 要求

- 新 Agent 保持独立身份；成功卸载且已证明身份归属时给旧身份写移除墓碑，保留历史与审计，拒绝旧凭据恢复连接。保留配置/清除配置仍由原卸载计划显式选择，不自动删除业务数据、容器或卷。
- 对同一稳定主机绑定的旧实例，当前在线 Agent 自动进行只读 Docker 核验。仅确认不存在旧实例容器、旧 Agent 离线、没有活动或 unknown 执行、绑定未变化时，将旧实例退休并标记 stopped，释放其端口预留。存在容器（包括停止容器）、核验失败、绑定变化或 unknown 时不自动清理、不收养、不删容器。
- 手动和托管部署均可在核验完成后重装。核验和阻塞原因可见，不能再只显示容量/端口不足。旧执行迟到回执不能覆盖收尾结果。
- 管理员从“运维工具 → 镜像源”独立页面配置全局“来源仓库 → 代理仓库/路径前缀”，不与私有仓库部署入口混合。例如 docker.io → m.daocloud.io/docker.io；只命中该来源，不做任意字符串替换、不递归代理。私有镜像管理仅负责系统仓库、集群缓存和对外发布。
- 每条来源独立选择失败是否允许回源，默认禁止。未配置来源保持现有行为。先复用本机镜像、现有集群缓存，再用指定代理。严格缓存禁止回源时不得绕过。
- 普通容器、Compose、系统 Registry 引导和 OpenResty 预检/启动共用镜像准备；代理拉取成功后核对平台与镜像 ID，启动固定实际 ID，不把代理标签重写为原始标签。digest 引用保留 digest；可变 tag 代表管理员信任的代理返回，不声称已比对不可达原站同 tag。
- 代理配置仅接受 HTTPS 仓库及可选 repository 前缀，不含 userinfo、查询、片段或秘密。来源认证不转发到代理；首版不新增认证/CA 管理，不修改 Docker daemon 或重启 Docker。
- 保存有 revision CAS，领取任务时重验当前策略与主机绑定，新能力只派给支持的 Agent。中文/英文界面保留编辑输入并说明冲突、影响范围和生效时机。
- 拉取阶段及 Docker 网络超时有可读诊断，原始 stderr、凭据不进公共结果。

## 架构影响

适用：增加重装只读核验控制路径、全局镜像来源策略存储和 Agent 镜像准备能力。同步 docs/system-design.md 第75章及 Doca 系统设计基线的 SDD075 章节，保留已有原生图块。需要中心与 Agent 同时升级，默认空策略保持兼容。全局/集群/单机继承、daemon HTTP 代理、自动删除旧业务容器及有状态数据迁移不在本次范围。

## 验收

以中心真实 SQLite/AgentJob 流程验证无容器收尾、仍有容器、unknown/活动执行、重绑定、旧回执、手动/托管重建及身份墓碑；执行器验证完整来源匹配、Hub 简写、带端口仓库、digest/平台、代理失败策略、缓存优先级和网关预检；网页验证无需私库可配置、保存冲突与中英文。真实 Docker 验证代理拉取后固定 ID 启动。验收环境和生产发布分别报告。
