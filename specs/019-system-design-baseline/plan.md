# SDD 019：实施计划

## 阶段 1：事实盘点

1. 读取当前中心、Agent、SDK、AI、Web 和 Compose 的目录与入口。
2. 以运行时代码、公共契约、最新特性 SDD、验证脚本的优先级建立事实来源。
3. 记录当前实现与目标架构之间的差异，不在总设计中静默选择其中一方。

## 阶段 2：HLD 编排

1. 写产品使命、驱动目标、非目标和设计原则。
2. 写组件边界、部署拓扑、身份边界和两条 SDK 数据路径。
3. 写从接入到存储、查询、告警、AI 和运维的端到端数据流。

## 阶段 3：LLD 固化

1. 写模块、生命周期、HTTP/OTLP、SQLite/ClickHouse、队列和状态机。
2. 写凭据签发、Agent enrollment、SSH 计划、终端和 AI 工具审批。
3. 写前端路由、权限、状态、国际化和浏览器安全边界。

## 阶段 4：一致性验证

1. 校验 README、总设计和已有文档的链接。
2. 搜索“SDK 必须经过 Agent”“Agent 只是辅助组件”等过时表述。
3. 检查 Java/C#/PHP、Go/Rust 和 Ruby 的发布矩阵表述是否标明当前状态。
4. 运行文档链接和 Markdown 基础检查，记录未在本机执行的系统测试。

## 阶段 5：交付

1. 提交文档变更到功能分支。
2. 创建待审核 PR，保留用户人工合并。
