# 后续功能验收步骤

功能尚未实现，以下不是通过证据。

1. 基础验收不安装或配置任何内网仓库。两个独立Linux Docker daemon/Agent、同集群、无状态v1/v2，从已有镜像源完成安装/预热/升级，记录平台/镜像大小/链路。standby=1全部服务ready后阻断公网并停止原节点，备用相同release启动，测公网0字节和各阶段耗时；外部删镜像使ready失效，全部候选缺镜像时按回源策略下载或等待。
2. 可选缓存增强单独验收：已有独立持久化认证registry作为第三daemon，预填固定digest，原节点离线且接管无本机镜像，断公网仍从缓存启动；另验证多集群复用同端点而权限隔离。测miss+禁回源、宕机+允许回源、认证/摘要/架构错误及磁盘不足；不作为步骤1或版本升级的依赖。
3. 加端口冲突、容量不足和不同架构机器，证明缓存不能绕过硬约束；无独立合格备用显示degraded，本地数据库不迁移。
4. 全局→集群→单机profile继承/覆盖/清空/来源；原daemon预置无关键。保存不重启，审阅全部容器影响后逐机应用，测CAS、保留键、失败恢复和业务验证失败。私有凭据无越权与泄漏。
5. v1部署A/B，登记v2并检查模板迁移/停机/回退，仅升级A；同tag更新后B重启仍旧内容。失败/中断/过期回执/中心重启/模板冲突/撤权均有核对结果，unknown不重放。
6. 新商店版本出现提示，检查失败保留旧结果并标失败，无源明确未配置。浏览器完成选集群、准备、升级、逐机进度、保存刷新与失败保留。
7. P2窗口内执行已授权兼容无状态更新，主版本、窗口外、有状态、迁移未知、撤权与unknown均无任务。
8. 仓库功能关闭无新容器；在明确宿主机安装private/cache/both组合，重试无重复，核对独立存储/端口、引导镜像、停用/升级数据保留与引用保护。
9. A为唯一push origin，B独立存储起初为空；B直拉/缓存或完整复制后按同digest读取。push域名固定A，断源不能切到空B，准备未完成不报成功。验证可信内网匿名只读、来源限制、公网后端不可直达、HTTPS鉴权、pull/push组及真实Docker大镜像分块/Location。
10. 真实OpenResty验证全站/路径继承/关闭/覆盖、多用户重置/启停、跨集群待发布/部分失败/换机、账号材料私有、旧Agent拒绝；CORS/return/跳转/片段/缓存无旁路，Basic头不传上游，匿名401不误摘健康入口，失败保持旧鉴权。

每项保存预期/实际、环境、版本摘要、逐机有效lease回执与测量。DinD注明同物理宿主限制，不冒充多实机；不修改生产资源。文档检查不能替代上述功能验收。
