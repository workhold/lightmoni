# 首版运行与验收

当前已实现范围以[implementation-v1.md](implementation-v1.md)为准；通过证据见[evidence/validation.md](evidence/validation.md)。下面保留的完整生命周期步骤是后续路线，不代表已经实现。

1. 更新中心与Agent到本分支版本。管理员进入“私有镜像管理”，安装Docker Registry，指定集群、机器与该机器明确私网IP；确认该端点只允许可信网络访问。安装会分配受管端口和数据目录，固定机器与IP。
2. 在部署行或集群编辑开启内网缓存；刷新核对期望/实际状态，等待Agent执行。缓存按需填充，不预下载所有镜像。可在应用管理安装额外普通Registry，系统不会自动接管它们。
3. 准备域名及匹配证书，在“对外发布入口”选择一个部署、填写域名/账号/密码，必要时勾选安装OpenResty。DNS使用既有网站设置或在外部维护。构建机执行Docker login后向该唯一域名push；发布源确定后禁止静默切换到其他独立空库。
4. 源集群应用可通过登记端点直接拉取自身域名镜像；其他集群安装系统仓库并开启缓存。当前不修改Docker daemon代理或insecure-registry配置。内网匿名端点可读写，不具备多租户权限隔离。
5. 网站编辑支持全站/路径Basic。密码只写，留空保留同名账号；网站发布与凭据一起验证，旧Agent拒绝新能力任务。安装、保存和排队不等于Agent已应用，按状态与回执核对。

开发验收：先安装现有工作区依赖并构建SDK，运行runtime/web的typecheck。真实Docker验证运行`npm --prefix runtime run build`后执行`sh scripts/verify-private-registry-isolated.sh`；脚本依赖本机已缓存Registry 3.0.0、Alpine 3.23、OpenResty 1.27.1.2、Docker 27 DinD及现有cluster-demo QA执行镜像，使用隔离daemon并清理自身容器。浏览器QA启动`runtime/test/fixtures/cluster-ui-server.ts`于19959及代理到该API的web开发服务器19960，再运行`node web/src/app/ops/verify-registry-ui.mjs`。该fixture仅可用于临时本机QA，不能当作生产身份验证。

# 后续功能验收步骤

功能尚未实现，以下不是通过证据。

1. 基础验收不安装或配置任何内网仓库。两个独立Linux Docker daemon/Agent、同集群、无状态v1/v2，从已有镜像源完成安装/预热/升级，记录平台/镜像大小/链路。standby=1全部服务ready后阻断公网并停止原节点，备用相同release启动，测公网0字节和各阶段耗时；外部删镜像使ready失效，全部候选缺镜像时按回源策略下载或等待。
2. 可选缓存增强单独验收：已有独立持久化认证registry作为第三daemon，预填固定digest，原节点离线且接管无本机镜像，断公网仍从缓存启动；另验证多集群复用同端点而权限隔离。测miss+禁回源、宕机+允许回源、认证/摘要/架构错误及磁盘不足；不作为步骤1或版本升级的依赖。
3. 加端口冲突、容量不足和不同架构机器，证明缓存不能绕过硬约束；无独立合格备用显示degraded，本地数据库不迁移。
4. 全局→集群→单机profile继承/覆盖/清空/来源；原daemon预置无关键。保存不重启，审阅全部容器影响后逐机应用，测CAS、保留键、失败恢复和业务验证失败。私有凭据无越权与泄漏。
5. v1部署A/B，登记v2并检查模板迁移/停机/回退，仅升级A；同tag更新后B重启仍旧内容。失败/中断/过期回执/中心重启/模板冲突/撤权均有核对结果，unknown不重放。
6. 新商店版本出现提示，检查失败保留旧结果并标失败，无源明确未配置。浏览器完成选集群、准备、升级、逐机进度、保存刷新与失败保留。
7. P2窗口内执行已授权兼容无状态更新，主版本、窗口外、有状态、迁移未知、撤权与unknown均无任务。
8. 仓库功能关闭无新容器；在明确宿主机安装private/cache/both组合，重试无重复，核对独立存储/端口、引导镜像、停用/升级数据保留与引用保护。
9. A为唯一push origin，B独立存储起初为空；B直拉/缓存或完整复制后按同digest读取。push域名固定A，断源不能切到空B，准备未完成不报成功。验证可信内网匿名只读、来源限制、公网后端不可直达、HTTPS鉴权、pull/push组及真实Docker大镜像分块/Location。
10. 真实OpenResty验证全站/路径继承/关闭/覆盖、多用户重置/启停、跨集群待发布/部分失败/换机、账号材料私有、旧Agent拒绝；CORS/return/跳转/片段/缓存无旁路，Basic头不传上游，匿名401不误摘健康入口，失败保持旧鉴权。
