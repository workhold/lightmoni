# Feature Specification: 服务镜像生命周期、仓库应用与网站鉴权

**Feature Branch**: `codex/059-service-image-lifecycle`
**Created**: 2026-10-31
**Status**: 用户于2026-11-01授权实现首版；范围与验收见implementation-v1.md，完整路线保留
**Input**: 托管服务故障换机如何避免公网下载镜像、是否全节点预热或集群内分发；自定义服务和商店版本如何升级、提示与自动更新；支持机器容器镜像仓库代理地址。

**2026-11-01扩展**: 仓库作为应用按需安装，可兼作项目私库；可信内网免登录、公网经OpenResty鉴权；多个集群分别安装时明确唯一推送源和读取分发关系；网站密码访问对齐1Panel全站/按路径配置。此范围取代此前“只接已有仓库、不提供按需安装”的限制，仍不隐式每集群安装。

## User Scenarios & Testing

### User Story 1 - 故障换机已有镜像可用 (Priority: P1)

管理员提前知道哪些机器可接管。默认准备运行机器和至少一台合格备用机器，不要求所有机器保存所有服务镜像。

默认不新增或要求配置镜像仓库。Agent直接从已有镜像源预热到候选机器；内网仓库是可选增强，可复用同一可信网络内的共享服务，无须每集群安装一份。

**Why this priority**: 将镜像准备移出故障恢复路径。
**Independent Test**: 两台独立机器预热同一发布版本，阻断公网并停止原节点，备用机器启动相同版本，记录各阶段耗时和公网流量。
**Acceptance Scenarios**:
1. **Given** 备用已预热，**When** 无状态托管服务换机，**Then** 复用本机镜像且不访问公网仓库。
2. **Given** 接管机器缺少镜像但内网缓存已有，**When** 原运行机器离线，**Then** 从独立内网缓存获取并核验版本。
3. **Given** 缓存未命中，**When** 允许回源，**Then** 显示回源进度；禁止回源时明确等待镜像，不偷偷出公网。
4. **Given** 架构、容量、端口、数据或未知结果约束不满足，**When** 本机有镜像，**Then** 仍不可绕过约束或迁移本地数据库。
5. **Given** 没有独立合格备用或磁盘不足，**When** 安装，**Then** 显示备用准备不足及原因，不把部署成功当作恢复保障达标。
6. **Given** 未配置任何内网缓存，**When** 安装、升级和预热，**Then** 均可经已有镜像源完成，不因缺少仓库报错；故障优先选择已预热候选，全部候选缺失时按回源策略拉取或等待。

### User Story 2 - 自定义服务和商店应用可审阅升级 (Priority: P1)

管理员登记新镜像或发布清单，看到可用版本、兼容性和受影响集群，选择集群升级。商店与应用列表提示更新，默认不会直接升级。

**Why this priority**: 避免重启版本漂移和更新扩散到其他集群。
**Independent Test**: v1部署A/B两个集群，仅升级A到v2，B保持v1；v2不健康时暂停或按计划回退。
**Acceptance Scenarios**:
1. **Given** 自定义服务已构建v2，**When** 登记、审阅、预热并发布A，**Then** 逐实例升级，B的期望与运行版本不变。
2. **Given** 商店有新版本，**When** 自动或手动检查，**Then** 展示当前/可用版本、兼容要求和最近检查时间；失败不能显示已最新。
3. **Given** 同名镜像标签内容变化，**When** 重启或换机，**Then** 仍使用已发布内容，检查器只提示内容变化。
4. **Given** 用户修改过模板，**When** 升级，**Then** 保留参数、秘密引用、卷和端口，冲突需要处理。
5. **Given** 单实例、固定端口或数据迁移，**When** 预览升级，**Then** 显示停机及回退限制，不承诺零停机或数据自动恢复。

### User Story 3 - 配置机器镜像源与代理 (Priority: P1)

管理员管理全局默认、集群继承和单机覆盖，分别设置镜像加速、仓库映射、网络代理和私有仓库认证，预览并验证生效结果。

**Why this priority**: 不同机器出网条件不同，配置变更也可能影响整机容器。
**Independent Test**: 配置集群默认并覆盖一台机器；只应用该机，其他机器不变，无关Docker配置键保留。
**Acceptance Scenarios**:
1. **Given** 多层配置，**When** 查看主机，**Then** 显示最终值、来源、期望与实际差异。
2. **Given** 修改需重启Docker，**When** 预检，**Then** 展示全部受影响容器和维护计划；保存本身不重启。
3. **Given** 私有仓库或认证代理，**When** 保存/使用/失败，**Then** 页面、日志、摘要及AI均没有秘密。
4. **Given** 能力不足或人工配置冲突，**When** 应用，**Then** 明确拒绝，不覆盖整份Docker配置。

### User Story 4 - 有边界的自动更新 (Priority: P2)

默认只提示。管理员可为无状态应用的指定集群开启限定版本范围、维护窗口、批次和失败行为的策略，并可撤销。

**Independent Test**: 兼容小版本在窗口内更新；主版本、窗口外、有状态、迁移未知、撤权和unknown均不产生升级任务。
**Acceptance Scenarios**: 自动执行仍冻结版本、预热和逐批验证；仅按管理员已确认的范围执行，不能根据版本号自行认定数据迁移安全。

### User Story 5 - 按需安装项目仓库应用 (Priority: P2)

管理员开启仓库功能时选择已有仓库或安装商店应用，明确集群、宿主机和持久目录，选择私库、只读缓存或两者独立运行。

**Independent Test**: 三种组合分别安装并验证push/pull、端点与存储隔离；关闭功能不产生容器，重复确认不重复建应用，故障不自动切到空目录。
**Acceptance Scenarios**:
1. 默认不安装；明确确认后复用普通应用安装和日志，实际验证成功才显示启用。
2. 私库支持push，代理缓存拒绝push；两者共存时服务/端口/数据分开。
3. 停用或卸载保留数据，被镜像来源/上游/网站引用时先处理引用。

### User Story 6 - 多集群共享一个镜像发布源 (Priority: P1)

应用发布选定一个仓库作为写入源，其他集群可以直拉、缓存或复制同一内容，构建机不必向多个独立入口推送。

**Independent Test**: A私库收到v2，B先为空，B经缓存/复制按同一摘要读取；公网push域名始终只绑定A，A故障不切到B空仓库。
**Acceptance Scenarios**:
1. 同应用多集群的仓库数据独立，不隐式声明同步或负载均衡可写；切换发布源需数据验证和显式迁移。
2. 可信内部入口可匿名访问，限制明确网络且默认只读；公网入口必须HTTPS和密码访问，后端没有公网旁路。
3. 数据复制未完成/摘要不符/源不可达分别显示，预备好的内容可按策略离线使用，不能把缓存未命中当作已同步。

### User Story 7 - 网站全站与按路径密码访问 (Priority: P1)

管理员在网站配置开启Basic Auth，管理账号组，并为路径选择继承、免登录或独立账号组。支持普通静态/反代网站及仓库的Docker客户端。

**Independent Test**: 匿名/错误密码401，正确密码访问成功；路径覆盖、账号重置、跨集群发布和网关换机后策略一致，失败保留旧版鉴权。
**Acceptance Scenarios**:
1. 密码只写不回显，账号组变更标记待发布，逐集群确认生效，不复用平台管理员账号。
2. 结构化路径规则、CORS、直接return、缓存和自定义片段不能绕过鉴权；公网只通过TLS接收密码。
3. 仓库pull/push账号组兼容Docker login与上传，Basic Auth不冒充repository级多租户授权。

### Edge Cases

- 缓存离线、未命中、认证失效、网络错误、磁盘不足、摘要和架构不匹配分别呈现。
- 外部清理镜像后ready失效；机器加入/退出、换Agent、发布或策略变化后重新计算。
- 节点失联可能仍在运行，沿用未知结果、端口和退役实例规则；镜像准备不提供单写或数据隔离保证。
- 多集群部分成功、中心重启和过期回执分别记录；unknown先核对，不盲目重放。
- 商店模板版本、实际镜像版本和Agent版本是不同对象，分别提示。
- 相同push域名不得指向存储独立的集群仓库；源故障不自动改变数据权威。
- 可信网络免登录不代表同网络内项目隔离；公网IP/请求头伪装不能访问免密端口。
- 新鉴权文件部署失败、旧Agent无能力或部分入口unknown不能降级为公开访问。

## Requirements

### Functional Requirements

- **FR-001**: 托管默认准备运行机器及至少1台独立合格备用，支持按需、指定备用数量、全部合格候选三种策略；手动默认按需。
- **FR-002**: 只准备已发布服务的当前及保留的上一可回退版本，不下载未安装商店应用。
- **FR-003**: 默认无新增仓库依赖，安装/预热/升级完整可用；恢复优先本机，仅配置时使用内网缓存，再按显式策略从已有镜像源拉取。可选缓存允许多集群共享，不自动每集群安装；未配置不报故障，禁回源实际限制下载路径。
- **FR-004**: 按机器、发布和架构保存准备状态、来源、错误、检查时间与覆盖；执行前再核验。
- **FR-005**: 镜像准备不绕过资源、端口、健康、权限、数据和unknown约束。
- **FR-006**: 容量/清理保护运行、当前、回退和在途内容，只清理平台登记无引用内容，不全机无差别清理。
- **FR-007**: 发布不可变并固定所有服务的实际镜像内容和平台选择；重启/换机复用同一版本。
- **FR-008**: 自定义服务支持手动新版本、受控发布清单或显式跟踪标签，不猜测任意仓库标签的版本顺序。
- **FR-009**: 商店保存独立模板版本、应用版本、兼容声明、变更说明与安装来源快照。
- **FR-010**: 默认每日检查，支持立即检查；失败保留上次结果并标过期，未配置来源明确显示。
- **FR-011**: 商店与应用显示可用/当前及逐集群版本，仅选定集群的发布改变期望版本。
- **FR-012**: 升级先审阅配置差异、参数迁移、数据风险、镜像准备、停机和回退方案。
- **FR-013**: 升级保留用户配置、秘密引用、卷和端口，模板冲突不静默覆盖。
- **FR-014**: 托管有界批次升级并验证，手动明确选机；失败暂停或授权回退，unknown先核对。
- **FR-015**: 默认只提示，自动升级需管理员确认集群/范围/窗口/失败行为，有状态或兼容未知不自动执行。
- **FR-016**: 全局→集群→单机逐字段继承，支持显式清空并展示来源和期望/实际差异。
- **FR-017**: 分开Hub镜像加速、其他仓库映射、daemon网络代理和私有认证。
- **FR-018**: Docker设置应用有预检、合并、版本守卫、备份、维护确认和生效验证，保留无关键并如实报告恢复。
- **FR-019**: 凭据按目的地与范围使用，缓存不扩大私有镜像可读范围，响应和错误脱敏。
- **FR-020**: 复用管理员、任务中心、Agent有效租约与真实回执，中心无机器Docker socket。
- **FR-021**: 旧应用不因升级中心而重启、重拉或改变发布；能力不足的Agent明确提示升级。
- **FR-022**: 仓库和Doca同步目标设计并回读文字/原生图，设计交付不冒充功能验收。
- **FR-023**: 仓库功能按需选择已有源或商店安装，明确集群/机器/持久目录，默认单机单写，复用应用生命周期且不隐式安装到所有集群。
- **FR-024**: 私库与只读代理缓存分别配置；同时启用时进程/端口/目录隔离，缓存不能接收push。
- **FR-025**: 每个应用发布绑定一个明确写入origin，公网push域名固定源集群，不轮询独立存储；切源须验证迁移。
- **FR-026**: 各集群显式选择源直拉、上游缓存或发布前复制，完整核验内容摘要/架构，分别报告就绪及失败，不隐式复制。
- **FR-027**: 内网免登录仅限显式可信监听与来源网络，默认只读；内网写独立启用，不能用可伪造请求头豁免。
- **FR-028**: 公网仓库入口经HTTPS和已发布网站鉴权，内部后端不可从公网绕过；Basic不宣称repository级RBAC。
- **FR-029**: 仓库网站支持完整/v2/、上传大小/分块/Location/方法/状态与鉴权挑战，pull/push账号组分开，缓存始终只读。
- **FR-030**: 网站支持全站Basic及路径inherit/off/basic，账号组和realm，明确最终策略与影响，旧网站默认关闭兼容。
- **FR-031**: 网站账号口令只写，存储受保护哈希并版本化，不回显、不进入日志/AI；账号变更显示待发布及逐集群生效。
- **FR-032**: IP控制与Basic默认同时满足，自定义片段、CORS/return/跳转和缓存不得绕过鉴权；不支持组合拒绝发布。
- **FR-033**: 配置与受管口令文件一体发布验证/回退，旧Agent拒绝忽略，失败或unknown不退化公开访问；401不误判后端不健康。
- **FR-034**: 前置Basic凭据默认不发往上游，与上游登录协议冲突要明确处理；回执仅含受限状态/版本，不泄漏秘密材料。
- **FR-035**: 仓库停用/卸载保留持久数据，删除/切源/改端口检查引用、数据与执行状态，防止空目录替代原仓库。

### Key Entities

不可变应用发布、商店模板版本、更新来源/发现结果、逐集群升级策略/执行、镜像准备策略/逐机记录、镜像源配置档/凭据引用、Docker维护应用计划、仓库应用模式、唯一写入origin、逐集群读取映射、网站账号组/版本及路径鉴权策略。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 双节点预热断网换机使用同一版本，公网下载0字节，检测/排队/镜像/启动/验证耗时均可核对。
- **SC-002**: 无内网仓库配置时完成安装、预热、升级及已预热接管；启用可选缓存时，三节点演练中原节点停止、接管无镜像、公网阻断，仍从共享内网缓存启动，缓存miss+禁回源时公网0字节。
- **SC-003**: 两集群仅升级一处，另一处版本不变；同tag内容变化不影响已发布服务重启。
- **SC-004**: 一次成功检查后显示新商店版本，失败、来源未配置、冲突及不兼容可以区分。
- **SC-005**: 设置继承、覆盖、清空、并发修改和失败恢复均有证据，无关Docker配置键100%保留。
- **SC-006**: 自动更新的主版本/窗口外/有状态/未知兼容/撤权/unknown反例均无升级任务。
- **SC-007**: 双端新增设计和图一致，既有Doca块/节点/连线保留，功能任务继续未勾选。
- **SC-008**: 仓库三种组合按明确机器安装且重试无重复，私库/缓存端点和目录100%隔离，默认未开启时无新增容器，故障/停用不丢数据。
- **SC-009**: A写入、B缓存/复制读取同一摘要，push域名仅绑定A；B未完成或为空时不接收源域名流量，也不报告已同步。
- **SC-010**: 内部可信匿名pull成功而外部旁路/未授权写失败；公网匿名/错误密码401，正确账号完成真实Docker上传/拉取，缓存push被拒绝。
- **SC-011**: 全站/路径/账号变更、CORS/return/缓存/片段旁路、旧Agent、网关换机及部分发布失败均有验收；无公开降级或凭据泄漏。

## Assumptions

- 继续Linux Docker/Compose、单中心、稳定主机归属和现有逐集群发布模型。
- 本轮先交付方案与SDD；实现和实测后续分阶段完成。
- 首版基础预热无仓库依赖；仓库应用安装为显式可选能力，允许用户分别装入多个集群但没有自动数据复制。真正P2P另评估。
- 网站对齐1Panel的密码访问能力，首版不包含SSO/OAuth或项目repository级授权。
- 不提供数据库复制、持久卷跨机搬迁、源码自动构建或不可逆数据迁移回退。
- 镜像与依赖已准备才可避免公网，不承诺所有故障固定秒数恢复。

## 2026-11-01 首版实施补充（优先于历史设计）

- **FR-036**: 独立私有镜像模块引导安装/选择集群机器，仅模块登记的系统仓库被集群缓存/公网载体使用，普通业务仓库可多份共存。
- **FR-037**: 集群缓存是cluster.spec.image_cache.enabled唯一配置源，集群编辑和私有镜像部署行可设置并实际应用同一策略。
- **FR-038**: 系统服务使用固定sys-openresty/sys-docker-registry及宿主登记，普通应用不能占用sys-或伪造角色，迁移保留现有资源/数据与引用。
- **FR-039**: 私有镜像模块选择一个对外集群部署，自动关联普通网站，配置域名/证书/账号密码；需要入口时明确确认安装，不能轮询数据独立仓库。
- **FR-040**: 内部缓存不要求后台重启Docker或全局关闭TLS，Agent受限读取/校验后导入Docker，只有登记端点和匹配来源可用。
- **FR-041**: 网站Basic口令只写/私密hash，支持全站和路径策略，变更/新节点发布不泄漏或降级公开。
- **FR-042**: 首版完整实现V001–016；历史发布版本/自动升级/镜像预热策略仍为路线，不以首版验收冒称完成。
