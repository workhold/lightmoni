# SDD 025：迁移至 GitHub 开源

日期：2026-10-27。用户指定目标组织 `https://github.com/workhold`，目标仓库 `workhold/lightmoni`。

## 目标与需求

1. 将 Gitea 主干、正式分支和标签迁移到 GitHub，保留原有提交历史、作者和提交摘要；不重写历史、不强推现有目标内容。原 Gitea 仓库保留，历史 PR 验收链接保持真实来源。
2. 先核对目标组织权限及重名仓库，检查全部待迁移 refs 的凭据与敏感文件，确认适合公开后开放仓库。发现真实凭据时停止原样公开并报告路径/影响，秘密不得进入输出或迁移记录。
3. GitHub 成为后续开发入口，默认分支为 `main`，分支保护要求通过 PR 合入并禁止强推和删除，管理员也受约束；不配置尚未存在的 CI 必需检查。现有开发继续使用 SDD、功能分支及 PR，架构变更继续要求仓库与 Doca 同步。仓库迁移本身不改变产品架构。
4. 用户已明确选择 Apache-2.0，项目自有代码采用该许可证，根目录提供完整标准文本。当前发布的 Go、TypeScript、Python、Rust SDK 的包须包含该文本并提供相应生态的许可元数据；保留 Spec Kit 与历史 Doca 第三方许可，不变更第三方版权或其适用许可。
5. 补充 GitHub PR 模板、贡献和安全反馈说明、准确仓库地址及 SDK 元数据；Go 模块路径随新仓库统一。修改通过独立 PR 交付。
6. 不因源码开源更换既有平台域名、已发布镜像地址或 Doca 基线，不发布未经验证的 GHCR 镜像。公开用户可按现有源码构建路径部署；私有预构建镜像需明确注明。

## 验收

- 目标仓库归属、可见性和默认分支正确；每个源 heads/tags 与目标逐项核对摘要，并记录数量。
- 全历史扫描结论与已确认误报有可复核记录；不提交原始扫描中的秘密片段。
- 许可证、第三方许可、贡献入口及模板清晰，变更通过 PR；Go/TypeScript 与打包相关检查按实际修改执行。
- 明确 Git refs 与 Gitea issues/PR 评论等平台元数据的区别，记录实际迁移范围，不声称平台元数据随 Git push 自动迁移。
- 原仓库与线上服务保留，本次不停止服务、不改生产凭据。

## 架构影响

不适用：代码托管和贡献入口迁移，不改变 LightMoni 组件、数据/控制路径、凭据边界、存储、协议或部署拓扑。`docs/system-design.md` 与 Doca 仍为同一设计基线，不为托管域名变化改写架构图。
