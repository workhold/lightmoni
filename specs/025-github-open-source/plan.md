# SDD 025：实施方案

1. 读取 Gitea 最新 refs、审查目标组织管理权限，先创建空的私有暂存仓库，防止审核完成前意外公开。
2. 对所有源分支/标签做全历史秘密扫描与人工审查，检查大文件、第三方许可和验收媒体。只保存不含秘密的扫描摘要。
3. 直接迁移已审核源 heads/tags，不使用可能覆盖目标保留 refs 的无差别 `push --mirror`；迁移后逐项比较。保留 Gitea 远端，目标作为 GitHub 开发入口。
4. 先记录规格，再更新开源文档、GitHub 模板、Go 模块路径。用户已选择 Apache-2.0：添加根 LICENSE，补充当前四种 SDK 的许可元数据与发布包文本，保留现有第三方许可及 NOTICE。历史 PR 链接不批量替换，新贡献链接使用 GitHub。
5. 对实际变更做相关类型、SDK、打包与格式检查；离线检查 npm、Python 分发、Cargo 和 Go SDK 发布包中的许可，创建 GitHub PR 并记录迁移验证。发现未解决真实凭据时不声称已完成开源；准备 PR 未合并前明确主干尚未应用新许可证文件。
6. 用户已授权将项目公开；公开前必须完成内容审核。代码准备 PR 的合并遵守现有仓库规则，未取得合并授权不自动合入。Gitea 平台的历史 issues/PR 评论不会被 Git push 迁移，保留其原始入口并明确范围。
