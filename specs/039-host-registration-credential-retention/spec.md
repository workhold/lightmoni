# 039 主机登记与凭据保存时长

## 驱动目标

用户打开“登记主机”即可填写登录凭据和保存时长，无需先登记再寻找第二步。密码和 SSH 私钥是可选的登录认证方式，主机公钥指纹是独立的远端身份校验信息，不能作为登录认证。有限时保存默认 6 小时，用户也可明确选择永久保存。

## 需求与边界

1. 登记弹窗一次展示主机名称、地址、SSH 端口、登录用户名、登录方式（密码/SSH 私钥）、相应秘密输入、保存时长、主机公钥指纹；中文/英文一致，窄屏可用。
2. 同一保存时长适用于所选登录秘密，默认 6 小时，可选其他有限期限、自定义或永久。指纹与主机 ID/名称是资产元数据，随主机保留，不受凭据有效期影响。UI 明确说明“公钥指纹不能替代密码或私钥”。
3. 有限保存使用 retention=managed，默认 expires_in_seconds=21600，不因 Agent 激活而提前清除。永久使用 retention=permanent、expires_at 为空字符串表示没有固定过期时间，必须显式 confirm_permanent=true，不使用虚构的远期时间戳；仍可随时撤销并清除秘密、断开关联终端。
4. 按用户反馈，永久选择不再显示“没有固定过期时间/建议优先短期保存”的提示块，保留明确确认选项与原保存契约；明文只输入一次，加密存储，不回显，不进入 AI、审计、日志或计划。
5. 永久凭据在终端、SSH 检查、单机/批量安装及卸载中与有效有限凭据一样可用；不能被到期扫描、NaN 时间判断或 Agent 激活错误清理。撤销后所有路径立即不可用，保留现有并发/指纹/计划审阅保护。
6. 登记与凭据保存即使仍用两个请求，也必须在一个表单完成；凭据失败保留已创建主机 ID 并就地重试，不重复建档、不在失败时执行 SSH。关闭重开清理秘密。可保留仅登记且稍后配置的明确路径。
7. 修改既有“添加凭据”使用相同登录方式/保存时长表单；保留必要的现有一次性/临时凭据行为，不恢复独立 Agent 接入或共享 Key。
8. 按 SDD 更新契约、仓库系统设计与 Doca 并回读。更新 GitHub PR16，不自动合并。本地重新构建启动并让用户查看，无生产/vchive 写入。

## 验收

覆盖默认 6h、密码/私钥切换、指纹说明、永久保存/显式确认、有限到期、永久不被激活/清理删除、撤销关闭终端、安装卸载与批量永久凭据可用、登记失败重试不重复、权限、英文及390px。测试使用隔离数据库/API夹具，无真实远端操作。

## 界面文案修订

登记和编辑中的“主机公钥指纹”改称“主机身份指纹”，说明其来自远端主机的 SSH 公钥，用于核验服务器身份，与登录私钥用途不同。本轮仅删除提示块和澄清字段名称，不改变指纹确认机制、认证、凭据保存与清理边界；架构及 Doca 同步不适用。
