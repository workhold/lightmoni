# SDD 170：助手历史与 Agent 更新终态

## 背景

生产助手暴露两类确定性问题：历史整理达到输出上限后，整个会话报 `history summarization failed`，即使原历史仍保留也无法继续；Agent 更新卡片只在创建或审批时赋值，原生更新已经成功仍永久显示“正在更新”。此外，`vchive` 的未知更新记录持续阻塞维护，需要明确区分离线、未安装与 unknown 围栏，不能用重复安装绕过。

## 用户场景与验收

### US1：摘要输出截断仍可继续会话

- 模型返回空摘要、长度截断或超过摘要上限时，不伪装成完整摘要，也不再直接终止整个会话。
- 使用低推理开销和受限摘要请求；无法获得合格摘要时，优先保留已有摘要并追加明确的降级说明，预算不足时至少保留固定降级说明，原始 checkpoint 与当前用户请求不变。
- 持久事件、时间线和 UI 均标记“历史整理已降级”，不得把降级结果当成完整事实摘要。
- 供应商网络/鉴权错误仍保留 `summary_failed`，不能借降级掩盖服务故障。

### US2：Agent 更新卡片展示真实终态

- `running/verifying` 的卡片在原记录 ID 不变的情况下定时读取原生记录，直至 `succeeded/rolled_back/failed/unknown/cancelled`。
- 成功明确显示“更新成功，已核验目标发行”；回退、失败、未知和取消分别展示，不把 apply 接受、HTTP 200 或成功创建计划当成业务成功。
- 轮询失败保留最后已知状态并可重试；组件卸载或终态后停止请求，不能重复 apply 或制造并行读取。
- 主机列表在原生更新运行期间使用已有的快速刷新节奏，终态后及时展示新 Agent 心跳所确认的发行，而不是继续停留在旧列表快照。

### US3：离线或未知维护不再被误解

- 只读 SSH 预检确认 Agent 存在时，助手/页面不得将其解释为“未安装”。未知更新仍是维护围栏，离线也不自动清除。
- 对 unknown 更新只能只读核对或使用现有恢复卸载流程，不能重复派发、盲目升级或强制重装。
- 本次不自动执行生产核对、恢复、更新或卸载，只完善状态解释、降级与终态展示。

## 功能要求与成功标准

1. 四种模型协议的历史截断测试均完成降级、checkpoint 和主回答，且后续请求包含当前用户消息。
2. 更新卡片成功、失败、未知和停止轮询测试通过；不改变原审批 API、revision、owner、恢复和 unknown 语义。
3. 相关 Runtime、AI Runtime、Web 测试、类型检查和生产构建通过，保存可复现验证记录。
4. 不执行生产升级、卸载或审批，不直接推送 `main`，不操作生产数据。

## 架构影响

仅在现有 compaction 事件和 UI 时间线上增加向后兼容的 `degraded` 元数据，不改变组件职责、模型/工具权限、数据或控制路径、凭据边界、存储、部署拓扑以及审批/执行状态机。同步更新 `docs/system-design.md` 的助手历史和 Agent 更新展示约定。
