# 设计

UI保留主机→全部容器入口，增加创建、详情/修改、行操作与镜像清理；列表是主角。详情/编辑和删除确认独立弹窗，展示主机、完整对象标识及归属风险。提交按钮loading反馈、面板进入/退出、Tabs滑块沿用现有组件动效，减少重复说明；窄屏表格横向滚动并提示。

执行沿用agent_jobs→受管执行桥→operations.managed.v1签名计划/一次性启动许可→root管理组件；不复用受限container.managed.v1，不给普通Agent增加权限。新增严格结构化host_docker动作与/api/v1/ops/machines/:id/container-jobs。固定/var/run/docker.sock和API v1.43，校验已钉住的daemon ID；HTTP响应有大小/超时限制，不走shell，原始inspect只在节点内处理。

复用节点操作锁和中心主机围栏，执行前及每次Docker调用校验授权与租约。动作载荷无凭据、环境变量或原始标签。对象完整ID+非敏感配置摘要作为版本，写前再读取；多步骤失败保守记unknown并保留锁。所有容器、镜像、配置及删除均回读验证。

管理组件Docker清单增加management_version=1标记，中心只采信签名管理组件来源。新增任务不与普通Agent兼容派发，旧组件没有标记时UI给出升级说明。job结果严格绑定操作、请求摘要与观察时间，白名单映射公开字段；历史可回读，结果未知不自动重发。当前能力策略关闭或目标绑定变化会阻止领取/启动。

镜像预览按完整ID分批，每批最多100项且小于80KB，next_cursor允许继续读取；换批清空选择，创建镜像选择器可追加后批。节点仍完整读取所有容器引用，不能把镜像分页当作引用分页。大小为估计。清理载荷绑定当前批原预览任务ID、候选版本及扫描时间（5分钟），最多100个；节点按精确ID逐一读取引用，拒绝元信息漂移，跳过新引用镜像，以force=false,noprune=true删除，不触及其他资源。节点间外部Docker操作仍有检查后状态竞争，由Docker非强制删除的引用保护兜底；未知结果需人工核对。

架构有影响：新增受管Docker动作及公开结果契约，更新docs/system-design.md并按本对话用户AGENTS要求同步Doca目标章节、保留并回读原生图块。仓库AGENTS/constitution目前写repository-only，与本对话用户明确提供的同步要求冲突时，以用户指令为准。
