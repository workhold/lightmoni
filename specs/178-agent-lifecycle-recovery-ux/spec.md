# SDD 178：Agent 生命周期恢复体验闭环

## 背景

生产恢复暴露的问题不仅是单点故障：模型读取既有更新时不会渲染已有卡片；更新卡片没有真实阶段进度；重装默认完整管理可能提升原仅监控主机权限；成功激活新 Agent 后，同机旧 active enrollment 仍可能遗留；长操作的刷新告警没有明确说明自动重试。

## 用户场景与验收

### US1：真实读取路径展示卡片和阶段进度

- `propose_agent_update` 与 `get_agent_update` 的合法原生记录都渲染同一更新/恢复卡片。
- running/verifying 显示由真实事件阶段驱动的进度条、当前阶段和记录时间；百分比不得因时间经过自动增长。
- 平台记录为 succeeded 才显示成功；远端先行上报的 succeeded/rolled_back 事件在健康核验通过前不得显示为成功或已恢复。failed/rolled_back/unknown/cancelled 保持原语义，malformed 或未知事件不得伪造阶段。
- 恢复卡片的原审批、只读核对、revision 和凭据边界不变。

### US2：重装不默认提升权限

- 主机存在当前或历史真实运行模式证据时，页面与后端省略 `runtime_mode` 都沿用该模式；只有管理员明确选择 root 才安装管理组件。
- 无证据的新主机保持现有默认；批量安装首次读取详情后，任一历史仅监控主机会让未触碰的批量默认改为仅监控，手动修改后不被详情覆盖。
- 计划审阅明确显示最终模式，不隐藏权限变化。

### US3：新激活自动收口旧身份

- 新 Agent 成功激活的同一事务中，同机其他 active enrollment 自动取消；当前激活记录不变。
- 其他主机记录不变；pending/issued 状态继续按原协议与到期处理，不改变并发激活错误语义。
- 旧 Agent 在新激活前仍保留，不在签发或预检时提前失效。

### US4：恢复引导与长操作反馈

- 卡片在 failed/unknown 时显示条件化恢复顺序：原记录核对 → 必要时状态修正 → 需要全新安装时恢复卸载 → 按原权限重新安装。它只作引导，不把步骤标成已完成。
- 活跃安装/卸载刷新失败时明确“正在自动重试，请勿重复提交”；终态不显示自动重试。

## 非目标

不合并审批、不自动恢复/卸载/安装、不扩大模型/MCP 权限、不伪造进度或业务成功，不处理全量 Runtime 基线失败。
