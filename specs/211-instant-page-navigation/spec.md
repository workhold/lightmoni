# SDD 209：页面导航秒开与加载态

## 背景

侧边栏每个菜单点击后都要等待一段时间页面才“打开”。排查确认路由层没有守卫或 loader 阻塞，等待感来自两处：

1. 页面组件全部懒加载且无预取，首次点击某菜单时才下载对应 JS chunk，期间内容区只有 Suspense 空白转圈。
2. 运维五个菜单（集群 / 应用 / 网站 / 域名 / 证书）是五条独立路由渲染同一个 `OperationsPage`，每次切换都重挂载组件并重新执行“先配置后总览”的顺序加载，已加载数据不可复用。

## 目标

1. 点击菜单后前端立即切换路由并渲染目标页面结构；未就绪的内容以既有 Spin / 表格加载态呈现，数据到达后自动补齐。
2. 侧边栏链接悬浮或键盘聚焦时预取目标页面 chunk；工作台首屏渲染完成后在浏览器空闲时段串行预取全部页面 chunk（仅下载模块，不发起 API 请求）。
3. 运维页在五条路由之间切换时复用上一次的 `/ops/overview` 数据立即渲染，并在后台静默刷新；10 秒轮询与窗口聚焦刷新保持不变。
4. 用户登出时清空运维数据缓存。

## 非目标

- 不改启动登录门槛（`/auth/me` 阻塞首屏属首次加载，不在本需求范围）。
- 不把各页面整块 Spin 重设计为骨架屏；加载中形态保持现状。
- 不改变任何后端 API、数据路径或轮询周期。
- 不引入路由框架模式（data router / loader）。

## 验收

1. 首屏完成后点击任意未访问过的菜单，页面结构（工具栏、筛选器等）立即出现，数据未到时显示加载态，不再长时间空白。
2. 悬浮侧边栏菜单即预取对应 chunk，点击时直接命中缓存渲染。
3. 运维菜单切换（如 应用管理 → 集群管理 → 应用管理）立即显示上次数据，无整页 Spin；`/ops/overview` 静默刷新有新请求。
4. 登出后再登录不残留上一会话的运维缓存。
5. `npm --prefix web run typecheck` 通过；浏览器回归脚本通过，无页面错误。
