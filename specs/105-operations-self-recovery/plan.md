# 设计：有证据的恢复与公平调度

## 调研与影响

线上只读证据显示 2026-11-07 13:51 UTC 时应用的最后观测停留在 11:30–11:32 UTC，同机 `deployment.instance` 大多为 `machine_busy`；近几轮只有已移除 ABC Demo 的 `workload.inspect` 与失败的 `website.remove` 交替。清理代码无差别调用所有网关的 `ownedGateway`，因此空的未初始化网关目录也阻断删除。需进一步用实际目录证据核实失败目录，不能自动补 owner 标记。

架构适用：改变既有协调调度、回执消费和清理失败控制路径；不新增权限、凭据、网络端点或存储拓扑。按本轮用户明确要求同步 `docs/system-design.md` 与 Doca 基线；本轮要求优先于仓库旧的仅仓库同步规则。

## 删除

先验证平台根和 gateways 父目录；逐项 lstat，符号链接继续拒绝。允许只读跳过真正完全空的未初始化目录。线上进一步核实存在非空 layout1 目录，包含旧网站身份及同域名历史，但没有 layout2 归属标记；不能把名称或域名相同当作本网站身份。

进一步读取证实三个旧网关均为 layout1，包含同一目标网站修订，且保留已停止容器，因此不能只读排除它们。采用限定的历史清理：中心从同机旧绑定/退役的已登记 OpenResty 实例及其不可变 gateway.apply 载荷，生成实例/应用 ID、已授权网站片段 ID 和健康证明摘要；未知旧执行继续阻断。Agent 核验固定目录、layout1 身份、已停止容器的平台/实例标签和精确只读 bind 来源，然后逐历史版本用词法结构识别健康证明对应的网站 server 块及其独有 upstream/限流/缓存定义，只清理目标片段目录并剔除 state 中目标配置。其他网站配置和文件逐字保留；旧目录不补 owner、不迁移、不删除容器。未知证明、活动/外部容器、异常路径、外部 include 或无法完整分类的索引均阻断。只读 inspect 同样检查历史残留，不能提前声称 absent。当前有归属标记的 layout2 网关若夹带旧版本，范围仅限非 current 且没有 websites.json 的历史版本；需同实例的不可变载荷证明，保留活动索引与进程，不要求停止当前服务。

现有非空 layout2 或未知目录继续要求精确归属。受管网关仍检查活动容器、当前/保留/历史网站引用。

删除进度使用现有 targets_json 扩展 failures、blocked_agent_version、retry_at。归属/路径/布局等确定性错误阻断破坏性重试，每5分钟仅先只读核对，新 Agent 发行可提前核对。成功的核对重新建立归属和清理条件证明后才重新清理。暂时失败采用 5s 指数退避，最大 5min；连续五次失败进入阻断。未知执行继续使用既有 signed-job fence，解除后仅先 inspect。已完成主机不重放。

## 应用

协调器消费本实例当前、期望 hash/代次一致的成功观测后，再考虑同机任务锁。等待锁时保留已经取得的 proof；排队/领取不算健康。已移除/停止实例按观察结果确认期望状态后进入低频核对，避免争抢每一轮。

同机忙等待保留原 due 顺序和状态时间，使未得到执行机会的资源优先于刚派发过任务的资源；其他已评估资源更新调度时间，仍受全局每轮 100 项上限约束。检验超过一轮窗口以及重启后的公平性。

已知漂移沿当前发布配置和原 apply/stop 路径恢复；托管部署复用 min_available 和摘流保护。连续已知变更失败达到五次或确定性归属/授权错误时阻断，不反复重建。仅检查失败不推断容器不存在。手动操作或期望代次变化提供新的证明链。

## 界面

沿用现有卡片和主题，增加既有状态中的稳定恢复原因投影：等待执行、核对状态、恢复中、需要处理。删除显示等待重试或具体阻断。无需设计主题变更；不把调度/协议字段直接展示给普通用户。

## 验证和发行

真实文件系统验证空目录、错配 owner、非空无 owner、符号链接、活动引用与幂等清理。领域测试验证多应用公平调度、正常服务只 inspect、已知漂移恢复、未知/撤权围栏、重启预算。完成 TypeScript、相关运行时与 Web 检查。通过 GitHub PR 合入，再构建双架构固定 tag；中心与包含执行器代码的统一 Agent 配套升级，沿现有维护审阅与健康确认，不直接改主机业务文件。线上先只读验证已有删除流程和应用新鲜状态，未通过不得声称已修复。
