# Feature Specification: 网站清理与应用自动恢复

**Feature Branch**: `codex/105-operations-self-recovery`
**Created**: 2026-11-07
**Status**: Implemented
**Input**: 用户反馈“删除网站卡住了”，以及 OpenResty 经常停留在“待处理 / 服务地址已保留，按中心配置恢复”，要求程序自适应修复。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 网站清理正确收敛 (Priority: P1)

管理员已经确认删除网站，系统先撤流，再清理该网站的受管文件和历史引用。无关旧网关目录不应导致永久失败；无法证明归属或仍在使用的目标必须明确阻断。

**Why this priority**: 当前 ABC Demo 删除已持续失败，持续重试也占用同机任务。
**Independent Test**: 在含无关旧目录的主机删除一个已撤流网站，核对目标消失、其他网站和目录保留。

**Acceptance Scenarios**:
1. **Given** 目标已撤流且只有受管历史引用，**When** 清理执行，**Then** 清理目标及其过期索引并完成删除。
2. **Given** 无关网关缺少归属标记，**When** 清理当前网站，**Then** 有充分隔离证据时不修改无关目录且可继续；无法排除目标引用时明确阻断。
3. **Given** 目标仍被活动网关使用或目标目录归属不明，**When** 清理执行，**Then** 不删除数据，显示具体原因并停止高频破坏性重试。

### User Story 2 - 自动恢复已发布应用 (Priority: P1)

已启用应用出现过期观测或已知故障后，平台依据当前已发布配置主动核对实际情况；正常应用恢复准确显示，确认偏离时有界修复。

**Why this priority**: 长期“待处理”无法判断实际服务是否健康，用户被迫手动操作。
**Independent Test**: 分别模拟正常容器观测过期、容器停止、配置偏离、执行失败与结果未知，观察自动处理和真实状态。

**Acceptance Scenarios**:
1. **Given** 容器正常但观测过期，**When** 自动核对完成，**Then** 状态恢复健康且不重建容器。
2. **Given** 机器在线、授权有效且确认应用偏离，**When** 自动恢复，**Then** 使用已发布配置恢复并通过独立观测确认。
3. **Given** 执行结果未知、身份变更、权限撤销或归属无法证明，**When** 自动恢复评估，**Then** 保留围栏并展示阻断原因。

### User Story 3 - 故障恢复不挤占正常运行 (Priority: P2)

管理员能看到等待、恢复、需要处理的原因。单个持续失败的任务不会无限高频重试或让其他应用长期得不到观测。

**Independent Test**: 连续产生同一失败并重启平台，核对退避、尝试次数与同机其他应用观测进度。
**Acceptance Scenarios**:
1. **Given** 同一故障连续失败，**When** 重试与重启发生，**Then** 持久化退避和阻断，重启不重置预算。
2. **Given** 同机有多应用和一个失败清理，**When** 协调运行，**Then** 其他应用仍能及时取得新鲜观测。

### Edge Cases

- 网关空目录、缺失标记、错配标记、旧布局、损坏索引、符号链接与跨目录路径。
- 在线状态变化、机器重新绑定、维护中、授权撤销、发布修订变化。
- 已接受任务回执丢失、未知执行围栏、中心或 Agent 重启。
- 手动部署固定端口、托管部署最低可用数量、停用或已删除实例不得复活。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 清理必须绑定既有删除授权、网站及机器身份，先撤流再清理，仅删除证明归属的平台数据。
- **FR-002**: 无关目录不得被删除、改标记或自动接管；无法安全排除目标引用时返回稳定阻断原因。
- **FR-003**: 自动恢复必须以当前已发布配置、当前有效授权和绑定为准，不应用未发布草稿。
- **FR-004**: 健康观测过期必须先核对；成功且配置一致才能恢复健康状态，不凭任务排队或历史成功声明正常。
- **FR-005**: 已知漂移可通过既有执行链恢复，保留最低可用数量、端口、流量摘除、持久数据和任务互斥保护。
- **FR-006**: 未知执行不得自动重放；需先沿既有核对流程解除围栏。
- **FR-007**: 可重试失败必须退避，连续确定性失败必须进入可说明的阻断；重启不能消除该状态。
- **FR-008**: 状态必须呈现恢复阶段与具体原因，不能永久只有“待处理”；不得输出凭据、配置正文或原始敏感错误。
- **FR-009**: 网站清理和应用观测必须公平获得执行机会，避免单个失败工作造成同机饥饿。

### Key Entities

- **删除进度**: 网站、删除授权、机器、当前任务、尝试次数、退避和阻断原因。
- **恢复观测**: 应用实例、已发布版本、期望状态、最新有效观测与执行围栏。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 测试中已撤流且归属可证明的网站完成清理，无关目录和其他网站数据零修改。
- **SC-002**: 在线且任务可执行时，正常应用在三个协调周期内恢复新鲜状态，无容器重建。
- **SC-003**: 可恢复故障自动恢复后，状态必须由新的成功观测确认；未知和权限阻断测试中自动变更为零。
- **SC-004**: 连续确定性失败停止高频执行；重启后保持退避或阻断，其他应用持续获得观测。

## Assumptions

- 用户授权延续原任务的 GitHub PR 合入、固定 Docker 发行、部署和线上验证，新增修复仍通过功能分支。
- 已发布且启用的配置代表持续恢复意图；停用、移除及未知执行不包含自动重启授权。
- 不自动接管外部目录，不升级商店镜像，不迁移业务数据，不改 DNS 策略或主机权限。
- 架构控制路径变化需同步仓库系统设计与用户指定的 Doca 基线，并回读原生图块。
