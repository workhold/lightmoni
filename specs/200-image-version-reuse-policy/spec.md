# SDD 200：镜像升级版本不可复用约束

## 背景

0.1.10 期间在同一版本号下产生了多个时间戳镜像，虽然固定标签未覆盖，但流程允许同一版本内容变化继续发布，容易导致“版本号相同但制品不同”的误判和回滚引用混乱。

## 目标

1. 每次容器镜像升级发布前统一提升 SemVer PATCH（小版本号），并同步所有已登记版本面。
2. 构建前必须通过 `npm run version:check`。
3. 禁止覆盖已发布的固定版本标签、时间戳标签或 `latest`。
4. 同一版本内容发生变化时，必须提升到下一个 PATCH，并生成新的不可变时间戳/架构标签。
5. 镜像标签必须包含版本、UTC 时间戳和架构，OCI revision 必须与源码提交一致。

## 非目标

- 不改变应用运行时协议、部署拓扑或镜像构建流水线。
- 不要求每次文档-only PR 提升镜像版本；只有实际打包容器镜像升级时适用。
- 不引入自动 registry 删除或标签改写流程。

## 验收

1. `AGENTS.md` 明确 PATCH 提升与标签不可覆盖约束。
2. 后续发布 PR 必须能通过 `npm run version:check` 和 registry 标签存在性检查。
3. 架构影响：不适用；本约束只规范发布流程，不改变系统架构。
