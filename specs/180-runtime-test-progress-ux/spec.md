# SDD 180：Runtime 测试语义与待审批进度提示

## 背景

两个 Runtime 基线失败来自旧测试与现行设计不一致：人类管理员会话边界先于资源准入返回 403；未领取 queued 工作允许延后，而不是阻止维护计划。助手的待审批卡片又完全隐藏进度区域，容易让用户误以为升级已经开始或进度丢失。

## 用户场景与验收

### US1：测试准确验证现行安全边界

- 无有效人类管理员会话的 operations 写操作继续返回 403；合法会话下，orphan/revoked 身份仍按领域规则返回 409。
- 未领取 queued job 不妨碍生成维护计划，计划仍可正常取消；leased、accepted、preflighting、staging、activating、verifying、unknown 保持 409。
- 不放宽生产代码的会话、身份、执行或卸载围栏，不用修改生产逻辑迁就旧测试。

### US2：待审批显示真实零进度

- `awaiting_approval` 始终显示 0% 和“等待管理员审批 / 确认后开始执行”，即使输入含 stale 执行事件也不提前增长。
- 过期计划显示已过期和重新准备提示，不显示可开始执行。
- 审批后 running/verifying 继续只按真实事件阶段推进；succeeded 仍为 100%，未核验远端终态不冒充成功。
- 待审批不启动轮询，原审批、取消、revision 和权限边界不变。

## 非目标

不改变 queued 调度语义，不合并审批，不自动升级 Agent，不修改镜像仓库或生产配置，不发布镜像。

## 架构影响

不适用。本切片只修正测试夹具/断言和现有助手卡片展示，不改变组件职责、数据或控制路径、协议、存储、凭据或部署拓扑，因此无需改写 `docs/system-design.md`。
