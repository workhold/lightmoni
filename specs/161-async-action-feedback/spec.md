# SDD 161：耗时操作反馈与 Agent 升级交互

## 用户场景

- 管理员点击主机操作后，立即看到该主机、该操作的等待状态；请求结束后进入窗口或显示错误，可以安全地再次操作。
- 管理员一键升级 Agent 后，先看到启动中，再看到原操作的真实阶段和最终结果；关闭窗口后可从该主机直接返回原记录。
- 管理员审阅旧计划、回退或升级批次时，直接看到待审批的目标、校验指纹、步骤和影响；完成后的技术详情及完整阶段记录按需展开。
- 管理员在任务、告警响应及运维结果页手动刷新或提交耗时请求时，正在执行的按钮显示等待状态，避免重复提交。

## 功能要求

1. 主机详情、终端、SSH 检查、部署、卸载和升级入口在读取详情期间显示对应主机和操作的 loading。重复点击同一入口不增加请求；切换主机时旧响应不能打开错误主机窗口。
2. 单机“升级 Agent”沿用 SDD 133 的一次点击授权及 `POST .../start`。已有待审阅、运行中、结果未知的更新时，主机行直接提供原记录入口，以最新主机详情的 `last_operation_id` 回读，不再次发起升级。入口读取期间显示 loading；记录不存在或失配时明确报错并要求刷新。
3. 单机窗口按“启动中／审阅已有计划／执行进度与结果”呈现。运行中显示最后已知真实阶段及阶段时间，提供完整阶段日志；只有服务端确认成功才显示完成，不按时间推算百分比。启动请求期间允许关闭窗口，主机行维持启动中状态，回读原结果后才允许新升级；结果不确定时引导核对历史。
4. 待审批计划的当前和目标发行、主机、SSH 目标、目标包 SHA、安装指纹、步骤与执行影响直接可见。其它构建详情、凭据 ID 与操作 ID 可展开查看；确认复选框仍要求审阅全部影响。`unknown` 只读核对和恢复审批保持原有保护。
5. 批次窗口的创建、审阅、执行/暂停/继续/取消、历史各动作只在对应按钮显示 loading；其他写入按钮暂时禁用。待审批的每机计划默认展开，其它状态默认折叠，主机状态和异常优先展示；批次审阅仍须明确确认全部计划。
6. 任务中心手动刷新、告警统计查询/结束静默/转交/创建静默、运维执行结果刷新显示准确的本地等待状态。自动轮询不触发手动按钮的 spinner；失败后恢复可操作并显示错误。
7. 中英文、窄屏和键盘操作可用。等待和状态有可访问名称或文字，按钮不跳动到无关操作上。

## 验收标准

- 延迟主机详情请求时，仅被点击的操作显示 loading；完成、失败、跨主机切换均正确清理，双击不重复请求。
- 已有更新从主机行直达最新主机详情指定的原记录；启动中的升级只提交一次，关闭启动窗口时仍锁定该主机入口，运行阶段由服务端记录驱动，回读后可继续查看。
- 单机和批次的取消、刷新、暂停等操作仅自身显示 loading；技术细节可展开，审批及 unknown 的安全语义保持。
- 其它列出的手动操作在延迟请求期间给出反馈，失败后不留下永久禁用状态。

## 架构影响

不适用。本次只调整前端展示、交互状态及已有只读/写入接口的入口；不改变组件职责、服务端控制路径、持久状态、凭据边界、协议、存储或部署拓扑。沿用 SDD 133 一键升级及 SDD 045 的回退/批次审批契约，因此不改写 `docs/system-design.md` 与 Doca。
