# Implementation Plan: SSH 主动运维与永久凭据

**Branch**: `codex/123-ssh-managed-operations` | **Date**: 2026-11-11 | **Spec**: [spec.md](spec.md)

## 当前边界

主机安装、升级、卸载和 Docker 首装已直接 SSH。受管资源、服务部署、容器和平台巡检经 `agent_jobs` 与 `privileged_jobs`，由远端执行器主动领取。Agent 的采集/上报/定时任务与这些管理员主动运维任务分离。SSH 凭据库保存加密秘密，绑定到主机登录账户，支持有限期/永久策略；改动前的 UI 默认六小时。

## 设计

1. 凭据层：机器页面的新凭据写 `retention=permanent, expires_at=''`；页面移除期限输入，旧 API 显式有限策略继续可用；启动时仅把仍持有秘密、未撤销且当前有效的有限凭据转永久，记录迁移事件；已清除与过期记录保持失效。机密加密、账户绑定、指纹核验与撤销仍按现有路径。
2. 执行层：保留原有 `agent_jobs`、`privileged_jobs`、`task_runs` 持久批准计划与回执，中心扫描待执行记录并以默认 SSH 绑定连接目标。同机一次只启动一条固定命令，携带经校验的精确作业 ID。`managed-once`、`jobs-once`、`task-once` 分别处理签名受管作业、普通作业和手动脚本；受管资源和容器等沿用原固定领域载荷及执行器的签名授权、制品、密钥与回执 HTTPS 契约。旧常驻轮询对主动任务关闭，Agent 保留采集/上报/心跳/定时任务。中心 SSH 凭据始终留在中心。
3. 恢复层：SSH 前未领取的失败记录为明确失败；已领取记录由原租约、未知结果与只读核对处理，不能自动重放。SSH 命令成功返回却未领取时继续排队，等待同机围栏解除。手动脚本和定时脚本使用不同恢复标记，主机升级检查两者。旧发行包没有单次命令时明确失败并要求升级。
4. 页面与 API：机器页显示凭据永久和撤销操作；受管计划显示 SSH 执行账户、连通性与未知核对入口。资源操作身份仍指向已登记机器，不能仅凭 Agent ID 推导 SSH 目标。

## 实施顺序

先改规格、凭据和页面，再将既有持久作业统一纳入中心 SSH 派发，关闭常驻主动任务轮询；最后验证服务部署、网站/证书、Compose/备份、容器、平台巡检及手动脚本共享入口。本次按用户确认的范围实施 T006–T010，全部完成并验证后再创建 PR。

## 宪法与架构

管理员审批、资源修订、主机身份、秘密边界、主机互斥和未知结果均保留。SSH 信任边界由中心扩张到日常运维，因此系统设计与 Doca 的 HLD、凭据和运维章节必须同步，并回读原生图。未完成全部迁移前，设计明确区分当前能力与目标能力。
