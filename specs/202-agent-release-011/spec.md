# SDD 202：0.1.11 Agent 恢复与操作保活发布

## 背景

0.1.10 之后已合入恢复续跑（SDD197）、已确认 Agent 操作脱离页面生命周期（SDD198）、已恢复原发行的健康核对闭环（SDD199），以及助手会话保活与卡片统一（SDD201）。生产中 `vchive` 原更新记录仍被远端 `/run/lightmoni-agent-lifecycle.lock` 阻塞；同时按新的不可复用版本约束，必须发布下一个补丁版本。

## 目标

1. 统一平台、Agent、SDK、MCP、构建与 Compose 版本到 `0.1.11`。
2. 从合入后的 `main` 本地构建 linux/amd64 镜像；不覆盖任何 0.1.10 或 0.1.11 已发布标签。
3. 隔离验证健康、首页、认证边界、实例/MCP 版本和 ClickHouse 后发布固定标签与 `latest`。
4. 生产切换后验证中心、版本徽标、vchive 旧记录、维护入口、助手保活和 Agent 状态。
5. 处理 vchive 远端 lifecycle lock，只通过原生只读核对、审批恢复或明确管理员恢复入口闭环，不直接改数据库或盲目重试。
6. `vchive` 恢复后再单独生成 0.1.11 Agent 升级计划并验证版本、源码 revision、包 SHA256、心跳和平台状态一致。

## 非目标

- 不自动回滚生产数据库、不删除备份、不改写 unknown 历史。
- 不宣称应用业务恢复完成；应用绑定和业务数据仍按领域流程核对。
- 不在无原生回执的情况下通过任意 SSH 重装、卸载或改写 Agent 状态。
- 不把单中心进程重启承诺为 HA 任务队列。

## 验收

1. `version:check` 46/46 通过且没有版本复用。
2. 镜像 OCI revision 与最终源码提交一致，镜像内双架构 Agent 与 SDK 校验通过。
3. 隔离 Compose 核心验证通过后才发布。
4. 生产中心 healthy、公网访问 200、未认证 API/MCP 401。
5. `vchive` durable 记录回读为非阻塞终态或具备明确人工核对证据；心跳、SSH 与版本一致。
6. 全部主机最终回读 0.1.11 发行身份。
7. 回归测试、类型检查、构建、diff check 通过。
