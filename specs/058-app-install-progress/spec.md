# 简化应用安装与可追溯进度

日期：2026-10-31。分支：`codex/058-app-install-progress`。

## 需求与验收

- 参考 [1Panel 安装部署](https://docs.fit2cloud.com/1panel/user_manual/appstore/install/) 的基本参数、高级设置、提交后安装日志流程，沿用 LightMoni 现有视觉及多集群模型。
- 模板安装首屏仅展示名称、版本、目标集群/机器、必需参数及端口。服务标识、部署模式、资源限制、多集群和可选参数收入高级设置。单集群及单台在线机器可自动选择；不自动选择离线机器。保留高级配置能力与 OpenResty 单例约束。手动模式默认建议宿主端口等于容器端口；托管模式留空由平台分配，显式填写则使用填写值。切换模式保留主动填写的端口，未改动的建议值随模式变化；OpenResty 固定 80/443。
- 一次点击开始安装并打开进度；保存失败保留输入。创建完成但部署被拒绝仍打开已创建应用的诊断，不能重复创建或显示安装完成。
- 进度按真实回执显示排队、Agent 接收、准备、执行、验证、成功/失败/未知。展示每台机器及历史记录、阶段时间、错误码、可读原因及处理建议；不编造百分比或 Docker 下载字节。
- 每 2 秒回读；关窗不影响后台执行。应用列表可重开进度，刷新/重启后可读历史；读取失败明确提示并保留最后快照，切换应用/执行时不串日志。
- 多集群部分失败、调度等待/容量不足、Agent 离线、未知结果、无步骤的旧记录不能误报成功。未知结果提示先检查实际状态，通过现有操作显式重试，不自动重复执行。
- 安装日志仅保存有界结构化阶段与白名单错误信息。不得记录密码、环境变量、命令、stdout/stderr 或上游原始错误文本。
- 验证中英文、390px、200% 等效布局、减少动效、实际 HTTP/SQLite/Agent job 链路以及三轮浏览器回归。

## 架构影响

适用：复用 Agent job 控制通道，将已有 Agent 阶段投影至既有 `ops_platform_run_events`；应用安装进度直接读取管理资源、执行记录和阶段。扩展 Agent 内部可选 progress 回调、平台执行器白名单阶段与故障分类。无新增存储表、网络端点、凭据、远程命令权限或 AI 写入能力。同步 `docs/system-design.md` 第 44.6 节及 Doca 系统设计基线，写后回读原生图与新增章节。
