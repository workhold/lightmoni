# Research

1. **Decision**: Enumerate models using GET <base>/models; only root addresses can retry <base>/v1/models on 404/405 or non-directory JSON/HTML. Stop on auth/network/limit/server errors. **Rationale**: Compatible services usually use these paths. **Alternatives**: Vendor guessing or scanning many paths would send credentials too broadly.
2. **Decision**: Protocol is fixed openai-chat-completions and labeled as such, not detected. **Rationale**: Current runner calls createOpenAICompatible().chatModel; a models directory proves no tool/stream/context capability. **Alternatives**: Adding native adapters is a separate feature.
3. **Decision**: Reuse saved keys only after explicit use_saved_key and exact canonical API base match. Apply equivalent protection during config PUT, and disable /v1 fallback for saved-key reuse. **Rationale**: Same host may contain unrelated tenants. **Alternatives**: Reuse on same origin is insufficient.
4. **Decision**: Trim whitespace/trailing slash, lowercase scheme/host, remove terminal /chat/completions or /models while preserving escaped path meaning and custom prefixes. No cleaning of arbitrary tenant paths. **Rationale**: Common address mistakes can be corrected without changing provider identity.
5. **Decision**: Debounced query with cancellation/version guard, AutoComplete allowing manual text, no automatic model selection, isolated errors. **Rationale**: Keeps manual values and avoids stale overwrite. **Alternatives**: Select-only input excludes services lacking directories.
6. **Decision**: Limit query to 8s/1MiB/500 models, deduplicate/sort IDs, forbid redirects even on custom clients, sanitize errors. **Rationale**: Credential and resource bounds. All design unknowns resolved; read-only research agent independently reviewed boundaries.
