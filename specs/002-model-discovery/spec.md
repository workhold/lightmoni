# Feature Specification: 自动获取模型与明确连接协议

**Feature Branch**: Existing working branch (no branch switch)
**Created**: 2026-10-14
**Status**: Ready for implementation
**Input**: 用户询问模型配置能否自动识别，以及连接协议是否自动识别或需要手动选择。

## User Scenarios & Testing

### User Story 1 - 自动获取可选模型 (Priority: P1)
管理员填写服务地址和密钥后，配置页自动查询可选模型，也可以主动刷新，并从列表选择或直接输入模型名称。

**Why this priority**: 减少查找模型准确名称的步骤，同时保留兼容服务的手动配置能力。
**Independent Test**: 使用返回多个模型的受控服务，填写连接信息后出现去重的可选模型；选择后可保存，查询过程不保存配置。
**Acceptance Scenarios**:
1. **Given** 服务可提供模型目录，**When** 管理员填写地址及密钥，**Then** 自动展示模型名称并保留已有手动输入。
2. **Given** 管理员填写根地址或完整聊天地址，**When** 目录可被识别，**Then** 展示实际可用的 API 地址，管理员保存时采用该地址。
3. **Given** 服务无需密钥，**When** 管理员只填写地址，**Then** 仍能自动获取模型。
4. **Given** 服务无目录或目录为空，**When** 查询结束，**Then** 给出具体提示且允许手动填写并保存。

### User Story 2 - 清楚了解当前连接协议 (Priority: P2)
管理员可以看到当前支持的 OpenAI 兼容 Chat Completions 协议，理解模型目录识别的边界。

**Why this priority**: 避免把获取模型列表误认为已验证所有模型调用能力。
**Independent Test**: 打开配置，能直接看到固定支持的协议及能力限制。
**Acceptance Scenarios**:
1. **Given** 打开设置，**When** 查看连接方式，**Then** 显示 OpenAI 兼容 Chat Completions，不提供尚未支持的协议选项。
2. **Given** 获取了模型列表，**When** 查看执行限制，**Then** 上下文预算、输出上限、工具能力均不根据模型名称伪造识别结果。

### User Story 3 - 安全使用已保存密钥 (Priority: P1)
管理员可在原连接上复用已保存密钥刷新目录；更换服务地址后必须重新提供密钥或明确清除旧密钥。

**Why this priority**: 防止地址编辑意外发送原服务密钥。
**Independent Test**: 原地址查询收到已保存密钥；修改地址查询或保存时被阻止，直到提供新密钥或选择清除；普通成员无法查询。
**Acceptance Scenarios**:
1. **Given** 原服务已有密钥，**When** 同一规范地址刷新列表，**Then** 后端复用密钥而浏览器只得到模型名称。
2. **Given** 更改服务地址且未填写密钥，**When** 查询或保存，**Then** 要求重新填写或清除密钥，在此之前新服务未收到旧密钥。
3. **Given** 请求重定向、失败或取消，**When** 返回结果，**Then** 不跟随重定向且不展示密钥或远端响应正文。

### Edge Cases
- 地址或密钥快速编辑、关闭模态框、重复刷新时，过期查询不得覆盖新状态。
- 未授权用户、非管理员、非法地址、超大输入在访问服务前被拒绝。
- 超时、认证失败、限流、错误格式、超大目录、重复/无效模型名有明确且不泄密的结果。
- 自定义 API 路径保留；只对根地址尝试常见版本路径，不猜测其他供应商或跨地址探测。

## Requirements

### Functional Requirements
- **FR-001**: 只有管理员可查询模型目录；未保存的连接信息可以参与查询。
- **FR-002**: 系统自动查询及支持主动刷新，并提供去重、排序且数量有上限的模型选项。
- **FR-003**: 模型名称可手动输入；获取目录不得覆盖已输入名称，不自动替用户选择多模型目录。
- **FR-004**: 系统识别常见地址填写方式，并展示识别出的 API 地址；保存前不改变持久配置。
- **FR-005**: 设置必须明确显示唯一支持的 OpenAI 兼容 Chat Completions 协议，不宣称自动验证其他协议或工具支持。
- **FR-006**: 已保存密钥仅可在规范化后完全相同的原 API 地址复用；包括根地址回退到版本路径在内的地址变化，均需新密钥或明确清除。
- **FR-007**: 目录查询须限时、限大小且禁止重定向；失败信息不包含密钥、远端正文或底层请求错误。
- **FR-008**: 输入改变或关闭设置后，取消原查询并忽略过期结果。
- **FR-009**: 查询不触发聊天、不修改配置、不改变预算或启用状态。
- **FR-010**: 合同和集成测试必须验证授权、密钥边界、地址识别、失败回退与无持久副作用。

### Key Entities
- **连接输入**: 待查询地址、临时密钥、是否使用原密钥。
- **模型目录**: 实际 API 地址、有界模型名称列表、是否截断、当前连接协议。
- **查询状态**: 空闲、等待、查询中、成功、失败；仅与当前输入关联。

## Success Criteria

### Measurable Outcomes
- **SC-001**: 受控服务上的原地址、根地址及完整聊天地址三类填写方式均可获取模型，自动查询在输入稳定后 1 秒内开始。
- **SC-002**: 每次查询在 10 秒内结束，最多访问同一服务的两个目录地址，返回最多 500 个模型。
- **SC-003**: 所有目录不支持或请求失败场景仍可手动填写模型；已有模型名被保留。
- **SC-004**: 授权和密钥边界测试中，非管理员及地址变更未提供新密钥的请求访问远端次数为零；浏览器响应泄露密钥次数为零。
- **SC-005**: 所有查询均不改变存储配置；旧响应覆盖新输入次数为零。

## Assumptions
- 本次扩展保持现有唯一连接协议；原生 Responses、Anthropic 及自动供应商切换不在本次范围。
- 模型目录不能可靠揭示上下文窗口、输出上限或工具能力，保留当前手动预算设置。
- 支持管理员主动配置的本地及内网服务，使用现有登录和加密存储。
