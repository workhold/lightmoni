# SDD 214：助手任务提案目标归一化

## 背景

助手模型创建任务时，可能按照派发任务的习惯把目标主机放到顶层 `host_ids`，同时又在任务定义内填写 `host_ids`。旧校验把这种冗余表示判为 `invalid_input`，导致用户请求创建只读诊断任务时反复失败，也没有可定位的字段错误。

## 目标

1. `task.create` 和 `task.update` 接受顶层 `host_ids` 作为目标主机的等价表达。
2. 任务定义和顶层目标同时存在时，合并去重后仍写入任务定义；派发专用顶层 `host_ids` 语义不变。
3. 合并后的目标仍必须通过原有静态目标授权校验；不能绕过主机范围或扩大授权。
4. 任务派发、取消、重试的原有契约不变。
5. 审批前仍保存完整目标，人工审批后才会创建或修改任务。

## 非目标

- 不自动审批或执行诊断任务。
- 不改变任务存储结构。
- 不把外部服务主体的任务创建权限扩展到动态目标。

## 验收

1. 助手以顶层 `host_ids` 创建脚本任务时能生成待审批提案。
2. 提案内任务目标等于顶层与任务定义目标去重合并结果。
3. 顶层 `host_ids` 不会残留在派发/取消/重试 intent 中。
4. 既有创建、更新、派发和审批测试继续通过。
