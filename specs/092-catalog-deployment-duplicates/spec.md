# Specification: 应用安装部署位置去重

**Branch**: `codex/fix-duplicate-install` · **Date**: 2026-11-04

## Problem and acceptance

用户在应用商店安装 Gitea 时看到 `duplicate_application_deployment`。已用真实 HTTP/SQLite 夹具复现：唯一集群下添加第二行，页面刷新触发默认值补全，两行指向同一集群和机器，后端返回 400。

- FR-001：默认位置补全只使用尚未被其他行选择的集群；页面刷新不能制造重复位置。
- FR-002：部署行数量达到可用集群数量时禁止继续添加；多集群仍能逐行配置，移除后可重新添加。
- FR-003：自选位置提交前检查重复集群，明确提示“每个集群只能配置一次部署”，保留名称、业务参数和资源配置；同一集群的多台机器放在同一部署行。
- FR-004：后端继续拒绝重复集群，不合并配置、不放宽数据约束；返回此错误时界面展示可操作的中文/英文提示。
- FR-005：自动选址及合法的单集群、多集群安装仍可创建应用并返回真实部署请求状态。
- FR-006：移除部署行时同步移除其高级资源字段，不保留空部署或错误的行数；仍保留其余部署的资源配置。

## Verification

单集群刷新及安装、多集群添加/移除/切换和安装、重复集群被表单阻止、后端错误翻译与输入保留；真实 HTTP 回归确认非法请求无资源/执行副作用。验证不执行远端 Docker 或修改生产配置。

## Architecture impact

不适用：仅修复既有安装表单默认值、行数约束及错误展示，沿用现有 API、部署唯一性约束、组件职责与安装控制路径；无存储、协议、部署拓扑或凭据边界变更。`docs/system-design.md` 与 Doca 无需改写。
