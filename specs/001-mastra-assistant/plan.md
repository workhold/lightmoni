# Implementation Plan: Mastra monitoring assistant

**Branch**: existing main | **Date**: 2026-10-14 | **Spec**: [spec.md](spec.md)

## Summary
Replace production Go model/tool orchestration with a host-managed Mastra worker over private NDJSON stdin/stdout. Keep authenticated Go routes, encrypted credentials, SQLite sessions, query validation and existing UI. Each turn gets an isolated worker: no extra exposed port or user identity supplied by the model. Add bounded history compaction, reported usage and batched persistence.

## Technical Context
- Language: Go 1.26+, TypeScript 5.9, Node >=22.13 (container Node 24).
- Dependencies: pinned @mastra/core 1.66.0, @ai-sdk/openai-compatible 3.0.48, Zod 4; stdio transport uses standard libraries.
- Storage: existing Go SQLite assistant_records; additive optional fields only.
- Tests: Go race/unit plus actual Mastra worker against deterministic HTTP model fixtures; TypeScript context tests, web typecheck/build.
- Target: macOS ARM local development and Linux Compose image.
- Scope: interactive read/draft tools only. 8 default steps / 2-minute timeout remain. Input estimate is deliberately conservative UTF-8 byte count, not advertised as exact tokenization.
- Constraints: tool results <=128 KiB, private pipe frame <=2 MiB, durable session <=2 MiB. Source histories are kept; display storage limit remains explicit.

## Constitution Check
PASS before and after design: Go executes all tools with the authenticated Principal, Mastra cannot register writes; keys travel only in private stdin; summaries are data; user confirms draft saves; Doca current AGPL code is not copied; deployment includes Node and worker dependencies.

## Project Structure
- ai-runtime/src/{runner,context,protocol}.ts and tests: Mastra execution and history budgeting.
- internal/assistant/{runtime,service,types}.go: worker adapter, event/history persistence, settings and bounded tool execution.
- web/src/features/assistant/: compaction progress and reported usage in timeline/settings.
- deploy/server/Dockerfile: Node runtime and compiled worker shipped with Go binary.
- specs/001-mastra-assistant/: specification, decisions, contracts, tasks and verification.

## Decisions
Mastra owns the multi-step agent loop. Go does not reimplement a parallel production loop; the old provider parser and loop are moved to test-only source while runtime injection isolates existing host tests. Worker spawning adds startup overhead but preserves one-container distribution, avoids callback endpoint security and isolates turn failure. No persistent Mastra memory database: Go retains canonical history and summary to avoid conflicting ownership. Summary is generated by a bounded tool-free Agent, preserving recent complete rounds. Abort kills the scoped worker and cancels Go tool contexts. Runtime stderr is discarded; provider error bodies never reach browser events.

## Delivery
Implement US1 transport first, US2 context compaction, US3 usage/UI/cancel. Verify before task closure. Container build may be unverified without Docker; document that limitation rather than claiming it passed.
