# 实施计划：应用总览加载与状态核对

**分支**：`codex/162-app-overview-state`　**日期**：2026-11-14　**规格**：[spec.md](spec.md)

## 基线与设计决策

- `OperationsPage` 的 `/ops/overview` 与可选主机应用清单共同完成一次页面读取。当前 `observationRequest` 每次 `load()` 都递增，10 秒自动轮询及窗口焦点会让尚未完成的首屏响应失效；证书申请中的 2 秒轮询也经过同一路径。为一次读取保存请求控制器，自动刷新和焦点事件遇在途读取时跳过；显式刷新及会触发新读取的范围变化取消旧请求并开始新请求，纯本地筛选不发新请求。卸载页面时取消在途读取。请求序号仍防止迟到结果覆盖新范围；取消本身不显示错误。
- `/ops/overview` 当前为列表和 `total` 各调用一次 `store.list()`。在路由内一次读取、一次按 `publicKinds` 与集群过滤，再分别取前 1000 条和集合长度；资源公开投影、升级信息、权限与响应字段不变。这个优化不加入缓存，避免跨用户或跨请求复用过期状态。
- 应用状态由前端 `resourceState()` 解释中心部署、实例和恢复摘要。中心从实例 `current_run_id` 对应的未人工核对 unknown 运行记录派生可选 `unresolved_run_id`，覆盖日志作业结果未知而实例仍为 `running/healthy` 的情形。状态仅按启用、已发布集群的当前非退休实例判断，避免禁用集群遗留状态污染；实例 `unknown` 或 `unresolved_run_id` 优先显示结果未知，明确失败优先于保护态；再判 `retained`、`grace`、`protected` 与未知恢复阻塞为 `unverified`。运行中需每个目标的当前实例数、`ready_instances` 均满足副本/机器目标，且已发布修订和健康证据一致；不单独信任可能对空集合成立的 `applied_revision`。零副本目标可无实例或仅有已停实例；全零目标整体已停止，混合就绪目标仍可运行。2→1 缩容要求目标槽位就绪、额外未退休实例已停。没有启用发布集群时，禁用集群仍有非退休活动实例或实例摘要截断则显示待核实，不能误报停止；已退休旧实例不阻塞停止或本轮新增应用动作门禁。保存修订比发布修订新时单列“已保存未发布”，不宣称新版本运行。
- `InstalledApplications` 与详情共享投影；筛选选项单列 `unverified`，`pending`/失败筛选显式排除它，统计复用同一过滤函数。任一需要核对的卡片，其“核对状态”打开既有 `ApplicationInstallDrawer`，由它只读取得该应用资源与 `/ops/runs` 最近 100 条历史、优先选择当前未核对的 unknown 记录。若 `unresolved_run_id` 不在列表，按既有 `/ops/runs/:id` 补读原记录；仅有未知恢复阻塞时，抽屉显示待核实并优先选择同应用历史中的 unknown 原记录。有当前未核对记录时，已核对的旧 unknown 不抢占默认选择，用户手选其他记录后轮询也不抢占；不派发会被围栏拒绝的新 `inspect`。所有非退休实例扫描 `state=unknown`、未知恢复阻塞与 `unresolved_run_id`；命中时限制部署/重新部署、停止、卸载、升级和删除登记，包含禁用集群及已移除但尚有未核对执行的实例；已退休历史不触发本轮新增应用动作门禁，但登记删除仍受既有 `store.remove` 对未核对历史运行的独立保护。一般待核实卡片限制升级、停止、卸载和删除登记。记录抽屉在待核实/结果未知时禁用编辑、重新部署及快装重试。
- 服务端对用户发起的 `deploy|stop|remove|reconcile` 在写入 `desired_revision`、`enabled` 或实例 `desired_state` 前检查未核对当前 unknown 运行结果，返回冲突而不改变部署意图；前端门禁只是提示，不能替代此检查。既有人工核对解除后重新读取可恢复动作，不改写历史 unknown 回执；服务自动恢复保持原机制。

## 实施顺序

1. 先完成规格、设计、兼容契约和任务；明确请求替换语义、状态优先级和安全边界。
2. 修正 Web 读取调度及清理，验证慢响应、自动刷新、焦点、手动刷新、范围切换、错误和卸载时序。
3. 调整 Runtime 总览资源读取，定向验证一次 `store.list()`、`total`、上限和原接口兼容。
4. 调整实例公开摘要、状态投影、卡片/详情、筛选与核对入口；覆盖半数副本就绪、零副本停止、2→1 缩容、禁用集群遗留实例、已退休实例、新配置未发布、日志作业 unknown 和失败优先级。核对抽屉在 100 条历史上限之外补读当前未核对记录；服务端在变更部署意图前拒绝未核对执行。
5. 同步仓库系统设计第 162 章与 Doca 在线基线，保存后以最新版本回读目标文字及原生图节点、连线。
6. 运行相关类型检查、测试与 Web 构建，在 `validation.md` 记录行为、兼容、架构同步及未覆盖的线上现场。同步 `origin/main`、处理冲突后，通过功能分支向 GitHub `main` 创建 PR；未经合并授权不合入。

## 兼容与风险控制

前端请求控制器仅协调本页既有 GET，不改变服务器超时、轮询周期和页面对其他领域的权限。自动读取跳过在途请求可能延后一次更新，现有请求结束后下一次轮询仍可取得最新数据；显式操作仍立即刷新。中心总览按请求现读，不缓存资源或凭据。`unverified` 不持久化，`unresolved_run_id` 仅公开既有未核对当前运行 ID；旧消费者可忽略此可选字段。不将地址保留、端口占用、旧健康或未知任务推断成运行成功；未知结果仍由现有管理员人工核对，保持原互斥和审计。后端 `applied_revision` 的空集合判定留作后续风险，本轮前端必须另核目标及就绪数量。

## 架构影响

适用：“核对状态”从可能派发受管 `inspect` 改为读取原应用执行记录，历史列表缺少 `unresolved_run_id` 时按既有 `/ops/runs/:id` 补读；中心增加从当前未核对运行记录到实例公开摘要的证据路径，并在部署意图变更前检查围栏。这些是数据和控制路径调整。仍使用既有抽屉、GET 接口与任务记录；仅增加可选摘要字段，不增加持久状态、凭据边界或部署拓扑。仓库 `docs/system-design.md` 第 162 章与 Doca 在线设计在同一 SDD/PR 同步，写后最新版本回读目标文字、原生图节点与连线。
