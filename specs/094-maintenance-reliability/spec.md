# SDD094 Agent 维护可靠性与中断恢复

## 目标

补全 SDD093 现场回测发现的可靠性闭环。复用同一维护器、主机账户和审计记录，让用户通过平台处理已停止的维护事务，不依赖手工改回执或清锁。真实主机只做有界读取；资源与故障注入先在本机隔离环境验证。

## 必须满足

1. 真正的 SSH 自包含 probe 与维护器统一使用固定分块哈希，指纹不变。
2. 准备阶段最长五分钟，切换前保留完整的确认和恢复预算；远端硬期限二十分钟，平台默认观察二十一分钟。准备超时应在原服务运行时失败，不在接近硬期限时切换。
3. 结果未知时保留只读核对；另提供需要明确确认的恢复操作。先验证原事务、维护 unit/cgroup/进程已停止、生命周期锁归属、身份、运行模式和权限代次，再处理。准备阶段仅在原程序完整健康时归档失败；切换后只恢复审批固定且完整验证的原快照。运行中的 worker、不明指针、无效快照或其他操作锁均拒绝恢复。
4. 恢复不重放 apply/start/worker，不重接入，不裸清锁、不删除原包/快照/claim；恢复结果和核验所用账户/凭据修订写入原维护记录。丢失恢复响应时仍保持 unknown，先只读核对。
5. 解包完成预验证后，在写出文件前按实际文件占用和数量校验磁盘与 inode，保留系统余量；准备失败只清理本操作新建且无引用的候选。
6. 维护退出时保留小型、无秘密的 unit 退出与资源证据，unknown 文案不承诺死 worker 自动回退。
7. 升级 GET 轮询及手动刷新必须有超时/取消，失败保留最后状态并能关闭；不得因读失败重复派发写操作。
8. 硬资源预算必须先用真实包验证，再启用经过验证的值；本机测慢准备、取消、各阶段中断、恢复、低空间/inode 与背景负载。记录无法覆盖的边界，不作零故障承诺。

## 架构影响

新增维护恢复控制动作和固定 SSH 恢复命令，属于既有维护组件职责内的控制协议扩展。需要更新仓库 system-design 的维护状态机、期限和恢复边界，并同步 Doca 后回读。旧独立 executor 与非受管安装不兼容；不引入新服务账户或第二套执行引擎。
