# SDD 182：统一镜像与仓库页面

## 背景

私有镜像管理和镜像源分别承担仓库托管/发布与上游拉取配置，当前两个左侧入口割裂了完整的镜像使用路径。用户希望合并页面，但不能混淆凭据、部署和代理的安全边界。

## 用户场景与验收

### US1：单一导航与兼容深链

- 左侧只显示一个“镜像与仓库”入口，位于集群管理之前；不再重复显示镜像源和私有镜像管理。
- `/image-management` 提供镜像与版本、仓库与发布入口、凭据与来源代理三个标签。
- `/private-images` 重定向到 `tab=registry`，`/image-sources` 重定向到 `tab=sources`；成员角色仍不能访问管理员页面。

### US2：功能复用且请求隔离

- 镜像与版本标签保留仓库摘要、镜像列表、引用与清理。
- 仓库与发布入口标签保留部署、内网复用和对外网站入口，不显示镜像版本面板。
- 凭据与来源代理标签完整保留凭据 CRUD、关联应用、代理和回源配置，不显示仓库部署面板。
- 只挂载当前标签，避免重复轮询；部署、凭据、代理、清理、审批和恢复仍走原 API 与状态模型，不合并 secrets 或授权。

## 非目标

不迁移数据、修改 Registry 配置、合并底层资源、改变权限或发布生产镜像。

## 架构影响

仅统一前端导航和组合方式，API 与控制路径不变；在 `docs/system-design.md` 59.7 记录统一页面及兼容深链。
