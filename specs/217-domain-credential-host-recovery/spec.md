# SDD 217：域名状态、连接凭据轮换与主机观测恢复

## 背景

托管域名同步成功后保留历史 `cloud_request_failed`，造成“已同步但仍报错”的矛盾；连接凭据只能改名或撤销，不能替换失效密码/私钥；历史 Docker 安装结果未知会阻断终端、运行模式切换和 AI 主机信息操作；AI 主机清单返回过多账户、网络地址和维护历史，容易超过模型输入预算。

## 目标

1. DNS zone 同步成功时清除历史同步错误，状态与错误详情一致。
2. 连接凭据支持在不回显旧秘密的前提下替换密码或私钥；登录方式不可变，SSH 私钥指纹同步更新。
3. Docker 只读核对发现远端操作目录不存在时，可安全判定安装未开始并将记录置为 failed，解除无关操作围栏。
4. AI/MCP 主机清单和单机详情返回稳定摘要，不再携带完整 SSH 账户、网络候选和维护历史。
5. 所有修改继续要求管理员身份，不回显秘密，不自动审批主机变更。

## 非目标

- 不允许可逆已撤销凭据。
- 不自动安装 Docker、切换运行模式或批准权限计划。
- 不改变 DNS 提供商 API 和网站发布流程。

## 验收

1. DNS 同步成功后 `last_error` 为空且状态为 synced。
2. 连接凭据 PUT 支持可选新秘密；省略秘密时仅更新名称；方法不可变；SSH 私钥重复指纹被拒绝。
3. Docker 状态命令在操作目录缺失时返回结构化 failed 证据，验证后记录变为 failed。
4. AI 主机清单字节量显著下降且不包含账户、私钥元数据或完整网络候选。
5. 相关后端测试、类型检查和构建通过。
