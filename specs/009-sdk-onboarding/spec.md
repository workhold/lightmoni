# Feature Specification: SDK 接入与豁免表

**Feature Branch**: `codex/sdk-onboarding`
**Created**: 2026-10-18
**Status**: Implemented and verified
**Input**: 左侧数据接入改为 SDK 接入；只提供 Go、Node.js、Rust、Python 四种 SDK 样例；选择或就地创建 SDK 密钥；支持仅可写豁免表的无密钥模式；页面只有 SDK 样例、SDK 密钥、豁免表三个 Tab。

## User Scenarios & Testing

### User Story 1 - 生成带密钥的 SDK 样例 (Priority: P1)
用户选择语言、服务、逻辑表和 SDK 密钥，复制与这些选择一致的安装命令、环境变量和代码。
**Why this priority**: 让业务第一次接入无需离开样例页面。
**Independent Test**: 无密钥时打开选择框，只看到创建按钮；填写名称后创建一个仅允许当前表的密钥，并自动选中；有密钥时，选择框底部始终可新建。
**Acceptance Scenarios**:
1. 导航名称为 SDK 接入；页面恰有 SDK 样例、SDK 密钥、豁免表三个 Tab，样例语言恰为 Go、Node.js、Rust、Python。
2. 密钥模式未选择密钥时，不能复制接入样例；不静默进入无密钥模式。
3. 新建仅填名称，自动授权当前逻辑表、选中并将一次性返回的完整值带入环境变量；失败保留输入与原选择，重试不重复提交。
4. 选择已有有效密钥时，只提供其有权写入的表（所有表密钥允许填写新表）；禁用或无授权密钥不可用于生成。
5. 已有密钥的完整值不从摘要恢复；环境变量指出所选名称供用户填入保存的完整值。刷新不会保存新建密钥明文。

### User Story 2 - 无密钥接入 (Priority: P1)
用户主动选择无密钥模式，只能选择已启用的豁免逻辑表；没有豁免表时可从常见用途推荐中创建。
**Why this priority**: 明确支持简便接入，同时保持目标表边界。
**Independent Test**: 配置一个豁免表，不携带凭证上报三种信号均成功，普通表、停用表、系统表均拒绝。
**Acceptance Scenarios**:
1. 推荐应用日志、业务指标、前端事件用途，以随机后缀生成复杂表名，说明应避免容易猜测的名称。
2. 推荐不会自动授予豁免权限，管理员明确保存后才允许上报；刷新后名单保留。
3. 无密钥环境变量明确清除旧密钥；四种语言样例不读取或携带密钥。
4. 停用或删除豁免后，新请求和已确认批次重试均拒绝；携带错误或禁用密钥不得降级成无密钥。
5. 无密钥数据的密钥身份为空；不能借自监控字段写入系统表，匿名与带密钥批次分开去重。

### User Story 3 - 管理与兼容 (Priority: P2)
管理员维护 SDK 密钥及豁免名单，成员可阅读样例与豁免表但不能管理授权。
**Why this priority**: 保留授权与原有数据管理能力。
**Independent Test**: 成员写管理接口返回拒绝；旧链接仍能到达执行节点安装和数据表管理。
**Acceptance Scenarios**:
1. SDK 密钥保留名称、授权范围、状态、上传记录与禁用/启用；列表无明文密钥。
2. 豁免表可添加、修改说明、启停、删除；删除豁免不删除数据，逻辑表精确匹配且禁止通配符和系统表。
3. 执行节点接入移动到节点助手；数据表保留时长和日志规则移动到管理后台；图表模板仍可从大盘编辑器使用。

### Edge Cases
- 加载、创建失败不以空名单冒充成功，保留输入与选择；异步刷新撤销失效选择。
- 表名最长 48 位、小写字母开头，不带 log_/metric_/trace_ 前缀；同名豁免返回冲突。
- 窄屏、键盘操作、减少动态效果正常工作；密钥列表为空时下拉无多余空状态。

## Requirements
### Functional Requirements
- **FR-001**: 导航、三个 Tab 及四种语言必须符合用户指定。
- **FR-002**: 密钥选择、新建后选中、当前表的最小授权与一次性密钥展示必须一致。
- **FR-003**: 无密钥仅可向管理员明确启用的豁免逻辑表写入，身份与系统写入边界必须由服务端保证。
- **FR-004**: 名单持久化，所有授权变更仅管理员可操作，立即影响后续请求。
- **FR-005**: 保留现有有效密钥、数据、执行节点、SDK 协议与历史包下载兼容性。
### Key Entities
- SDK 样例配置：四种语言、服务、逻辑表、上报地址、密钥或无密钥模式。
- SDK 密钥：原有身份、摘要与允许写入范围；新建密钥完整值只用于当前页面。
- 豁免表：精确逻辑表名、说明、启用状态、创建时间；覆盖该逻辑表的日志、指标、链路。

## Success Criteria
### Measurable Outcomes
- **SC-001**: 只有三个指定 Tab 和四个语言选项；新建只需填写一次名称即完成选择。
- **SC-002**: 四种语言的样例与所选服务、表、模式一致，用户可以复制使用。
- **SC-003**: 三种信号的未授权、失效豁免、错误密钥与系统表越界检查全部通过。
- **SC-004**: 真实页面空态、新建、失败重试、刷新回读和窄屏流程通过连续三次验收。

## Assumptions
- SDK 样例默认直连中心；执行节点安装和既有 SDK → Agent 协议继续保留。
- SDK 语言限制针对接入页面及安装目录展示，历史其他语言包和客户端保持可用。
- 密钥与豁免管理沿用管理员权限；密钥仍只保存摘要，不能取回历史明文。
- 不默认开放任何豁免表；复杂名称用于降低偶然猜测，不等同访问凭证。
