# 单域名证书与域名下同步任务

2026-10-31。用户要求去掉证书名称：每张证书对应一个域名或泛域名，名称展示域名；同步任务放到对应域名证书下，机器目录同步支持选择集群并同步全部成员机器。

## 验收

1. 新建证书只输入一个域名或泛域名，无名称字段；中心规范化域名后派生资源名称，拒绝新建多域名。普通与快捷创建一致，所有证书选择、详情、日志、下载入口使用域名名称。
2. 保留已存证书 ID、材料、历史与引用。已有单域名名称按域名展示，编辑保存写入派生名称；历史多域名不自动拆分、缩减或重新申请，显示全部域名，编辑保留原集合。新建模型不再产生多域名证书。
3. 删除证书列表底部全局同步任务表。每个域名行下有自己的同步任务与添加入口，新增时绑定该证书；详情也保留同样入口，编辑不串到其他证书。
4. 目录同步支持单机 agent_id 或 cluster_id 二选一；脚本仍限单机，云目标不变。集群目录、文件名、权限及所有者配置统一应用到所有成员；表单展示成员范围及未接入 Agent 的机器，集群管理仅字段旁快速跳转。
5. 每次同步解析当前集群的全部机器，空集群、缺少/移除 Agent 等预检错误明确拒绝派发，不静默跳过。离线但身份有效的 Agent 可排队。每台机器独立 run/版本/结果，全部回执证实版本和指纹才显示集群 applied；部分成功不能代替全部成功。
6. 幂等键按任务版本、证书版本、机器和 Agent 绑定分开；重复同步不重放已成功或在途动作。重试只覆盖失败成员，unknown 须先检查现场；自动同步新证书/新成员，撤销授权、离开集群或更换 Agent 的旧私有载荷不能继续读取材料。旧回执不得覆盖当前配置/版本/成员结果。
7. 复用既有中心加密快照、operations.platform、control + job lease；普通资源/任务/日志不包含 PEM、私钥或云秘密。保持单机、云和脚本兼容，提供 API/控制器、真实 Agent 目录落盘及浏览器验收证据。

## 架构影响

适用：证书命名与新建基数约束、集群成员解析后多 Agent 派发、私有载荷成员守卫和逐机器汇总改变数据/控制路径。复用既有表与节点协议，无新增外部服务。与实现同 PR 同步 docs/system-design.md §33.5/§33.6 和 Doca 系统设计基线，保留原生图块，写后回读文本、节点与连线。
