# Feature Specification: 应用 Logo 与 YAML 配置

**Feature Branch**: `codex/068-application-logos`
**Created**: 2026-11-01
**Status**: Implemented and verified
**Input**: 每个应用都要有自己的 logo，自定义的应用也支持上传 logo。

## User Scenarios & Testing

### User Story 1 - 用品牌识别应用 (Priority: P1)

管理员浏览应用商店、已安装列表和应用详情时，通过品牌图形快速识别应用。

**Why this priority**: 首字母和通用图标无法表达 31 个应用各自的品牌。
**Independent Test**: 核对全部 31 个模板的独立品牌素材和已有安装记录的显示。

**Acceptance Scenarios**:

1. **Given** 商店已有 31 个应用，**When** 浏览任意分类，**Then** 每个条目显示对应品牌 Logo，无首字母替代。
2. **Given** 历史商店安装记录，**When** 打开已安装列表和详情，**Then** 自动按原模板识别 Logo，无需重新安装。
3. **Given** 深浅色、中英文或手机窗口，**When** 查看图形，**Then** 不变形、不裁切，不依赖第三方网络请求。

### User Story 2 - 管理自定义 Logo (Priority: P1)

管理员创建自定义应用时可上传图片并预览，保存后刷新仍显示；已有应用可独立替换或移除图片。

**Why this priority**: 自定义应用也应有可识别的展示信息。
**Independent Test**: 从真实创建入口上传、保存、刷新、替换和移除；模拟保存失败后仍可恢复。

**Acceptance Scenarios**:

1. **Given** 创建自定义应用，**When** 上传有效 PNG/JPEG/WebP 并保存，**Then** 图片与应用一起保存，刷新后仍显示。
2. **Given** 已有应用，**When** 单独修改 Logo，**Then** 应用配置版本、部署与运行状态不变，不创建执行任务。
3. **Given** 取消、图片损坏/过大、保存失败或被其他管理员更新，**When** 操作，**Then** 显示明确提示，保留原 Logo 与可重试输入，不产生重复应用。
4. **Given** 移除自定义 Logo，**When** 保存，**Then** 商店应用恢复品牌 Logo，自定义应用使用通用应用图标；删除应用登记时同时清理图片。

### Edge Cases

- 无 Logo 的历史记录、未知模板、图片加载失败、同一图片重复上传。
- 非图片伪装扩展名、脚本 SVG、超大图片、损坏或解压异常图片。
- 并发替换/移除、取消选择、快速连续选择文件、无权用户请求图片。
- 配置保存失败不留下图片或应用孤儿；Logo 更改不影响正在执行的部署。
- 应用配置按 YAML 显示；创建与修改都提供高级 YAML。托管时从服务 ports 发现容器端口，YAML 中的宿主映射不生效；expose 仍为内部端口。
- 旧端口名称、网站引用、本机监听、脱敏环境占位与单容器程序类型保留；无效 YAML 不覆盖现有配置。

### User Story 3 - 用 YAML 创建和修改应用 (Priority: P1)

管理员可以在创建和修改时直接编辑 YAML；已有 Compose 对象以 YAML 展示。单容器高级编辑保持原程序类型，复杂 Compose 继续使用完整 Compose 文档。手动模式采用高级 YAML 的宿主端口，托管模式仅采用容器端口意图，由平台分配宿主端口。

**Independent Test**: 创建和修改两种程序，验证 YAML 格式、脱敏占位往返、端口发现、托管映射不受 YAML 宿主端口影响，旧端口引用和监听边界保持。

## Requirements

### Functional Requirements

- **FR-001** 全部 31 个商店应用具有可追溯来源的品牌 Logo，并覆盖已有商店安装。
- **FR-002** 自定义应用支持创建时上传，以及保存后的替换、预览和移除。
- **FR-003** 图片和应用保存需保持一致；刷新与中心重启后保留。
- **FR-004** Logo 是展示信息，单独修改不触发部署、不改变应用配置版本、不进入 Agent 任务。
- **FR-005** 上传大小、尺寸、格式和内容有界；不执行图片内脚本、不读取远端 URL。
- **FR-006** 沿用管理员权限；并发更新可识别冲突，失败后保留输入。
- **FR-007** 同步仓库与 Doca 系统设计并回读，保留已有原生图和无关内容。
- **FR-008** 应用创建与修改提供高级 YAML，已有 Compose 显示 YAML，不显示 JSON；保存失败保留文本。
- **FR-009** 托管模式从 YAML 发布意图自动发现容器端口，忽略 YAML 宿主端口；内部 expose 不自动公开。
- **FR-010** 手动高级 YAML 映射生效，已有表单与商店行为兼容；环境脱敏占位回填旧值，新键占位不接受。

### Key Entities

- 品牌素材：应用模板、图形、来源与使用说明。
- 应用 Logo：应用标识、图片内容、独立版本与更新时间。

## Success Criteria

### Measurable Outcomes

- **SC-001** 31/31 商店条目使用对应品牌素材，历史安装无需重新安装即显示。
- **SC-002** 真实上传、保存、刷新、替换、移除和失败重试均通过。
- **SC-003** 单独修改 Logo 前后应用配置版本和执行任务数量相同。
- **SC-004** 中英文、深浅色、390px/1440px 图片清晰且布局无横向溢出。
- **SC-005** 非法文件、越权和并发冲突被拒绝；仓库与 Doca 新章节一致。

## Assumptions

- 沿用现有视觉、权限和中心数据备份；未上传的自定义应用使用通用图标。
- 用户选择 PNG/JPEG/WebP，原图不超过 5 MiB；上传前生成适合 Logo 的有界图像。
- 内置品牌素材随网页打包，不新增 CDN、外部存储或付费服务。
- 沿用用户已授权的 GitHub PR 合入与 Docker 发布流程。
