# Feature Specification: SSH 单次命令发行就绪判断

**Feature Branch**: `codex/127-ssh-production-qa`

**Created**: 2026-11-12

**Status**: In progress

**Input**: 线上 SSH 主动运维验收发现，旧 Agent 的既有能力心跳仍可能让中心显示受管操作已就绪，但其安装包没有 `managed-once`、`jobs-once`、`task-once`。

## User Scenarios & Testing

### User Story 1 - 旧发行在审批前显示升级要求 (Priority: P1)

管理员在旧版主机上查看受管运维、容器或提权执行能力时，能看到需要升级的原因；生成新计划时不会先批准再以远端命令缺失失败。

**Why this priority**: 避免把不可执行的操作提交到生产主机。

**Independent Test**: 使用有 SSH 凭据和旧版能力心跳的主机读取状态并创建计划，确认显示升级要求且不产生新作业。

**Acceptance Scenarios**:

1. **Given** 主机有有效 SSH 凭据但安装包不支持单次命令，**When** 管理员读取受管执行状态，**Then** 能力不显示已就绪并给出升级原因。
2. **Given** 相同主机，**When** 管理员提交受管、容器或提权计划，**Then** 中心在创建作业前拒绝，并保留原资源和历史状态。
3. **Given** 主机已安装经过线上验证的首个 SSH 单次发行，**When** 中心先行升级，**Then** 该主机仍可创建并执行新作业。

### User Story 2 - 普通作业和手动脚本使用同一发行门禁 (Priority: P2)

管理员发起普通只读作业或手动脚本时，中心检查对应单次入口的发行能力；旧版不排队，新版可执行。

**Why this priority**: 避免不同入口对同一旧主机给出矛盾的“已就绪”结果。

**Independent Test**: 分别在旧版和兼容发行上提交普通作业、手动脚本；检查创建结果和错误原因。

**Acceptance Scenarios**:

1. **Given** 旧版 Agent 心跳未证明 `jobs-once`，**When** 中心发起普通作业，**Then** 拒绝新作业并提示升级。
2. **Given** 旧版签名 helper 心跳未证明 `task-once`，**When** 管理员手动执行脚本，**Then** 拒绝新任务；已有定时任务仍按原 Agent 循环运行。
3. **Given** 兼容发行的历史心跳证明单次能力，**When** 常驻 Agent 暂时离线但 SSH 仍可用，**Then** 不仅因心跳时间过旧而阻断中心主动操作。

### User Story 3 - 旧队列安全处理 (Priority: P3)

中心升级后扫描到此前已入队的旧作业，先检查发行能力，再尝试 SSH 命令；不支持的记录得到明确失败码，不会自动改走常驻 Agent 或重放已领取作业。

**Why this priority**: 生产升级时可能保留尚未领取的队列记录。

**Independent Test**: 启动扫描器处理旧版主机的未领取与已领取记录，确认只终结未领取记录。

**Acceptance Scenarios**:

1. **Given** 旧版主机有尚未领取的主动队列记录，**When** 中心扫描，**Then** 以升级要求结束该记录，不连接远端执行。
2. **Given** 作业已经领取或结果未知，**When** 中心扫描，**Then** 原租约和只读核对机制保持生效，不创建第二次执行。

### Edge Cases

- 能力声明缺失、格式不合法或只有部分单次入口时，仅允许被证明的入口；提权脚本属于特权作业，使用 `managed-once`，任务中心手动脚本使用 `task-once`。
- 2026-11-12 已上线且已验证的 `16b151337cc94c1b7f3f7de56bdcad561759c85b` 发行尚未发送新能力字段；中心精确识别该完整修订，避免先升级中心后误阻断已兼容主机。
- SSH 凭据撤销、主机绑定变化及无法访问中心仍由既有安全门禁和回执处理。

## Requirements

### Functional Requirements

- **FR-001**: 中心须根据远端已认证的发行能力证据，逐一判断 `managed-once`、`jobs-once`、`task-once` 是否可用；缺失证据不能解释为可用。
- **FR-002**: 首个已在线验证的兼容发行可用完整精确修订号作为迁移证据；其他旧修订不得凭版本字符串或修订号排序推断兼容。
- **FR-003**: 新发行须分别报告普通 Agent 与签名 helper 的单次入口能力；中心验证字段格式并只信任当前身份绑定的报告。
- **FR-004**: 不支持对应入口时，计划状态、创建接口和旧队列扫描须给出可修复的升级原因；失败前不产生远端副作用。
- **FR-005**: Agent 暂时离线不应单独取消已证明的单次能力；定时任务继续沿原通道执行。
- **FR-006**: 已领取和 unknown 作业的原租约、审计与只读核对不得因发行判断被重放或覆盖。

### Key Entities

- **单次入口能力证据**：由普通 Agent 或签名 helper 随心跳报告的受支持命令集合，绑定原 Agent/执行器身份和已安装发行。
- **兼容发行迁移记录**：首个已在生产验证的完整源码修订号，仅用于新能力字段上线前的过渡。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 对缺少单次入口的三类主动操作，计划前检查均在创建作业前给出升级原因；测试中产生的不可执行作业数为零。
- **SC-002**: 已验证兼容发行在中心先升级后仍可创建对应计划，且离线历史心跳不会单独导致误阻断。
- **SC-003**: 定时脚本在旧发行上的既有领取与执行测试继续通过，已领取和 unknown 主动作业没有新增重放路径。

## Assumptions

- 生产确认的 `16b151337cc94c1b7f3f7de56bdcad561759c85b` 已包含三个单次入口；其余旧源码修订未按该条件放行。
- 远端仍需有当前绑定的 Agent 控制凭据或签名执行器身份才能领取任务；本特性不重建缺失的控制凭据。

## Architecture Impact

新增 Agent 与签名 helper 向中心报告单次入口能力的协议字段，改变主动操作的准入控制；同一 SDD 与 PR 同步 `docs/system-design.md` 第 127 章和 Doca《LightMoni 系统设计基线》，写后按最新版本回读目标章节和原生图块。
