# 主机管理与 Agent 生命周期回归加固

## 目标

在已合入主机身份、集中凭据、Agent 升级与 MCP 功能的主干上检查主机管理与部署链路，复现并修复真实缺陷。覆盖登记、凭据绑定与失效、SSH 预检、首装、卸载、升级/回退、批次及界面恢复；不引入新的资产、凭据或控制通道。

## 不变约束

- 主机 ID 是平台资产身份；用户名称、SSH 目标与 Agent 观测身份彼此独立，观测不自动改写可信目标。
- 主机操作使用当前有效且有权使用的凭据，审批绑定已审阅目标；旧响应、过期检查或失效凭据不能启动新远端操作。
- 同一主机的冲突生命周期操作互斥，部分失败与未知结果不能报告成功或自动重放。
- 首装保留一次性 enrollment 与服务端主机预约，维护保留已有 Agent 身份和实时数据，卸载保留明确约定的持久目录。
- 后端能力决定是否可操作；界面正确显示默认凭据、当前计划、错误和恢复入口。

## 验收

每个修复必须先有可复现条件或失败回归，再有修复后的验证。记录实际覆盖与未覆盖范围，隔离 fixture 不冒称真实 SSH/systemd 验收。通过相关测试、类型检查和构建，以 GitHub PR 交付；本轮不发布镜像、不部署生产，不干扰现有本地服务。

## 架构影响

存在架构影响：首装持久化安装阶段与 enrollment 关联，新增结果未知及只读核对/人工结束控制路径。必须同步仓库系统设计第 13 节和 Doca，保留原生图并最新回读。其余凭据使用记录、架构复验、卸载任务保护与界面恢复属于既有契约修正。

## 首装恢复要求

- 安装计划的阶段在副作用派发前持久化，enrollment ID 与该安装记录关联；旧记录阶段未知时不能推断从未派发。
- 平台重启将未确认的 running 记为 unknown；bootstrap 已派发后 SSH 断开/超时也保留 unknown，不能自动重跑或提前撤销健康核对所需的新身份凭据。
- 管理员可使用当前有效 SSH 凭据对固定原目标只读核对；仅服务端 enrollment、当前主机关联、有效 control 凭据、远端完整受管服务与启动后新鲜心跳共同证明成功。部分安装或证据不足继续 unknown。
- 明确尚未派发的阶段可以结束为失败；未能自动证明时提供有原因、操作者和时间的人工结束出口，保留原 unknown 历史。人工结束不执行远端命令，取消本次未激活 enrollment 并仅撤销本次新身份凭据，不影响原 Agent 或其他主机；管理员须明确确认远端安装流程已结束。
- 未结束的安装阻止冲突生命周期动作与新的有限任务提交/领取；已运行任务按原协议完成，心跳与持续遥测保留用于观测。人工结束不得绕过未完成任务。
