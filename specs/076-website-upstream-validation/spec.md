# 网站手动后端校验与错误反馈

日期：2026-11-01。

## 问题与要求

新建网站保存失败只显示 `INVALID_WEBSITE_UPSTREAM`。现有手动后端 URL 表单仅检查非空，未解释服务端要求的 HTTP(S) origin 格式；删除全部后端后也能提交无效请求。

用户补充截图确认输入为 `127.0.0.1:5000`，缺少协议；正确填写示例为 `http://127.0.0.1:5000`。新增回归必须覆盖这一原始输入。

用户进一步明确：核心修复是指出具体错误字段，并将原因放在该字段下方。对可在表单中确定的错误，不用顶部通用“保存失败”提示替代字段反馈。

- 每个集群的手动后端 URL 在提交前检查与现有 Nginx 上游相同的边界：HTTP(S)、主机、可选端口；禁止账号密码、非根路径、查询和片段。域名、IPv4、IPv6 和根路径末尾斜杠遵循既有 URL 规范化行为。
- 空白地址和空后端列表显示可操作的中文/英文提示。填写示例并说明路径转发通过路径规则的 URI 选项设置。失败后保留名称、域名、集群和已填后端，定位首个无效字段，不发送保存请求。
- 服务端仍为最终校验边界；返回上游相关错误时显示可理解的双语解释，不只展示内部错误码。
- 有效手动后端可保存并回读；应用命名端口、托管服务、返回/重定向与静态网站不因隐藏的空手动后端被阻止。

## 架构影响

不适用：仅补齐现有网页字段校验、格式说明和错误翻译，API、服务端校验及 URL 规范化、资源存储、发布路径、凭据边界和部署拓扑不变。`docs/system-design.md` 和 Doca 系统设计基线无受影响章节，无需改写或同步。

## 验收

隔离 SQLite/真实 HTTP API 和浏览器表单验证：无协议/带路径/查询/片段/凭据地址、空地址/空列表均被拦截，定位且保留输入；纠正后创建与编辑保存成功；覆盖跨集群与应用后端切换、服务端兜底错误及英文。记录生产网页构建和相关回归结果，不声称用户生产环境已更新。
