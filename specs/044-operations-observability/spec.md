# Feature Specification: 运维日志、应用发现与自动监控

**Branch**: `codex/044-operations-observability` | **Created**: 2026-10-30
**Input**: 运维操作记录移至右上日志入口；商店分类；主机/集群查询全部应用及主机非平台 Docker；自动采集应用容器指标、日志和网站 QPS，应用天然拥有监控目录。补充：所有应用指标统一一个独立系统 ClickHouse 表，日志另一个独立系统表。

## User Scenarios & Testing

### US1 运维操作日志按需查看 (P1)
页面只展示资源，右上日志图标打开当前页面范围的操作记录，资源详情也通过图标查看记录。切换页面后范围正确，空状态、刷新、执行结果详情可用。

### US2 按类别找应用 (P1)
商店提供全部、数据库、网站与网关等类别及数量，类别与关键词可组合，安装返回后保留浏览条件；未知类别有可读兜底。

### US3 从主机和集群看运行应用 (P1)
主机入口展示该主机实际实例对应的全部平台应用和全部 Docker（含停止、非平台容器），区分平台归属。集群详情可跳到所属应用，主机和集群筛选可组合。无 Agent、Docker 不可用、过期观测不显示成空且正常。

### US4 天然的应用监控目录 (P1)
创建应用后无需创建大盘即有监控入口，按部署和容器筛选 CPU、内存、网络与磁盘负载及相关网站 QPS，查看自动上传的容器标准输出/错误日志。无数据明确显示等待上报。共享同一指标表、同一日志表；应用数增长不增加物理表。

### US5 系统日志统一存储 (P1)
中心运行、Agent 运行、运维操作、执行任务及主机生命周期事件统一进入现有系统 ClickHouse 日志表。SQLite 继续维护事务状态和可靠投递 outbox，不作为唯一日志存储。历史记录可幂等补录，ClickHouse 失败不能丢失操作日志。

## Requirements
- FR-001: 集群、应用、网站、域名、证书页面没有内嵌操作历史，右上提供可访问日志按钮与抽屉，按页面、资源和集群过滤。
- FR-002: 商店类别与搜索组合筛选，有数量与无匹配状态。
- FR-003: 查询主机/集群下全部应用，根据实际实例和声明部署分别体现运行和配置，实例不能跨主机或集群混入。
- FR-004: Agent 自动发现主机所有 Docker，容器 ID、名称、镜像、状态、端口可查，非平台容器仅发现，不自动接管。
- FR-005: 平台应用容器自动周期上报负载和增量日志，经既有持久队列、重试和中心确认链路；采集失败可见。
- FR-006: 应用遥测使用两个独立共享系统表；应用目录为自动派生视图，无逐应用物理表或人工大盘创建。
- FR-007: 指标与日志有应用、集群、部署实例、主机及容器关联；中心认证 Agent 并核验实例归属，不信任客户端应用归属。
- FR-008: 网站访问产生结构化请求日志与 QPS，按网站和集群查询，容器负载另按部署实例过滤；不把容器网络吞吐冒充 QPS。
- FR-009: 日志游标仅随已持久化批次推进，重启不全量重复，积压分批补传，队列满时不丢失游标。
- FR-011: 全部平台系统事件进入共享系统日志表；运行日志与操作日志使用 component/source 区分，可按资源或执行 ID 查询，秘密与交互终端输出不得进入日志。
- FR-010: 更新仓库与 Doca 架构并回读；保留所有无关段落和原生图块。

## Edge Cases
停止容器、重建容器、新增部署、Docker 无权限/缺失、Agent 离线、容器日志轮转、输出过大、同纳秒多行、队列满、过期遥测、无网站流量、伪造实例归属、用户业务 Key 写系统表。

## Success Criteria
- 四类用户流程可从实际入口完成；页面日志不占正文空间。
- 一个应用跨两集群部署的指标与日志可分别筛选；非平台 Docker 可查但不能被当作平台应用。
- 两个及以上应用的自动遥测仍只有一个指标物理表和一个日志物理表。
- 拒绝业务 Key 写系统表、跨 Agent 伪造归属；日志持久化失败后游标不前进。

## Assumptions
沿用现有 Ant Design 视觉及管理员运维权限。Docker 采集使用宿主默认 Docker 上下文；网站 QPS来自平台 OpenResty 的结构化访问日志。容器自动采集为 gauge 观测，复用 metric 查询链路；网站 QPS 从结构化访问日志按分钟计数计算。通用业务代码内部指标仍由 SDK 打点；不尝试修改用户程序。历史业务遥测表不迁移、不删除。
