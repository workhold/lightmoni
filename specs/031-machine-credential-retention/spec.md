# 031 多机连接凭据保留策略

## 目标与驱动

多台受管主机使用独立 Agent 身份进行日常控制；SSH 服务于首次接入、管理员临时维护和故障恢复。默认只短期保存 SSH 秘密，需要长期恢复通道时由管理员明确选择托管。解决凭据过期后按钮无解释、撤销仍留密文、私钥默认长期保存的问题。

## 需求与验收

1. 新 SSH 私钥默认 `temporary`，默认/最长 1 小时（最短 60 秒）；管理员显式选择 `managed` 且确认长期托管后，默认 90 天、最长 365 天。密码固定 `one_time`，默认 15 分钟、最长 1 小时，不支持长期托管；自动部署仍只允许私钥。手动脚本不存秘密。
2. 撤销、密码使用结束（包括失败/取消）、到期，以及 SSH 安装收到 Agent 激活确认后，清空相关当前数据库记录的 `secret_encrypted`。保存 ID、类型、策略、时间、清除原因和事件等无秘密元数据。Agent 激活只清理此主机所有临时私钥/一次性密码，保留显式托管及历史托管私钥；失败部署在期限内可重试。
3. 启动时、读取/使用前和每 30 秒清理失效秘密；停止时释放定时器。有效期严格限制新操作，清理不得依赖用户打开页面。到期/撤销使终端租约失效，现有终端机制关闭连接。已经进入有界 SSH 执行流程的私钥副本只在该操作内使用，不宣称数据库清理能擦除进程、SQLite WAL/free pages、备份或远端 authorized_keys。
4. 安全迁移：已存在有效托管私钥保留原期限和托管语义，标记为 `legacy` 来源并明确展示；失效历史记录立即清空密文。重启不把新记录重新标成历史托管。不自动改变远端 SSH 密钥。
5. 管理员可添加替代私钥，再撤销旧凭据以轮换；秘密不回显、日志/事件/AI 不包含秘密。密码不生成可用于离线猜测的秘密摘要，迁移清空历史密码指纹；私钥继续使用现有指纹标识。沿用现有 AES-256-GCM 和独立 master.key 文件，不引入 Vault 或改动 Agent control/data 凭据。
6. 前端中英展示策略、期限、秘密是否清除、具体清除原因、Agent 状态与 SSH 恢复通道状态。终端/检查/部署使用后端逐项能力，置灰有原因和添加凭据入口；密码用后、终端关闭和部署结束后刷新，页面定时刷新到期状态。
7. 旧 API 不提交策略时使用新的临时默认；明确选择 managed 需 `confirm_managed: true`。越界期限、密码长期保存、无确认托管均拒绝，不静默改变管理员意图。旧 UI 已显式传入大于 1 小时的私钥期限时应返回可理解的策略提示。

## 范围

只开发和隔离验收，不修改线上主机、线上凭据或已安装 Agent，不自动部署或发布镜像，不新增 Agent 任意命令/模型能力。
