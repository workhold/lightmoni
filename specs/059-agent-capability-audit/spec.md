# SDD059：Agent 能力与维护链路验收

## 目标

核对真实受管主机上的 Agent 采集结果、任务执行与维护能力，修复导致错误结果的实现缺陷。验收对象为已授权的 vchive；不修改业务服务，不自动扩大 Agent 的系统权限。

## 需求与验收

1. 以操作系统只读数据为基准，核对主机名称/身份、CPU、内存、运行时长、磁盘及网络。区分用户主机名、系统 hostname、平台主机 ID 与遥测 host_id。
2. 通过任务中心下发一次性有界只读脚本，核对执行用户、读取结果与执行回执；不得读取密码、私钥、环境秘密或业务文件正文。
3. 核对更新、主动回退、标准卸载、恢复卸载、离线卸载和重新接入。只有实机执行过的状态才标记为实测；没有不同发行或上一发行时，明确限制并验证拒绝行为。
4. 平台 SSH 探测和远端维护器必须对同一安装得到相同指纹，覆盖卸载 helper 存在/缺失及 helper 内容变化，避免把正常安装误判为变化。
   远端已有的 `uninstaller_updated` 可选布尔回执必须保留到平台，包括明确的 `false`；不得误报卸载器已更新。
5. 进程采集的多个匹配条件独立统计；权限不够导致字段读取失败时，不得把不完整结果标为完整成功。
6. 明确区分代码实现支持、当前主机权限可用、未配置和未实现。Docker/systemd 管理不能用 root SSH 的成功代替 Agent 用户验收，也不为测试授予 root 或 Docker 组权限。
7. 验收结束时恢复 vchive Agent 在线，保留无秘密证据；测试脚本、临时任务定义及会话及时清理。

## 架构影响

本次修复保持既有身份、凭据边界、平台—Agent 协议、存储和 systemd 部署拓扑，只纠正既有安装指纹与采集统计实现。架构同步不适用；若后续引入权限代理或改变运行账户，必须另行设计并同步仓库系统设计与 Doca。
