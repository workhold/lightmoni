# SDD 186 设计

在现有升级和卸载计划中增加可选的 `force_unknown` 和 `force_reason`。维护准备时，从中心当前栅栏提取最多 32 条未解决的 `unknown` 阻塞项。仅当所有需要忽略的项均为 `unknown`，且 SSH 探测确认远端空闲时，才将 `{kind,id,state}` 固定到计划。计划和执行使用同一份精确列表过滤历史未知项。过滤只影响 Agent 升级/卸载的维护入口，不修改任务状态或普通作业的执行栅栏。

执行前再次验证管理员交互会话、主机绑定、SSH 凭据、计划有效期、固定阻塞项的当前状态、没有新增阻塞项及远端锁。沿用原有发行包签名、指纹、回滚、卸载归属和凭据撤销验证。计划审阅中明确展示忽略项和原因。

架构影响：变更 Agent 生命周期控制路径中的中心任务栅栏，见 `docs/system-design.md` Agent 生命周期章节。凭据边界和远端脚本保持不变。
