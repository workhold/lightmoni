# 发布与部署设计

1. 固定合并后 `main` SHA，复核三个 PR 的合并状态、重叠处理和本地集成检查。用 `git archive` 导出源码，排除工作区及凭据。
2. 使用仓库 `deploy/server/Dockerfile` 和现有校验边界构建双架构新固定标签；先在隔离环境验证并远端回读，再更新 `latest`。不覆盖同名不同内容的固定标签。
3. 建立 SDD163 发布分支，仅改根 Compose 的镜像固定标签及发布证据；从最新 `origin/main` 创建面向 `main` 的 GitHub PR。PR 合入与 GitHub Release 另行回读；Release 指向构建源码提交，而非发布配置提交。
4. 在 1Panel 原项目回读当前容器、镜像、Compose、数据卷和任务状态；在服务器 root 私有目录备份配置、主密钥与 SQLite 一致快照。确认新旧镜像与回滚版本可用，拉取固定标签，仅重建中心。根 Compose 的本地校验不代替生产现场配置核对。
5. 验证健康、登录、首页、应用中心与主机心跳；按现有 Agent 更新流程逐台处理安全可升级主机，遇到未知执行或忙状态保持原状并记录。
6. 以线上只读页面和 API 回读状态与控制门禁。记录执行时间、版本、摘要、结果及未覆盖边界；不清除未知执行或改动业务实例。
