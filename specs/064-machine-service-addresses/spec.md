# 机器地址统一来源与本机镜像复用

2026-11-01。用户要求仓库按普通应用部署：不填写内网IP，地址由主机管理提供；开启内网缓存后，其他机器使用Agent识别的服务私网IP和端口；同机有镜像直接复用，没有才访问缓存仓库。SSH连接域名不代表服务地址。

验收：
0. 所有受管机器的服务私网/公网地址统一来自主机管理：现代集群容量/服务发现、网站网关与DNS、仓库和缓存，以及兼容旧node_pool/gateway_group路径。集群表单只显示主机管理地址，不再另填IP；SSH域名只用于连接。取址优先物理/覆盖网络IPv4，再IPv6；不使用平台观测来源IP或容器桥地址。旧地址字段不再覆盖有主机管理身份的机器。
1. 系统仓库只需集群、机器、通用端口/资源和缓存开关；取消手工地址与网络确认项。SSH域名或公网节点地址不阻止安装。
2. 从主机管理当前Agent所属网卡快照选择真实私网地址；跳过Docker/容器桥、veth和loopback，不从SSH目标或平台观测来源IP猜测。未发现可供其他机器使用的地址时仍可部署在loopback，同机缓存可用，其他机器走原镜像源；不得向其他机器下发该loopback端点。
3. 端点使用实际实例绑定IP与分配端口。主机管理地址与集群路由/SSH地址解耦；改节点域名不要求迁移仓库，仓库数据仍固定原机器。历史已登记地址和旧API在无新网卡快照时兼容。
4. Agent先检查Docker中所需引用、平台和digest，有则固定本地image ID、禁止Compose再次拉取；不存在才从缓存仓库下载，缓存失败沿用原回源策略。相同内容换了仓库名称时，依据本地RepoDigest或config身份复用，不能仅因tag相同替换不同digest。
5. Registry持久目录与Docker镜像库保持各自格式，不共用数据目录或改Docker全局daemon配置。公网仍使用已有HTTPS入口；自动地址不产生匿名公网旁路。
6. 定向HTTP/SQLite/Agent载荷、模拟与真实Docker验证本地命中0远程请求/缺失缓存路径、跨机器loopback隔离和域名节点部署；三轮浏览器验证无IP字段、端口/刷新/失败保留及现有入口。

架构影响：适用，机器服务/DNS/仓库地址统一为主机管理的网卡快照，缓存策略按消费机器投影；Agent增加本地镜像优先和内容复用路径。同步docs/system-design.md和Doca基线，保留原生图与无关内容并回读。无新增表、凭据或共享Docker/Registry目录。
