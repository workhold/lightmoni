# 主机与节点统一管理

## 目标与术语

主机是机器资产；主机或容器安装并接入 LightMoni Agent 后具备节点能力。节点通过平台控制通道执行监控任务和已支持的固定运维操作，AI 助手复用平台受授权工具，无需为日常操作依赖 SSH。SSH 用于初次安装、身份核对、卸载及离线恢复。周期采集和拨测已支持；通用定时脚本调度、任意 shell 及 Agent 自卸载不在本轮范围。

## 需求

1. 左侧统一“主机与节点”入口，保留功能分类抽屉。页面集中展示主机/节点、监控任务及任务标签；已有 `/machines`、`/agents` 链接和任务查询参数保持可用。
2. 展示仅登记主机、独立接入 Agent、已关联主机与 Agent 三种情况。已关联对象不在统一列表重复，既有 Agent 不要求配置 SSH；不按 IP、主机名自动合并。
3. 监控与运维能力如实展示：Agent 通道负责已支持任务与 AI 工具，SSH 恢复通道独立判断；不把未安装 Agent 的主机称为在线节点。
4. 节点提供“移除节点”确认：原子撤销该身份 control/data 凭据并归档，保留节点身份、凭据墓碑、历史数据和审计。未结束/结果未知任务或卸载流程阻止移除；不宣称远端程序已卸载，不撤销共享 SDK Key。旧鉴权不能绕过移除，后续心跳不能复活已移除节点。
5. 已移除节点可在历史视图查看，重新接入使用新 enrollment 身份，不提供恢复旧秘密。旧版共享 Key 节点需先迁移独立凭据才能走完整移除流程，界面给出原因。
6. “卸载 Agent”复用已有受审阅 SSH 流程。无关联主机或有效 SSH 私钥时明确给出添加连接/身份核验或手动卸载指引，不隐式执行任意命令。
7. 独立安装节点可经管理员显式只读 SSH 身份核验后关联主机；核对 Agent ID、标准受管服务、有效连接、主机目标版本与已有绑定，不能仅凭用户提交的 Agent ID 建立可信关联。
8. 删除主机仍是平台连接记录清理，与移除节点、卸载程序分开。所有删除/移除入口位于列表操作区并二次确认；保留 PR14 的失败提示和异步防重/隔离。
9. 普通成员保留查看节点/任务能力，不请求或展示管理员主机地址、连接凭据或生命周期操作。新增写入均管理员限定。
10. 本地隔离数据目录启动，创建清楚标识的演示主机与节点；不使用线上凭据、不操作 vchive 或生产平台。提供可持续打开的本地界面供用户体验。
11. 自动安装默认采用宿主机独立 systemd 服务，与业务生命周期分开。独立 Agent 容器、Kubernetes DaemonSet 和业务 sidecar 为后续形态；只有 sidecar 需要在部署业务时显式加入配置，本轮不注入业务容器。容器节点能力受其真实执行权限限制，SDK 始终可独立直报中心。
