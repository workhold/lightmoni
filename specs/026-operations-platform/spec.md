# SDD 026：网站、容器、备份与计划任务

日期：2026-10-27。状态：主体实现与分层验证完成，交付收尾中；最新补丁的最终验证、Doca 同步和 GitHub PR 仍待核对。授权：用户要求完成运维扩展的前两批。

## 驱动目标

让个人与小团队在同一平台完成“登记资源 → 审阅方案 → 管理员批准 → 节点执行 → 现场验证 → 追溯/恢复”。第一批为网站、证书和容器运维；第二批为目录备份、安全恢复及固定动作计划任务。配置保存、命令返回和模型文字均不能代替真实验证。

## 用户场景与验收

### US1 网站与证书（P1）

管理员选择节点，登记小型静态站或已有服务的反向代理，设置域名、端口和可选证书，审阅并确认后查看真实访问结果、日志及历史版本。上传证书或以 ACME HTTP 验证申请、续期证书。错误候选不得替换已验证配置；共享证书引用须保护域名匹配；网站与业务服务独立启停；续期失败有记录。公网 CA 验收尚未完成，不能显示为已验证能力。

### US2 容器与 Compose（P1）

管理员先登记受限 JSON Compose 项目，再发现/检查节点现状；外部项目只有经过准确清单与重建确认才能接管。启动、停止、重启、更新和配置回退均绑定观察到的 generation。发现不授予写权限，停止和回退不删除卷；部分失败显示 unknown，不自动重放或承诺数据迁移可逆。

### US3 备份与恢复（P1）

管理员为 root 受管普通文件目录设置本地或 S3 兼容目标，创建、校验、清理和恢复备份。显示归档摘要、源摘要及对象版本；拒绝损坏清单、越界、链接和特殊文件。恢复必须使用当前目标摘要进行 CAS，并先保存恢复前副本，替换后再次校验。常规清理不得删除恢复前副本。数据库在线一致性、存储端加密和云供应商生产验收不在已验证范围。

### US4 计划任务（P1）

管理员对已登记资源的固定动作、输入与版本进行持续授权，设置五字段 Cron 和 IANA 时区，查看历史、停用或人工运行。相同 UTC 分钟只触发一次；跳过中心停机错过的分钟；单计划不重叠；目标版本改变、授权者降权/停用和 unknown 时停止，重新授权不重放历史任务。

### US5 AI 与界面统一（P1）

管理员可以在同一界面完成全部资源配置、动作预览、批准与回执检查；中英文和深浅主题均可用。AI 仅能读取资源摘要、读取有界回执、生成方案，不能批准或执行。大站点正文不能导致已创建方案丢失审阅链接；敏感业务日志整段不送模型，列表缩短时明确给出续页/截断信息。

## 功能要求

- FR001：资源绑定节点身份、配置 revision 与归属，配置、方案、授权和历史持久保存；配置修改不自动执行。
- FR002：每次人工动作使用独立方案与批准；绑定资源版本、精确输入和有效期，重复批准幂等入队。固定动作计划以管理员启用作为持续授权，不能由 AI 代为启用。
- FR003：复用 Agent control 身份、job 租约、序号与回执；成功依赖匹配 operation/resource 的现场证据，失联或中断保留 unknown。
- FR004：资源配置、不可变任务载荷与计划输入加密落库；私钥和 S3 秘密不出现在公开 GET、明文 job 动作、模型上下文或平台错误输出。私有载荷仅供匹配节点的有效任务租约读取。
- FR005：执行器只接受列举的领域动作与结构化参数，不开放任意 shell；受管目录、权限、归属、路径和输出均受限。
- FR006：网站使用独占 Nginx 配置与端口、语法检查、现场配置证明和版本恢复；不改写已有 1Panel/其他 Nginx。静态站限定为最多 200 个文本文件、512 KiB 文本和 900 KiB 序列化配置。
- FR007：证书校验公私钥、域名及有效期；更换共享证书保护现有绑定站点的域名与真实 TLS 状态，失败恢复旧证书。ACME HTTP 前置条件明确，续期需显式操作或计划。
- FR008：Compose 检查固定镜像、项目归属和 generation；外部接管绑定 inventory 摘要与重建确认。用户不可配置 build、宿主 bind、docker.sock、privileged、host 网络或 external 存储。配置回退不恢复卷数据。
- FR009：备份有文件数/字节限制、逐文件与清单摘要；本地与来源不重叠，S3 按 bucket/prefix/resource 隔离。恢复先备份、校验当前目标摘要、暂存校验、原子替换和现场复验；常规保留不清理恢复前副本。
- FR010：计划支持五字段 Cron、IANA 时区、UTC 分钟持久去重、不补跑和单计划不重叠。资源 revision 或授权者状态变化立即使授权失效，unknown 须人工核实后重新授权。
- FR011：“运维工具”入口支持网站、证书、Compose、备份、计划任务，中英文、深浅主题和明确的配置/审批/执行状态。网站与 Compose 可关联既有业务服务，关联不赋予源码构建或跨节点发布能力。
- FR012：同一节点 dataDir 的运维写动作采用持久互斥；unknown 或崩溃保留锁，管理员核实进程、daemon 和现场状态后人工解除，禁止仅按 PID/超时自动回收。锁期间仍可检查只读状态；禁止克隆同一 Agent 身份到多个 dataDir 绕过互斥。
- FR013：Docker 固定节点本机 default context，不继承环境变量或用户配置选择的远端 daemon。依赖缺失、权限不足和输出超限不得伪报成功。
- FR014：资源和回执有明确输出上限及截断标识；AI 不转发网站/Compose 正文，分页不漏项，方案成功持久化后返回轻量 ID、状态及审阅链接。

## 成功标准与验收状态

五个场景都有明确的用户入口、权限和结果标准；领域、中心和调度已有自动验证，网站/Compose 已有真实 Linux 验收。本地备份已执行真实文件恢复，S3 只有独立验签 HTTP 夹具，网页交互只在隔离模拟后端验证。公网 ACME、真实 S3 厂商、生产并发与大容量尚未验收，不纳入已完成声明。

每个变更须可追溯到资源、版本、节点、管理员或持续授权计划、动作和回执。最新定向检查、Doca 最新版本回读、远端主干同步和待审 PR 仍是交付条件，详见 [任务](tasks.md) 与 [验证记录](validation.md)。

## 假设、依赖与边界

首期面向 Linux 受信主机，Agent 独立运行。管理员按启用能力准备 Nginx、OpenSSL、Certbot、Docker 与 Compose plugin；平台不静默安装这些依赖。SDK 默认直报中心，不以安装 Agent 为前提。备份目录必须由 root 管理、不可被业务用户写入，系统 sticky 临时祖先例外；不支持不受信进程同时修改源目录。备份内容可能含业务秘密，归档本身没有内容筛除或加密承诺，管理员需保护本地目录和云存储权限。

不覆盖数据库一致性备份、Kubernetes、应用商店、WAF、DNS challenge、通配符证书、任意脚本、任意 YAML、源码自动构建、跨节点滚动发布或数据库迁移自动回滚。原 systemd 部署和人工 SSH 功能保持既有边界。
