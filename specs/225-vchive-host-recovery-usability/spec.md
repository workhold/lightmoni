# 225 · vchive 主机恢复与执行权限可用性

## 背景

`vchive` 的 Docker 安装记录停留在 unknown，阻塞终端、SSH 检查、Agent 生命周期和 AI 主机读取。0.1.32 已恢复“操作目录不存在”和“status 文件缺失”两类证据，但父目录不存在时仍会先 stat 父目录并退回通用 unknown。执行权限页还会把同一主机的历史 Agent 身份计划当作当前记录校验，导致“运行模式记录格式无效”。AI 工具仍返回近乎完整 UI 主机投影，容易耗尽上下文。

## 需求

1. 只读 Docker 核对在安装根目录或操作目录不存在时，必须稳定产出 `docker_install_not_started`，不再依赖父目录已存在。
2. 根目录或操作目录是符号链接、权限/属主不符合固定要求时，必须产出失败证据 `docker_install_evidence_untrusted`，不能跟随不可信路径，也不能永久阻塞主机。
3. Agent 权限模式历史只展示当前 `agent_id` 的记录；Agent 重装后旧身份计划不得造成当前面板失败。
4. “打开主机执行权限”必须直达主机详情的 Agent 与权限页，而不是只打开概览。
5. `list_managed_machines` 和 `get_managed_machine` 返回有界、可操作的核心主机投影，不得返回账户全量、最近 SSH 检查明细、主机公钥或完整网络接口列表；密码、私钥和指纹继续不可暴露。
6. 不自动重放安装、升级或恢复；失败证据只解除未知阻塞，实际修复仍按现有审阅流程执行。

## 非目标

不改变 SSH 安装命令、Docker 安装脚本、Agent 审批边界或自动修复策略。
