# 证书查看下载与 ACME 失效订单诊断

日期：2026-10-31。用户提供证书日志截图：恢复已有订单后，读取返回 invalid，但只展示 `acme_order_invalid / ACME order is invalid`，同一步先成功后失败，仍无法判断原因。

后续确认：新建订单已成功申请；补充管理员查看和下载已签发证书。用户明确选择下载证书 PEM、证书链和私钥。

交付沿用用户已授权的 Git/main 与 Docker 发布：功能分支经 GitHub PR 合入 main，从合入提交导出干净构建上下文，双平台隔离验证后发布固定标签与 latest，回读摘要并更新默认 Compose/发布记录。无直接 main 推送，不自动升级既有实例。

## 验收

1. 读取到 invalid 订单时先将本地订单标记 invalid，不再将其用于后续人工申请；本轮不得自动创建新订单。下一次明确人工申请可创建新订单，未知写入结果的既有保护不变。
2. 优先保留订单 problem detail；订单缺少原因时，用现有 ACME 客户端只读获取 authorizations，提取失败挑战的 problem detail/type/status 和已配置域名。支持有界的 subproblems，不序列化完整响应。
3. CA 不提供原因或诊断读取失败时明确说明原因不可用和人工下一步，不推断为 DNS 问题；辅助读取/清理失败不能覆盖已确认的订单失效或已有 CA 原因。
4. 单次订单读取返回 invalid 时只记录失败，不能先记录同一次读取成功。恢复本地订单的步骤有明确结束状态。
5. 日志、回执和资源状态继续脱敏、限长；账户/云凭据、私钥、CSR、挑战 token/TXT 值、Authorization 和 URL 查询不能进入公开诊断。多域名选择、其他挑战类型与嵌套 problem 都按同一边界处理。
6. ACME、上传、自签的已保存版本均提供“查看 / 下载”：显示实际版本的域名、主体、签发者、有效期、指纹和公开 PEM；支持下载 cert.pem、chain.pem、fullchain.pem、privkey.pem。没有中间链时说明并禁用链下载。续期失败保留的旧版本仍可查看。
7. 查看与下载只面向当前有效管理员，按证书与不可变版本精确查询。私钥只在独立 POST 下载动作按需返回，不进入查看 JSON、DOM、日志、普通资源或 AI/工具；下载响应 no-store、附件文件名安全。旧版本查看后的下载仍使用同一版本，不受新签发切换影响。
8. 未签发、缺失版本、错误资源类型、越权、非法下载类型均明确拒绝；加载失败可重试。抽屉关闭/切换资源取消旧请求，下载失败保留当前查看内容。兼容桌面/窄屏、中文/英文、明暗主题。

## 架构影响

适用：新增管理员浏览器按需读取公开证书、显式导出私钥的数据路径与凭据边界。复用既有加密不可变版本表、管理员会话和中心解密，不新增存储或外部服务。同步 docs/system-design.md §33.5/§33.6 与 Doca 基线；保留原生图块与无关内容，写后回读确认。失效订单诊断本身不改变架构。
