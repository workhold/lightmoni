# Agent 安装与网站部署权限

日期：2026-11-01。沿用 PR #58 的 `codex/070-docker-low-port-preflight` 分支，与 SDD 070 一同交付。

## 需求

用户要求安装后的 Agent 自带部署所需权限，网站配置下发也应核对完整路径，不能等部署失败后再手工补组、目录或低端口权限。

- 标准服务继续使用 `lightmoni-agent` 用户，自动获得本机标准 Docker socket 的服务附加组和 `CAP_NET_BIND_SERVICE`；声明受管私有目录及独立公开网站目录的写入范围。
- 安装与升级在启动服务前准备 Docker 组及公开目录；Docker 尚未安装时也可安装监控 Agent，后续安装标准 Docker 不再要求手工补组或重新安装 Agent。
- 每次服务启动以实际服务用户、附加组、capability 和挂载沙箱执行权限检查，验证私有配置可读、私有/公开目录的写入与原子切换、低端口绑定权限。存在 Docker socket 时确认服务用户可访问；缺少 CLI/daemon 属于依赖未就绪，不能伪造可部署成功。
- 网站配置、PID、日志、Nginx 临时文件和证书私钥位于受管私有目录；静态资源使用独立公开目录。配置校验、下发、重载、TLS 证书轮换、失败恢复和旧版本恢复必须经真实普通用户执行验证。
- 新安装、已有 Agent 升级、启动失败自动恢复及主动回退都覆盖权限配置；配置、身份、队列不清空。已有未迁移版本保持其原 unit 和协议。
- Docker 管理权限实际接近宿主 root，标准部署授权明确包含此影响。普通脚本会继承 Agent 的实际服务权限；本次不声称提供脚本沙箱或实现 Doca 中规划的 SDD 060 独立执行器。

## 架构影响

适用：改变标准 Agent 服务的附加组、Linux capability 和可写路径，新增安装/升级准备及启动前实际权限检查。同步 `docs/system-design.md` 第 71 节、部署指南与 Doca 系统设计基线；保留全部原生图块和无关内容，写后回读新增章节、节点与连线。在线规划的独立特权执行器保持独立，不以本次普通 Agent 权限配置冒称已迁移。
