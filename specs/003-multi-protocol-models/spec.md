# Feature Specification: 主流模型协议与清晰的模型获取入口
**Feature Branch**: Existing branch (preserve ongoing work)
**Created**: 2026-10-14
**Status**: Ready for implementation
**Input**: 用户在旧标签表单中看不到自动获取模型，并要求支持市面主流协议；服务地址 https://cn.huayanapi.com:27502/v1。

## User Scenarios & Testing
### User Story 1 - 看得见的获取模型入口 (Priority: P1)
管理员可在地址和密钥旁看到独立的获取模型按钮，输入稳定后仍会自动查询；模型支持列表选择和手动输入。
**Why this priority**: 小链接不够明显，旧页面仍驻留使用户无法使用新增能力。
**Independent Test**: 打开新版设置，按钮可见；授权失败提示检查密钥，成功目录可选择，手动名称保留。
**Acceptance Scenarios**:
1. **Given** 新版设置，**When** 填写地址及有效密钥或无密钥服务，**Then** 自动展示目录并提供独立刷新按钮。
2. **Given** 目录需要鉴权，**When** 查询返回认证失败，**Then** 明确提示需要有效密钥，不将失败误报为无模型。
3. **Given** 旧标签有未保存输入，**When** 交付新版，**Then** 保留旧表单并在新标签展示新版，避免丢失用户输入。

### User Story 2 - 使用四种主流协议 (Priority: P1)
管理员可选择 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 或 Gemini 原生协议，实际聊天、工具调用与历史整理使用所选协议。
**Why this priority**: 单一兼容协议无法覆盖原生模型供应商及代理网关。
**Independent Test**: 各协议受控服务上真实运行助手，验证文本、工具后续回答、历史、用量及取消。
**Acceptance Scenarios**:
1. **Given** 选择任一支持协议并保存，**When** 对话发起，**Then** 请求对应原生接口并正确处理流式与工具结果。
2. **Given** 旧配置未保存协议，**When** 升级读取，**Then** 继续采用 OpenAI Chat Completions。
3. **Given** 同一地址切换协议，**When** 原密钥有效，**Then** 可以复用；地址变化仍必须新密钥或明确清除。

### User Story 3 - 有依据的自动推荐与人工选择 (Priority: P2)
管理员选择自动识别时，系统根据官方地址、完整接口路径及成功的协议 profile 推荐协议；目录返回格式只用于解析模型，无法证明调用协议的共享网关提供候选并要求明确选择。
**Why this priority**: 自动化应减少工作且保持判断诚实。
**Independent Test**: 官方地址/完整路径和原生目录能得到对应建议；OpenAI共享目录给出Chat和Responses候选，不误称已验证调用能力。
**Acceptance Scenarios**:
1. **Given** 原生服务或完整接口地址，**When** 自动查询，**Then** 返回可解释的协议建议。
2. **Given** 未知网关提供 OpenAI 风格目录，**When** 获取成功，**Then** 显示无法仅凭目录区分 Chat/Responses，管理员选择后保存。
3. **Given** 无目录，**When** 管理员手动指定协议及模型，**Then** 仍可保存使用。

### User Story 4 - 主流地址自动修正与配置验证 (Priority: P1)
管理员只需提供服务地址和密钥，系统可在同一服务地址下尝试常见目录路径并回填实际可用的规范地址；管理员选择具体协议和模型后，可以主动验证一次真实模型请求。
**Why this priority**: 目录探测应减少常见 `/v1`、接口后缀和末尾斜杠造成的配置摩擦，但不能把目录访问误报为生成能力。
**Independent Test**: 根地址在 `/v1/models` 可用时被回填为 `/v1`；手动协议不跨协议探测；具体协议和模型的测试请求不创建会话、不保存配置并隐藏供应商错误正文。
**Acceptance Scenarios**:
1. **Given** 根地址的 `/models` 不存在且同源 `/v1/models` 可访问，**When** 管理员使用新密钥获取模型，**Then** 系统返回 `/v1` 规范地址和模型列表。
2. **Given** 管理员已选择具体协议，**When** 获取模型，**Then** 只使用该协议的鉴权和目录规则，不猜测其他协议。
3. **Given** 目录不可用，**When** 管理员填写模型名称，**Then** 仍可保存；保存不假装已验证模型能力。
4. **Given** 已选择具体协议和模型，**When** 管理员点击测试连接，**Then** 系统发送一次最小真实生成请求，成功只返回状态和耗时，失败不返回供应商密钥或原始响应。

### Edge Cases
- 快速切换地址、密钥、协议与清除选项时，旧请求取消、旧建议不能覆盖新状态。
- 不支持的协议、非法URL、成员用户、超大输入在联系供应商前被拒绝。
- 自动修正只改变可证明的路径/后缀候选；域名、密钥和模型错误不得静默修改。
- 测试连接可能产生供应商费用，不能由模型目录刷新或地址自动查询隐式触发。
- 密钥不进入浏览器响应、日志、命令参数或错误正文；不跟随重定向，不自动发送聊天探测产生用量。
- 有界目录、空列表、分页继续标记、Gemini embedding-only模型、缓存/思考用量缺失、生成错误和取消均有准确结果。

## Requirements
### Functional Requirements
- **FR-001**: 设置有独立可见的获取/刷新模型按钮，同时保留自动查询及手动模型输入。
- **FR-002**: 四种协议有实际运行支持，含流式、工具、历史、整理、用量和取消；未知协议明确拒绝。
- **FR-003**: 自动推荐有来源标记；模型目录成功不等于调用/工具能力验证；模糊共享目录要求选择具体协议后保存。
- **FR-004**: 存储具体协议；旧配置缺省 Chat Completions；发现查询不写配置、不发聊天。
- **FR-005**: 目录使用各协议鉴权和格式，模型名称去重排序并限500；原生目录分页剩余标记截断。
- **FR-006**: 复用旧密钥限完整规范API基地址匹配；原地址切换协议允许复用，地址变化不得静默复用。
- **FR-007**: 所有探测同源、有界、禁止重定向；最多6次请求、总8秒、每响应1MiB。旧密钥不得用于根地址版本路径回退。
- **FR-008**: 旧标签未保存输入保留，新版另开，提供明确入口。
- **FR-009**: 用量适配各协议原始字段；缺失字段未知，不冒充零；预算仍由管理员配置。
- **FR-010**: 必须有各协议实际SDK运行和安全边界测试；不以目录测试冒充对话验证。
- **FR-011**: 原生协议历史需要的签名及加密状态应被有界保留和重放，不保留或向浏览器展示隐藏推理正文。
- **FR-012**: 自动识别按候选基址顺序探测常见 `/models`、`/v1/models` 或 Google `/v1beta/models`，成功后返回实际规范 Base URL；具体协议模式只探测所选协议。
- **FR-013**: 管理员可调用独立的测试连接接口；接口要求具体协议和模型，使用真实运行时发送最小请求，不保存配置、不创建会话、不返回生成正文，并将超时、网络和供应商错误映射为安全错误。

### Key Entities
- 连接配置：地址、具体协议、模型、加密密钥、执行预算。
- 目录识别：规范地址、建议协议、候选协议、依据、是否需选择、能力未验证、模型列表、截断标记。
- 查询状态：包含协议输入的有界生命周期，编辑和关闭均失效。

## Success Criteria
### Measurable Outcomes
- **SC-001**: 四种协议受控服务均完成流式回答、一次工具后继续回答，保持会话历史和取消。
- **SC-002**: 用户不需要寻找小链接即可获取模型；401提示明确检查有效Key；手动模型始终保留。
- **SC-003**: 所有查询最多6个同源请求、8秒、500个模型；非管理员和跨地址旧密钥请求联系远端次数为零。
- **SC-004**: 共享目录模糊协议不会作为自动验证成功保存；手动选择协议后能保存。
- **SC-005**: 旧配置和旧标签输入均保留；实际协议和用量证据由受控测试覆盖。

## Assumptions
- 四种文本/工具协议覆盖主要原生模型与 OpenAI兼容国产/本地服务；Azure/Bedrock/Vertex专有鉴权不属于本次。
- 模型目录只能推荐协议，不自动发付费生成请求确认；模型名称不用于推断协议。
- 测试连接是明确的用户动作，可能产生少量费用；模型目录刷新仍然是只读 GET。
- 用户给出的服务目录无Key探测返回401，尚未验证该网关支持的生成协议。
