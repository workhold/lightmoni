# Protocol contract

## Configuration
Config.protocol is one of openai-chat-completions | openai-responses | anthropic-messages | google-generative-ai. Omitted/blank on old input means Chat; auto/unknown rejected400 before persistence. Config.reasoning_effort is provider-default | none | minimal | low | medium | high | xhigh; omitted/blank means provider-default and is not sent as an extra provider parameter. ConfigView returns stored concrete protocol and reasoning effort. Changing only protocol on exact canonical base may keep saved key. Changed base still new key or clear_key required.
Canonical URL retains escaped tenant paths and current validation; additionally strip terminal /responses, /messages, and Gemini /models/{id}:generateContent or :streamGenerateContent, along with existing /chat/completions and /models. Model field remains independent; do not infer protocol from name.

### Discovery matrix and address repair
`protocol=auto` probes a URL hint first, otherwise profiles in OpenAI-compatible, Anthropic and Google order. Protocol policies own supported conventional versions, version repair, root candidates, catalog authentication and query parameters. Root completion prefers `/v1` across protocols; only Gemini has a `/v1beta` fallback before the unversioned root. A 401/403 remains an authentication result when candidates fail; 429, server errors, redirects and timeouts do not trigger blind fallback. The response `base_url` is the candidate that actually served the directory.

Protocol-specific normalization is distinct from canonical URL identity. OpenAI Chat/Responses and Anthropic replace only a literal terminal `/v1beta` segment with `/v1`, preserving preceding escaped bytes and tenant prefixes. Gemini preserves explicitly supplied `/v1` and `/v1beta`. Arbitrary custom prefixes/versions remain untouched. Discovery normalizes each attempted profile before contacting the provider; shared catalogs on an incompatible beta path cannot override the protocol rule. Test-connection and config PUT apply the same normalization. Saved keys remain tied to the actual stored canonical destination: a repair that would move the secret to a different base requires a new key/clear; no normalization is applied to the stored identity to bypass that comparison. Existing stored configurations are not silently migrated. Endpoint extraction occurs once per submitted URL; stored canonical bases use URL identity normalization without a second suffix extraction, preserving tenant segments named `messages`, `models` or `responses`.

The repair scope is deliberately bounded: trim slashes and known generation/catalog suffixes, preserve tenant paths, and try the standard version suffix. It does not guess arbitrary vendor prefixes, domains, keys or model names. A directory success proves only catalog access; it does not prove generation, tool use or model context limits.

## POST /api/v1/assistant/test-connection
Admin-only, strict 16KiB JSON input:
```json
{"base_url":"https://example.com/v1","api_key":"optional","use_saved_key":false,"protocol":"openai-chat-completions","model":"model-id","reasoning_effort":"provider-default"}
```
`protocol` must be concrete and `model` non-empty. `reasoning_effort` is optional and uses the same provider-default | none | minimal | low | medium | high | xhigh enum as configuration; omitted or blank follows the provider default. The endpoint applies the same canonical URL and saved-key address checks as configuration/discovery, then invokes the existing Mastra runtime with no tools, a fixed short prompt, `max_input_tokens=4096`, `max_output_tokens=256`, and a short timeout. Runtime frames and model text are discarded; no session or configuration is written.

Success returns `{ "ok": true, "base_url": "...", "protocol": "...", "model": "...", "latency_ms": 123 }`. Invalid input or saved-key mismatch is 400, timeout is 504, and network/provider/runtime failure is a generic 502. Provider response bodies, API keys and generated text never appear in the response.

## Runtime
OpenAI Chat /chat/completions via existing SDK; Responses /responses via createOpenAI.responses; Anthropic /messages via createAnthropic; Gemini /models/{model}:streamGenerateContent?alt=sse via createGoogleGenerativeAI. Custom base/version prefixes preserved, Gemini model IDs tolerate single models/ prefix. Native packages pinned to matching model-provider interface.
All share Mastra/tool authority/budgets/history/cancel. Responses stateless store:false. `reasoning_effort` is passed through the AI SDK `reasoning` model setting when concrete; provider adapters map it to native fields where supported. `provider-default` leaves the request unchanged. Unsupported model/provider combinations may return a sanitized provider error; they do not silently claim the requested level was applied. Raw usage fields mapped per protocol including Anthropic additive cache input and Gemini output thoughts; missing raw fields stay unknown. Model errors fixed codes/no SDK error echo.

Auto recommendation displays source and caveat; ambiguous OpenAI directory requires choosing Chat or Responses before save. The model field explains whether a directory list is available and keeps manual entry. Execution limits include a reasoning-effort selector labelled as best effort: 跟随模型, 关闭, 最小, 低, 中, 高, 极高.
Successful address repair updates the Base URL field to the returned canonical value. An adjacent persistent notice shows the submitted address, corrected address and the applicable reason (version-path completion, endpoint-to-base extraction, trailing-slash/whitespace cleanup or other URL normalization). No notice is shown for an unchanged address. Refreshing the same connection preserves the notice without a feedback query; editing connection information or loading/resetting configuration clears it. Failed, cancelled and stale discovery results cannot change the field or resurrect a notice. Protocol and model fields are never changed by address repair; subsequent test/save actions use the corrected field value. A test response that corrects the URL adopts it with the same notice and cancels older directory work. Automatic endpoint-based detection retains its original URL evidence for same-connection refresh; editing connection information clears that evidence.

## Native durable metadata
Neutral ToolCall may carry `provider_options:Record<string,Record<string,string>>`; Message may carry `provider_state:{type:"reasoning"|"text",text?:string,provider_options:Record<string,Record<string,string>>}[]`. Allowlisted keys are `google.thoughtSignature` and `openai.itemId` / `openai.reasoningEncryptedContent` only. A text record retains the original visible answer slice to associate its signature with that exact native part; reasoning records may not carry text. Runtime reconstructs SDK providerOptions and native parts when replaying. Persist only ciphertext/signatures/item IDs plus already-public answer slices, never hidden plaintext reasoning. Go stores and passes through bounded allowlisted state, but excludes provider_state/provider_options from browser-facing session responses. Each opaque string≤256KiB, aggregate encoded provider metadata≤1MiB per checkpoint and resulting stored history, with existing2MiB session/NDJSON limits. Metadata contributes to history/context limits; oversized state is an explicit failure, not silent dropping. Fixtures verify Gemini text/tool signatures and Responses ciphertext across a second fresh worker.
