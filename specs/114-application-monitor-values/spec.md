# 应用监控数值展示

日期：2026-11-09；分支：codex/114-application-monitor-values。

## 问题与目标

应用监控的 CPU、内存、网络和磁盘卡片只有曲线及序列名称，直接进入页面时悬停提示样式也可能未加载。沿用现有卡片和曲线，在图下按序列常驻展示最新有效值、当前查询范围的平均值和最大值，并让鼠标悬停可靠显示该时间点的具体数值。

## 验收要求

1. 每条序列显示完整名称、与曲线一致的颜色、最新值、平均值、最大值；多容器分别计算，不混合汇总。
2. 最新值取时间顺序最后一个有限数值；平均值和最大值只使用当前查询结果内的有限数值。0 是有效值；null、undefined、空字符串、NaN 和 Infinity 不变成 0。全缺失序列显示“—”；无数据继续展示既有空态。
3. 复用现有格式化与统计函数：CPU 百分比、内存 IEC 字节、网络/磁盘每秒速率，以及网站 QPS、耗时和 SDK 自带单位均与坐标轴/提示框保持一致。两位小数。
4. 自动/手动刷新及集群、部署、容器、时间筛选后，展示值跟随同一批曲线数据更新。保留悬停提示框、错误与等待上报状态。
5. 中英文、深浅色、1440px、390px 和 200% 阅读可读；长序列名称可换行，不挤掉数值和单位。
6. 全新浏览器直接打开应用监控，无需先进入监控大盘，鼠标移入曲线区域即可显示采样时间、各容器名称、同色标记、该时间点数值和单位；移到其他采样点内容更新，移出后隐藏。右侧边缘、窄屏、深色及 200% 下提示框位于视口内，内容可读。
7. 悬停显示当前采样点的值，与图下“最新值”等统计各自对应；0 与缺失值保持区分，不用最新值填补该点空值。网站与 SDK 共享图表保留相同行为。

## 架构影响

不适用：仅扩展既有 TelemetryPlot 的数据展示，复用相同查询结果和统计/格式化工具。不改变组件职责、采集或控制路径、API、协议、凭据、存储或部署拓扑，因此无需改写 docs/system-design.md 与 Doca 系统设计基线。

## 合并、Docker 发布与部署

用户于 2026-11-09 授权合并、Docker 发布与部署。经 GitHub PR #156 合入 main，固定合并提交构建 Linux amd64/arm64 中心镜像并发布 `docker.heyphp.com/lightmoni/lightmoni:20261109-monitor-values-v1`。保留既有 latest 标签；此次 UI 补丁无需升级已安装 Agent。

发布前验收双架构成品的 revision、非 root、健康、登录、数据库连接和下载制品，并核对生产构建中的常驻图例与悬停样式。部署前通过现有生产管理通道备份配置、环境、主密钥与一致 SQLite 快照，保留权限；仅更新中心服务镜像。核对实际镜像摘要、revision、健康、原挂载/环境/端口/网络、主密钥和其他容器，以及线上应用监控的常驻/悬停数值。失败恢复旧程序引用，不自动替换线上数据库。
