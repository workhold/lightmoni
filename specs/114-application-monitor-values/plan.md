- 保留现有两列卡片、图表高度、主题变量及 uPlot 交互；将图下仅含名称的文字替换为按序列排列的数值图例。序列名称使用相同颜色标记，三个指标等宽排列，最新值适当加重。窄卡片将名称和指标分两行，完整保留单位。不引入新动效。
- 在现有 TelemetryPlot 中先将时间排序，规范化缺失/非有限数值为 null；图例与曲线使用同一组 points。复用 calculate(lastNotNull/mean/max)、formatValue 和 colorForSeries。网站与 SDK 使用该组件，获得一致展示，不新增组件边界或后端逻辑。
- 图例补充最新有效样本时间的原生提示，明确“最新”来自当前范围内的有效样本。无序数据也按时间确定最新值。
- 悬停修复：TimeSeriesPlot 直接引入自身光标和提示框样式，移出 DashboardPage 延迟加载样式中的同一规则，消除首次进入应用监控时的样式缺失；使用既有 body 提示层与数值格式化，保留隐藏序列和告警显示规则。提示框固定定位、主题适配、长名称换行，右边缘翻转并限制在视口内。

- 通过项目现有 Vite/Playwright 模式运行真实 ApplicationMonitoring 页面，API 使用只读夹具。覆盖单位、多个容器、缺失/零值/乱序、刷新、筛选、网站及 SDK 标签、空态与悬停；三轮验证，记录报告与桌面/窄屏/深色/200% 截图。主 Agent 查看实际截图自检，局部低风险变更不独立派审。
- 运行 Web 类型检查和相关统计/格式化检查；不运行生产构建或无关全量测试。

## 已授权发行流程

1. PR 合并后使用精确 main 合并提交的 git archive 作为 Docker 输入，沿用现有双架构构建、隔离成品验收与 Registry 校验流程。用户已明确要求 Docker 发布，此阶段执行生产构建。
2. 镜像发布固定版本标签，回读多架构索引、各架构 manifest/config 与 digest。运行时读取已有系统凭据，不将凭据写入报告。
3. 使用已有生产管理会话核对目标中心、空闲执行边界和旧配置；创建受保护配置/密钥与 SQLite 一致性备份。拉取并核对新镜像后，原子替换 Compose 中单个中心镜像，只重建中心服务。
4. 回读线上 revision、digest、健康和不变量，刷新真实应用监控并检查常驻与悬停数值。归档脱敏证据，通过另一个 GitHub PR 更新固定 Compose 标签和验收记录，按本轮授权合入。发行不改变架构。
