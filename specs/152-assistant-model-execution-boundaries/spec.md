# 152 · AI 助手模型接入与审批执行边界

状态：文档约束修订，待评审；不修改运行时代码。继承 SDD 001/003/046/047/134～151，并作为相关早期文档中“只读/草稿”“不写操作”和供应商适配范围的现行解释。

## 用户决策

1. 模型配置与多协议只维护 AI 助手所需的基本能力；未来复杂供应商接入由模型网关承担，不要求 LightMoni 持续补全所有供应商特性。
2. 写操作是允许的产品能力，但 AI/MCP 只能生成结构化提案，必须由管理员审阅确认后，才通过原领域路径执行真实写入或动作。

## 需求与范围

### 模型接入

1. 保留 Base URL、API Key、具体协议、模型名称、启用状态、连接测试及必要的输入/输出/步骤、超时和取消控制。
2. 保留现有 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 和 Google Gemini 适配作为兼容能力；本轮不移除、不重写，也不继续扩展供应商特定功能。
3. 基本模型契约必须支持助手实际依赖的流式文本、工具调用、多轮历史、取消/超时和安全错误；只支持普通文本聊天不满足要求。
4. token/价格信息按真实返回记录；网关或供应商不提供时必须保持未知，不能猜成零。
5. 未来网关复用现有具体协议入口。供应商路由、协议适配、故障切换、配额、供应商秘密和成本治理由网关负责，不在中心复制第二套网关。

### 审批后写操作

1. 内部 AI、外部 MCP 和会话 HTTP 可以为已开放领域创建真实原生提案；提案不是业务写入已经发生。
2. 管理员在原业务页面/API 审阅目标、参数、差异、影响和风险后明确确认；模型、客户端弹窗或工具注解不能代替审批。
3. 审批后允许原领域服务执行真实写操作，包括已开放的任务、告警、部署、运维和 Agent 首装路径。原生业务 Store、状态机和回执仍是事实来源。
4. 提案与审批绑定目标、参数/diff/digest、资源 revision、owner、来源、稳定 grant 和有效期；内容变化需要重新审阅。
5. 审批和执行/领取前按各领域现有协议复验当前账户角色、scope、资源/主机范围与稳定授权；撤销、过期、降权或范围缩小后不得开始尚未执行项。
6. 不向模型或 MCP 提供通用 apply/approve/execute、任意 SQL 写入、任意 SSH/shell 或自动批准工具。
7. 重复请求使用业务幂等；`queued/running/unknown` 不是成功，unknown 不自动重放，取消不能伪造远端已停止。

## 非目标

- 不实现模型网关、不删除已有协议、不改变供应商计费或模型质量承诺。
- 不新增运行时 API、不扩大当前工具清单、不开放新的直接写能力。
- 不把官方 MCP SDK 或 fixture 测试说成真实客户端、真实供应商或生产业务 E2E。
- 不将自动执行、持续授权或服务主体纳入本轮。

## 验收

1. 当前系统 HLD、平台 MCP HLD/LLD、接入指南与相关 Spec 对模型接入和审批后写操作的描述一致。
2. 文档明确区分“模型可调用 effect”和“管理员审批后的原生业务执行”，不再将后者笼统描述为禁止写操作。
3. 文档明确基本模型能力仍包含流式工具调用，不以“精简模型配置”为由削弱助手核心闭环。
4. 不改变历史验收证据；未执行的网关、真实客户端和生产验证仍明确标记为未完成。
5. Markdown 链接、代码围栏、空白与差异检查通过，无秘密或运行时代码变更。
