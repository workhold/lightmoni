# SDD 152 现行契约澄清

本文件不新增 HTTP/MCP 端点，只统一既有契约的解释。

## 模型接入

- 保存模型配置必须具有具体 `protocol` 和 `model`；未来网关复用具体协议，不增加自动猜测的 `gateway` 协议。
- 最小生成契约包括流式文本、工具调用、多轮历史、取消/超时和安全错误；普通文本-only 接入不满足 AI 助手要求。
- 目录可用不等于生成或工具调用已验证；真实连接测试、fixture 和真实供应商 E2E 分别记录。
- usage/cost 只使用真实返回与已配置价格；缺失信息保持未知。

## 提案与审批后执行

- `read`：返回授权范围内的安全事实。
- `draft/propose`：创建或返回待审阅提案，不代表目标已修改。
- `code`：产生受限代码结果/diff，仍由用户确认应用。
- `execute`：不向模型/MCP 提供通用直接执行工具；管理员审批后的原领域 Apply 不属于该模型工具权限。

审批通过允许原领域发生真实写操作。审批记录必须绑定冻结目标、内容摘要、revision、owner、来源、稳定授权和有效期；任何影响执行语义的变更都要求重新审阅。

外部提案在审批及尚未开始项领取/启动前均按领域协议复验；撤销、过期、降权、主机范围缩小或校验器缺失时失败关闭。内部/历史提案保持既有权限和兼容路径。

`proposal completed` 只表示提案流程完成；`approved/queued/running/unknown` 均不能代替真实业务成功。最终结果从原生任务、告警、部署、运维或 Agent 记录读取。
