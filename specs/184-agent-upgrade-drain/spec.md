# SDD 184：旧 Agent 自动检查占用时的一键升级

## 现象

2026-11-18 在生产主机 zz-bj-1 观察到 Agent 0.1.1 缺少 `operations.platform.reconciliation.v1`。中心每 15 秒对四个应用实例轮流派发兼容性 inspect；每次约 20 秒，SSH 车道持续繁忙。一键升级在创建维护预约之前要求 `idle()`，因此无法取得升级计划。一次 inspect 结果未知已按远端状态核对并人工结束，不能把未知记录当成成功。

## 用户场景与验收

1. 管理员对有有效可复用 SSH 凭据的旧 Agent 发起一键升级时，即使当前只读 inspect 占用车道，也可进入请求；中心先建立最多 120 秒的持久维护预约，阻止新的 Agent 作业入队或领取，并让 SSH 派发器保留未领取的排队作业，再等待现有执行结束，随后执行原有只读 SSH 探测、指纹固定和维护流程。
2. 仅一键升级使用等待能力。普通计划、批次和回退保持现有即刻空闲要求。
3. 已运行任务、未知结果、部署、卸载、Docker 安装和其它维护仍不可与升级并发。超过等待期限、请求取消或检查失败时只释放自身预约，不启动维护，不清理或伪造既有任务状态。
4. 预约完成后原有 `awaiting_approval` 更新记录接管围栏；一键升级继续沿用现有启动、回执、健康确认和 unknown 核对逻辑。

## 范围

中心的维护预约顺序、等待逻辑和主机升级按钮能力投影；不修改 Agent、远端维护器或业务容器。不自动部署生产中心或升级生产主机。

## 架构影响

改变中心自动检查与 Agent 维护的控制路径和调度优先级，同一 PR 更新 `docs/system-design.md`。不改变凭据边界、存储表结构和远端协议。
