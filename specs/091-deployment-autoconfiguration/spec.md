# Feature Specification: 自动部署、统一域名入口与 SDK 环境配置

**Feature Branch**: `codex/091-deployment-autoconfiguration`
**Created**: 2026-11-03
**Status**: Draft
**Input**: 修复服务发布报错和入口 DNS 卡住；自动生成集群入口域名，网站仅 CNAME；镜像仓库统一一个 5000 入口；应用快速安装自动选位置、端口、托管解析与 SSL；部署注入 SDK 配置，允许显式覆盖。

## User Scenarios & Testing

### User Story 1 - 发布可完成且失败可恢复 (P1)
管理员发布网站或应用时，已结束或已完整核对的作业不再造成误阻塞，真正活动或未核对的作业仍互斥。DNS 展示保存、发布、供应商回读的真实状态，错误可定位和重试。

**Independent Test**: 已核对 unknown、活动 root 作业与顺序提交两项网站发布分别验证。
**Acceptance**: 有效核对后新作业可提交；同一主机受管作业能串行排队；未核对未知结果继续拒绝新写入，不伪造执行或健康成功。

### User Story 2 - 网站统一 CNAME (P1)
平台在可用托管区域下为各集群生成稳定唯一入口域名，自动维护入口地址；用户仅填写业务域名。

**Independent Test**: 新建入口、发布网站、入口机器变化，业务域名保持 CNAME 目标。
**Acceptance**: 不要求手填入口名，不提供网站直接 IP 解析模式；无托管区域、无公网服务地址、DNS 厂商失败均给出明确状态，不永久显示空泛等待。

### User Story 3 - 快速安装应用 (P1)
应用商店选择应用和域名，填写应用自身必要参数后即可安装；平台自动选择合适的在线机器、集群与端口，匹配托管区域并申请证书、配置网站。

**Independent Test**: 多集群、多机器下省略部署位置安装 HTTP 应用，确认资源、证书、网站、发布与失败状态可追溯。
**Acceptance**: 默认不要求基础设施字段；高级设置允许覆盖；最长域名匹配托管区域；非 HTTP 应用可不配置域名；失败保留已创建资源并允许重试，不重复创建。

### User Story 4 - 一个镜像仓库入口 (P2)
系统内置仓库统一一个用户可见端口（容器 5000），只部署在一个集群的一台固定机器上；底层只有一个可写仓库和一份存储，额外仓库由用户自行部署。

**Independent Test**: 仓库部署只声明一个宿主端口，标准推送和拉取复用同一仓库。
**Acceptance**: 用户不再配置 5001/5002；内网镜像复用可关闭；私有仓库保持可推送，删除独立 Hub / 发布源缓存实例；拒绝新增系统仓库的集群副本，变更存储位置或旧多位置配置须先迁移。

### User Story 5 - SDK 默认读取部署环境 (P2)
部署应用自动携带服务名、SDK 上报凭证、中心后端与机器/集群/应用身份。业务 SDK 初始化可以省略这些配置，程序显式配置优先。

**Independent Test**: 检查容器与 Compose 载荷中的环境信息，使用 SDK 空配置上报并验证显式覆盖。
**Acceptance**: 凭据只进入加密配置与批准的受管载荷，成员/AI/进度 API 不返回秘密；浏览器 SDK 不读取服务端环境；提供各后端 SDK 一致的环境变量契约。

### Edge Cases
- 未托管业务域名、域名冲突、根域不支持 CNAME、区域权限错误和证书签发失败。
- 集群无在线或资源足够机器、无 OpenResty、端口冲突、执行未知结果与重复点击。
- 多托管区域采用最长后缀；入口名稳定且不与业务域名冲突。
- 应用自身环境变量和显式 SDK 配置覆盖默认值；已有 SDK Key 禁用后不绕过撤销。
- 快速安装链路按真实阶段展示，应用运行不等于 HTTPS 已可用。

## Requirements
- **FR-001**: 发布与执行互斥使用一致的活动/核对谓词；受管队列保留串行处理能力。
- **FR-002**: 平台自动生成稳定入口域名并管理入口 DNS，网站仅使用 CNAME。
- **FR-003**: DNS 状态包含原因、失败与可重试信息，供应商回读不等同公网传播。
- **FR-004**: 快速安装自动选位置、端口、DNS 区域、证书和网站，仍支持高级覆盖。
- **FR-005**: 系统仓库仅暴露一个 5000 端口，底层也仅一个仓库，支持私有推送与复用。
- **FR-006**: 应用部署注入 SDK 环境默认值，SDK 显式配置优先，身份标签可自定义。
- **FR-007**: 密钥不进入公共响应、日志、Git、PR 和设计正文；人工确认、版本检查和真实回执保持。
- **FR-008**: 架构同步同一 SDD/PR 更新仓库与 Doca，保留原生图和无关内容，成功保存后回读。

### Key Entities
集群入口（稳定域名、托管区域、健康机器、DNS 状态）；安装流程（应用、证书、网站、阶段、失败原因）；SDK 部署配置（中心地址、受控凭证引用、服务与资产身份）；仓库统一入口（一个可写仓库和一份存储）。

## Success Criteria
- **SC-001**: 五个用户场景均有可重复执行的契约/集成证据；真实未决任务继续阻塞危险写入。
- **SC-002**: 快速安装 HTTP 应用不要求用户填写集群、机器、宿主端口、DNS 区域或证书 ID。
- **SC-003**: 新入口配置不要求手填域名；网站表单无直接 IP 选项；仓库只出现一个端口。
- **SC-004**: SDK 省略连接和身份选项时采用部署环境，显式覆盖测试通过，公开响应无秘密。

## Assumptions
沿用当前应用商店、云凭据、DNS 与 ACME 能力；托管区域必须已配置有效凭据。没有托管区域时明确说明先决条件。用户已明确单入口底层也只有一个仓库，不保留独立缓存仓库；额外仓库由用户从商店另行部署。保留现有 UI 样式与高级配置。用户于本轮追加授权：改完后自行打包、部署、发版并实测，使用功能 PR 合入主干后固定源码构建，保留回滚与数据备份。
