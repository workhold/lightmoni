# SDD 196：0.1.10 Agent 生命周期修复继续发布

## 背景

0.1.9 版本准备 PR #269 已合入，旧 0.1.9 镜像也已发布并短暂切换到生产。随后合入左上角版本标识 PR #270，并在生产验收中发现已绑定 Agent 主机的批量“部署 Agent”入口仍可能因连接能力可用而误启用，修复在 PR #271 中。用户明确要求不再继续使用 0.1.9，改用 0.1.10。

## 目标

以包含 PR #270 与 PR #271 的最终 `main` 为源码，统一版本升至 0.1.10，重新本地构建 linux/amd64 中心镜像，完成隔离验证、发布、生产切换与 Agent 批级升级闭环。

## 范围与验收

1. 统一平台、Agent、SDK、MCP、构建与 Compose 版本为 0.1.10；`version:check` 全部通过。
2. 左上角品牌区显示与 Web 包版本一致的 `v0.1.10`。
3. 已绑定在线 Agent 且部署连接能力可用的主机，单机与批量“部署 Agent”均禁用覆盖安装；SSH 检查、卸载、移除节点和升级入口语义保持不变。
4. 从最终合入后的 `main` 构建 linux/amd64 镜像，OCI revision 与源码提交一致；镜像内双架构 Agent 与 SDK SHA256 校验通过。
5. 隔离 Compose 验证中心、ClickHouse、首页、`/healthz`、未认证 401、实例版本和 MCP 版本后，才推送固定标签与 `latest` 并回读摘要。
6. 生产保留既有 Compose 项目、`.env`、主密钥、状态卷与遥测卷；切换前已有 0.1.9 前备份，若状态发生变化则补充轻量一致性备份。切换后验证中心、ClickHouse、品牌版本、维护围栏与批量按钮。
7. 先核对并结束被 0.1.9 批次暂停的 vchive 旧更新记录，不把 rollback_failed/unknown 伪装为成功；然后按现有审批批次协议继续升级全部主机到 0.1.10。每台主机必须回读版本、源码修订、包 SHA256 和心跳。
8. 不自动重放 unknown 维护，不清理历史 unknown，不改变服务端身份、远端残留、凭据、计划和锁复核。

## 兼容与边界

- 本发布不改变组件职责、协议、存储、凭据或部署拓扑；架构影响已由 SDD 192 与 SDD 194/195 记录。
- 0.1.9 固定标签保留为历史制品，不覆盖或删除；生产回滚优先使用已有备份和固定标签。
- 应用绑定、私有仓库清单与历史 unknown 业务执行仍按原领域流程处理，不因中心或 Agent 版本升级宣称恢复完成。
