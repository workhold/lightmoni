# Mastra + Pi 代码任务

**状态：** 已实现并验证，待 PR 审阅
**日期：** 2026-10-18

## 目标

让 LightMoni AI 助手在保持 Mastra 对话和权限编排的前提下，处理轻量脚本、配置和代码修改任务。Mastra 负责判断何时需要编码并调用 `code_task`；Pi 负责一次任务内部的读取、修改、检查和修复循环。

## 用户场景

### 轻量代码修改

管理员在 AI 助手中提出“修改这个脚本并检查 JavaScript 语法”。助手可以读取受允许目录内的文件，在隔离副本中修改并运行白名单检查，返回摘要、diff、测试结果和执行步骤。原工作区不会被自动修改。

### 用户确认应用

管理员查看任务返回的 diff 后，通过显式的应用接口确认。应用接口再次校验任务归属、工作区和路径范围，只把已批准的变更写回原工作区。Pi 不负责提交、推送、部署或合入。

### 取消和失败

任务超时、被用户取消、超过步骤限制或最终检查未通过时，执行器停止后续动作并返回可审计的状态。隔离副本会被清理，原工作区保持可用。

## 需求

- Mastra 仍是 LightMoni AI 助手的主运行时和用户对话入口。
- `code_task` 是一个显式的代码工具；没有配置 workspace 时不能调用。
- Pi 每个任务最多执行配置的步骤数，默认 8 次模型请求、最多 12 次，最长 120 秒。
- 工作区仅在运维显式配置后对管理员开放。Pi 文件工具只允许读写 workspace 内的路径；真实路径和符号链接必须经过范围检查。
- 检查命令只能执行运维配置的完整白名单，默认关闭；临时副本不等价于 OS 沙箱，执行命令需信任源码。
- Pi 只能在隔离副本中写文件；工具输出和 diff 需要限制大小并保护凭据，超出审阅上限直接失败。
- 任务结果包含 `status`、摘要、修改文件、统一 diff、检查结果和步骤事件。
- 应用变更必须由用户通过独立接口显式确认，且不自动 commit、push、PR、merge 或 deploy。
- 取消信号必须传递到 Pi 的 agent 和当前 shell 子进程。
- 模型凭据只通过内存传给 provider，不进入 argv、日志、SSE 或任务结果。

## 非目标

- 不把 Pi 接入 LightMoni Agent 节点，也不让节点访问中心模型凭据。
- 不做完整 IDE、后台队列、自动修复生产代码或自动发布。
- 不替换已有的 Mastra 监控查询、多轮工具调用和会话存储。

## 验收

1. Mastra 可以调用 `code_task`，并得到带 ID 和检查结果的有界收据，网页按 ID 获取完整 diff。
2. 同一任务内 Pi 可以经历“读取 → 修改 → 检查 → 修复 → 再检查”的多轮循环。
3. 越界路径、符号链接逃逸、未白名单命令和不存在的 workspace 都被拒绝。
4. 取消或超时后不会继续执行后续步骤。
5. 有变更且最终检查通过的预览为 `awaiting_approval`；应用接口只应用已保存且当前管理员可访问的 diff。
6. 现有 Assistant 监控工具和模型配置测试不回归。

## 首期边界

只处理专用工作区的 UTF-8 文本和轻量脚本，不安装依赖，不复制 node_modules。检查命令以中心服务身份运行，默认关闭；不提供不可信代码的操作系统隔离。多文件应用采用逐文件原子替换和失败回滚，不宣称跨文件崩溃事务。Pi 每次模型请求计入模型管理用量与估算费用，缺失供应商计数保持未知。详见计划和验收记录。
