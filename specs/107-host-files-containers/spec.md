# Feature Specification: 主机容器与文件管理

**Feature Branch**: `codex/107-host-files-containers`
**Created**: 2026-11-08
**Status**: Implemented and verified; pending PR review
**Input**: 主机列表支持查看机器上所有容器，以及面板式目录浏览、查看文件、修改文件、上传文件。

## User Scenarios & Testing

### User Story 1 - 查看全部容器 (Priority: P1)

管理员从主机列表直接打开容器视图，查看运行中和停止的容器，区分平台应用与外部容器。

**Independent Test**: 给定同时存在运行、停止、平台和外部容器的主机，逐一核对列表。
**Acceptance Scenarios**:
1. 主机列表有直接容器入口；列表显示容器名称、镜像、状态、端口和完整 ID。
2. 可搜索、按状态筛选和刷新；显示观测时间、离线/过期/不可用和截断状态，失败不能伪装成空列表。

### User Story 2 - 浏览与修改文件 (Priority: P1)

管理员选择主机 SSH 账户，按路径和面包屑浏览目录，打开文本文件，修改并保存。

**Independent Test**: 浏览含中文、空格和隐藏文件的目录，修改文本，重新打开核对；远端并发变化必须拒绝覆盖。
**Acceptance Scenarios**:
1. 目录显示名称、类型、大小、权限和修改时间，可进入目录、返回上级、输入绝对路径。
2. 支持不超过 1 MiB 的 UTF-8 文本编辑；二进制、超限、特殊文件和符号链接给出明确提示。
3. 保存前核对读取版本，保存后回读摘要；失败保留编辑内容，离开未保存编辑需要确认。

### User Story 3 - 上传文件 (Priority: P2)

管理员向当前目录上传不超过 8 MiB 的文件，可创建文件，已有同名文件必须明确确认覆盖并核对版本。

**Independent Test**: 上传含二进制字节的文件，读取远端原始字节比对；取消覆盖不能发送写请求。
**Acceptance Scenarios**:
1. 上传显示待上传名称、大小和目标目录；成功后刷新目录。
2. 拒绝超限、非法文件名和无写权限操作，失败时保留路径与编辑内容。

### Edge Cases

凭据过期/撤销、账户或目标改变、SSH 指纹不匹配、SFTP 不支持、权限不足、主机繁忙、目录超过 2000 项、远端文件变化、断线和写入结果未知均显示可操作错误。无 Agent 的 SSH 主机仍可管理文件；容器清单依赖现有 Agent 的 Docker 观测权限。

## Requirements

### Functional Requirements

- FR-001：仅已登录管理员可读写主机文件；凭据不进入浏览器、审计正文或 AI 工具。
- FR-002：容器视图复用机器级清单，覆盖全部状态与非平台容器。
- FR-003：文件权限遵循选定 SSH 账户，不隐式提权；文件写入由人工点击保存/上传触发。
- FR-004：文本保存和覆盖上传使用内容摘要及元数据版本核对，临时文件原子发布并回读；创建使用排他方式避免覆盖竞争。
- FR-005：文件操作保存操作者、主机、账户、动作、结果等审计元数据，不保存文件内容。
- FR-006：所有入口、错误、空态、加载和写入反馈支持中文与英文，390px 窄屏可操作。

### Key Entities

主机容器观测、SSH 账户与凭据租约、目录条目、文件版本、文件操作审计。

## Success Criteria

- SC-001：从主机列表一次点击即可打开容器或文件管理。
- SC-002：验收机器的全部运行及停止容器均可查阅，过期和截断清单有明确标识。
- SC-003：目录导航、文本修改后重新读取、二进制上传字节比对全部通过。
- SC-004：无权限、并发变更、符号链接、超限及保存失败用例全部拒绝不合法写入。

## Assumptions

本轮覆盖请求中的容器查看与文件浏览/编辑/上传；容器启停继续使用既有受管操作。文件浏览是管理员人工维护，与现有网页 SSH 终端同一信任边界；不新增常驻服务或 Agent 任意文件工具。目录按需读取，不递归扫描。

## Architecture impact

新增人工维护 HTTP → SSH/SFTP 文件通路和审计表，需同步 `docs/system-design.md` 第107章与 Doca 对应章节并回读；现有原生图块保持不变。
