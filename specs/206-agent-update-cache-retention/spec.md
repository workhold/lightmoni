# SDD206：Agent 更新缓存保留策略

**分支**：`codex/206-agent-update-cache-retention`
**日期**：2026-11-22
**状态**：实施中

## 背景

Agent 升级审批通过 `AgentReleaseCatalog` 把发行包与维护脚本按 SHA256 内容寻址固定到 `<dataDir>/agent-update-cache`，保证审批引用不可变字节。该目录此前只增不减：每次新发行（含每日构建）都会固定新的 bundle（约 80MB）与脚本，生产实例 zz-bj-1（zsw-bj-1 中心）已积累约 40 个文件、2.9GB，且没有任何回收路径，缓存将随发布持续无界增长。

## 用户场景与验收

管理员长期滚动发布 Agent 发行后，中心磁盘不会被历史升级缓存无界占用：

1. 给定缓存中的固定文件未被任何 `awaiting_approval/running/verifying/unknown` 状态的维护计划引用，且不在最新 8 个之内，当中心启动或新维护计划创建完成时，该文件被删除。
2. 给定某文件被活动维护计划引用（含结果未知待核对），无论多旧都不被删除。
3. 给定缓存清理失败（文件系统异常），计划创建与中心启动不受影响。

## 要求

- **FR-001**：`AgentReleaseCatalog` 新增 `prune(retained, keep=8)`：按 mtime 保留最新 `keep` 个固定文件，保留 `retained` 引用集合；仅处理 SHA256 命名的普通文件，staging 文件与其他条目不动。
- **FR-002**：维护计划创建成功入库后与中心启动时触发清理；保留集合从活动状态计划 `plan_json` 中出现的 SHA256 值提取。
- **FR-003**：清理为尽力而为：任何异常不阻断计划创建与启动，不产生远端或数据库副作用。
- **FR-004**：不改变固定、校验与下载服务路径；审批不可变字节语义与活动计划围栏不变。

## 架构影响

不适用。仅新增本地缓存目录的回收维护；组件职责、控制路径、协议、凭据、存储 schema 与部署拓扑均不变。
