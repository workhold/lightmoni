# 实现设计

基于最新 GitHub origin/main 的独立工作区实现，保留原工作目录发布文件。

1. availability.ts 将成员期望与健康观测分开：手动已就绪成员持续保留，健康异常不撤流；托管继续按宽限、最低预算和就绪切换调度。
2. cluster-workloads.ts 两种模式均保留中心配置强制对账。手动在原机器修复，托管复用预算/替换/排空。明确 configuration_matches=false 时复用现有 force_recreate 在首次修复强制重建。对账只使用当前作业的证据，旧检查不能确认新配置。保留权限、身份和未知执行门禁。
3. 手动网关失败在既有 status_json 保留最后成功发布证据，DNS 仅取成功版本与中心当前授权域名/策略交集，当前失败仍可见。
4. UI 明确手动成员固定、异常时自动恢复中心配置；不提示必须人工重新部署。
5. HTTP/SQLite/DNS fixture 回归证明异常不改中心、手动自动原机恢复、托管有容量补齐副本、人工停止有效。运行相关测试、类型及构建检查，记录验收与架构文档。

仅修改代码与设计，不执行生产配置或 DNS 写入、发行部署。
