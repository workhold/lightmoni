# 应用监控固定窗口指标查询修复

日期：2026-11-10；分支：`codex/120-application-metric-windows`。

## 问题与用户场景

用户在应用的“容器负载”页签看到 `query range boundaries and interval must align to 30 second metric windows`。该页面同时请求容器、日志、网站及 SDK 数据。SDK 查询含固定窗口 histogram 表，但传入任意当前时间和一分钟固定分桶，执行器只为 dashboard/alert 自动对齐，因此 SDK 查询报错并在容器页显示。

## 验收要求

1. 应用监控打开、手动/自动刷新及切换时间范围/集群/部署/容器时，SDK 指标遵循实际存储周期的公倍数对齐，不再因任意当前时间报错。
2. 固定窗口点按窗口起点筛选与分桶；普通 gauge/sum 和 window_seconds=0 的旧 histogram 点仍按事件时间读取。多周期历史遵循执行器已有公倍数规则。
3. 仅 SDK 指标使用返回的实际对齐范围；容器曲线、应用/SDK 日志与网站流量保持原请求范围和身份筛选。
4. 查询错误正常显示，不能隐藏错误或跳过 SDK 指标；无数据仍保持原空态。
5. 任意普通 SQL 的严格窗口边界规则、权限、AST、参数与查询资源限制不变。

## 架构影响

不适用：修复既有应用监控查询配方与现有执行器对齐策略的接入，复用原窗口元数据、Query、响应 frame 元数据和图表路径。组件职责、控制/数据路径、协议、存储、凭据和部署均不变，无需升级 Agent 或改写系统设计文档/在线副本。
