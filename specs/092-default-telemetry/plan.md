# 实施设计：默认采集与上报可见性

## 现场基线与根因排查

2026-11-04线上中心a9588e6，目标主机Agent为0b45683。主机指标持续进入metric_host_*（近10分钟gauge1700、sum2352条），并非全部数据通道失效。共享应用日志0条，应用指标表未创建；root观测队列保留自11月3日的1批日志/1批指标。对现有采集器进行真实调用得到 observations/batches 403 website_observation_ownership_required。该队首拒绝使后续采集和两种信号发送均停滞；runner捕获后不对外报告。SDK只有上一轮一次性验收日志；现有应用监控仅查共享容器表，没有查询SDK表。

## 设计决策

首次线上候选验收补充：中心已有147条待写入批次；绑定校验通过，但ClickHouse INSERT返回27。日志source_seq为LosslessNumber，canonicalJSON将其保存为包装对象，回读JSON.parse后丢失数值类型。修复在既有中心outbox路径内将日志序号规范为精确十进制字符串，并兼容恢复已保存的严格包装形状；不清除积压。每轮20条的窗口使用稳定游标轮转，避免20条失败记录长期占据窗口。补充大整数和超过单轮窗口的真实回归，再重新构建成品与部署。

1. 保留普通Agent主机采集、root helper容器采集、SDK直报三条既有链路和凭据边界。普通Agent不获取Docker权限。真实队首日志属于已删除网站：保留原始容器日志，将失效website_id转为unregistered_website_id，不授予站点统计归属；仍拒绝普通应用冒充入口和现有网站的外集群上报。托管网站集群从保存服务部署推导，不仅依赖手动cluster_ids。不放宽执行器、应用或容器归属校验。
2. root采集状态包含尝试/成功时间、安全错误码、队列批次数/字节；通过现有签名心跳投影到监控。清单ready不再等价于遥测ok。中心outbox失败也投影为采集故障，不能长期吞错。
3. 指标与日志发送按信号分开限额/重试；一个失败批次不阻塞其他信号。日志采集失败后已产生指标仍持久化；不清队列、跳游标或伪造成功。
4. 应用遥测API保留容器查询，增加有界SDK数据发现和查询。只从真实Catalog生成标识符，以resource_json的lightmoni.application_id和部署身份筛选；应用专用Key可辅助既有身份定位，但不凭service_name扩大范围。支持gauge、sum、分布聚合及日志；无SDK数据明确空态。沿用只读Query AST/时间/资源预算。
5. 新增网站自身监控路由和站点范围查询，覆盖静态、手动后端、托管服务。访问日志增加host、method、去除查询串的uri、状态和耗时，不写Authorization/Cookie等秘密字段。QPS仍从原始访问日志计算。
6. 复用既有页面布局、图表和日志表，不重构无关UI。新入口展示可用性、最近上报和实际错误，支持刷新和时间筛选。
