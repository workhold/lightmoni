# 设计

将发行版约束移入“确实缺少 Engine 或 Compose”的软件包补装分支；Linux、架构、root、systemd 和生命周期锁仍在共同入口核验。已有组件执行当前固定 default Docker context 的服务启动与 Engine/Compose 验证，成功保存 verified 回执。状态机、SSH 身份校验、目录、并发栅栏与签名观测投影保持现有契约。

环境面板说明补装支持范围与已有环境验证范围；缺少执行器观测时展示明确说明及现有主机执行权限链接，禁用无法执行的重新采集入口。成功文案统一为依赖已验证。

## 架构影响

不适用：修改同一固定安装器内部前置条件与现有字段的界面说明，没有新增组件职责、存储、凭据、协议、部署拓扑或跨组件数据/控制路径。继续采用已有受保护 SSH 安装及独立执行器签名观测，不修改 docs/system-design.md 或 Doca 架构基线。

## 验证策略

以临时目录和受控命令替代真实主机的固定系统路径，执行生产 shell，断言回执及包管理/服务调用的实际副作用。测试不在用户主机安装或升级 Docker。页面使用仅回环监听的合成数据服务，通过浏览器核验中英文、缺少观测、依赖验证成功及错误提示。
