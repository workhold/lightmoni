# SDD 168：主机 Agent 生命周期操作体验

## 背景

本地 Linux/systemd、主机页面和卸载流程验收已通过。页面仍存在三类体验问题：Agent 安装与管理入口只有图标；安装和卸载对话框重复展示状态及长篇计划；卸载完成后缺少明确收尾动作，恢复卸载的“强制”文案也容易被理解为会强杀任务。

## 用户场景与验收

### US1：快速找到 Agent 管理入口

- 未安装主机显示带文字的“部署 Agent”按钮，已安装主机显示带文字的“Agent 管理”按钮。
- 原有监控、容器、文件、终端和任务入口保持紧凑，不删除任何能力或菜单项。
- 中英文、窄屏和表格横向滚动场景下按钮仍可使用，文字不能覆盖相邻列。

### US2：清晰审阅和结束卸载

- 卸载对话框只显示一个主状态标题，进度条保留真实阶段，不重复显示相同状态文字。
- 待审批计划继续完整展示目标、方式、数据策略、远端快照、步骤和影响，不降低审批要求。
- 成功后优先展示远端移除、数据保留/清除、凭据撤销和核验时间；原计划默认折叠且可展开。
- 成功页提供明确“完成”按钮，刷新仍只读；不得新增重新执行入口。

### US3：操作语义不误导

- 普通 Agent 安装确认使用主按钮而不是危险红色按钮；卸载、清除等破坏性操作继续使用危险语义。
- 展示名称统一为“SSH 恢复卸载”，说明其用于身份残留或登记不完整场景，且不会强杀任务；底层 `mode=recovery` 不变。

## 功能要求与成功标准

1. 仅修改现有 Web 展示、样式和验收脚本，不修改 API 请求字段、状态机、审批、执行、恢复或权限判断。
2. 相关 UI 验收覆盖可见入口、安装按钮语义、卸载单一状态、成功回执优先、折叠计划和完成按钮。
3. 主机安装/权限、卸载、进度、任务与生产构建回归通过，保存桌面和窄屏截图。
4. 不连接生产主机，不执行真实安装、卸载、审批或 Docker 变更。

## 架构影响

不适用。本次仅调整现有 React 组件的信息层级、可见文字、按钮样式和原生对话框关闭动作，不改变组件职责、数据或控制路径、凭据边界、存储、协议、部署拓扑以及 AI/工具边界，因此不修改 `docs/system-design.md`。
