# 发行计划

1. 审查PR清单和差异、联合类型检查/相关回归，通过GitHub依次合入155/160并固定main提交。
2. 从合并提交git archive双平台构建，复用已校验镜像源，保留TLS/完整性验证；隔离SQLite/ClickHouse和随机凭据验收成品、SDK/Agent下载、备份工具与新字段/路径。
3. 通过系统凭据助手运行时读取Registry凭据，固定标签发布并验证全部blob、平台manifest和索引，保持latest不变。
4. 在已有授权1Panel终端备份原Compose/环境/主密钥/inspect及一致SQLite快照，仅主机root私有目录；核对原部署健康、空间和任务空闲。
5. 预拉取与核对revision/digest，只原子更改中心镜像，保留卷/环境/端口/其他容器，失败回退原引用；独立核对公网健康和管理员页面。
6. 原有维护入口升级当前可维护Agent，不新增SSH或执行权限；记录无法升级的只监控节点与兼容范围。
7. 脱敏发行证据通过功能PR提交并按本轮授权合入，最终确认无剩余开放PR，不直接推送main。

构建现场调整：npm镜像站500且官方源下载缓慢。将唯一仍固定第三方源的YAML tarball改为官方同版本/同integrity；Docker依赖步骤使用独立npm缓存挂载，并将源码revision环境延后至依赖安装后，避免每次源码提交重下依赖。缓存只导入当前四份锁文件声明且逐字节完整性校验通过的公开tarball，不导入元数据或凭据，也不进入成品层；成品仍从固定合并源码构建。此为构建缓存/依赖地址维护，不改变运行时存储、权限和部署架构。
