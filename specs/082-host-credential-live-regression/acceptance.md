# SDD082 验收记录

日期：2026-11-02，Asia/Shanghai。线上回测在当日凌晨进行；目标仅为用户授权的 vchive 开发机及本轮 `LMQA082` 测试记录。其他主机、凭据和业务服务未修改。此文不包含真实登录秘密、生产地址或完整生产记录。

## 当前结论

主机、集中连接凭据、密码/私钥 SSH、网页终端及普通 Agent 升级→卸载→全新安装主链路实际通过。普通 Agent 重新上线，主机 ID 不变，Agent 身份按重新接入流程更换；默认密码凭据仍有效。默认指标采集恢复，配置修订已同步，投递队列为空，没有采集或上报错误。

发现并修复两处问题：

1. **Agent 移除缺少独立执行器门禁**：隔离回归在旧实现复现 HTTP 200，导致普通身份被移除、未撤销 root 执行器遗留。现在同一事务拒绝未撤销执行器，返回 HTTP 409。真实主机未用来复现此缺陷。见 [契约](contracts-node-remove.md) 与 [验证](evidence-node-remove.md)。
2. **离线卸载提示不准确**：原中英文提示称 purge 删除整个数据目录，脚本实际保留 `operations` 业务目录。现提示与已有卸载行为一致，没有改变清理范围。

这两项代码修复尚需 PR 合入及发布，不能视为已在当前线上镜像生效。

## 普通 Agent 实机维护

1. **升级**：平台固定 SHA 的计划、审批及独立 systemd 维护完成，记录 succeeded；新 boot ID、构建身份、配置同步和健康回执一致，远端 current 指向目标发行。
2. **维护门禁**：重放同一升级/安装记录、同发行重复升级、错架构升级及已有安装上的 fresh 覆盖均被 409 拒绝。
3. **回退边界**：现场没有具备可验证构建身份的上一发行，计划被 409 拒绝。因此本轮只验证了现场回退保护，**未执行实机成功回退**；成功回退和自动失败回退使用隔离回归覆盖。
4. **卸载**：通过标准卸载计划明确 purge，平台核验远端移除后撤销精确 control/data 身份。独立 SSH 确认 systemd unit、程序、配置及身份均不存在；原业务容器仍运行。
5. **重新安装**：新 SSH 检查确认 absent 后重新计划和审批，记录 succeeded。原主机记录保持，新 Agent 身份正确关联；没有创建第二台主机。
6. **账户隔离**：升级和重装后 User/Group 均为 lightmoni-agent，无附加 Docker 组，NoNewPrivileges=yes；独立 root 执行器未安装。
7. **任务派发**：向该主机下发一条本轮只读 Node 脚本，state=succeeded、exit_code=0；execution_principal=agent。返回 UID/GID 与远端普通 Agent 账户一致，主机名、CPU 数量和内存总量与 SSH 核对一致。测试任务在成功后删除，执行审计保留。
8. **采集与上报**：新心跳中的 cpu/memory/filesystem/disk/network/system 均 ok；队列和 quarantine 为 0，上报 receipts 递增，last_error 为空。
9. **手动卸载器**：平台管理员脚本接口可读取；仓库、平台返回及重装后本机脚本 SHA256 一致：`cc33b9dd648e6acf5a10f2775535a9888182cde91d1a74327f585f04a05e0f51`。本轮没有再次手动卸载新装好的 Agent；离线执行分支由隔离回归覆盖。
