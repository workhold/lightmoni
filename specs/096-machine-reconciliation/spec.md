# Feature Specification: 中心到机器的注册式期望状态与对账

**Feature Branch**: `codex/096-machine-reconciliation`
**Created**: 2026-11-05
**Status**: Implemented; validation recorded in evidence/acceptance.md
**Input**: 中心记录部署、域名集群关系、端口、文件/证书和 Agent 配置；变更立即下发，周期对账纠偏；独立模块、上游注册扩展。

## User Scenarios & Testing

### User Story 1 - 单机完整期望清单 (Priority: P1)
管理员可查每台机器应运行的部署、网站与域名、端口、文件和连续采集任务及其来源，区分等待执行、漂移、已核验与阻塞。
**Independent Test**: 三机器、两集群产生不同配置清单，同一业务在多机器保留独立状态；重启清单仍在。
**Acceptance Scenarios**:
1. 给定网站只在两个集群中特定域名生效，保存并部署后，清单包含各机器实际网关配置、端口和相应域名。
2. 修改目标或删除受管内容后，旧目标保留待清理记录，离线恢复后完成清理；未注册内容不得清理。

### User Story 2 - 失败和漂移自动恢复 (Priority: P1)
修改配置即尝试下发；机器离线、任务失败或实际配置被改动时，中心保留期望，周期检测后修复。
**Independent Test**: 注入失败、离线、同版本漂移，恢复后无需重复人工提交，当前代次实际观测匹配才显示一致。
**Acceptance Scenarios**:
1. 成功部署之后修改机器文件或容器配置，周期实际检查识别漂移，重新下发并核验。
2. 新修改覆盖旧修改，旧结果不能把新版本确认成功；重启后仍继续对账。
3. 失去执行授权、机器绑定改变或未知执行结果时显示阻塞，不凭历史回执声称成功。
4. 连续配置的内存或持久文件改变，即使版本号相同也修复；一次性脚本不自动重复执行。

### User Story 3 - 注册和依赖 (Priority: P2)
新功能注册管理类型、期望生成和对账处理器即可接入，不修改调度核心。
**Independent Test**: 测试注册新类型，完成创建、修改、失败退避、删除和依赖阻塞。
**Acceptance Scenarios**:
1. 重复类型或重复资源键拒绝，生成失败不把已有清单当成删除。
2. 依赖未就绪时不执行下游；缺少处理器的持久资源保留并显示阻塞。

### Edge Cases
- 离线与中心重启、快速连续修改、旧代次回执、证书续期、同版本文件损坏、目标迁移。
- 执行互斥/未知结果必须保留，不能以自动重试绕过权限或重放未知副作用。
- 路径归属冲突、非受管文件和撤销授权保守阻塞；错误不泄漏密钥或正文。

## Requirements

### Functional Requirements
- **FR-001**: 系统必须持久保存按管理类型、机器、Agent 和资源键标识的期望、版本、来源和对账状态。
- **FR-002**: 上游可注册部署配置、受管文件/证书、Agent 连续配置管理器，支持未来类型及依赖。
- **FR-003**: 变更后立即安排现有执行通道下发，并定期全量重建目标以恢复漏通知和重启。
- **FR-004**: 实际核验独立于成功下发；同版本漂移也必须发现，旧代次或旧绑定的观测不得确认新状态。
- **FR-005**: 已知失败采用有界退避持续重试；活动作业去重，未知结果和权限失效保留阻塞。
- **FR-006**: 仅清理已登记且仍可验证归属的内容，目标移除保留删除意图，生成失败不产生假删除。
- **FR-007**: 每台机器清单可按类别读取，并展示来源、期望摘要、状态、最近核验、失败次数和后续调度时间；秘密内容不返回。
- **FR-008**: Agent 只接收自身内容，管理读取和触发遵循现有管理员授权；特权操作保持现有签名执行通道。
- **FR-009**: 自动化测试覆盖持久恢复、漂移、失败、删除、依赖、代次/绑定隔离以及现有运维回归。

### Key Entities
- 管理器：唯一类型、管理类别、完整期望生成器、对账处理器。
- 受管资源：目标机器与 Agent、来源业务、稳定键、加密期望、摘要、代次、删除意图、依赖。
- 对账状态：最近实际观测、待执行/一致/漂移/阻塞、失败计数、重试时间及关联作业。

## Success Criteria

### Measurable Outcomes
- **SC-001**: 多机器、多集群清单与有效授权目标一一对应，中心重启不丢失。
- **SC-002**: 默认每 15 秒推进对账，已核验资源每 60 秒重新实际核验；失败退避上限 5 分钟，连通后能恢复。
- **SC-003**: 同版本的 Agent 内容及受管证书损坏可检测修复；旧回执、未知结果、权限撤销不会误报一致。
- **SC-004**: 新管理器通过注册接入，核心调度无需修改；现有相关测试通过。

## Assumptions
- 使用现有中心数据库、Agent 控制身份和签名执行通道；立即下发指变更后持久排队，实际领取延迟由既有控制轮询决定。
- 首批覆盖现有应用/网关（包含网站静态文件与 TLS）、目录证书和 Agent 连续配置；云 API、一次性脚本与任意非受管系统文件不自动重放。
- 初始实现阶段不发布线上镜像或修改生产机器；后续合并、发行和生产操作以本文追加的用户授权为准。架构变更必须在同一 SDD/PR 同步仓库设计及 Doca，并记录实际回读。
