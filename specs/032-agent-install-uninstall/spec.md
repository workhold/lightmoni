# 主机 Agent 安装验证与安全卸载

## 目标

主机管理能够完成真实、受鉴权的 Agent 安装，并允许管理员通过可审阅、可追踪的固定流程卸载指定节点。不得把删除主机记录当成卸载，也不得为验证安装覆盖已有节点身份。

## 需求

1. 安装脚本及发行包继续要求下载鉴权；中心通过 SSH stdin 提供一次性 enrollment token，远端以 0600 临时 curl 配置完成脚本下载，秘密不进入命令参数、环境、日志或回执。
2. SSH 检查显示是否已有 Agent。全新安装在拟定计划和执行时均检查已有程序、服务、配置或身份；发现既有安装拒绝覆盖，并解释需要先核对现有节点或卸载。不得悄悄签发新身份替换原身份。
3. 管理员可预览卸载计划、确认执行、取消未执行计划及查看历史。计划绑定主机地址、端口、用户名、可信指纹、凭据、节点身份与有效期，任何变化均使旧计划失效。
4. 卸载使用确认指纹和有效 SSH 私钥，只能执行平台内置的固定脚本，禁止提交任意命令。一次性密码不用于自动卸载。
5. 网页卸载仅支持保留数据：停止并禁用独立 systemd 服务，确认停止后移除服务文件、启动器和 Agent 运行目录。保留配置、身份、缓存、服务用户、业务部署及其制品、容器和卷。停止失败不得删除程序；重复卸载应安全。
6. 计划必须识别远端节点并与中心节点/主机关联一致。不得只凭主机表中的旧绑定卸载另一个 Agent。运行中、已派发或结果未知的节点任务需要先完成或核对，不能直接卸载。
7. 远端移除已核验后撤销该节点 control/data 凭据，保存主机和节点历史，并展示卸载状态。保留文件用于核查和数据恢复；重装需要重新 enrollment。旧凭据不可继续使用。
8. SSH 断连或执行结果不确定不得报告成功。提供固定只读核对流程，以实际移除状态完成后续凭据撤销；不得自动盲目重跑破坏性步骤。
9. 所有管理 API 限管理员，复用主机互斥；待审批卸载与部署、终端、改主机/删主机之间需正确保护。AI 暂沿用现有读取/安装计划能力，不获得绕过网页确认的卸载权限。
10. 中英文界面提供能力置灰原因、已有安装说明、卸载影响、保留内容及凭据撤销结果。

## 真实验收边界

使用用户授权的 vchive 先只读核对 systemd、版本、身份、心跳和上报。通过本次临时专用 SSH 凭据验证平台预检及终端后撤销、移除测试授权。已有 Agent 不执行全新安装，不为了测试卸载现有节点；真实首装/卸载使用隔离 Linux/systemd 或可替代的受控测试夹具，明确记录环境差异。不得声称线上已经运行未部署的修正。
