# Feature Specification: LightMoni Agent 执行节点与任务标签

**Feature Branch**: `fix/assistant-model-settings`（保留当前工作区）
**Created**: 2026-10-17
**Status**: Implemented and validated
**Input**: 用户要求按已确定的 LightMoni Agent、执行节点、任务、任务标签术语，使用 SDD 完成名称及前端展示。

## User Scenarios & Testing

### User Story 1 - 理解并接入执行节点 (Priority: P1)

用户从“节点助手”查看运行实例，从“数据接入”安装 LightMoni Agent，并理解软件、实例及采集任务的关系。

**Why this priority**: 避免监控 Agent 与 AI 助手混淆，名称不限制未来智能任务能力。
**Independent Test**: 以管理员及成员查看节点和接入页面，在桌面和窄屏验证术语及操作。
**Acceptance Scenarios**:
1. Given 已有运行实例，When 打开节点助手，Then 列表称执行节点，显示身份、状态、任务标签、配置状态和诊断。
2. Given 需要接入，When 查看安装说明，Then 软件称 LightMoni Agent，安装入口称接入执行节点，SDK 可选择通过执行节点上报。
3. Given 尚未开发智能任务，When 查看页面，Then 仅展示已有采集和拨测能力，不出现可用的 AI 执行或远程命令控件。

### User Story 2 - 以任务标签分发独立任务 (Priority: P1)

管理员独立配置指标采集、服务拨测和目录日志任务，将任务关联一个或多个任务标签，为执行节点关联多个标签。

**Independent Test**: 两节点各绑定不同标签；一个节点绑定两个标签后取得对应的两种任务，同一任务多次命中只执行一次。
**Acceptance Scenarios**:
1. Given 独立任务和标签，When 绑定节点标签，Then 中心下发匹配的启用任务；取消匹配或停用后撤除任务。
2. Given 同类任务配置冲突，When 保存任务或节点标签，Then 明确拒绝并指出冲突，保留上次有效配置。
3. Given 节点未匹配任何任务，When 同步配置，Then 内部采集与拨测暂停，业务上报转发继续可用。
4. Given 普通成员，When 浏览任务或标签，Then 可读取，无法新增、修改、删除或改派节点。

### User Story 3 - 保留已有部署与配置 (Priority: P1)

升级后的已有节点继续执行原任务，原分组对应同名任务标签及独立任务，重新连接不会覆盖中心分配。

**Independent Test**: 使用旧数据升级、重启两次，再检查身份、任务、表、节点标签和原始数据不变。
**Acceptance Scenarios**:
1. Given 旧分组和节点，When 升级，Then 各节点只关联原分组对应标签，原任务及其参数保留，用户自定义名称不覆盖。
2. Given 旧安装命令和节点程序，When 首次注册或重新连接，Then 仍能接入；重新连接以中心已保存的标签为准。
3. Given 用户已删除迁移任务，When 再次启动，Then 不重新创建该任务。

### Edge Cases

- 多个标签重复命中、标签改名、空标签选择、删除被任务或节点引用的标签。
- 多个任务合并后的采集间隔、目标表、拨测名称或日志来源冲突；超出原有采集数量上限。
- 页面加载失败、保存失败、迟到响应、成员权限、长名称与390px屏幕。
- 安装默认标签无匹配任务、旧节点重连、离线配置缓存及无任务时显式关闭默认采集。

## Requirements

### Functional Requirements

- **FR-001**: 软件统一称 LightMoni Agent，实例称执行节点，导航称节点助手；AI 助手保留独立名称。
- **FR-002**: 任务、任务类型、任务标签是不同对象；标签用于匹配，不再以单一分组冒充多标签。
- **FR-003**: 执行节点支持多个任务标签；任务关联多个标签，任一标签相交即命中，空目标不广播。
- **FR-004**: 三种当前任务类型分别为指标采集、服务拨测、目录日志，启用和配置独立保存。
- **FR-005**: 任务及节点标签更新须验证实际下发配置；冲突整体拒绝，不能静默覆盖或部分保存。
- **FR-006**: 节点接入、状态、心跳、队列及采集错误继续可读；原有部署与历史数据保留。
- **FR-007**: 管理操作仅管理员可执行，普通成员只读，不泄露上报密钥。
- **FR-008**: 安装及接入文案、SDK方式、空态、概览和自监控新模板使用同一术语。
- **FR-009**: 不宣称已有模型调用、智能任务循环或通用命令执行；这些是后续独立功能。

### Key Entities

- **执行节点**: 一个 LightMoni Agent 运行实例，包含固定身份、运行状态及任务标签。
- **任务**: 独立启停的工作，包含名称、类型、配置及目标任务标签。
- **任务标签**: 中心管理的命名标记，可关联多个节点及多个任务。
- **Collector/采集器**: 节点内部的采集功能，不作为整个执行程序的产品名称。

## Success Criteria

- **SC-001**: 节点助手、数据接入及 SDK 说明中不再出现原“Agent 分组与任务”等旧导航术语。
- **SC-002**: 一个节点可同时接收至少两标签对应任务，另一节点不接收无匹配任务。
- **SC-003**: 无任务及配置冲突场景均明确反馈；失败更新不改变有效配置。
- **SC-004**: 原单分组部署升级及再次启动后，节点身份、任务参数和目标表保持一致。
- **SC-005**: 管理员/成员、桌面/390px及完整任务下发链路通过隔离验收，不改真实用户配置。

## Assumptions

- 本轮按此前定义实现任务标签的实际多标签分发；未来 AI 执行、任意脚本及模型机器接口不在本轮范围。
- 初次安装可选择一个初始标签，接入后可在节点助手绑定多个标签；已有命令继续有效。
- 保留现有任务执行范围与限制，同类任务配置不兼容时明确拒绝；保持已有前端视觉体系。
- LightMoni Agent 独立运行，由自身的进程管理器或容器编排管理生命周期，独立于业务实例的启动、停止和重启。业务通过 SDK 向节点上报，同一节点可接收多个业务的数据；业务退出时只需完成其 SDK flush/shutdown。当前已有前台运行和信号退出，安装页生成 Linux systemd 命令；容器自动部署流程不属于本轮范围。
