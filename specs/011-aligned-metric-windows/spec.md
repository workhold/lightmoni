# 固定窗口业务指标

状态：实现中；在当前 codex/sdk-onboarding 分支继续，推送远端，通过 PR 合入，禁止直接推主干。

1. 每个逻辑业务表只持久化一张指标物理表，现有 histogram 物理表继续使用，新增短名查询视图（逻辑表名）不复制数据。所有 metric_name/key1…key16 共存。公开字段 value/count/min/max/distribution，旧视图与查询兼容。
2. 根 SDK 初始化仍只要求 service/env，唯一五参数 record 不变。每张逻辑业务表选择一个上报聚合周期，任一时刻仅一个周期生效，同表所有指标与实例遵循该配置；不同表可独立选择。四种 SDK 默认30秒、UTC Unix epoch 固定边界聚合；固定支持10秒、30秒、1分钟、5分钟、10分钟、30分钟、1小时（10/30/60/300/600/1800/3600秒），由中心按逻辑表下发。候选周期按升序构成整倍数关系，任一较大周期均为前面所有较小周期的整数倍。观察归属按调用时刻确定，周期和起点参与分组；定时只发送已结束窗口，显式flush/shutdown可发送当前窗口增量，重试保持批次不可变。多实例/重启/提前flush以独立幂等片段保存，不互相覆盖。
3. 中心窗口配置有生效时间历史，变更在至少60秒后的新旧周期共同边界生效；SDK保持最近有效配置，失败保留旧快照。新配置请求显式协商版本，旧SDK配置响应不变。匿名只能获得实时豁免表配置。
4. 每行含window_start/window_seconds/received_at；event_time等旧字段保留。前端查询步长须为所选数据实际上报聚合周期的正整数倍，时间范围边界须对齐该周期；例如30秒上报允许1分钟、5分钟查询步长，不允许10秒查询步长。查询跨配置变更前后的多个历史周期时取公倍数。未知历史窗口不伪造对齐，不对其强加新约束。迟到不改变原窗口，最新窗口可能继续补充。
5. 同一批次同一资源/指标/维度/窗口的指数分布和Summary合成一行，完整分布数不足时min/max/P为空；不同批次独立增量。record_id/event_id保持原有幂等机制。普通sum/count/平均不依赖桶。
6. 分布正负连续桶槽总数不超过1024、编码大小不超过16KiB；超限降scale，数量/统计不因合桶丢失。新数据仅保存紧凑scale/offset/计数，不再重复持久化代表值数组。历史桶保留，公开分布字段在视图计算。总SDK缓冲/维度上限继续有效。
7. p005/p05/p10/p30/p50/p70/p90/p95/p995(distribution)、metric_min/max(distribution)在中心查询AST安全展开，统一完整性/空数据检查。使用quantilesExactWeightedArray，避免ARRAY JOIN导致统计重复；SQL样例采用短名和window_start。

验收：四SDK固定边界/切换/显式片段/自动封窗；总桶上限和数值极端；配置版本/鉴权/回退；实际CK单表、紧凑存储、跨实例和周期统计、P值/不完整保护、查询对齐、重试与旧数据；相关完整回归/构建，推送当前分支。

## 澄清记录（2026-10-19）

用户确认：“每张表选择一个周期，支持七档选项”。配置历史表示不同时刻生效的单周期设置。相应验收场景：

- 未配置的表使用30秒；七档分别可选，20秒、2分钟等枚举外周期拒绝保存。
- 表A选择10秒、表B选择5分钟，分别下发并独立生效；同表不同metric_name和实例使用相同生效配置。
- 每次记录仅归属调用时刻生效的一个周期；配置切换前的窗口和冻结重试保留原周期。
- 重复保存待生效周期不推迟原定时间；选择当前生效周期可撤销待生效修改。页面显示当前与待生效状态，加载失败可重试，保存失败保留输入。
- 七档升序中任一较大周期均可被所有前序周期整除；查询步长和范围边界按实际数据窗口校验，跨历史周期满足公倍数关系。
