# SDD 132：主机页按需加载文件、容器与终端弹窗

状态：规格先行，2026-11-12。

## 背景与目标

`/machines` 首屏会静态载入 `MachinesPage`。该页面静态导入文件管理、容器和终端弹窗；文件弹窗直接导入 `CodeEditor`，容器弹窗经 Compose 接管界面导入 `CodeEditor`，终端弹窗载入 xterm。因此即使只查看主机列表，浏览器也要下载并解析 Monaco 编辑器和终端脚本。降低主机页首屏脚本成本，同时保持点击后的明确反馈和原有操作语义。

## 场景与验收

1. 用户打开 `/machines` 只查看主机列表：文件、容器、终端弹窗，以及 Monaco 和 xterm 资源不随首屏请求；主机数据和管理员权限仍按现有流程加载。
2. 管理员打开文件管理、容器面板或 SSH 终端：按需加载所选弹窗，加载期间有可感知的对话框反馈；加载完成后原有会话、凭据、目录、容器和终端操作正常。关闭等待中的弹窗不会随后意外打开或创建 SSH 会话。
3. 管理员仅浏览文件目录或容器清单：不下载 Monaco。打开可编辑文本文件或 Compose 接管界面时才加载编辑器；文件编辑区加载期间有明确反馈，保存按钮、草稿与版本校验沿用现有逻辑。
4. 非管理员不能通过本轮改动触发文件管理入口或额外的敏感 API。既有中英文、键盘和窄屏弹窗行为不退化。
5. 升级前已打开的页面首次点击按需模块时，旧哈希资源可能因新镜像替换而返回 404；失败只影响当前弹窗或编辑区，用户仍可关闭弹窗或刷新页面获取新 HTML，不出现整页空白，也不创建未挂载模块的 SSH 会话。

## 功能要求

- FR-001：将主机页上的文件、容器与终端弹窗从静态依赖改为按需模块；避免其他静态导入路径使 `CodeEditor`/Monaco 或 xterm 重新进入主机页首屏。
- FR-002：文件弹窗的目录浏览与编辑器代码分开加载；只在文件文档已获取并进入编辑区时请求 `CodeEditor`。容器弹窗的清单与 Compose 接管界面分开加载，点击接管时才请求 Compose 子弹窗及其编辑器依赖。
- FR-003：按需加载期间保持弹窗标题、关闭操作和可访问的加载反馈；实际弹窗加载后仅挂载一次，不额外发起 SSH/API 请求。
- FR-004：不修改 `/machines`、文件会话、容器管理、终端会话、凭据或写入接口及权限判定；静态资源仍遵循 SDD 131 的内容哈希与缓存策略。
- FR-005：按需模块加载失败时显示局部错误和刷新页面入口；刷新读取不缓存的 HTML 与当前内容哈希资源。不得自动重试写入操作。

## 成功标准

- 构建产物与隔离浏览器网络记录证明 `/machines` 首屏不请求 Monaco、xterm 或三个弹窗的独立资源；目录及容器清单浏览不请求 Monaco；打开文本文件或 Compose 接管后才请求编辑器资源；点击终端后才请求 xterm。
- 主机页、文件管理与终端定向 UI 验证通过，包括首次文件会话单请求、目录、编辑保存、终端连接入口与关闭；`web` 类型检查和构建通过。
- 模拟按需 JS 资源 404 时，主机页仍可操作，文件弹窗与会话可正常关闭，刷新入口可见。

## 架构影响

不适用：本次只调整现有 React 组件的浏览器打包与挂载时机。组件职责、数据/控制路径、凭据边界、存储、协议、部署拓扑和 AI/工具边界均未变化；无需改写仓库系统设计或 Doca 设计文档。
