# 实施计划：主机页按需加载文件、容器与终端弹窗

**分支**：`codex/132-host-files-lazy`　**日期**：2026-11-12　**规格**：[spec.md](spec.md)

## 基线与决策

- `/machines` 通过 `App` 懒加载 `HostsNodesPage`，但 `MachinesPage` 静态导入 `HostFilesDialog`、`HostContainersDialog` 和 `MachineTerminalDialog`。前两条路径均到达包含 Monaco 和语言注册的 `CodeEditor`；终端路径载入 xterm。必须切断这三条静态路径。
- 使用 React `lazy` 与局部 `Suspense` 加载三个弹窗，保留管理员条件渲染和 host ID `key`。加载占位使用现有 `Modal`/`Spin`，不在占位期调用数据 API；关闭可取消等待中的挂载。终端仍先由现有流程读取主机详情；模块挂载后若有有效默认凭据，原有自动连接行为保持，关闭时清理在途会话。
- 文件弹窗自身按需加载 `CodeEditor`，目录列表无需编辑器；打开文本文件后才渲染编辑器，并预留与编辑器相同高度的加载区。容器弹窗延迟加载 Compose 接管子弹窗，使普通清单浏览无需 Monaco。编辑、保存及未保存草稿保护逻辑不动。
- 按需块在部署后可能因旧页面持有的内容哈希地址失效而返回 404。为弹窗与嵌套编辑器设置局部 React 错误边界，提供刷新页面入口；HTML `no-store` 会取到新版本资源地址。加载失败不挂载对应模块，也不自动重放文件写入。
- 不增加新的依赖或服务端接口。使用现有 Vite 内容哈希产物，符合 SDD 131 的缓存头。

## 顺序与验证

1. 固定规格、计划、前端加载契约与任务，记录基线构建的静态导入原因。
2. 实现三个弹窗的按需加载及文件编辑器内部切分，检查可访问加载反馈和关闭。
3. 运行类型检查、构建和隔离浏览器验证，记录首屏/目录/编辑/终端阶段的实际脚本请求与交互结果，并模拟按需 JS 404 验证局部恢复。
4. 同步 `origin/main`，检查差异，补验收记录并交由主流程创建 GitHub `main` PR。

## 兼容与风险

首次点击弹窗在冷缓存下需要加载独立 JS 块，因此加载期间要能看见进度和关闭；再次打开受浏览器缓存加速。懒加载不改变授权边界，服务端继续实时校验管理员、会话、主机及凭据。网络断开或部署替换旧块时，局部错误边界保持主机页可用并提供整页刷新；不自动重试任何文件写入。
