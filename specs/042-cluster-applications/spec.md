# Feature Specification: 集群与应用统一部署

**Feature Branch**: `codex/042-cluster-applications`
**Created**: 2026-10-29
**Status**: 用户于2026-10-30确认跨集群模型并授权实现首版与Demo
**Input**: 一机一集群；取消网关组及独立托管服务；应用手动/托管两种模式、多套部署、多命名端口、同集群网站；方案保存到 Doca 轻量告警系统知识库，真实运行 Web + MySQL Demo，域名和证书允许 mock。

## 2026-10-30 最终模型

用户最终确认：应用和网站为全局顶层对象。一个不可变全局serviceName可部署多个集群；选择manual或managed后，为每个集群选择机器或设置实例数、每实例CPU/内存。托管支持固定端口，冲突机器不可部署。OpenResty为host80/443应用，每集群最多一份部署，可托管换机；DNS按实际已验证入口实例动态更新。
网站的域名、HTTPS、证书、超时、路径及其他Nginx设置统一管理，只有各路径的上游URL或serviceName/命名端口按集群设置。绑定应用要求该应用在对应集群有部署配置；没有则拒绝保存/发布，暂时无健康实例则保留绑定并返回503。删除被引用的集群部署/端口必须先解除绑定。各集群发现严格局部，不跨地域兜底。

### 新增验收场景
- 同一应用在两个集群分别配置2个1CPU/512MiB与3个2CPU/1GiB实例，状态、端口、资源及发布修订独立。
- 托管固定端口冲突时跳过候选，现场冲突失败后可选另一候选；无候选保持待调度且不能改端口。
- 同一OpenResty应用部署多个集群，80/443固定且每集群单例；故障替换后新入口经HTTP/TLS验证才贡献DNS。
- 同一网站全局公共配置，两个集群路径指向各自本地服务；没有对应部署的绑定被拒绝。
- 网站DNS一次聚合全部集群入口公网IP，单集群更新不清除其他集群记录。
- 保存/发布一个集群部署不隐式升级其他集群；旧单集群Demo状态无破坏地读入为单项部署。

## User Scenarios & Testing

### User Story 1 - 从集群开始运维 (Priority: P1)
管理员先建集群，加入已登记机器，再安装应用与配置网站。
**Why this priority**: 统一运行资源的归属与调度边界。
**Independent Test**: 两集群重复添加同一机器失败；Agent 重装不改变归属。
**Acceptance Scenarios**:
1. 应用部署和网站作用范围必须选择集群，空状态引导创建集群。
2. 集群成员使用稳定主机身份，事务约束一机一集群。
3. 有运行应用的机器不能直接移出，非空集群不能直接删除。

### User Story 2 - 应用多套部署与两种模式 (Priority: P1)
商店或自定义模板可重复安装成独立应用；每个全局应用可以部署多个集群，手动指定各集群机器，托管按各集群期望副本和每实例资源维护实例。
**Why this priority**: 统一人工部署、服务发现和自动调度。
**Independent Test**: 同名 MySQL 两套成功，端口与数据独立；serviceName 重复/修改失败；两种模式故障行为不同。
**Acceptance Scenarios**:
1. 每套应用有全局唯一且创建后不可变 serviceName，默认模板英文标识加序号；展示名默认模板名，允许重复及修改。
2. 手动模式不自动换机器或补副本；容器本机重启策略单独配置。托管模式持续维护健康端点与期望副本。
3. 列表展示来源、模式、版本、安装机器和实际端口映射。
4. 数据库、本地持久数据默认手动，商店及安装表单显示托管建议及原因。

### User Story 3 - OpenResty 与多域名网站 (Priority: P1)
同一个全局 OpenResty 应用可部署多个集群，每集群最多一份 OpenResty 部署，在实际部署机器固定监听80/443，网站公共配置完整同步，仅上游按集群编译。
**Why this priority**: 网站复用普通应用部署与生命周期。
**Independent Test**: 同一集群第二份 OpenResty 部署、绑定没有本集群部署的应用均失败；不同域名分别访问同应用不同命名端口。
**Acceptance Scenarios**:
1. OpenResty 可选安装，网站自动关联本集群唯一入口应用，所有引用后端必须同集群。
2. 多命名端口整体预留与映射；重启核对恢复，删除被引用端口拒绝。
3. 网站逐域名绑定证书、解析及公共路由，只有上游按集群设置；完整配置逐机校验、切换、重载、访问验证，失败保留旧版。
4. 自动解析仅指向已验证入口机器公网地址，保留非平台管理的DNS记录。

### User Story 4 - 独立基础资源与快捷创建 (Priority: P1)
证书、托管域名独立页面；DNS、ACME、集群及机器在使用位置快捷创建。
**Independent Test**: 快捷创建成功后回到原表单，输入保持并自动选中新资源；刷新读回正确。
**Acceptance Scenarios**: 账号、证书和域名可跨集群复用；实际部署目标仍受集群约束。

### User Story 5 - 真实网站 Demo (Priority: P1)
平台安装 MySQL、自定义 Web 程序、OpenResty 和网站，通过浏览器读写数据库。
**Independent Test**: 请求真实经过 OpenResty → 程序 → MySQL，Web 重建后数据保留。
**Acceptance Scenarios**: 使用保留测试域、本地解析及自签证书；真实容器/端口/数据库不以夹具冒充。

### Edge Cases
- Agent 离线不等于容器停止，不释放未知端口；重装不丢失机器归属。
- 并发 serviceName 生成、多个端口部分分配失败必须保证唯一性与原子回滚。
- 保存草稿不改变已发布版本；过期回执不能覆盖实际实例状态。
- 多个数据库实例不隐式建立复制关系，本地数据不自动跨机复制。
- 部分入口发布失败展示逐机版本差异；DNS失败与应用运行分别记录。

## Requirements

### Functional Requirements
- FR-001: 产品统一称集群，稳定机器ID唯一归属；不复用采集标签分组语义。
- FR-002: 应用为全局对象，调度和后端发现显式带集群；机器归属唯一。
- FR-003: 取消可独立创建的托管服务和网关组，应用是唯一部署主体。
- FR-004: 应用选择manual/managed；deployments逐集群设置机器或副本/每实例资源，维护局部发现和故障替换。
- FR-005: serviceName 全局唯一、不可变、默认英文标识加序号；展示名可重复及修改。
- FR-006: 同模板可多套安装，配置、目录、数据、端口、版本和状态独立。
- FR-007: 商店内置受控版本模板；自定义应用支持镜像/Compose，用户程序通过Dockerfile生成镜像发布。
- FR-008: 多命名端口统一预留、映射、探活和恢复，网站按域名/路径引用应用端口。
- FR-009: 每集群仅一套OpenResty部署，支持托管，host80/443固定；同集群全部网站完整配置同步。
- FR-010: 证书/域名独立共享页面，DNS/ACME/集群/机器支持快捷创建回填。
- FR-011: 商店与安装页显示托管建议，本地持久存储与数据库默认手动。
- FR-012: 保留管理员授权、revision、不可变载荷、Agent lease、真实回执及秘密脱敏。
- FR-013: Doca保存方案，架构仓库/Doca基线同步并回读文本和原生图。
- FR-014: Demo实际覆盖 Web+MySQL+OpenResty、多端口及数据持久性，仅DNS/证书mock。

### Key Entities
集群、稳定主机、应用模板、应用部署/版本、实例、命名端口/分配、发现端点、网站/域名绑定、共享域名/证书/账号、执行记录。

## Success Criteria
- SC-001: 一机多集群、重复/修改serviceName、同集群第二份OpenResty部署及不存在本集群部署的应用引用全部被拒绝。
- SC-002: 相同展示名多套MySQL与自定义应用可创建，列表准确展示机器和全部端口。
- SC-003: 两种模式独立验收；多端口失败不泄漏预留，重启不随机改变映射。
- SC-004: 浏览器经网站真实完成数据库读写，Web重建后数据仍存在。
- SC-005: Doca方案与基线保存成功、文本/原生图回读一致；UI入口/保存刷新/失败交互通过。

## Assumptions
- Linux Docker/Compose、单中心；集群不隐式提供网络和数据复制。
- 首版商店内置受控目录，Agent拉取镜像。第三方商店源及平台源码自动构建流水线后续扩展，Demo提供源码与Dockerfile。
- serviceName 规则为小写字母、数字、短横线，首尾字母数字，最长63字符。
- Demo只操作隔离容器与测试资源，不写真实公网DNS/ACME或业务资源。
- 旧模型停止作为新入口；保留存储数据和历史执行，不静默删除容器或业务数据。
