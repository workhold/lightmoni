# Feature Specification: 私有镜像拉取凭据

**Feature Branch**: `codex/111-registry-pull-credentials`
**Created**: 2026-11-08
**Status**: Accepted for implementation
**Input**: 用户要求增加需要鉴权的仓库账号密码保存及应用拉取功能，合并主干并推送 Docker 发行。

## User Scenarios & Testing

### User Story 1 - 保存与维护仓库账号（P1）
管理员从镜像管理保存仓库地址、用户名、密码或 Token，可编辑、轮换、撤销并查看关联应用。密码不回显，编辑留空保留同账号密码。

**Acceptance Scenarios**:
1. 保存成功后刷新仍显示名称、仓库、账号和状态，任何浏览器读回均不含秘密。
2. 修改同账号的说明或范围可留空密码；换账号或仓库需重新输入密码。
3. 撤销后尚未开始的任务不得再取得秘密；有引用时删除被拒绝，展示引用。

### User Story 2 - 应用使用私有镜像（P1）
管理员在应用配置选择一个或多个仓库凭据，容器和 Compose、多仓库、升级、重试与托管换机共享同一流程。

**Acceptance Scenarios**:
1. 已绑定、仓库与仓库内路径匹配的有效凭据可拉取私有镜像并启动应用。
2. 未配置凭据的应用行为保持兼容；代理规则和匿名镜像继续有效。
3. 凭据按精确仓库和路径边界匹配，可限制集群；相同镜像存在多个匹配凭据时明确拒绝歧义。
4. 目标 Agent 缺少能力时明确提示升级，不能静默以匿名方式尝试或持久登录。

### User Story 3 - 知道失败原因并保护秘密（P2）
错误账号显示仓库拒绝访问，轮换和撤销使旧待执行授权失效。临时文件在成功、失败和取消后清理，日志、命令行及 AI 不含秘密。

### Edge Cases
Docker Hub 别名和 library、带端口仓库、仓库路径前缀边界、多镜像/多账号、用户名变更、过期或撤销、版本竞争、未匹配凭据、取消与拉取失败、旧 Agent、故障换机与应用配置更新。

## Requirements

### Functional Requirements
- FR001: 仅管理员可管理仓库凭据，保存后仅返回脱敏元数据。
- FR002: 支持用户名和密码/Token；秘密加密保存，输入不进入 URL、进程参数、通用资源或 AI 工具。
- FR003: 应用保存凭据引用；未选凭据继续原有部署行为。
- FR004: 每次派发与秘密领取检查应用/集群、镜像仓库/路径、有效期、凭据修订及执行能力。
- FR005: 认证镜像直接访问原仓库，避免向镜像代理和匿名共享缓存泄露账号或私有内容。
- FR006: 每个认证拉取使用独立临时认证文件，仅含当前目标仓库，完成后清理；预拉取成功后固定本机镜像 ID 启动。
- FR007: 支持凭据轮换/撤销、引用展示和删除保护；不自动重启现有业务。
- FR008: 通过 GitHub PR 合入 main，双架构固定标签 Docker 发行带匹配 Agent 包并回读校验；一并包含用户指定的 DNSPod 默认线路修复 PR149。

### Key Entities
仓库凭据、应用凭据引用、冻结任务授权、执行时临时认证文件。

## Success Criteria
- SC001: 管理员无需节点手工登录，即可完成私有镜像容器与 Compose 部署。
- SC002: 凭据保存与刷新、空密码编辑、轮换与撤销、失败重试均有自动化验收。
- SC003: 所有公开读回及执行记录均不含测试秘密，所有已结束认证拉取的临时文件均不存在。
- SC004: 主干 PR 和双架构固定标签发行可由链接及摘要核查。

## Assumptions
支持标准 HTTPS Registry 用户名/密码与 Token；Token 填密码字段。首版不自动获取云供应商短期身份，不配置不安全 HTTP/自签 CA。仓库内路径为空表示该仓库全部路径，集群列表为空表示已绑定应用的所有部署集群；应用必须显式选择凭据。保存不等于远程认证已验证，实际拉取结果以执行回执为准。
