# Feature Specification: 网站与运维控制平台

**Feature Branch**: `codex/033-operations-control-plane`
**Created**: 2026-10-29
**Status**: Approved scope; design before implementation
**Input**: 重构网站、域名解析、证书、Docker 应用与轻量服务托管；增加云服务换证和证书更新脚本。用户明确未上线，无兼容迁移要求，可重构底层结构。

## User Scenarios & Testing

### User Story 1 - 统一应用部署 (Priority: P1)
管理员配置单容器或 Compose，指定镜像、端口、网络、资源和挂载文件，选择机器部署，查看逐实例状态和负载。
**Independent Test**: 在隔离 Docker 主机部署、更新和停止，检查配置版本、容器健康与数据保留。
**Acceptance Scenarios**: 新建配置不执行；确认部署产生逐机器任务；文件完整校验后落盘；失败不能显示成功；停止不删数据。

### User Story 2 - 域名解析 (Priority: P1)
登记阿里 DNS/DNSPod 凭据及托管域名，分页查看并增删改查解析；网站与证书共用解析能力。
**Independent Test**: 两平台签名协议和 CRUD 夹具；有运行时凭据时做真实测试域验收。
**Acceptance Scenarios**: 托管范围外写入被拒；自动化保留外部记录；平台接受与传播状态分开。

### User Story 3 - 证书生命周期 (Priority: P1)
建立 ACME 账号，DNS 验证申请或续期；上传或自签证书；展示到期和自动签发策略。
**Independent Test**: 检查 PEM、公私钥、SAN、版本与续期计算；ACME staging 真实发证另记证据。
**Acceptance Scenarios**: 上传不能自动续期；自动/自签在授权范围内轮换；签发和分发分别记录；私钥不回显。

### User Story 4 - 证书目标及自动脚本 (Priority: P1)
将证书同步到网站、机器目录和阿里云/腾讯云/火山云 CDN 域名；证书更新后运行管理员设置的脚本，补充未覆盖集成。
**Independent Test**: 云 API 签名、上传、域名绑定、回读；Agent 原子安装和有限时脚本执行、失败重试及版本去重。
**Acceptance Scenarios**: 每目标独立状态；脚本明确指定 Agent、解释器、正文、超时和重试；每证书版本触发一次逻辑任务；未知结果不盲重放；stdout/stderr 默认不公开；脚本只拿显式配置的文件/环境，不能隐式获取平台所有凭据。

### User Story 5 - 服务托管 (Priority: P1)
为应用设置容器端口、资源大小、副本和机器组，平台选择机器及保留端口；Agent 部署、探活和上报。
**Independent Test**: 并发副本预留、资源不足、端口冲突、离线与健康状态、滚动变更。
**Acceptance Scenarios**: 资源与端口预留不重复；陈旧节点不调度；只有就绪实例进入发现；失联不等于停止；本地数据不静默迁移。

### User Story 6 - 网站联动 (Priority: P1)
配置静态、手工反代或托管服务网站，选择网关组、域名、HTTPS 和自动解析；同步到组内全部 OpenResty。
**Independent Test**: 两网关配置和证书摘要、失败保留旧配置、服务端点更新、DNS 所有权。
**Acceptance Scenarios**: 网关是 host Docker 应用；80/443 冲突拒绝；逐节点检查/重载/访问验证后才将节点加入受管 DNS；静态文件按版本分发。

### User Story 7 - 管理与持续运维 (Priority: P1)
五个核心能力提供人工可用的界面与领域 API，复用主机、日志、监控、告警和执行记录；显式启用自动化后持续收敛。
**Independent Test**: 真实 HTTP 保存/刷新/冲突、权限、秘密脱敏；页面创建和失败保持输入；中心重启继续核对。
**Acceptance Scenarios**: 自动动作具有管理员持续授权；管理员停用/降权停止新动作；AI 只读/提案，无脚本执行或批准工具。

### Edge Cases
- 云平台写入超时后先回读，无法确定时 unknown；避免重复上传或重复脚本副作用。
- 同域 ACME TXT 并发按记录值分别清理；通配符和普通域并存。
- 网关部分失败、节点失联、证书签发成功但目标失败，保持分别可见。
- 本地目录、卷和初始化文件保留运行期数据；禁止删除工作负载时顺带删除业务数据。

## Requirements

### Functional Requirements
- FR-001: DNS、证书为全局资源，不绑定单个 Agent；秘密加密保存，公开查询不回显。
- FR-002: 应用版本、部署任务、实例和服务有稳定关联，期望状态与观察状态分离。
- FR-003: 支持 Docker 单容器/Compose、挂载文件/初始化目录/数据目录、端口/网络及资源限制。
- FR-004: 托管服务具有机器组、资源/端口预留、期望副本、健康发现和有界重启/发布。
- FR-005: 支持两 DNS 平台 CRUD、平台能力差异和自动管理记录所有权。
- FR-006: 支持 ACME DNS-01、上传、自签、到期提醒和授权的自动续期。
- FR-007: 证书目录、云 CDN 和更新脚本目标独立执行/回读；新版本触发任务有持久去重和可追溯失败。
- FR-008: 网站静态/反代/托管服务联动，网关组内多节点分发和 host OpenResty。
- FR-009: 所有写操作检查管理员/授权者和 revision；Agent 只通过身份和有效 job lease 读取私有载荷。
- FR-010: 脚本是管理员显式授权的证书自动任务，固定目标/正文/解释器/环境/期限；内容修改使旧授权失效，AI 不得授权。
- FR-011: 系统提供中英文、主题、加载/空/失败、表单保存与结果记录；真实运行状态不得由登记配置冒充。
- FR-012: 全部架构变化同步仓库设计与 Doca 并回读，外部真实服务未验收须显式记录。

### Key Entities
凭据、DNS 区域/记录、ACME 账号、证书/版本、证书目标、应用/版本、部署/实例、机器池、端口预留、托管服务、网关组、网站、执行与持续授权。

## Success Criteria
- SC-001: 五项核心能力及三类证书分发目标均有可操作入口和实际执行路径，无空占位能力。
- SC-002: 每次变更可追溯资源版本、操作者、机器或云目标、实际结果和观察时间。
- SC-003: 重复调度不重复创建同一实例/端口/证书版本目标任务，失败与 unknown 可区分。
- SC-004: 测试覆盖真实 SQLite/HTTP/租约通路、协议签名、故障和权限；Docker/页面现场证据及真实外部验收分别报告。

## Assumptions and Scope
单一受信管理员边界、Linux Docker 主机、可达机器网络、单中心 SQLite。管理员配置脚本可调用自有集成；脚本无沙箱承诺，必须由 Agent 所在机器管理员信任。首版云适配器覆盖三云 CDN HTTPS 证书部署，更多产品通过可扩展适配器及脚本完成。用户未授权真实生产资源变更，不在开发验证中操作其业务资源。
