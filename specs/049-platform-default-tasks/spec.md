# SDD 049：平台默认任务与统一任务目录

状态：需求与设计已确认，开始实现；作为 SDD 048 的需求修订追加至 PR #24。

## 目标

平台初始化后已有可管理的默认任务；登记主机并安装 Agent 后，自动获得目标范围内的任务。任务中心不再需要独立模板目录或“从模板创建”的概念。默认任务与用户任务共用 Task、目标选择、启停、调度配置、主机覆盖及状态展示，以服务端维护的来源区分。

## 需求

1. 新平台持久化三条默认任务：指标采集、服务拨测、目录日志，默认启用并面向所有登记主机。指标可直接采集；空拨测目标、空日志目录为“待配置”，不执行空任务、不伪造成功。
2. Agent 通过现有出站配置通道获取适用任务；后注册、重装的主机无需复制模板或手动关联默认任务。停用默认任务、修改参数或缩小目标后，重启不得重置。
3. 所有默认任务都直接出现在任务定义列表，可配置、停用和设置单机覆盖。默认任务不提供删除，停止使用通过停用；用户脚本可删除且保留历史。来源不可由 UI、API 或 AI 伪造，任务类型创建后不可改变。
4. 新建任务只创建自定义脚本，直接进入代码编辑/上传；移除模板页、类型选择卡及模板接口/字段。已有非脚本用户任务保留原定义、目标、启停和编辑能力，新建原生采集任务被服务端拒绝。
5. 升级采用一次性事务迁移：保留已有默认任务 ID、用户修改、启停、目标、主机覆盖与历史；补齐缺少的三类默认基线，尤其日志默认任务。既有自定义任务不被提升为平台来源。迁移标记保证再次启动不会补建或重新开启。
6. 持续采集继续使用 Agent 原生处理器与配置 revision；有限脚本保留 TaskRun 和租约。两者统一管理语义，不强行把每次指标采样转成有限脚本。心跳、鉴权、配置领取、任务结果回传属于不可停用的基础协议。
7. 保留 SDD 048 的上传检查、日历预览、参数、工作目录、v2 能力校验、执行策略、快照和人工审批。内置 AI 与 Web 使用同一服务端契约。

## 验收

覆盖新平台默认目录、一次性升级/重启、停用与修改持久化、主机自动匹配、日志/拨测待配置、默认删除拒绝、来源伪造/类型变更拒绝、新建仅脚本、既有原生任务编辑与单机覆盖。浏览器验证无模板入口、新建直接编辑、默认任务编辑停用、双语与窄屏；运行相关回归、类型及构建。更新仓库与 Doca 设计并回读，不混入独立 MCP PR #23，不发布生产。
