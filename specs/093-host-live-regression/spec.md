# SDD093 主机现场回归修复

## 目标

对线上 790cca5 与单台授权测试主机执行主机、SSH 凭据、Agent 生命周期、执行身份、任务和采集回归；只清理本轮自建测试资源并恢复原仅监控模式。

## 发现与验收要求

1. 仅监控状态升级后再启用完整管理时，历史发行没有保留 helper 单元。回退计划必须在执行前识别组件不完整并给出明确处理提示，不能提供必然失败的完整管理回退；worker 同时保留独立防线，不能在无法验证组件时切换服务或静默拼装旧组件。
2. 中文部署历史显示本地化状态。
3. 主机任务跳转执行记录时关闭任务抽屉，并保留所选主机过滤。
4. 记录现场成功、失败、恢复和未覆盖边界，不把隔离或旧版结果当成本轮线上成功。
5. 维护包解压不得把全部解压内容同时留在内存；使用受限临时文件与有界分块，保留完整路径、链接、大小与校验保护。配置维护工作单元的 CPU/IO 优先级并以隔离压力结果说明内存边界；不能直接对真实主机复测高风险包。
6. 维护出现 unknown 时不重复 apply；停止本轮测试并先恢复主机，保留原失败证据。
7. 同一维护操作只能有一个 worker 取得原子执行权。重复、并发及中断后重放均不得改写已有回执、清理制品或释放拥有者的锁。
8. `preparing` 阶段收到可捕获终止信号时，协作取消并保留原服务；切换后、中断断电及 SIGKILL 不承诺自动恢复，仍需核对事实。
9. 大文件校验保持原指纹公式，以固定大小分块读取；真实发行包必须在本机、无网络、2GB 内存且无 swap 的隔离容器验证维护文件路径。模拟服务的结果不得作为真实 systemd 升级验收。

## 架构影响

不适用：修复既有维护协议的候选完整性判断、资源使用、单 worker 执行不变量、错误说明和前端导航；临时 TAR 和执行权标记均为既有维护目录内部实现，不改变组件职责、外部控制协议、凭据边界、业务存储或拓扑。系统设计与 Doca 无架构内容需要更新；现场故障、恢复和验证边界记录在本 SDD。
