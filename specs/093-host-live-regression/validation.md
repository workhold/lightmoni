## 中断现场与恢复

1. 仅监控跨版升级及合法的仅监控回退成功。完整管理回退到缺少 helper 快照的历史候选失败，未切换服务；本 PR 补上提前门禁与明确提示。
2. 另一轮完整管理跨版升级停在 `preparing`，平台为 `unknown`，随后 SSH 与 Agent 失联。一度观察到维护单元约 956 MB 峰值、约 2 GB 内存且无 swap、较高系统负载。没有取得完整内核证据，不能断言发生 OOM 或单一故障原因。
3. 用户通过云管理页面重启。恢复后核对维护单元停止、cgroup 不存在、原指针与审批原指纹一致、身份一致、原 Agent/helper 健康、无其他维护锁。保留原回执与恢复证据后，将远端记录归档为 `failed / worker_interrupted_before_switch`，再调用平台只读 reconcile 归档失败。没有重放 apply/start/worker，没有修改平台数据库。
4. 失败操作的回执、包与解包现场在卸载前移出安装目录，保留于测试主机的 root 私有维护证据目录；未标记升级成功。

## 现场收尾与未覆盖项

现场已恢复新版仅监控模式，Agent 在线，helper 已卸载，三项管理能力授权均关闭；原默认 root SSH 账户保留。临时系统/平台账户、sudo 规则、脚本任务定义、容器、日志夹具、本机测试密钥及主机覆盖已清理。测试专用 root 凭据已撤销；原凭据已到期，后续 SSH 操作需要用户重新保存凭据。主机 ID 保留，卸载重装后 Agent 身份重新签发，历史执行与审计保留。

以下仍需后续发行验收，不能称为“全部通过”：

- 修复版在真实 systemd 主机上的完整管理跨版本升级及回退；本轮没有再次向现场派发原高内存升级。
- OOM、SIGKILL、断电及服务切换后的强制中断恢复。不可捕获退出不承诺经过 finally；现有只读 reconcile 不会自动恢复仍停在 preparing 的死 worker，需要事实核对后的人工恢复。
- Docker 后安装/daemon 身份变化、任意业务服务部署、网络隔离故障及多主机批次；本次容器使用既有 daemon 与本地不可变镜像。

架构影响：不适用，原因见 spec。Doca 没有需要同步的架构章节，本轮未声称进行在线设计写入。
