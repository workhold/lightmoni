# 设计

1. 卸载记录继续使用 machine_uninstallations，plan 中持久 mode（standard/recovery）、reason、purge、固定 SSH revision、实际远端观察快照与撤销范围，无秘密；旧记录按 standard + 保留数据理解。
2. 恢复探测使用固定命令输出有界结构化证据，区分有效/缺失/无效身份，以文件摘要及固定路径状态约束审批目标；不输出原始配置/私钥。apply 在副作用前再次检查快照，执行模板在生命周期锁内再次检查，成功后按保留/清除策略验证。
3. 标准和恢复共享持久互斥与有限任务屏障。跨主机的相同实际 Agent、当前主机 ID、安装和维护 unknown 均不可绕过。恢复模式允许实际身份与无效旧登记不一致，但不能操作另一已登记主机的实际 Agent；成功不把孤立 Agent 自动绑定至当前主机。
4. 单次操作状态 CAS 防止迟到核对/回执覆盖已结束记录。核对只观察固定原 SSH 目标和批准身份；不能证明完成则保持 unknown，可证明原程序完整未移除时记失败。purge 后身份缺失是批准策略的结果，必须同时证明固定程序/服务及数据路径缺失。
5. 精确撤销：标准沿原规则确认实际归属；恢复仅在本主机绑定等于有效实际身份时撤销该身份的凭据，否则回执记录未撤销及原因，绝不使用损坏/缺失身份或旧绑定猜测。
6. GET /api/v1/agent-maintenance/uninstaller 返回管理员可用的固定脚本与 SHA256；前端下载 Blob，无令牌及请求路径。构建将同一脚本纳入发行包，安装至 /usr/local/sbin/lightmoni-agent-uninstall；已有安装可从界面下载。手动运行不冒称平台已撤销凭据。
7. 卸载窗提供标准、SSH恢复、手动脚本入口；计划前选择数据策略，恢复需原因；审阅包含模式、目标、实际身份、清除/保留路径、凭据边界。未知响应先恢复已有计划，unknown 支持选凭据只读核对。现有更新/批次交互保持。
