# SDD 133：Agent 一键升级与维护排队

## 用户场景

- 管理员在主机列表点击“升级 Agent”，系统自动核对主机架构、选择该架构最新可用发行并立即开始升级；窗口持续展示带时间的升级阶段和结果。
- 已排队但尚未领取的业务任务等待 Agent 维护结束后继续执行，不要求管理员先清空队列。
- 维护已经执行或结果未知时，管理员进入原记录查看进度、核对或恢复；不会重复派发升级。

## 功能要求

1. 单机升级不要求用户选择 amd64/arm64、发行摘要、SSH 凭据或生成和批准中间计划。使用主机显式默认的有效可复用 SSH 凭据，远端探测确定架构，发行目录选择该架构最新构建；当前已安装最新构建时明确提示。
2. 点击动作即代表管理员授权本次升级。服务端仍固定目标摘要、当前指纹、主机身份、凭据和权限代次，并在远端切换前再次核对。回退和批次现有审阅协议保持兼容。
3. 未领取、没有启动证据的排队任务允许等待维护；已领取、运行中、结果未知或无法证实未执行的工作仍阻止升级。维护期间不领取排队任务，结束后原记录可继续处理。
4. 升级日志持久记录安全的阶段、时间和结果，页面自动刷新并可在历史记录中回看；日志不得包含 SSH 输出、令牌、凭据或任意远端正文。
5. 请求响应不确定时只查询原操作，不能自动再次发起升级。已有待审阅、执行中或未知维护时允许打开原记录。

## 验收标准

- 一次点击进入升级状态，能观察到预检、启动、远端阶段、健康核验和最终结果；没有架构选择或计划确认。
- 同主机存在未领取任务时升级可启动且该任务不被领取；维护结束后任务记录未丢失。
- 已执行或未知任务、未知维护、错误主机身份、错误架构或无有效凭据仍明确阻止危险切换。
- 断连、刷新或关闭窗口后仍可按操作 ID 回读阶段日志和最终结果。

## 假设与边界

- “最新”按现有发行目录构建时间排序；只有匹配远端架构且完整可验证的发行可用。
- 保留旧计划接口供回退、批次和已有链接使用；本轮简化单机升级入口。
- 不自动操作生产主机；实际主机升级需在新版本发布后由管理员点击。
