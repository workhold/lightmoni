# 实施设计

## 路径

主机列表升级按钮打开进度窗口并提交一次 `POST /machines/:id/agent-updates/start`。服务端在短期维护准备栅栏内完成只读 SSH 探测，按探测架构选择最新已验证发行，复用现有固定计划与 `apply` 维护器协议；本次管理员点击直接授权执行。窗口按操作 ID 轮询持久结果和阶段日志。

## 排队与安全

排队且无领取/开始证据的 AgentJob、TaskRun 和 PrivilegedJob 不占维护通道。已有租约、运行中、未知或不一致的记录仍阻塞。计划准备和已创建维护仍阻断新派发及领取；原排队记录保持不变，结束后由既有调度继续。主机能力投影与服务端使用相同维护忙碌判断。

## 失败收敛

预检或切换前失败时结束尚未执行的内部计划并返回明确错误。切换请求一旦可能派发则沿现有 unknown/只读核对协议，不重试。阶段日志单独存储固定枚举和时间，避免回执覆盖；限制每次操作的事件数量，重复远端阶段合并。

## 架构影响

适用：新增管理员单次升级控制路径、维护队列判定与持久阶段日志。同步 `docs/system-design.md` 第 28 节和 Doca 系统设计基线的 Agent 维护章节，并回读文本、原生图节点和连线。凭据边界、SSH 固定维护器和成功证明不改变。

## 验证

运行维护队列、升级 API、Web 类型与交互回归；验证构建目标选择、重复提交、任务领取栅栏及事件回读。无真实主机写入，生产验收另记。
