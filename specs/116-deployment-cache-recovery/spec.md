# 集群镜像优先与升级后的只读观察恢复

日期：2026-11-09。分支：`codex/116-deployment-cache-recovery`。

## 用户要求与现场证据

用户要求排查“小猪绘本”部署失败，再次确认有集群缓存仓库时应优先从该仓库下载，并反馈每次升级后所有应用都显示“服务地址已保留，按中心配置恢复”。

只读排查确认：目标 zz-bj-1 在线，磁盘余量约 6.9 GiB、负载正常。ABC Demo 已开启内网镜像复用，注册端点为 http://172.21.0.16:20000，对外域名 docker.doc-a.cn。新镜像 20261109-78e657f 的 amd64 压缩层共约 373.78 MiB、最大层约 265.87 MiB。鉴权及清单请求成功，公网层请求最长约 299.8 秒，认证拉取在 300 秒超时；内网读取该层前 1 MiB 约 4 ms。

执行器账本中当前唯一未释放未知任务 2e04234d8fc5e2b814bb3b85c6b2ea2c 是 operation=inspect、task=workload.inspect，reported=true、released=false。其他应用容器仍运行，但这条只读观察占住整机任务通道，阻止新健康观察，触发各手动服务的地址保留提示。不得把该提示简单隐藏或直接宣称容器故障。

## 要求与验收

1. 对当前签名任务允许的镜像，保留已验证本机复用；实际需要下载时先尝试匹配的已注册集群内仓库/缓存，再按 allow_upstream 回退。绑定认证凭据不能跳过集群读取。相同 manifest/config 的不同仓库名称复用 Docker 已有镜像，不重复下载层或导入；可变标签升级先解析当前清单，不沿用旧版本。同机 Registry 与 Docker 各自持久化，不能将仓库 blob 目录当成 Docker 镜像；仅仓库有内容时仍经已校验的内网读取与导入。现场新版本的 config 摘要不在 Docker 本地，且无匹配 RepoDigest 别名。缓存失败后仅向原仓库临时取密认证，不把秘密发送给缓存或匿名来源代理，不改节点持久登录或 daemon。
2. 对中心/Agent 升级、断连、租约失效造成的未知只读平台观察，签名执行器通过原任务、原身份及原租约核对后可自动解除该条只读任务互斥，保留 unknown 历史，派发新的观察恢复真实健康状态。
3. 自动恢复严格限制冻结载荷中的 node.inspect、workload.inspect、gateway.inspect、registry.inspect，核对操作类型、任务/资源/Agent 身份与载荷摘要；未知 apply/stop/remove、脚本、容器写入、来源不一致或身份不匹配仍保留阻塞，不重放原动作。
4. 保留本机执行锁的精确 operation_id 和进程存活核对。新观察成功前不伪造 healthy，不移动手动部署、不改写成员地址或 DNS。
5. 增加真实 HTTP 缓存读取与签名协议/重启恢复回归；同步仓库与 Doca 原生设计并回读；通过 GitHub PR 合并并发布 Docker，按用户 2026-11-09 明确授权部署线上、重跑失败应用并核验恢复。

## 架构影响

适用：认证镜像的读取优先级及受管只读观察未知结果的自动核对路径变化。更新 docs/system-design.md 第111章及新增116章，同步 Doca 系统设计基线的对应原生段落/图块；保留其他节点与内容。无新增凭据、网络端点、数据库表或权限，继续使用既有集群端点、签名 reconcile、审计与互斥账本。
