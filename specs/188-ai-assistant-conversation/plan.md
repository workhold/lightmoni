# SDD 188 设计

1. 在现有 `/sessions/:id/turns` 中增加可选附件元数据/内容。图片为有界、校验 MIME 与字节数的编码载荷；PDF 由浏览器提取有界文本，中心重新校验。附件正文单独加密保存，Session 只持有引用与元数据；公共 Session 和 SSE 只返回元数据。
2. Worker 把图片转换为模型的 image part，把 PDF 提取文本作为不可信文件内容追加到用户输入。上下文压缩与预算估算不复制图片二进制；worker 传输和模型上下文均设置上限。旧客户端纯文本请求保持兼容。
3. 会话列表由中心结合进程内运行图和持久终态/工具回执派生 `running | needs_action | failed | idle`。运行图在中心重启后自然清空，持久事件仍可恢复失败与待确认摘要。
4. Web 把会话、流、草稿和待发消息按 session ID 管理。发送时冻结文本、附件和上下文；同一会话串行消费队列。立即发送先请求取消，再等待原轮终止，随后优先发送选中消息。切换会话时后台流继续更新所属会话，页面卸载时关闭请求。
5. 助手页采用 shadcn 的聊天滚动交互模式，使用既有平台主题变量呈现收窄的正文和输入区。移除常驻标题、模型和范围顶栏，原有数据范围及管理员设置放入输入区弹出控件。工具输出保留原审阅动作；完成时自动收起普通工具，待确认与整轮失败保持展开，已完成轮次的失败步骤保留折叠摘要标记。安全 Markdown 继续禁止原始 HTML 与外部媒体自动加载。
6. 先完成规格、契约和任务，再实现；最后运行相关测试、视觉与键盘验收，记录结果，同步主干并创建 GitHub PR。

## 兼容与风险

- `attachments`、会话 `status` 和 `user.message.data.attachments` 均可选。旧 Session、旧 SSE 客户端和纯文本 API 请求继续可用。
- 附件仅在会话所有者的模型请求中解密；不提供公开附件下载接口。模型供应商对视觉输入的支持由配置模型决定。
- PDF 提取保留文本与页数，不承诺 OCR、版面或嵌入图像理解；页面需明确提示。
