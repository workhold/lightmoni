# SDD 188：AI 助手会话交互

## 背景

当前助手的正文、工具和输入区域横向铺满内容区；流式回复持续推动滚动，输入框在响应期间禁用，用户不能准备后续问题。会话列表不显示执行、失败和待人工处理状态。工具调用逐项常驻，遮挡最终结论。用户希望采用接近 Codex 的聚焦阅读、队列与工具轨迹交互，并能附带图片及 PDF。

## 用户场景与验收

### US1：聚焦阅读与附件提问

- 桌面宽屏上消息和输入区保持舒适阅读宽度，窄屏填满可用宽度，无横向溢出；亮色与暗色均可辨识。
- 全页移除助手标题、模型标签和数据范围的常驻顶栏；表、服务、时间范围、模型设置及代码工作区可从输入区的按需设置入口访问，抽屉同样保持紧凑。
- 用户可在输入框选择、预览和移除图片或 PDF。图片随问题提供给支持视觉输入的模型；PDF 的可读文本随问题提供，文件名和页数在会话中可见。没有可读文本的扫描 PDF 必须报明确错误，不能假装已分析。
- 不支持的文件、超出大小或数量限制、读取失败均在发送前提示，已输入问题和其他附件不丢失。附件数据不经公共会话响应回传，也不进入 SSE、日志或 URL。
- Enter 发送、Shift+Enter 换行；图标按钮有可访问名称、可见焦点和明确的禁用/错误状态。

### US2：排队、停止与优先发送

- 当前会话正在响应时，用户仍可编辑并发送新问题；新问题进入可见的 FIFO 队列，包含附件和发送时冻结的页面上下文。
- 当前轮终止后自动发送队首。点击任意待发问题的“立即发送”会请求终止当前轮，并优先发送所选问题；其他待发问题仍保留原顺序。用户可移除单条待发问题。
- 响应中发送按钮变为正方形停止图标，点击终止当前响应；停止结果以服务端回执为准，不把未确定的远端操作标为成功。网络中断或拒绝发送时，待发内容不会静默丢失。

### US3：识别会话和步骤状态

- 会话列表对正在处理的会话显示动态 loading，对最近失败的会话显示失败，对有待人工审批或审阅的会话显示“待确认”。状态有文字，不只依赖颜色。
- 正文实时渲染安全的 Markdown、代码块和 SQL 操作。工具步骤以短摘要显示执行中/成功/失败/取消，SSH 安装检查展示受限检查命令语义与检查结果，不暗示提供任意 SSH shell。
- 整轮正常完成后自动收起工具轨迹，保留可展开的步骤记录；待人工确认或整轮失败时保持展开，已完成轮次中的失败步骤在折叠摘要上标明。最终回答优先呈现。没有公开的模型推理正文时，只显示分析进度，不伪造“思考内容”。

## 边界与假设

- 改造范围是 AI 助手整页和复用的侧边面板；不批量替换平台其他领域组件。
- shadcn 组件可在其他页面按需复用，本次验收聚焦助手及其共享入口。
- 待发队列属于当前浏览器页面，页面关闭或刷新时不自动执行未发送内容；已送达中心的轮次仍由中心事件确定最终状态。
- PDF 只提取可复制文本，不上传原始文件给模型；扫描件需另行 OCR。图片需要当前模型支持视觉输入，供应商拒绝时如实显示错误。
- 继续使用现有登录、会话所有权、模型和工具授权、审批接口及受限 SSH 检查。停止助手轮次不等于撤销已经产生副作用的原生操作。

## 成功标准

1. 桌面与 375px 窄屏的消息、输入框和队列没有水平滚动，输入区在宽屏不超过 800px；亮暗模式可用。
2. 两条待发问题按顺序发送；点选第二条时先取消当前轮、再发送第二条，第一条仍可继续发送或移除。重复点击不会重复提交。
3. 图片和文本 PDF 可在隔离端到端测试中进入模型输入；扫描 PDF、过大和非法附件被拒绝；会话 GET/SSE 仅含附件元数据。
4. 运行、失败、待确认状态和自动折叠在历史回放与实时流中一致；工具真实失败、取消及审批状态保持区分。
5. 相关 Runtime、AI Runtime、Web 检查和浏览器验收通过，验证证据写入本 SDD。

## 架构影响

新增附件从浏览器到中心再到模型 worker 的有界输入路径，并在会话记录中保留引用和可见元数据；会话列表增加派生状态。控制路径和存储边界发生变化，同一 PR 更新 `docs/system-design.md` 的 AI 分析与变更流章节。工具权限、审批边界、部署拓扑不变。
