# 网站服务端口可见性与 YAML 协议配置

日期：2026-11-09。分支：`codex/115-website-service-ports`。

## 问题与要求

用户反馈手动部署的后端在网站“服务名与端口”模式下没有端口可选，并确认截图中的 PostgreSQL 只是示例，实际要绑定 Web 服务。

现有网站只接受 TCP 上的 HTTP/HTTPS 命名端口，部署模式不构成限制。界面过滤其余端口后仅显示“暂无数据”，没有说明协议条件或修正路径。高级 YAML 新端口默认无应用协议；已有端口的空白或旧协议会覆盖 YAML 中显式填写的 app_protocol。单容器 YAML 的生成与表单转换也未完整传递该字段。

## 验收要求

- 手动与托管部署的 HTTP/HTTPS 端口都可以在网站逐集群服务后端及自动服务发现中选择、保存、回读。
- 未选服务、未声明端口、没有 HTTP/HTTPS 端口时显示不同原因；已声明的其他端口可见但不可选。说明 Web 服务需设置应用协议，YAML 端口项可使用 `app_protocol: http` / `https`。保留数据库 TCP/UDP 不能用于网站反代的边界。
- YAML 显式协议优先于之前保存的端口协议；未写协议时保留已有协议。单容器 YAML 生成及转回表单保留协议，外部 YAML 声明也可被识别。保持命名端口身份与宿主映射。
- 真实隔离 HTTP API 与浏览器验证手动 Web 应用、协议修正、两种网站绑定方式、中英文及窄屏；不修改生产部署。

## 架构影响

不适用：修复现有端口协议字段的读写优先级、单容器配置转换及网站选项反馈，沿用已有 HTTP/HTTPS 校验、资源契约、存储、服务发现与发布路径；不引入新协议、端点、组件职责、凭据边界或部署拓扑。`docs/system-design.md` 和 Doca 系统设计基线无受影响章节，无需改写或同步。
