# 发布设计

1. 从 GitHub origin/main 建立隔离工作区，合并两个功能分支并解决交叉冲突；保留原工作区未提交内容。
2. 运行 runtime/AI/web 类型检查、完整构建及平台、恢复、安全和受管执行器相关回归；使用单一集成 PR 合入 main，原功能提交保持可追溯。
3. 以合入后的 main 源码发布带 revision 标签的双平台固定版本，检查镜像和内置 Agent 产物；通过后用单独发行 PR 固定 compose 镜像。
4. 在用户指定 1Panel 终端核对现有目录和容器，备份现有部署配置与状态，沿用项目和数据卷拉取并启动；核对镜像 revision 与健康状态。
5. 浏览器验证仪表盘、私有镜像管理、应用/网站存储；升级必要的既有 Agent，通过最新回执验证能力。仅使用临时测试资源验证破坏性分支，保留用户业务数据。
6. 将发布摘要、检查及线上验收证据提交同一 SDD 的后续 PR，并按授权合入 main。
