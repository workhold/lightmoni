# SDD 165：AI 助手上下文韧性修复

## 背景与实测问题

生产只读诊断确认：20 张表的内部 `list_tables` 结果达到 65,430 UTF-8 字节；工具结果持续进入后续模型请求后，32K、64K 乃至 128K 本地预算均可能耗尽。自由日志分析还出现多轮无效 SQL 修正耗尽全部步数、没有最终回答，以及已选表仍读取全量目录的问题。Responses 的纯文本成功而工具请求失败已临时通过 Chat Completions 配置规避，本 SDD 不把供应商兼容或模型质量写成已修复。

## 用户场景与验收

### US1：有界目录与查询证据

管理员使用内部 AI 助手读取目录和执行遥测查询时，结果始终有明确、可验证的字节上限；目录只提供选择目标所需的摘要，列定义按需通过 `describe_table` 获取。外部 MCP 的现有目录与 60KB 查询样本契约保持兼容。

- 内部目录不再包含全量 `columns`，包含稳定 `id/name/kind` 和可用时的 `services`，完整序列化结果不超过 12KB。
- 超出目录预算时保留合法 JSON，并显式标记 `truncated=true`、`byte_limited=true`，不得截断字符串或制造无效结构。
- 内部助手 SQL 样本不超过 16KB；MCP 继续采用既有 60KB 上限。既有行数限制与 `sample_truncated` 语义保留。

### US2：最后一步形成最终回答

模型已经调用一个或多个工具但尚未总结时，运行时的最后一个允许步骤必须禁止继续调用工具，让模型根据当前证据生成最终文本。

- 在四种现有协议 fixture 下，最后一步请求均禁用工具；不再以 `step_limit` 代替可生成的最终回答。
- 最后一步仍执行取消、超时、输入预算、检查点和用量记录；模型未返回有效文本或上下文仍超限时，继续返回真实错误，不伪造成功。
- `max_steps=1` 时该唯一步骤为无工具回答步骤。

### US3：缩小查询范围并给出可纠正 SQL 反馈

页面已选择数据表时，系统指令要求直接读取该表结构，不先读取全量目录。内部助手 SQL 必须使用宿主时间宏，并优先单表、已核验列和简单聚合，避免无依据的跨表拼接与连续试探。

- 内部助手缺少有效 `$__timeFilter(column)` 时，在查询执行器之前返回明确、可纠正的错误；MCP 行为不变。
- 工具描述明确单表优先、时间宏、分组/排序列核验和有限纠错要求。
- 保持宿主 SQL AST、权限、时间范围和资源限制不变，不放宽只读边界。

## 功能要求

1. 内部助手目录适配层必须产生不超过 12KB 的摘要结果；外部 MCP 目录字段与列元数据不变。
2. `describe_table` 必须继续返回单表完整列定义和服务信息。
3. 助手查询样本必须按 `source=assistant` 应用独立 16KB 上限，并保留显式截断状态。
4. 运行时必须在最后一个允许步骤禁用工具选择，同时保持现有流式事件、checkpoint、取消和用量闭环。
5. 已选表上下文与 SQL 工具说明必须给出确定性的范围收敛指引。
6. 助手时间宏校验必须在宿主查询执行前完成，且不能改变 MCP 查询兼容性。
7. 所有错误必须保持诚实终态，不把部分查询、工具接受或最终步骤接受写成业务成功。

## 成功标准

- 使用至少 20 张带冗长列定义的表构造目录时，内部结果不超过 12KB，单表描述仍完整；外部 MCP 对照测试不变。
- 构造持续请求工具的模型 fixture 时，四种协议均在配置的最后一步收到禁用工具请求并正常 `done`，无 `step_limit`。
- 大结果样本分别满足助手 16KB、MCP 60KB；缺少时间宏的助手请求不进入查询执行器并返回可操作错误。
- 相关单元/集成测试、AI runtime 四协议测试、类型检查、构建和文档检查通过。

## 非目标与架构影响

- 不改变外部 MCP 工具名称、Scope、目录列元数据、审批或执行边界。
- 不自动切换模型协议，不宣称已修复特定网关的 Responses 工具调用，不认证真实模型 SQL 质量。
- 不调整生产配置、不发布镜像、不操作生产环境；本次只提交代码、测试和 SDD。
- 架构影响：不适用。组件职责、数据/控制路径、凭据、存储、协议和部署拓扑均不变，仅为现有助手适配层与运行时补充资源约束和终局行为，因此不改写 `docs/system-design.md`。
