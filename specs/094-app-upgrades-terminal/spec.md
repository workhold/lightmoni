# Feature Specification: 应用升级与容器终端

**Feature Branch**: `codex/094-app-upgrades-terminal`
**Created**: 2026-11-04
**Status**: Accepted for implementation
**Input**: 继续默认采集的后续验收；商店应用新版本点击升级，自定义应用升级；每个应用选择部署机器并通过 SSH 进入对应容器。

## User Scenarios & Testing

### User Story 1 - 点击升级商店应用 (Priority: P1)
管理员在应用列表看到已配置版本及商店最新版本，打开升级审阅后提交。升级保留环境、密码、端口、数据和部署位置，执行状态可追踪。
**Independent Test**: 将测试目录版本更新，已有应用显示更新；确认后目标镜像和版本更新且原配置逐项保留。
**Acceptance Scenarios**:
1. Given 商店提供新版本，When 刷新应用页，Then 显示可升级与目标版本。
2. Given 已审阅目标，When 确认升级，Then 保存新修订并按既有部署流程执行，显示逐机真实结果。
3. Given 应用配置或商店版本已变化，When 提交旧审阅，Then 拒绝过时请求，要求重新读取。

### User Story 2 - 升级自定义应用 (Priority: P1)
管理员逐服务填写新镜像，或重拉同一可变标签，确认后自动拉取并更新容器。
**Independent Test**: 单容器和多服务应用均能升级；仅选定镜像变化，配置与数据保留。
**Acceptance Scenarios**:
1. Given 自定义应用，When 修改目标镜像并升级，Then 目标配置成为新修订且部署使用该修订。
2. Given 相同标签，When 确认重新拉取，Then 不误报存在新版本，仍生成可追踪的重新部署。

### User Story 3 - 按机器进入应用容器 (Priority: P1)
管理员点击应用的容器终端，选择部署机器、实际运行容器、SSH 账户和 sh/bash，连接后直接进入对应容器。
**Independent Test**: 多机、多服务清单正确隔离；真实 SSH PTY 执行容器命令，断开关闭连接。
**Acceptance Scenarios**:
1. Given 多机多服务实例，When 打开终端，Then 仅列出该应用对应机器和容器。
2. Given 已选有效目标，When 连接，Then 服务端重新核验归属，远端只进入对应容器；失败明确显示，不能回落为主机 shell。
3. Given 无容器、容器停止、实例退役、凭据失效或配置变化，When 请求或连接，Then 拒绝或终止；成员无权限。

### Edge Cases
商店模板移除或服务结构变化、用户覆盖镜像、升级中并发请求、未知执行、离线主机、失败重试、同标签更新、无 shell 镜像、Docker 权限不足、过期容器快照、容器重新调度、一次性密码、关闭窗口、恶意镜像及容器输入。

## Requirements

### Functional Requirements
- FR-001 商店更新提示来自后端目录；明确区分配置修订、当前商店版本与可用版本，不按字符串大小猜版本先后。
- FR-002 升级必须审阅目标并由管理员点击确认；商店镜像审阅绑定目标指纹；变更配置和部署授权绑定修订，不进行无人批准升级。
- FR-003 仅更新镜像与来源版本，保留已有秘密、环境、命令、存储、端口、资源配额、身份和机器选择。模板服务拓扑不兼容时拒绝并提示手动配置。
- FR-004 自定义应用支持单容器与多服务镜像更新及同标签重拉；不声称自动发现远端仓库最新标签。
- FR-005 升级记录复用现有逐实例安装进度、失败/未知核对及主机执行互斥；不能把配置保存或队列提交当成功。
- FR-006 容器终端目标由后端应用实例及采集清单推导；绑定应用、部署实例、机器与完整容器标识，拒绝跨应用和跨主机请求。
- FR-007 终端复用现有 SSH 身份校验、凭据租约、会话所有权、限时、流控和撤销。远端再次核验容器标签与运行状态；仅允许 sh/bash，不能注入命令或回落主机 shell。
- FR-008 审计记录目标身份与连接状态，不保存交互输入输出和凭据；AI 无权调用终端。
- FR-009 补齐 PR94 未完成生产验收，按真实回读记录容器、网站、SDK 与队列结果，保留失败证据。

### Key Entities
- 升级审阅：应用配置修订、商店目标版本、逐服务旧/新镜像。
- 容器终端目标：应用、机器、部署实例、容器与 shell。

## Success Criteria

### Measurable Outcomes
- SC-001 商店更新后一次刷新可看到提示，升级审阅和提交在两分钟内可完成。
- SC-002 单容器与多服务升级测试全部保持原环境、存储和部署位置；过时及重复升级请求均被拒绝。
- SC-003 多机容器列表不混入其他应用，权限、跨机、失效目标和命令注入回归全部拒绝。
- SC-004 真实 SSH PTY 能连接选定容器并交互，断开后远端会话释放；应用页完整流程实际浏览器验证。

## Assumptions
- “自动升级”指用户点击后平台完成拉取、重建和核验；不启用定时无人升级。
- 商店目录由后端随平台发布维护，旧应用允许记录已不在当前目录的历史版本。
- 升级可能短暂中断服务；保留持久化数据不等于自动迁移数据库或备份数据。
- SSH 账户需有 Docker 权限或可无交互 sudo；目标镜像需提供选定 shell。
