# 应用管理与安装体验

日期：2026-11-01；分支：codex/062-application-management。

## 目标与参考

用户指出系统镜像仓库没有可配置端口映射，并要求整个应用管理、安装参考 1Panel。参考官方[安装部署](https://docs.fit2cloud.com/1panel/user_manual/appstore/install/)与[应用操作](https://docs.fit2cloud.com/1panel/user_manual/appstore/installed/)，采用“已安装 / 应用商店”、应用卡片、明确端口、基础参数与高级设置、安装后执行记录的工作流，保留 LightMoni 多集群和 Agent 回执模型。

## 验收

1. 应用管理页直接切换已安装与商店；支持名称、集群、主机和状态筛选。已安装卡片显示来源、镜像版本、真实状态、集群/机器及实际端口；直接进入配置、部署/启动、停止、安装记录、监控日志和详情。停止/移除沿用明确确认；移除保留持久化数据，删除登记不能被误称为删除数据。
2. 商店有分类、搜索和应用卡片；安装表单明确名称、版本、目标、必需参数、全部命名端口的宿主→容器映射。宿主端口0为平台自动分配；普通应用可选择全部地址或仅本机监听；OpenResty保留host网络80/443约束。高级设置保留标识、模式、资源和多集群。提交后显示真实执行进度，失败保留输入。
3. 系统仓库部署表单展示registry(5000)、hub-cache(5001)、origin-cache(5002)命名映射，可固定宿主端口或0自动；每集群独立保存、回读和重新部署。旧记录省略配置时保留原行为和已分配端口，不能因资源/缓存设置更新而丢失端口；固定机器/私网IP、系统应用身份和凭据边界保持。
4. 服务端验证端口名、整数0～65535和重复固定TCP映射；未知名称/非法类型不得静默接受。显式固定端口冲突必须失败，不自动换号。现有端口预留、节点现场检查、失败恢复和旧预留释放规则继续生效。
5. 多集群配置不互相覆盖；配置保存不自动发布其他集群；Agent任务忙时明确显示尚未生成安装执行，不能只提示已提交。旧API参数parameters.port和无host_ports的应用兼容。
6. 中英文、深浅色、390px、200%等效、减少动效和浏览器三轮回归；定向HTTP/SQLite/Agent载荷测试及类型检查。真实容器与受控回执分别记录，不把QA结果冒充生产部署。

## 范围边界

参考1Panel的信息组织和现有能力入口，不引入未实现的备份恢复、模板迁移/升级、任意Compose授权或宿主文件管理，不伪造相应按钮。保留现有自定义应用编辑能力。此次交付代码与PR，不自动发布镜像或改动线上应用。

## 架构影响

适用：既有application.deployments新增可选host_ports命名宿主端口覆盖；在既有投影/端口预留/Agent Compose链路生效，系统仓库部署API与商店安装API扩展字段。沿用既有修订快照和JSON存储、无新表或Agent协议。同步docs/system-design.md及Doca系统设计基线；写后回读新增章节、保留原生图与无关内容。
