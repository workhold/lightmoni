# 100 私有镜像列表与未使用版本清理

## 用户目标
管理员在私有镜像管理中选择仓库部署，查看镜像列表，按镜像查看全部版本，并一键清理没有任何应用使用的历史版本。

## 行为与验收
- FR-01 沿用现有页面与部署列表，新增「镜像与版本」面板；先选择部署，再选择镜像。版本按标签分页，显示摘要、使用状态与引用应用，支持刷新、空状态、错误重试，中英文文案齐全。
- FR-02 仓库内容由所选部署所在机器的受管执行器通过 Distribution V2 API 读取，中心不直连内网、不接受用户提供的任意端点，也不暴露凭据。完整遍历 catalog/tags 的分页；达到明确安全上限时返回错误，不能把部分结果当成全部。
- FR-03 清理作用于所选部署的整个仓库，与当前镜像筛选无关。用户确认后重新读取仓库和全局应用引用；保护所有应用当前配置（含未启动/停止）、部署冻结版本、尚未移除实例的观测/期望版本和执行中的发布载荷。只删除不被任何引用保护的 manifest 摘要，保护同摘要标签和多架构索引的依赖。
- FR-04 清理排队到确认终态期间冻结应用创建、修改、删除和新的应用 apply，避免引用检查与删除之间的竞态。unknown 保持冻结并使用现有任务人工核查/解决机制。开始执行前再次校验引用快照、仓库身份、修订、机器和端点。
- FR-05 清理显示实际删除、保留、失败数量，部分失败不能显示全部成功；重复点击不会重复排队；不自动重试不确定的删除。删除前完成全量扫描，读取不完整、未解析引用或缺失冻结版本时拒绝删除。
- FR-06 使用 Registry 已有删除接口，不运行垃圾回收、不承诺立即释放磁盘。系统仓库模板开启 manifest 删除；已有部署需重新部署生效，删除未开启时给出明确提示。

## 范围
仅系统登记的私有仓库；不管理商店安装的其他仓库，不删除机器 Docker 本地镜像，不改发布源/凭据边界，不引入定时清理。外部工具直接使用但未在 LightMoni 应用登记的镜像无法由平台判定使用情况，确认框说明这一范围。

## 架构影响
适用：新增受管执行器 registry.inspect/registry.cleanup 控制路径、应用引用快照与清理写入围栏；扩展 Registry 删除配置。同步 docs/system-design.md 与 Doca 系统设计基线，保留原生图块并最新版本回读，状态记录于 evidence/validation.md。

清理对象为 Registry catalog/tags 可枚举的历史版本；无标签孤立 manifest 与镜像层不通过此入口回收。清理期间不保证外部直接推送造成的可变标签变化，平台未登记的引用不在可判定范围。
