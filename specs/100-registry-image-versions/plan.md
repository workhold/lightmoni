# 实施设计

1. 在现有私有仓库控制器下增加内容查询与清理接口，复用 ops_platform_runs、签名受管作业、管理员授权、能力协商、租约与现有 unknown 恢复流程，不另建队列或凭据。
2. 中心生成可信端点、所有地址别名及全局引用快照；从当前应用、冻结部署/实例修订、未终结 apply 作业提取 container/Compose image。别名涵盖内部 host:port 与已关联网站域名（含标准 HTTPS 端口）。引用无法解析时清理拒绝。
3. 执行器封装有界 Distribution API 客户端：限制重定向、分页路径/来源、响应体、条目数、深度与请求时间。查询返回 catalog 或一个镜像的一页标签；清理在任何删除前完整扫描，按摘要去重并解析索引依赖，保护同摘要标签与多架构子项。
4. ops_platform_runs 中 registry.cleanup 的未终结状态作为持久围栏，事务内拦截应用写入和 apply；resolvePayload 再校验快照。读取不完整时不删除；删除中错误保留逐项结果并报告部分失败。
5. 前端沿用 Ant Design 表格与现有 lm-ops-panel；清理确认使用现有 Modal，加载使用 Spin/Button loading，结果使用 Alert。切换部署/镜像清除旧结果并忽略旧请求；不叠加装饰动画。
6. 用 API mock 验证真实 HTTP 协议分页、删除与保护，再用中心路由/作业 fixture 检查授权、引用、冻结与能力门槛，浏览器验证真实入口、分页、错误和清理确认。相关类型检查及针对性回归完成后记录证据。

## 兼容与部署
中心与受管执行器都需支持 operations.platform.registry.v1；旧执行器明确要求升级。系统仓库重新部署后启用删除；单仓库拓扑和存储路径不变。应用写入冻结只持续到清理确认终态，unknown 必须先人工核查。
