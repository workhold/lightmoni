# 网站发布与 DNS 管理流程整理

日期：2026-11-01。用户反馈网站创建后未同步入口解析/CNAME，排查发现入口选择了自行维护 DNS，网站只保存未发布；用户进一步明确“这块页面管理比较乱”。本次沿用现有视觉和授权边界，整理可见管理流程。

## 要求与验收

- 网站列表直接显示保存配置版本、发布状态、网站 DNS 状态及下一步操作。新建未发布不能显示为等待健康入口或已停用；历史停用与未发布区分，部分成功、失败、unknown 不冒充全部上线。
- 每个网站提供明确的“发布网站/发布当前配置”主动作，编辑配置为次要动作；检查、停用、流量与删除收于更多。发布仍进入原有版本/集群审阅和显式确认，不自动发布或同步未发布草稿。
- 网站保存后说明“配置已保存，需发布生效”，并打开该网站的发布与解析详情。网站 CNAME 与集群入口 A/AAAA 分开命名和显示；资格、厂商回读和公网传播不混称成功。
- 集群入口管理集中显示集群、入口域名、运行/解析状态与维护方式。修改入口域名和 DNS 托管只编辑相关字段，不再要求经过完整应用表单；仍保留部署详情与高级部署配置入口。自行维护、自动托管、尚未配置均有明确提示；自动托管必须显式选择托管域名，不能静默代选。
- 入口设置使用现有资源 revision 乐观锁，保存时只替换目标部署的入口域名与托管域名，保留其他集群、机器、副本、CPU/内存、镜像、端口和其他应用字段。冲突保留当前输入，不覆盖服务器新配置。
- 原有域名独立集群/流量、上游字段校验、HTTPS、证书及部署行为保持。中文/英文、浅色/深色、390px、200% 关键区域可用，减少动态效果可用。

## 范围与架构

不适用架构同步：本次仅重组现有网页信息与操作入口，复用原资源 PUT、actions 审阅/确认及只读 overview；不改变中心/Agent 职责、数据或控制路径、协议、存储、授权/凭据边界和部署拓扑。`docs/system-design.md` 与 Doca 系统设计基线无受影响章节，不进行无意义改写。

不修改用户线上配置、不发布真实网站、不改权威 DNS。DNS 数据资格与持续同步继续由现有后端决定。
