# 134 · 能力核心与 MCP 接入解耦

状态：已实现，待 PR 审核。继承 SDD 046/047 及全平台能力开放 Goal，本切片只交付 Slice 0：核心解耦与兼容基线，不扩展新的业务工具，不实现服务主体、直接执行或跨领域完整提案/执行索引。

## 需求与范围

1. Capability Registry/Dispatcher、会话主体、内部 AI 首批任务工具和通用 HTTP 能力入口始终初始化。
2. `LIGHTMONI_EXTERNAL_URL` 仅控制 MCP、PAT、OAuth 和外部授权管理；地址不合规时不得关闭核心能力层或让内部助手回退到另一套任务工具。
3. Session Principal 的当前用户、角色和安装级会话授权由核心访问模块负责；MCP Access 只负责外部 Bearer、grant 与 OAuth 生命周期。
4. 现有 MCP 工具名称、scope、输入、响应和审批语义保持兼容；现有 Web 领域 API 不迁移。
5. MCP 未配置时，历史或异常来源的 `source=mcp` 提案仍必须 fail closed；不得因缺少外部授权校验器而降级为内部操作。
6. 本切片保持单体内模块化和 SQLite 事实来源，不新增微服务、队列或第二套领域状态机。

## 非目标

- 不增加遥测行、日志、Trace、告警修改、部署、运维或 Agent 生命周期的新 MCP 工具。
- 不修改现有 Web 页面对领域 API 的调用方式。
- 不改变 PAT/OAuth 格式、授权页面、MCP 协议版本或真实客户端兼容声明。
- 不开放审批、自审批、任意 SQL、SSH、Shell、秘密读取或直接执行。
- 不操作生产主机、不发布生产镜像，不宣称真实 Codex/Claude OAuth 矩阵因本切片而完成。

## 验收

1. 外部 MCP 地址不合规时，中心仍创建能力安装记录、能力 HTTP 路由和共享助手工具；MCP 管理/传输按现有契约返回禁用。
2. 内部 `assistant` 与 `web` Principal 由核心访问模块刷新当前账户和角色，外部 `mcp` Principal 仅由已配置的 MCP Access 校验。
3. 无外部校验器时，外部提案审批失败且不创建 Task Run；内部助手提案的现有审批路径不变。
4. 现有 MCP 能力、授权、传输、任务和助手相关回归通过；全仓类型检查和构建通过。runtime 全量测试须执行并与 main 基线对比，不得把既有失败隐瞒为通过或把新失败归为无关。
5. 仓库系统设计与平台 MCP 文档在同一 PR 更新，明确核心与外部接入的独立生命周期。
