# SDD 189：受管单次任务优先领取

## 背景

`zz-bj-1` 的 Agent 与受管 helper 在线，Docker 容器持续运行且健康，但应用卡片在周期性 `inspect` 后反复出现“待核实”或“结果未知”。主机记录中，多数受管任务成功；部分未知任务没有进入 helper 的执行 journal。现有 `managed-once` 在领取指定任务前先进行应用指标和日志采集，该采集已有常驻 helper 执行，增加单次 SSH 派发的等待和竞争。

## 行为

- SSH 启动的 `managed-once` 先完成签名执行器心跳和策略更新，然后按指定作业 ID 领取任务；不在此路径同步采集应用指标与日志。
- 常驻 helper 继续按原周期采集应用观测并发送队列，单次任务仍执行原有计划、授权、租约、回执和未知结果围栏。
- 领取任务前的心跳或策略校验失败时仍拒绝领取；不得通过跳过心跳绕过能力与身份检查。
- 不把已丢失的历史结果改写为成功，也不因 Docker 容器运行就直接把未知任务标为成功。

## 验收

- 单次受管任务的模拟采集器阻塞时，精确任务仍能在心跳后领取并完成；模拟心跳失败时不能领取。
- 常驻 helper 的 `observeOnce` 路径仍执行应用观测；单次执行的签名和回执测试通过。
- 生产现场的只读观察与原回执分别记录，未部署本 PR 前不宣称线上抖动已修复。
