# SDD060：主机执行权限与独立运维执行器

状态：设计提案；本次交付规格、HLD/LLD、契约、实施任务和双端设计同步，不实现运行代码、不更改线上主机权限。

## 问题与目标

当前 Agent 以 `lightmoni-agent` 专用账户运行，普通脚本继承同一账户；默认不能操作 Docker socket、系统服务和受保护发布目录。把整个 Agent 改成 root 或加入 Docker 组，会同时扩大普通脚本与 Agent control 凭据的权限。用户既需要受控容器运维，也可能明确授权一次 root 或其他系统账户的脚本，二者必须分开。

采用普通 Agent 与独立 root 执行器。任务中心、平台 AI、外部 MCP 共用任务授权与记录；执行器独立出站连接中心，不接收普通 Agent 转交的任意命令，也不共享 control/data 凭据。

## 用户需求

1. 登记主机时在 SSH 用户名旁提前显示：“安装 Agent 需要 root，或支持免交互提权的 sudo 账户。登录账户用于安装和恢复，Agent 使用独立账户运行。”允许权限不足的账户先登记资产和登录终端。
2. 安装前真实预检 root/sudo，不能只判断用户名。需要交互密码的 sudo 首期不支持，不复用 SSH 密码；返回原因及可操作的修复说明。
3. 基础监控、普通脚本继续使用非 root Agent。主机分别显示普通 Agent、执行器、容器管理和提权脚本的授权及实际可用状态。
4. “容器管理”和“允许提权脚本”默认关闭，独立启用。开关授权安装/使用能力，不代替具体变更的计划批准。
5. 容器任务只接受结构化动作和受管资源范围；普通脚本不能访问 Docker socket。需要任意 root 脚本时，必须明确选择提权脚本模式，由管理员审阅代码、目标和身份后授权。
6. 提权脚本批准绑定完整不可变代码、解释器、参数、工作目录、环境/秘密版本摘要、目标主机、运行账户及组、超时和授权版本；任何变化重新审批。普通脚本不能因权限错误自动提权。
7. 首期支持一次性提权脚本。定时提权脚本为后续阶段，必须显式授权固定版本、固定目标和有限有效期；不能把一次批准无限复用于未来代码或标签新增主机。
8. 每次高权限执行和回执可追溯到任务、操作、计划、授权人、主机和执行器。离线不启动新的高权限步骤，未知结果不得自动重跑。
9. 启用、关闭、升级、回退、卸载和 SSH 恢复包含执行器及其权限状态；关闭权限不自动停止业务容器，回退程序不能恢复已撤销权限。

## 安全与非目标

- 普通 Agent 的 control 凭据不具有执行器 audience，不能领取、下载或报告高权限任务；本地同 UID 或用户自报 capability 不能作为高权限授权。
- root 执行器的代码、密钥、策略、暂存、journal 和锁均 root 所有，拒绝消费普通 Agent 可写路径。
- 用户批准 root 脚本等同授予该脚本整机管理权限，脚本可以破坏执行器或审计；签名、超时和子进程管理不构成 root 沙箱，也不保证独立业务健康证明。
- 本 SDD 不承诺抵御已攻陷的主机 root、中心签名方、Docker daemon，也不解决普通脚本与 Agent 同 UID 的全部隔离问题；不自动修改 sudoers、开放远程 Docker TCP 或安装 Docker。
- 不把 rootless Docker、Kubernetes、任意 Docker API、通用 root 终端和第三方现有容器接管纳入首期。

## 验收要求

| 编号 | 可验证结果 |
| --- | --- |
| AC01 | root、免交互 sudo、无提权和未知分别显示；普通用户登记成功不等于可安装 |
| AC02 | 开启两种能力分别审批；普通 Agent 和普通脚本拿不到 executor 私钥、Docker socket 和 root job |
| AC03 | 普通 control 冒充 capability、job/payload/artifact/event/result、跨主机或旧安装代次请求全部拒绝 |
| AC04 | 签名、摘要、授权代次、主机绑定、租约、期限、防重任一失败均不产生新副作用 |
| AC05 | Compose 危险字段、任意宿主路径、外部资源和未登记容器不能绕过受管容器策略 |
| AC06 | 提权脚本只按已批准身份及精确快照执行；修改/过期/撤权/离线/普通任务升级均拒绝 |
| AC07 | 重启、丢回执、断网、daemon 超时转 unknown；现场核对后才解除持久锁或创建新尝试 |
| AC08 | 关闭、回退、更新、标准/恢复/手动卸载不留下本平台隐式权限，不误删外部授权和业务数据 |
| AC09 | 所有入口形成统一任务 lineage；AI/MCP 只能提案，不能自行批准 root 脚本 |
| AC10 | 仓库系统设计与 Doca 文本、原生图及读回证据一致；目标能力明确标为未实现 |
