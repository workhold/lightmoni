# 规格：OpenResty 同机应用上游使用回环地址

日期：2026-10-31；分支：`codex/058-openresty-local-upstreams`。

## 用户场景与验收

管理员以托管服务模式将网站绑定到应用的命名端口。应用实例和 OpenResty 位于同一台机器时，网站请求应通过 `127.0.0.1` 访问该实例，避免绕行内网地址。

1. 同一集群有两台 OpenResty、两台机器各有健康应用实例：每台网关仅将本机实例 host 改为 `127.0.0.1`，另一台实例保留发现地址。
2. 同机后端保留所选命名端口的宿主端口和 HTTP/HTTPS 协议；异机 IPv6 地址保留方括号。
3. 应用实例不健康、过期、停用、退役或 Agent 身份失效时，不得因同机而进入上游；没有健康实例仍返回 503。
4. 手工指定应用端口的路径遵循同机规则；用户显式填写的代理 URL 原样保留。
5. 实例增减、迁移或健康变化后，各台网关使用当前拓扑重新生成配置；稳定拓扑不反复发布相同配置。

## 需求

- FR-001：按目标 OpenResty 实例的机器身份判断同机，不能以集群相同或 IP 字符串相同代替机器身份。
- FR-002：仅替换平台发现的同机应用端点 host，保持协议、端口、健康过滤、集群和域名范围。
- FR-003：每台网关独立生成完整配置及其签名，沿用 Agent 的检查、切换、重载与失败回滚。
- FR-004：发现接口继续报告实例实际地址；只有集群上下文的预览继续使用发现地址，不猜测目标网关机器。
- FR-005：不新增配置项、数据库迁移、Agent 协议或用户审批流程；更新仓库和 Doca 架构文字并保存回读证据。

## 成功标准与范围

双网关配置能够分别验证本机回环、异机原址，HTTP/HTTPS、IPv6 和多命名端口均正确；健康失效后配置移除对应后端；显式代理 URL 与发现 API 不变。相关集成测试和 Runtime 类型检查通过。

沿用已有 Linux host 网络 OpenResty 与应用宿主端口发布模型，不改变部署拓扑或跨集群策略，不推测容器内独立网络命名空间中的 localhost。
