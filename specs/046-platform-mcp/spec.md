# 046 · 平台开放能力与 MCP

状态：架构提案，尚未实现 MCP 服务。本轮只交付需求、设计、契约与实施验收计划。

## 驱动目标

用户既能使用本地 Codex、Claude 等 MCP 客户端，也能使用平台内置 AI 助手，调用 LightMoni 的监控、告警、主机、任务、部署和运维能力。任务中心负责主机任务的提交与记录；平台开放能力的范围大于任务中心。MCP 是面向 AI 客户端的协议适配器，统一业务能力层是权限与执行的事实来源。

## 必须满足

1. 外部 MCP、内置 AI、Web/HTTP 复用同一能力定义、鉴权、提案审批、幂等及安全结果投影；不得复制业务执行逻辑、伪造管理员或助手会话。
2. 采用远程 Streamable HTTP，计划入口 `/api/v1/mcp`。工具可发现、按授权过滤、输入输出有 schema；工具注解和客户端确认不是平台授权。
3. 用户授权采用 OAuth 2.1 授权码 + PKCE；个人令牌作为支持 Bearer 配置客户端的补充。首期不将个人令牌声称为完整 OAuth 互操作能力。SDK、Agent、SSH 和模型凭据不能用于 MCP。
4. 权限取当前账户角色、凭据 scope、资源授权与审批策略的交集。用户停用、降权、令牌撤销、目标变化后，已缓存的工具列表和会话不能保留旧权限。
5. 主机主动操作（含 SSH 预检等只读主机检查）统一关联执行 ID 与持久记录，保留既有任务、部署、运维和 Agent 生命周期状态机。中心元数据/遥测查询仅需调用审计；持续采样不逐条创建任务实例。
6. 首期对外开放安全读取和提案，不开放 apply/commit、任意 SSH、凭据读取或 unknown 人工确认。后续自动执行只接受管理员预授权的固定能力、目标、参数界限与期限，模型不能自行审批。
7. 长任务返回执行/提案 ID，连接中断不取消已接受操作。RPC ID、MCP 会话、提案与执行 ID 分离；重试使用业务幂等键，unknown 不自动重放。
8. 远端 MCP 不获得用户本地源码访问权。用户本地 AI 负责本地改代码，平台只处理明确授权的中心工作区或已提交版本/制品。
9. 分领域扩展工具；发现、资源读取和调用均执行同一授权。任意新工具注册必须声明输入输出、权限、目标解析、影响、执行策略、幂等和审计。

## 非目标

本轮不增加运行中的 MCP/OAuth 端点、不修改执行器或现有权限，不安装客户端配置、不发布镜像、不操作生产主机。多租户隔离、服务账户和受控自动执行是目标架构后续阶段，不能据字段预留声称已实现。

## 验收标准

设计覆盖 HLD、LLD、协议、身份/授权、审批、执行记录、凭据、工具矩阵、API 和失败语义。仓库系统设计、README 与 Doca 同步并回读原生图。后续实施须通过真实 Codex/Claude 版本矩阵、OAuth/令牌隔离、工具发现/调用越权、幂等/断连/撤销、既有领域回归与主机执行证明，详见 [plan.md](plan.md) 与 [contracts.md](contracts.md)。
