# SDD 048：脚本任务创建与日历调度

状态：实现与本地验收完成，已提交 [PR #24](https://github.com/workhold/lightmoni/pull/24) 待审阅。用户已确认“上传脚本或直接编写，共用编辑器；手动与 AI 创建相同任务”的设计，并授权开发。本轮独立于尚未合入的 MCP PR #23，基于最新 main。

后续修订：[SDD 049](../049-platform-default-tasks/spec.md) 取代本规格中的独立模板页与新建类型选择，改为平台默认任务和直接脚本创建；本规格其余上传、调度、执行及审批契约继续生效。

## 问题与目标

新建任务默认展开指标采集，脚本能力隐藏在类型下拉；已有脚本仅支持手动和固定间隔。用户难以创建“生产数据库主机每天凌晨两点运行 backup.sh”这样的普通运维任务。

任务统一由执行内容、触发方式、目标主机和执行策略组成。内置指标/拨测/日志保留持续运行语义；自定义脚本是有开始和结束、逐主机留回执的有限执行，不把每个采样点建成一次脚本运行。

## 本轮需求

1. 新建入口明确展示“自定义脚本 / 内置任务模板”，采用宽抽屉，内容、计划、目标和高级设置有清晰分区。既有内置任务仍可正常编辑。
2. 自定义脚本可直接在空白编辑区写代码，也可上传 UTF-8 `.sh`、`.js`、`.mjs` 文件填充同一编辑器；上传后可修改，最终只保存编辑后的代码。限制 64 KiB，拒绝不支持的扩展名、无效 UTF-8、NUL 和超限文件。已有代码被替换前明确确认。
3. 支持 POSIX shell / Node.js；增加显式参数数组和可选远端绝对工作目录。参数不经 shell 拼接，保持清洁执行环境，不注入平台或 Agent 秘密。带新参数/工作目录的任务要求 Agent 的新版本能力，不能在旧 Agent 上静默忽略。
4. 脚本计划支持手动、指定时间一次、固定间隔、日历 Cron + IANA 时区。日历提供每天/每周/每月的可视配置，Cron 为高级输入；调用同一后端预览未来五次时间。旧 `once` 保持“手动”含义。
5. 用户可选主机、标签或明确全部主机，预览实际匹配主机及 Agent 就绪状态。标签按派发时解析；每次运行保存准确的目标和代码快照。
6. 高级策略包含超时、输出上限、任务全局并发上限、队列等待期限及失败重试次数/间隔。默认重试关闭、同任务同主机不重叠、错过计划不补跑；未知结果禁止自动重试。只在明确失败回执后按原快照重试，任务版本、授权或绑定已变化时停止自动重试。
7. 计划由中心持久化并派发，Agent 仍向外领取；不向主机写 crontab。一次定时只消费一次，即使重启、禁用再启用或错过触发也不重放；重新安排须设置新的未来时间。日历和间隔停机后只安排下一次，不回放历史时段。
8. 保存前可审阅代码、计划摘要、目标和策略；保存草稿不执行，明确启用计划表示授权后续按该计划执行。内置 AI 创建/修改仍使用同一规范化与人工提案批准边界，不新增 MCP 自动批准或外部源码写工具。
9. 中英文及 390px 窄屏可用；持续任务与有限脚本的状态、计划和执行记录准确显示。

## 非目标

本轮不增加 Python/Java 等运行时、任意环境或秘密注入、脚本依赖自动安装、DAG 工作流、抢占正在运行任务、自动补跑历史计划或把 unknown 判为失败。SDK 独立直报与 Agent 安装链路不变。

## 验收

验证文件上传与直接编辑保存同一内容、计划 preview 与 scheduler 一致、时区/DST、单次消费、重启与错过计划、任务修改与重试边界、并发/队列期限、参数原样传递和工作目录，以及旧 Agent 对新执行选项的明确升级要求。UI 需实际浏览器验收；全量后端回归、类型与构建通过。按 AGENTS.md 同步仓库/Doca设计并回读，提交 GitHub PR。
