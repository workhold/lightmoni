# Feature Specification: 首次正式发布前的单一基线清理

**Feature Branch**: `codex/081-prerelease-cleanup`
**Created**: 2026-11-02
**Status**: Accepted
**Input**: 整个项目尚未正式发版，移除历史兼容代码和升级 SQL，交付最干净的版本。

## User Scenarios & Testing

### User Story 1 - 干净安装（Priority: P1）
管理员从空目录安装后直接得到当前完整数据结构和默认配置，无须执行历史升级。
**Independent Test**: 空目录启动、登录并检查目录、默认任务、主机及运维资源。
**Acceptance Scenarios**:
1. Given 空安装目录，When 首次启动，Then 直接建立最终结构并且所有当前功能可用。
2. Given 当前基线已初始化，When 重启，Then 用户修改和业务状态保持不变，默认内容不重复创建。

### User Story 2 - 单一当前契约（Priority: P1）
开发者只维护当前字段、凭据边界和执行路径，不再维护历史格式转换。
**Independent Test**: 执行相关契约与完整回归，并检查旧入口和迁移命令已删除。
**Acceptance Scenarios**:
1. Given 历史版本字段或接口，When 请求，Then 不转换成当前格式或恢复旧权限。
2. Given 当前 SDK、Agent 和独立执行器，When 正常使用，Then 上报、任务、运维和权限校验成功。

### Edge Cases
- 已有开发数据目录不自动清空或转换；不支持的中心基线在初始化业务模块前明确报错。
- 当前版本的重启恢复、任务 unknown 栅栏、普通身份权限拒绝与升级回退仍属当前功能。
- 第三方协议适配、应用自身的数据升级、业务迁移保护和故障容错不视为历史版本兼容。

## Requirements

### Functional Requirements
- FR-001: 移除首次发布前的历史结构升级、数据搬运、迁移标记和旧别名。
- FR-002: 新安装直接获得最终结构、当前系统应用身份、标签和默认任务。
- FR-003: 移除旧字段、旧配置与旧写入路径的转换及对应独占测试和运行手册。
- FR-004: 当前功能、权限隔离、审计、故障恢复和当前版本重启保持有效。
- FR-005: 不在用户实际环境执行数据删除；历史开发环境重建由管理员明确操作。
- FR-006: 同步仓库与 Doca 架构基线，保留在线原生图块和无关内容，并记录回读。

## Success Criteria

### Measurable Outcomes
- SC-001: 空目录首次启动及重复启动均通过验收，默认内容只创建一次。
- SC-002: 全项目已识别的历史兼容路径都有删除或保留理由，运行时不再执行补列/旧数据迁移。
- SC-003: 当前功能相关检查、类型检查、构建和完整自动回归通过，受环境限制的验证明确记录。
- SC-004: 仓库和在线设计记录相同基线，在线回读验证文本与原生图块保留。

## Assumptions

- 用户明确取消首次正式发布前的数据和协议兼容义务，优先于旧规格中的数据升级要求。
- 保留历史 SDD 与验收证据作为记录；当前 README、契约与设计不得继续要求已删除的升级路径。
- 用户追加授权：完成后创建并合入面向main的GitHub PR，发布Docker双平台镜像，并回读标签与摘要。
