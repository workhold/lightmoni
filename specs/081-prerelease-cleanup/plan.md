# 设计：首次发布前单一基线

1. SQLite 各领域 CREATE TABLE 直接声明最终字段与索引；删除 PRAGMA 探测后 ALTER、表重建、旧行回填和一次性迁移表。中心启动用明确的基线标记拒绝历史开发数据库，不执行自动清空。
2. ClickHouse 建表直接包含当前全部列；删除启动补列、旧系统逻辑表搬运/兼容视图，只保留现行公开表和动态业务表创建及保留期修改。
3. 删除旧任务分组到主机标签的搬运与旧分组入口，默认任务采用持久初始化标记，用户删除/修改后重启不复活。
4. SDK Key 删除已弃用的逐表范围数据库字段、请求字段与响应字段，匿名豁免表的当前内部授权仍有效。删除已被集群模型替代的 node_pool/service/gateway_group 控制器及旧实例表；保留当前集群共享的端口与节点观测表。删除旧凭据到中央凭据库的搬运、系统应用改名别名、旧单集群规格转换、旧主机地址回退、旧告警策略填补和旧模型费用回退。
5. 独立执行器直接使用 root 私有业务目录，删除离线旧目录迁移命令、运行门禁和发行脚本中的迁移验收；保留普通 Agent 非特权核验、签名、维护锁、unknown 栅栏和当前程序回退。
6. 部署统一根 Compose，删除 with-clickhouse 重复入口；应用端口只使用 host_ports 命名映射，拒绝 parameters.port。
7. 清理无调用者的历史帮助代码与旧独占测试，现行协议（OTLP/OpenAI兼容/S3等）、第三方应用迁移与业务数据安全保护按语义保留。

## 架构影响

影响存储初始化、旧协议/字段边界与运维离线控制入口，需同步 docs/system-design.md 与 Doca 系统设计基线。新增当前基线章节明确覆盖历史 SDD 的升级义务，局部修订旧初始化描述，保留图块与无关内容。

## 验证

使用现有领域回归与集成测试，加上必要的空库/重启和旧中心基线拒绝检查；npm run typecheck、npm test、npm run build。可运行的脚本做语法校验，Linux/真实 Docker 验收如无法运行须说明。
