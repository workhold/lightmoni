# Agent 卸载状态与继续操作

## 问题与目标

升级后创建 Agent 卸载计划，主机列表只显示“待确认的卸载计划”并置灰后续维护按钮。审阅、取消和核对入口藏在详情底部；卸载请求等待期间对话框仍显示待确认，且刷新被 busy 锁阻止，用户无法判断是否执行。

## 要求

- 管理员在主机列表直接打开已有卸载流程；待确认/过期计划可审阅或取消，执行中可查看状态，unknown 可只读核对。维护按钮禁用不能阻止打开原记录。
- 入口根据后端能力原因和已有卸载状态展示；打开时重新读取该主机持久历史，优先恢复未结束记录，验证主机与记录 ID，不创建新计划，不自动 apply。
- 发出 apply 后立即说明请求已发送、正在检查/等待结果；通过原记录 GET 定期读取真实状态，长请求不能阻止观测。不显示虚构百分比、逐步完成或卸载成功。
- 执行请求已发送后禁止重复 apply。若请求失败但原记录仍 awaiting_approval，允许取消尚未执行的计划；running/unknown 仍遵循既有状态约束。读取失败明确提示并允许重读。
- 对话框中的状态和审阅/取消/核对按钮保持可见，长计划正文在内部滚动。中文与英文均可用。
- 完成、取消或核对结束后刷新主机能力。迟到读取不能覆盖较新的操作结果，关闭后不再轮询。

## 架构影响

不适用：修复现有网页卸载状态呈现、原记录入口与 GET 刷新时序，继续使用既有主机详情和卸载 API，不改变组件职责、服务端控制路径、存储、协议、凭据边界或部署拓扑。无需修改 docs/system-design.md 或 Doca 设计基线。

## 验收边界

使用实际生产网页构建和隔离 HTTP fixture 覆盖待审批恢复/取消、过期取消、执行等待与轮询、unknown 核对、读取失败、防重和迟到响应。保留现有卸载与恢复卸载回归。此验证不代表实际 SSH/systemd 或用户生产主机卸载成功。
