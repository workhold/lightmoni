# Feature Specification: 统一运维发行与持续采集恢复

Created: 2026-11-04. Branch: codex/095-unified-operations-release.

## User Scenarios & Testing

### US1 保留并行改动并统一发行（P1）
管理员升级中心后，既有主机管理界面、安装修复、托管可用性、遥测、应用升级和容器终端同时可用，不因单一分支覆盖其他能力。
验收：固定发行包含各来源提交；当前生产界面与资源数量保留，双架构成品测试、摘要回拉和线上回读对应同一源码。

### US2 恢复持续遥测（P1）
六个应用自动上报容器指标/日志，四个网站具有访问日志和QPS，ABC SDK持续业务指标与日志可见。
验收：不删除中心/Agent积压、不重置游标，连续三轮真实请求/采样均产生新数据；对孤立历史批次如实诊断和处理，不篡改失败审计。

### US3 安全升级执行器与验证应用操作（P1）
中心和Agent/helper配套升级，支持镜像刷新及新版健康检查；升级前检查当前机器、凭据、策略、维护状态和回滚条件，升级后回读实际发行与能力。应用升级与SSH容器入口经过平台正常流程验证。
验收：不绕过维护锁与未知结果门禁；业务容器持续存在，升级结果与实际版本/能力相符，SSH进入所选容器。验收性业务升级以现有ABC演示为目标，保留业务配置和持久数据。

## Requirements
- FR000 本轮续接纳入商城PR100（fdf731b）：35个应用、8类，包括Meilisearch、SearXNG、Firecrawl、RustFS；复验商城表单、分类及官方容器业务，固定新源码后重建双架构发行，不复用旧候选宣称已包含商城。
- FR001 各来源功能保持，记录来源PR/SHA、冲突解决及最终差异；本轮已获用户合并授权；相关检查通过后通过PR合入GitHub main，禁止直接推主干。
- FR002 发行前固定源码，构建arm64/amd64，验证完整成品、Agent包、Web及镜像配置；发布固定标签，用户已于本轮明确授权验收后合入main、发布GitHub及Docker正式版本；latest在成品及线上验收通过后指向统一发行。
- FR003 生产切换前核验当前实际镜像和源码、队列空闲、备份状态库/密钥/部署配置，使用比较并交换防止覆盖并行发行；只更新中心容器，保留业务容器和数据；失败回滚旧镜像。
- FR004 Agent升级仅使用已登记凭据与平台维护审阅/审批路径，不写入明文秘密、不借用无关账户或重置执行锁；核对资源预算和兼容性。
- FR005 连续采样核实容器、网站、SDK、队列恢复；健康接口和容器running不等价于遥测验收通过。
- FR006 SDD/PR明确架构影响，组合后的控制路径及镜像刷新/健康能力边界同步仓库与Doca；保留原生图块并最新回读。

## Success Criteria
1. 来源PR92、94、95、96、97、98的相关能力全部保留；PR93发行记录保留，默认镜像由本次固定版本接续。
2. 两架构成品与发布后的不可变摘要内容一致，线上中心运行相同固定源码。
3. 六应用和四站点三轮采样持续产生新容器/访问数据，SDK三类指标与两类日志持续更新。
4. 正常平台流程能升级ABC应用并通过SSH进入选定容器，旧维护审计/业务数据不丢失。

## Assumptions
用户已授权跨聊天协调并保留各项改动，继续此前发行/部署与生产验收；用户后续明确授权本次全部变更通过PR合入主分支、发布Docker/GitHub并部署平台，逐项验收SDK上报、容器日志、应用大盘等功能。中心发行先行，Agent配套升级按正常维护流程执行；不可证明兼容时停止受影响写操作并报告具体原因，继续其他独立验收。
